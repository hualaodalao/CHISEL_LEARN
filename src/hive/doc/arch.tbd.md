# Hive NPU Core 架构待处理问题

本文记录[总体架构](arch.md)的审查问题、处理边界与状态。问题关闭需经过人工审查；“待人工审查”不等于已经批准。

状态定义：

- **待处理**：尚未修改架构正文；
- **处理中**：当前轮次正在修改；
- **待人工审查**：修改已完成并完成一致性检查，等待人工确认；
- **已关闭**：人工确认后关闭。

## P0：架构基线与验收闭环

| ID | 问题 | 需要完成的内容 | 状态 |
|---|---|---|---|
| P0-1 | G0 产品工作负载与路线图不一致 | G0 架构基线统一为 0.5B–1.5B W4 模型和 YOLO 等视觉模型；从 `arch.md` 移除 7B 模型及其派生容量、带宽、时延算例；7B 归入 G1，不在 G0 架构中体现 | **待人工审查** |
| P0-2 | G0 与 G0 Pro 的 SKU 定位不统一 | 两核 × 500 MHz、1T 定义为 G0；四核 × 500 MHz、2T 定义为后续 G0 Pro；统一配置、算力、互联、性能和验收章节中的名称 | **待人工审查** |
| P0-3 | G0 规范配置仍包含多个未冻结候选 | 建立 G0/G0 Pro 规范矩阵，区分 MUST、候选参数、明确不支持项和冻结里程碑；覆盖 SRAM、DMA、系统互联、同步单元、VPU 和内存配置 | **待处理** |
| P0-4 | 系统接口与内存模型未形成互操作契约 | 冻结 AXI profile、ring 事务、tag/事件生命周期、错误传播、顺序域、fence/drain、结果可见性、Host coherence 方案和原子线性化点 | **待处理** |
| P0-5 | 缺少持续性能与端到端工作负载的通过门槛 | 建立版本化 benchmark manifest，冻结模型、输入尺寸、数据格式、测量窗口、最低持续吞吐、时延、利用率、功耗状态和 G0 Pro 扩展效率 | **待处理** |
| P0-6 | DRAM 带宽、容量与算子映射未闭环 | 按 G0/G0 Pro 冻结 LPDDR4x 容量、位宽、速率、最低持续 payload 和流量预算；明确 attention、VPU、GEMM、DMA 的逐算子落点、格式转换及服务时间 | **待处理** |
| P0-7 | 缺少可执行的 PPA/面积决策框架 | 以 TSMC 12nm 为基线建立面积/功耗预算树；区分逐核复制成本与 cluster 固定成本；建立 SRAM 容量×bank×端口×ECC×macro 以及互联/VPU/DMA 候选决策表 | **待处理** |

## P1：接口、生命周期与可验证性

| ID | 问题 | 需要完成的内容 | 状态 |
|---|---|---|---|
| P1-1 | 命令和 tag 生命周期不完整 | 定义入口仲裁、slot/tag 分配与回收、依赖合法性、取消、异常终止、重复完成防护和入口公平性 | **待处理** |
| P1-2 | reset、timeout 与故障封锁语义不完整 | 定义局部 reset 时已接受事务的 drain/标错、peer 隔离、部分写可见性、fatal/timeout 恢复范围和 debug 生命周期 | **待处理** |
| P1-3 | QoS 与前进性只有原则，没有有界保证 | 为 GEMM、VPU、DMA、CPU/debug 和 peer 流量定义最小服务率、仲裁窗口或最大等待时间，并给出最坏竞争验收场景 | **待处理** |
| P1-4 | SRAM 容量公式未覆盖重叠生命周期峰值 | 将当前任务 A/B/C、下一任务预取、上一任务写回、VPU scratch、scale/参数和 guard 区放入统一生命周期峰值模型 | **待处理** |
| P1-5 | clock/reset/power domain 缺少生命周期表 | 明确时钟域、复位依赖、CDC、clock-gating 进入/退出、唤醒源、隔离和 retention 规则 | **待处理** |
| P1-6 | 需求缺少架构级可追溯标识 | 增加 Architecture Requirement ID，并映射责任规格、RTL/软件责任、验证项和通过标准；不与模块 Feature ID 混用 | **待处理** |
| P1-7 | PMU 尚不足以支撑性能验收 | 冻结计数事件、口径、位宽、溢出、清零、snapshot 和跨模块时间基准，将观测能力列为持续性能验收前置 | **待处理** |
