# IBM Granite 4.0-H-Tiny 逐层计算拆解

2026-10-29 ｜ 依据 `config.json`、权重清单（586 个张量，13,878,074,496 B）、`modeling_granitemoehybrid.py`（transformers main 分支）与 checkpoint 内实际张量值核对

## 摘要

Granite-4.0-H-Tiny 是文本模型，总参数 6,939,037,248。40 层里 36 层是 Mamba-2、4 层是普通 attention（第 5、15、25、35 层），每层再挂一个 64 选 6 的稀疏 MoE 和一个 1024 维的共享专家。hidden 1536，词表 100,352，embedding 与 lm_head 共享。

对芯片设计影响最大的几项：

- 参数量的 **87.0%** 在专家里（6.040 B），但 decode 每 token 只读 **1,465,470,528** 个参数（21.1%）。MXFP8 下每 token **1.511 GB**，310 GB/s 上限 **205 token/s**，S=131072 时降到 120。算术强度 **1.00 MAC/B**，与 0.8B 的 0.99 几乎相同，引擎规格可以复用。
- 容量比带宽更早撞墙：全量权重 MXFP8 是 **7.154 GB**，加 131K 的 KV 1.074 GB 一共 8.23 GB，8 GB 设备装不下。专家改 4 bit 才降到 4.136 GB。这是本模型与 0.8B（MXFP8 0.90 GB）最根本的差别。
- 36 层 SSM 状态 FP32 共 **58.061 MB**，是 0.8B 的 3.08 倍。这个数超过任何端侧 SRAM，只能落 DRAM，代价是每 token 多 **116.1 MB** 流量（+7.7% 时间），并把 36 层 scan 的串行段从 114 µs 拉到 **365 µs**。
- SSM 状态不随上下文增长，KV 也只随 S 线性长：4 层 × 4 头 = **8,192 B/token**，是 0.8B 的 2/3。131K 上限处 KV 只有 1.074 GB，是权重的 **71%**，永远追不上权重——与 0.8B 在 63K 就被 KV 反超的结论相反。
- 单算子最大的是 6 个专家的 gate/up 合并投影 **9.44 M MAC**，单张量最大的是 `in_proj`（[6448,1536]）**9.90 M MAC**。lm_head 只占 10.2% MAC 和 10.5% 带宽，不再是 0.8B 那种"头部瓶颈"，采样也不再是第二大延迟项。
- 批处理是唯一有效的手段：权重在批内只读一次，B=4 等效 **2.05×**、B=32 **7.01×**；但每序列 58.061 MB 的 SSM 状态 SRAM 只能放一份，状态落 DRAM 后 B=32 降到 4.56×。模型没有 MTP 头，投机解码这条路不存在，叠上专家 4 bit 后上限约 6.3×（1,286 token/s）。

后面按"模型事实、层结构、逐算子、算力与带宽、硬件映射、量化、结论"展开。

# 第 1 章　事实基线

## 1.1 数据来源与核对方法

这份拆解依赖四类材料：仓库 `ibm-granite/granite-4.0-h-tiny` 的 `config.json`；三个分片 `model-00001/2/3-of-00003.safetensors` 的 header（读出每个张量的名字、形状、dtype、字节区间，共 586 个）；`transformers` 的 `granitemoehybrid` 建模代码（Mamba-2 mixer、MoE、router 的实现都在这里）；以及从 checkpoint 里按字节区间直接取出的 `A_log`、`dt_bias`、`D` 小张量，用于判断数值范围。

核对有三条，全部对上。

第一，header 里 586 个张量的元素数之和是 6,939,037,248，全部 BF16，乘 2 得 13,878,074,496 B，与三个分片 `data_offsets` 拼起来的文件总字节数**完全相等，差额 0 B**。这批权重没有对齐填充，也没有 FP32 参数，所以这次的差额不像 0.8B 那样有 2,592 个参数的缺口。

第二，`index.json` 的 `metadata.total_parameters` 独立给出 6,939,037,248，与逐张量求和一致；`metadata.total_size` 给出 13,878,074,496，与文件字节一致。

第三，逐层求和：36 个 Mamba-2 层各 170,457,488、4 个 attention 层各 162,106,368、embedding 154,140,672、final norm 1,536，合计 6,939,037,248，与 header 分组统计逐位相符。张量计数也能反查：36 × 15 + 4 × 11 + 2 = 586。

**这里有一个与 0.8B 完全不同的结构事实：参数量的分布不是"每层若干、embedding 一大块"，而是"每层 155.81 M 的专家阵列 + 14.65 M 的 mixer"。** 专家占了 87.0%，embedding 只占 2.2%。所以在 H-Tiny 上，"embedding 占比随模型变小而升高"这条 0.8B 的规律不适用——这里 embedding 相对不算大，因为分母被专家撑大了。同一逻辑下，lm_head 的 154.14 M 只占每 token 流量的 10.5%。

## 1.2 关键超参

| 项 | 值 | 与 0.8B 的差异 |
|---|---|---|
| `hidden_size` | 1536 | 0.8B 是 1024 |
| `num_hidden_layers` | 40 | 0.8B 是 24 |
| `layer_types` | 36 × `mamba` + 4 × `attention`，attention 在 5/15/25/35 | 0.8B 是 18 DeltaNet + 6 attention（3:1），本模型 9:1 |
| `num_attention_heads` × `head_dim` | 12 × 128 | 0.8B 是 8 × 256，总宽都是 1536 |
| `num_key_value_heads` | 4（GQA 3:1） | 0.8B 是 2（4:1） |
| `attention_multiplier` | 0.0078125 = **1/128** | 0.8B 的缩放是 1/16 = 1/√256；本模型是 1/d 不是 1/√d |
| `attention_bias` | false | 相同 |
| `mamba_expand` × hidden | 2 × 1536 = `d_inner` 3072 | 0.8B 无此项（DeltaNet 的 v 维是 16×128=2048） |
| `mamba_n_heads` × `mamba_d_head` | 48 × 64 = 3072 | 0.8B 是 16 × 128 |
| `mamba_d_state` | 128 | 0.8B 的 key 维也是 128，但用途不同 |
| `mamba_n_groups` | **1** | 48 个头共享同一组 B/C，广播读 |
| `mamba_d_conv` | 4（带 conv bias） | 0.8B 也是 4，无 bias |
| `mamba_chunk_size` | 256 | 只影响 prefill 的分块形式 |
| `num_local_experts` / `num_experts_per_tok` | 64 / 6 | 0.8B 无 MoE |
| `intermediate_size`（单专家） | 512 | 0.8B 的 MLP 是 3584 |
| `shared_intermediate_size` | 1024 | 0.8B 无共享专家 |
| `vocab_size` | 100,352 | 0.8B 是 248,320 |
| `tie_word_embeddings` | true | 相同，header 里没有 `lm_head` 张量 |
| `position_embedding_type` | **`nope`**，没有 RoPE | 0.8B 有部分 RoPE（64/256）+ mRoPE |
| `embedding_multiplier` | 12 | 0.8B 无 |
| `residual_multiplier` | 0.22 | 0.8B 无（残差直接相加） |
| `logits_scaling` | 6 | 0.8B 无 |
| `rms_norm_eps` | 1e-5 | 0.8B 是 1e-6 |
| `max_position_embeddings` | 131,072 | 0.8B 是 262,144 |
| `hidden_act` | silu | 相同 |
| `torch_dtype` | bfloat16 | 与 0.8B 的 BF16 相同 |

有三处值得单独说。

**位置信息完全不进模型。** `position_embedding_type: "nope"`，建模代码里 `rotary_emb` 为 `None`，attention 的 `position_embeddings` 参数是 `None`，Mamba-2 侧也没有任何位置项。位置只能由因果卷积（3 个历史 token）和 SSM 的衰减隐式携带。对硬件的直接后果是：省掉了 RoPE 的置换网络与三角函数表，但 attention 层对"顺序"的感知只剩 4 层、每层靠 QKᵀ 与 KV 顺序，长上下文的位置精度只能靠训练保证，不能靠算法兜底。

**attention 的缩放是 1/128，不是 1/√128。** `attention_multiplier = 0.0078125`，等于 `1/head_dim`。标准做法是 `1/√128 ≈ 0.0884`，这里小了 11.3 倍。score 整体偏小意味着 softmax 更平、p 更接近 1/S。硬件若按 1/√d 实现，attention 输出会被放大 11 倍，而且形状完全对得上，属于不会报错的静默错误。

**三个全局缩放常数改变了数值范围。** embedding 后乘 12、每个子层输出乘 0.22 再加回残差、logits 除以 6。这三步都是逐元素，MAC 可以忽略（每 token 约 12.4 万次），但它们决定了残差流和 logits 的动态范围，量化时必须原样保留，不能折进相邻的 GEMM。

# 第 2 章　模型全景

## 2.1 组件关系

模型没有视觉塔，也没有 MTP 头，只有一条文本主干。

```
Granite-4.0-H-Tiny  6,939.04 M
├─ embedding  [100352,1536]        154.14 M  （与 lm_head 共享）
├─ 36 × Mamba-2 层                 6,136.47 M ─┬─ mixer（in_proj/conv/scan/out_proj） 527.24 M
│                                             └─ MoE（64 选 6 + 共享）             5,609.23 M
├─ 4 × Attention 层                  648.43 M ─┬─ mixer（q/k/v/o）                    25.18 M
│                                             └─ MoE                                5,609.23 M
├─ final norm [1536]                  0.0015 M
└─ lm_head = embedding（tied）           0 M  （不占容量，占带宽）
```

纯文本、单序列、不批处理，是这颗芯片要面对的唯一负载。没有视觉塔意味着第 7 章从"视觉塔 + 输出头"收缩成"输出头 + 路由"；没有 MTP 意味着第 10.3 节少了一条最有效的提速路径。

## 2.2 文本主干的层型配比

40 层按 9:1 放置，第 5、15、25、35 层是 attention，其余 36 层是 Mamba-2。这个比例比 0.8B 的 3:1 更极端。

| 层型 | 层数 | 每层参数 | 合计 | 每层 MAC（decode） | 结构特征 |
|---|---:|---:|---:|---:|---|
| A　Mamba-2 + MoE | 36 | 170,457,488 | 6,136,469,568 | 34,868,146 | 融合投影 + 深度卷积 + 标量衰减外积 + 64 选 6 |
| B　Attention + MoE | 4 | 162,106,368 | 648,425,472 | 25,310,610（不含 S 项） | q/k/v/o + KV cache，无位置编码 |
| C　共享专家（每层一份） | 40 | 4,718,592 | 188,743,680 | 4,721,664 | gate/up 合并 2048 + down 1024 |

两种层的参数只差 5.1%，因为 91% 的参数是两者共用的 MoE。**真正决定硬件形态的不是参数，而是状态**：Mamba-2 层的状态是每层 1.57 MB 的定长矩阵，attention 层的状态是随 S 增长的 KV。改成 9:1 之后，KV 的层数从 0.8B 的 6 层降到 4 层，每 token KV 从 12,288 B 降到 8,192 B。

为什么是这个比例：KV 是长上下文里唯一线性增长的项，压到 4 层后 131K 上下文只要 1.074 GB；而 Mamba-2 的状态与 S 无关，层数再翻倍也只增加固定的 58 MB。代价是 attention 只剩 4 次全局混合机会，位置信息又完全没有显式编码，这两点都由训练来补偿。

## 2.3 计算形态的四个类别

| 类别 | 特征 | 本模型里的算子 | 典型维度 |
|---|---|---|---|
| 稠密矩阵乘（GEMM / GEMV） | 激活 × 权重 | 所有 `*_proj`、6 个专家的 gate/up/down、共享专家、router、lm_head、QKᵀ、A·V | K 是读入维，N 是输出维，M 是 token 数 |
| 归约 | 沿一维求和或求最值 | RMSNorm（1536）、RMSNormGated（3072）、softmax（S）、top-6（64） | 1536 / 3072 / S / 64 |
| 逐元素 | 同形状逐点 | silu、softplus、exp、门控乘、三个缩放常数、残差、专家加权 | 任意 |
| 串行递推 | 后一步依赖前步 | SSM 状态更新（衰减 + 外积 + 读出） | 48 头 × 64×128 |

decode 时所有矩阵乘退化成 M=1 的 GEMV，prefill 时是 M=S 的 GEMM。Mamba-2 的串行部分是"逐元素乘 + 秩 1 外积 + 矩阵向量乘"，与 0.8B 的 delta 递推同类，但状态形状从 128×128 方阵变成 64×128 的长条，更新规则从 delta rule 变成"标量衰减 + 外积"。

外加三个非计算类别：查表（embedding）、搬运（KV cache、conv 状态滚动、状态读写）、控制（40 次 top-6 路由、采样）。

## 3.2 层的通用骨架

两种层共用同一个模板，只有中间的 mixer 不同。注意残差那一行的 0.22：每个子层的输出先乘 0.22 再加回主路，这是 Granite 与 Llama 系在骨架层的唯一差别。

```
x [1,1536]
 │
 ├─ 读出 ─► r = input_layernorm(x)  [1,1536]
 │            │
 │            ▼
 │          y = mixer(r)  [1,1536]        ← 层型 A（3.3）/ B（3.4）
 │            │
 └─ x = x + 0.22·y ◄┘                     ← 残差 ①，唯一写回 x 的点
 │
 ├─ 读出 ─► r = post_attention_layernorm(x)  [1,1536]
 │            │
 │            ▼
 │          z = moe(r) + shared(r)  [1,1536]   ← 子模块 C（3.5）
 │            │
 └─ x = x + 0.22·z ◄┘                     ← 残差 ②
 │
输出 x [1,1536]（形状与输入完全相同）
```

**读图约定（第 3 章所有 DAG 通用）**

| 记号 | 含义 |
|---|---|
| `─►` / `──►` | 同 token 内的数据依赖，箭头上带计算 |
| `┄` / `┄┄►` | 纯视图（split / reshape / transpose），0 MAC，只改索引与 stride |
| `═` / `══►` | 跨 token 状态读写（`conv_state` / SSM 状态 / KV cache） |
| `[G0]` `[G1]` … | 并行组：同组内互不依赖，可并发发射；组号小的必须先完成 |
| `[A①]` `[B①]` … | 各层型的算子编号，按执行顺序，与第 6 章一一对应 |
| 横向分支 | 只表示并行关系，不表示时间先后；汇合点之前的所有分支都必须就绪 |

层内只有三种形状变换，其余都是逐元素：

| 变换 | 形状关系 | 例子 | 通道语义 |
|---|---|---|---|
| 稠密线性 | `[K] → [N]` | `in_proj` 1536→6448、专家 `input_linear` 1536→1024 | 全部通道混合，每个输出 = 全 K 维内积 |
| 逐元素 / 逐通道 | `[N] → [N]` | RMSNorm 缩放、silu、门控乘、0.22 缩放、残差加 | 一进一出，通道对齐 |
| 纯视图 | `[N] → [M₁]…[Mₖ]`（∏Mᵢ = N） | `split` 6448→3072+3328+48、`reshape` 3072→48×64 | 不改数，只改索引 |

残差流的宽度全程恒为 `[1536]`。这个宽度只有每层专家内部宽度（3072）的一半，意味着归一化、门控、残差这些逐元素开销都按 1536 算，而矩阵乘的 K 维在 1536（mixer 入口）与 3072（`out_proj` 入口）之间跳。

## 3.3 层型 A：Mamba-2 + MoE（36 层）

Mamba-2 替代 attention 的方式，是把所有历史压进一个固定的 `48 × 64 × 128` 状态张量，每来一个 token 做一次"标量衰减 + 秩 1 外积 + 读出"。与 0.8B 的 DeltaNet 相比，状态元素数从 16×128×128 = 262,144 变成 48×64×128 = 393,216（多 50%），更新从 delta rule（3 次 128×128 matvec）变成标量衰减（1 次逐元素乘）+ 外积 + 1 次 64×128 matvec。

子模块共 9 个，全部挂在 `mamba.*` 下：

| 张量 | 形状 | 作用 |
|---|---|---|
| `mamba.in_proj` | [6448, 1536] | 一次投影出 z（3072）、x+B+C（3328）、dt（48） |
| `mamba.conv1d` | [3328, 1, 4] + bias | 深度可分离因果卷积，作用在 x+B+C 上，之后接 silu |
| `mamba.A_log` | [48] | 每头一个衰减基，运行时算 `A = -exp(A_log)` |
| `mamba.dt_bias` | [48] | softplus 之前的偏置，实际值低到 -23.9 |
| `mamba.D` | [48] | 每头一个跳连系数，作用在 x 上 |
| `mamba.norm` | [3072] | RMSNormGated 的增益，整行 3072 一次归约 |
| `mamba.out_proj` | [1536, 3072] | 输出投影 |
| `block_sparse_moe.*` | 见 3.5 | 64 个专家 + router |
| `shared_mlp.*` | 见 3.5 | 常开的 1024 维专家 |

独有的三个算子：

1. **融合投影**：z / x+B+C / dt 由一次 1536→6448 的 GEMV 产出，DMA 侧必须按 3072 / 3328 / 48 三段切分。
2. **深度因果卷积 + silu**：跨 token 的局部感受野，需要保存前 3 个 token 的 3328 维向量（滚动缓存）。
3. **选择性状态更新**：`S ← a·S + dt·x⊗B`，`y = S·C + D·x`；a 是每头一个标量，B/C 在 48 个头之间共享。

### 3.3.3 关键路径与并行机会

- 关键路径：`G0 → G1 → G3(conv) → G5(dt) → G6(scan) → G7 → G8 → G9 → G10 → G11 → G12 → G14`。
- `z` 支路从 G2 一直存活到 G7，跨度覆盖 conv、dt、scan 三段，是层内生命周期最长的数据（3072 × 2 B = 6 KB）。
- dt 的计算（288 MAC）只有 48 个元素，但它必须在 scan 之前完成，且必须 FP32。它是层内最小的算子，也是唯一不能与 scan 重叠的算子。
- scan 只占 3.4% 的 MAC，却是唯一不能与矩阵引擎重叠的串行段：48 个头可以并行，但每个头内部"衰减 → 外积 → 读出"三步有序。
- 权重侧：G1 的 9.90 M 与 G8 的 4.72 M 是 mixer 的全部，占本层权重的 43.5%；G12 的 6 个专家占 42.1%；G13 的共享专家占 14.0%。
- 该层有三处跨 token：conv（读 3 个历史 token）、scan（读改写 1.51 MB 状态）、以及隐式的"状态跨 36 层串行"。

## 3.4 层型 B：Attention + MoE（4 层）

Mixer 子模块只有 4 个投影，加骨架自带 2 个 norm：

| 张量 | 形状 | 作用 |
|---|---|---|
| `self_attn.q_proj` | [1536, 1536] | 12 头 × 128 |
| `self_attn.k_proj` | [512, 1536] | 4 个 KV 头 × 128 |
| `self_attn.v_proj` | [512, 1536] | 同上 |
| `self_attn.o_proj` | [1536, 1536] | 12 × 128 → 1536 |
| `input_layernorm` / `post_attention_layernorm` | [1536] | 骨架自带 |

与 0.8B 的 attention 层相比少三样、多一样：少 q_norm/k_norm、少 RoPE、少输出门控；多的是 MoE（占本层参数的 96.1%）。

### 3.4.1 计算流（decode 单 token，依赖 DAG）

```
x [1,1536] ──► [G0] input_layernorm ──► r [1,1536]
                                          │
        ┌─────────────────┬───────────────┴──────────┐
        ▼                 ▼                          ▼
  [G1] q_proj        [G1] k_proj                [G1] v_proj
   [1,12,128]         [1,4,128]                  [1,4,128]
        │                 │                          │
        │           [G2] 写 K cache ═              [G2] 写 V cache ═
        │           k[1,4,S,128]                  v[1,4,S,128]
        ▼                 │                          │
  [G2] ×(1/128)           │                          │
        └────────┬────────┘                          │
                 ▼                                    │
        [G3] Q·Kᵀ ◄═══════════════════════════════════│
                 │  s [1,12,1,S]                     │
                 ▼                                    │
        [G4] 因果 mask + softmax (FP32)               │
                 │  p [1,12,1,S]                      │
                 ▼                                    │
        [G5] A·V ◄════════════════════════════════════┘
                 │  o [1,12,1,128] → [1,1536]
                 ▼
        [G6] o_proj ──► m [1,1536]
                 ▼
        [G7] x = x + 0.22·m ──► x
                 ▼
        [G8] post_attention_layernorm ──► MoE（3.5，同 A 层）
```

`repeat_kv` 是 stride-0 的逻辑视图：12 个 Q 头共享 4 个 KV 头，每个 KV 头被 3 个 Q 头复用。硬件若按 12 头各读一份 KV，G3/G5 的 KV 带宽直接变 3 倍。

### 3.4.2 逐算子映射表

| 组 | 算子 | 形状（in → out） | 数值变换 | MAC/token | 依赖 |
|---|---|---|---|---|---|
| G0 | input_layernorm | `[1,1536] → [1,1536]` | `x·rsqrt(mean(x²)+1e-5)·w` | 3,072 | x |
| G1 | q_proj | `[1,1536] → [1,12,128]` | `q = W_q·r` | 2,359,296 | G0 |
| G1 | k_proj / v_proj | `[1,1536] → [1,4,128]` × 2 | `k = W_k·r`、`v = W_v·r` | 1,572,864 | G0 |
| G2 | 缩放 | `[1,12,128]` | `q_i ← q_i · 0.0078125`，在 QKᵀ 之前 | 1,536 | G1 |
| G2 | K/V cache 追加 | k/v → `[1,4,S+1,128]` | 纯搬运，无 norm、无旋转 | 0 | G1 |
| G3 | Q·Kᵀ | `[1,12,1,128] × [1,12,S,128] → [1,12,1,S]` | `s = Σ_{d=0..127} q_d·k_d` | 1,536·S | G2 |
| G4 | 因果 mask + softmax | `[1,12,1,S] → [1,12,1,S]` | `p = exp(s−m)/Σexp(s−m)`，FP32 | 36·S | G3 |
| G5 | A·V | `p × v → [1,12,1,128] → [1,1536]` | `o = Σ_{t=1..S} p_t·v_t` | 1,536·S | G4，G2(v) |
| G6 | o_proj | `[1,1536] → [1,1536]` | `m_o = Σ_i W_o[o,i]·o_i`，跨头混合 | 2,359,296 | G5 |
| G7 | 残差 ① | `[1,1536]` | `x = x + 0.22·m` | 3,072 | G6 |
| G8 | post_attention_layernorm | `[1,1536] → [1,1536]` | 同 G0 | 3,072 | G7 |

softmax 按每个元素 3 次运算计（exp、分母累加、归一化乘），12 头共 36·S；0.8B 那份文档按 1 次/元素计，两篇的 softmax 数字不可直接比较，比较时以本节口径为准。

### 3.4.3 关键路径与并行机会

- 关键路径：`G0 → q_proj → 缩放 → Q·Kᵀ → softmax → A·V → o_proj → 残差`。
- 三条并行支路：Q（投影→缩放）、K（投影→写 cache）、V（投影→写 cache）。K/V 不在关键路径上，代价体现在 G3/G5 的读取上。
- 没有 RoPE、没有 q/k norm，`q_proj` 之后直接乘常数，这是本层与 0.8B attention 层最大的实现差异：少了两处按头归约和一处 64 维旋转。
- G4 是层内唯一逐行全 S 归约加超越函数。S=131072 时每层 1,572,864 个 exp，SFU 按四分之一速率算要 18.4 µs，4 层 73.7 µs。
- decode 时 G3/G5 是 M=12、K=S 的 GEMV，算力利用率不到 10%，受 KV 带宽支配；prefill 时变成 `S×S×128` 的 GEMM，整层形态完全不同。

## 3.5 子模块 C：MoE 块（40 层各挂一份）

每层一个 router、64 个专家、1 个共享专家。router 与专家之间是"先选后算"的硬依赖。

| 张量 | 形状 | 作用 |
|---|---|---|
| `block_sparse_moe.router.layer` | [64, 1536] | 每 token 64 个 logits（FP32 计算） |
| `block_sparse_moe.input_linear` | [64, 1024, 1536] | 64 个专家的 gate+up 合并存储 |
| `block_sparse_moe.output_linear` | [64, 1536, 512] | 64 个专家的 down |
| `shared_mlp.input_linear` | [2048, 1536] | 共享专家的 gate+up |
| `shared_mlp.output_linear` | [1536, 1024] | 共享专家的 down |

计算：`y = Σ_{e∈top6} w_e · down_e( silu(gate_e(x)) ⊙ up_e(x) ) + shared(x)`

```
r2 [1,1536] ──► [M1] post_attention_layernorm（已在 3.2 计入）──► r [1,1536]
                                                                    │
                    ┌───────────────────────────────────────────────┴──────────┐
                    ▼                                                          ▼
        [M2] router [1,64]（FP32）                              [M7] shared gate/up [1,2048]
                    │                                                          │
                    ▼                                                          ▼
        [M3] top-6 下标 + softmax 权重                             [M7] silu(g)⊙u [1,1024]
                    │                                                          │
        ┌───────┬───┴───┬───────┬───────┬───────┐                             ▼
        ▼       ▼       ▼       ▼       ▼       ▼                    [M7] down [1,1536]
      [M4]    [M4]    [M4]    [M4]    [M4]    [M4]                            │
    gate/up  gate/up …（6 个专家，形状相同）                                    │
        ▼       ▼       ▼       ▼       ▼       ▼                            │
      silu·up silu·up …                                                        │
        ▼       ▼       ▼       ▼       ▼       ▼                            │
      [M5]    [M5]    …  down [1,1536]                                         │
        └───────┴───┬───┴───────┴───────┴───────┘                             │
                    ▼                                                          │
        [M6] Σ w_e·y_e ───────────────────────────────────────────────────────┤
                                                                               ▼

```

6 个专家之间完全并行，但它们的下标要等 router 出结果。这个"先算 64 维 logits、再按结果取 14.6 MB 权重"的顺序，是 MoE 层在硬件上唯一的串行点，第 10.2 节会给出它的绝对时间。

## 3.6 层型 D：没有投机头

0.8B 在这一节写的是 MTP 头（20.45 M 参数、1 个完整 attention 层、自带 KV）。H-Tiny 没有：header 里没有 `mtp.*` 前缀，`config.json` 里没有 `mtp_num_hidden_layers`，词表 100,352 也只对应一套 embedding。

对芯片的含义有两条，都是负面的：第一，第 10.3 节的提速手段少了一条最有效的（0.8B 上投机解码在 γ=3、8K 剪枝头时能到 2.27×）。第二，decode 的词表成本无法通过"草稿头剪枝"摊薄，lm_head 的 158.9 MB 每 token 都要付一次。

## 3.7 层间差异速查

| 问题 | 答案 |
|---|---|
| 36 层 Mamba-2 之间有区别吗 | 没有。张量名、形状、算子顺序完全一致 |
| 4 层 Attention 之间有区别吗 | 没有。同上 |
| 40 个 MoE 之间有区别吗 | 没有。都是 64 专家 + 共享 1024 |
| Mamba-2 和 Attention 的本质区别 | 状态传递方式：定长 48×64×128 vs 增长到 131072 的 KV |
| 位置信息怎么进来 | 完全没有显式位置编码；靠 4-tap 卷积与 SSM 衰减隐式携带 |
| 哪些层有跨 token 状态 | 全部 40 层：36 层有 conv_state + SSM 状态，4 层有 KV cache |
| 与 0.8B 的层结构有区别吗 | 有。比例 9:1 对 3:1；无位置编码；MLP 换成 64 选 6 的 MoE |
| 每层最贵的算子 | Mamba-2 层是 `in_proj`（9.90 M）；Attention 层是 6 个专家的 gate/up（9.44 M） |

├ [G10] silu(g) ⊙ u ─────► [6, 512]                      逐元素 + exp
├ [G10] down ×6 ────────► [6, 1536]                      GEMM 6×512×1536
├ [G11] Σ w_e·y_e ──────► y  [1, 1536]                   加权累加
├ [G12] shared gate/up ► [1, 2048] → silu·up → down      GEMM 1536×2048 + 1024×1536
│
x = x + 0.22·(y + z_s) [G12]  [1, 1536]                 逐元素
```

**并行结构速查（decode）**

| 并行组 | 内容 | 性质 |
|---|---|---|
| G0 | `input_layernorm` | 单点，1536 宽归约 |
| G1 | `in_proj` | 单点，一次 6448 输出的 GEMV |
| G2 | `conv1d` / `dt` | 两条可并发，conv 等 xbc，dt 等 dt 段 |
| G3 | `split` + dt 的 `exp` | 纯视图 + 48 路超越函数 |
| G4 | `SSM scan` | 汇合点：等 conv 后的 x/B/C 与 dt 的 a；48 头并行，头内 3 步串行 |
| G5 | `门控 + RMSNormGated` | 汇合点：等 scan 的 y 与 G1 的 z（存活最久） |
| G6–G8 | `out_proj` → 残差 → 后置归一 | 严格串行 |
| G9 | `router` + `top-6` | 单点，且门控了后续 14.6 MB 的权重读取 |
| G10 | 6 个专家 | 完全并行，但下标要等 G9 |
| G11 | 加权求和 | 汇合点 |
| G12 | 共享专家 + 残差 | 与 G10 并行，最后一并相加 |

对硬件和测试最直接的三点：

1. 关键路径是 `G0 → G1 → G2(conv) → G4(scan) → G5 → G6 → G7 → G8 → G9 → G10 → G12`。dt 支路（288 MAC）不延长路径，但它是 scan 的输入，必须与 conv 同批发射。
2. 测试向量的切分点就在 `[G]` 边界。per-op 对拍时按 G0–G12 各存一份参考值，尤其要单独存 scan 前后的状态，因为 scan 的错误在单 token 上看不出来，只有连续 decode 到第 3 个 token 之后才暴露。
3. 只有 G2（conv）与 G4（scan）跨 token，状态合计 1.57 MB/层。1.57 MB 恰好是一块 SRAM bank 的量级，但 36 层加起来 58.06 MB，这是全局问题（8.3）。

# 第 5 章　通用算子库

这一章收三种东西：跨层型复用的算子、形状容易看错的算子、以及本模型与 0.8B 写法不同因而最容易照抄错的算子。每个算子五段：形状、公式、MAC、精度、坑。MAC 的口径在这一章定死，后面章节不再重复：

| 运算 | 计账方式 |
|---|---|
| 点积（GEMM / GEMV / 卷积抽头） | 每个乘加 1 次 |
| 纯逐元素（加、乘、缩放、残差） | 每元素 1 次 |
| 融合乘加（`y += w·x`） | 每元素 2 次 |
| silu | 每元素 2 次（1 次 SFU 求 sigmoid、1 次乘） |
| 门控乘 `y ⊙ silu(z)` | 在 silu 的 2 次上再加 1 次 |
| RMSNorm | 每元素 2 次（平方累加、缩放并乘增益） |
| softmax | 每元素 3 次（exp、累加、归一化乘） |
| 纯视图（split / reshape / transpose） | 0 次 |

## 5.1 RMSNorm

| 项 | 内容 |
|---|---|
| 形状 | `[1,1536] → [1,1536]`，每层 2 次，加 final norm 每 token 共 81 次 |
| 公式 | `y_i = x_i · rsqrt(mean(x²) + 1e-5) · w_i`，增益是 `w` 本身，不是 `1 + w` |
| MAC | 每元素 2 次，单次 3,072，每 token 81 × 3,072 = 248,832（占 0.02%） |
| 精度 | 平方和在 FP32 累加，rsqrt 用 FP32，输出 BF16；增益 BF16 |
| 坑 | 三个：增益写成 `1+w` 会把 0.8B 的实现直接搬错；`eps=1e-5` 是 0.8B 的 10 倍，残差流小的时候不可忽略；rsqrt 每行只算 1 次，若按元素算会多出 1535 次超越函数 |

81 次的来源是 40 层 × 2 加 final norm 1 次。这个数在 0.8B 上是 49 次，本模型多了 65%，但绝对量仍只有 0.25 M MAC，不值得为它做专用指令；值得做的是把"平方累加"和"缩放乘增益"两级流水合到一个 1536 宽的归约单元里，避免每层两次全宽同步。

## 5.2 RMSNormGated

| 项 | 内容 |
|---|---|
| 形状 | `[1,3072] → [1,3072]`，36 次/token，只在 Mamba-2 层出现 |
| 公式 | `u = (y + D·x) ⊙ silu(z)`；`o = u · rsqrt(mean₃₀₇₂(u²) + 1e-5) · w` |
| MAC | 每元素 6 次（跳连 1、silu 2、门控 1、归一 2），3072 × 6 = 18,432/层，每 token 663,552 |
| 精度 | `u` 与方差在 FP32；`z` 来自 in_proj 的第 1 段，BF16 足够；输出 BF16 |
| 坑 | 归一化跨全部 3072 维，不是按 48 个头各归各的 64 维。按头归一会得到数值完全不同、形状却完全合法的结果；门控在归一之前，所以 `silu(z)` 起的是"方向掩码"作用，缩放不会把它抵消 |

这一条与 0.8B 的 DeltaNet 层在结构上等价：都是"先门控再整行归一"，都是每层一次整行归约。差别在宽度——DeltaNet 的输出门是 2048 维，这里是 3072 维，正好等于 `d_inner`。

## 5.3 SiLU 与 SwiGLU

| 项 | 内容 |
|---|---|
| 形状 | 逐元素，三种宽度：Mamba 门控 3072、专家 512、共享专家 1024 |
| 公式 | `silu(x) = x·sigmoid(x)`；专家内 `h = silu(g) ⊙ u`，其中 `[g;u]` 是 `input_linear` 输出的前后两半 |
| MAC | silu 2 次/元素，门控乘再加 1 次；每 token 394,240 个 silu 元素，共 1,182,720 次 |
| 精度 | BF16 输入输出，sigmoid 的 exp 需要 8 bit 有效精度；不需要 FP32 |
| 坑 | 专家 `input_linear` 的输出是 1024 维，前 512 走 silu、后 512 直接乘，切分点在 512 而不是 1024；切错不会报错，只会让数值缓慢漂移 |

394,240 这个数按四块加：36 层 × (3072 + 6×512 + 1024) = 258,048；4 层 × (6×512 + 1024) = 16,384；36 层卷积后的 silu 3,328 × 36 = 119,808。三块相加 394,240。摊到每 token 只有 1.18 M 次运算，是 MAC 总量的 0.08%，不值得为它单做一条激活流水线。

## 5.4 因果深度卷积

| 项 | 内容 |
|---|---|
| 形状 | `[1,3328] × [3328,1,4] + [3328] → [1,3328]`，每组通道独立，感受野 4 个 token |
| 公式 | `y_{c,t} = silu(Σ_{j=0..3} W[c,0,j] · xbc_{c,t-3+j} + b_c)` |
| MAC | 每元素 4 个抽头加 1 次偏置加 1 次 silu 共 7 次，3,328 × 7 = 23,296/层，每 token 838,656 |
| 精度 | 权重与状态 BF16 即可，累加 FP32；卷积状态是最近 3 个 token 的 3328 维向量 |
| 坑 | 因果对齐必须是"当前 token 在最右"，即 `t-3..t`；状态初值为 0 而不是复制第一个 token；输入是 3328 维（x 与共享的 B/C 拼在一起），漏掉 B/C 的 256 维会让后面 scan 的 B/C 取到错位数据 |

这一层卷积是全模型唯一的局部感受野。它跨 token，但只跨 3 个，状态 39,936 B/层，是 SSM 状态的 2.5%。硬件上可以把它当"4 抽头 FIR"发射到向量单元，也可以塞进矩阵引擎当 1×4 的深度卷积，两种都能在 1 µs 内做完 36 层。

## 5.5 位置编码：没有

| 项 | 内容 |
|---|---|
| 形状 | 无。`position_embedding_type = "nope"`，建模代码里 `rotary_emb = None` |
| 公式 | 无。attention 的 `position_embeddings` 参数恒为 `None`；Mamba-2 侧也没有任何位置项 |
| MAC | 0。0.8B 的部分 RoPE 在这里全省 |
| 精度 | 无 |
| 坑 | 不要按 Llama 流程在 `q_proj` 后插旋转。插了不会报错，但等于给模型加了训练时没见过的变换；另一个坑是误以为"没有位置编码就不能长上下文"——位置信息由 4 tap 卷积和 SSM 的指数衰减隐式携带，131072 的上限是训练出来的，不是算出来的 |

与 0.8B 对照，这一项省下的不只是乘加：RoPE 需要每 token 1536 次 sin/cos（可查表），还需要按头重排的置换网络。省掉之后 attention 层的 q 支路只剩一次缩放，这也是 4 层 attention 的 mixer 能做到 6.29 M 参数的原因之一。

## 5.6 top-k 路由

| 项 | 内容 |
|---|---|
| 形状 | `[1,1536] → [1,64]`，取 top-6，40 次/token |
| 公式 | `l = W_r·x`（FP32）；`idx = top6(l)`；`w = softmax(l[idx])` |
| MAC | GEMV 98,304 + 6 遍 64 选最大 384 + 6 元素 softmax 18，合计 98,706/层 |
| 精度 | logits 必须 FP32；权重 FP32 算完再转 BF16 参与累加 |
| 坑 | softmax 只在 6 个值上做，64 个 logits 的和不为 1；top-6 的平局顺序要与训练一致；BF16 logits 会让 top-6 边界翻转，翻转率需要跑前向统计，本文未核到（12.3） |

98,706 里 99.6% 是那次 1536→64 的 GEMV，但它的权重只有 98,304 个参数（101,351 B），读一次 0.33 µs。真正贵的是它后面的依赖：6 个下标决定下一拍读哪 14.59 MB 专家权重，这条链在第 10.2 节会换算成 47.1 µs/层。

# 第 6 章　层型的逐算子拆解

编号规则：A①–A⑫ 是 Mamba-2 层，B①–B⑨ 是 attention 层，M1–M8 是两者共用的 MoE 块。同一个数在第 3 章、本章、第 8 章出现时必须一致，三处都已经对齐到 34,868,146 / 25,313,718 / 19,011,474 这三个锚点。

## 6.1 层型 A：Mamba-2 + MoE

### A① `in_proj`（1536 → 6448）

| 项 | 内容 |
|---|---|
| 形状 | `[1,1536] × [6448,1536] → [1,6448]`，输出按 3072 / 3328 / 48 三段切 |
| MAC | 1536 × 6448 = 9,904,128，占单层 28.4% |
| 归属 | 矩阵引擎，M=1 的 GEMV；权重 10,211,156 B |
| 精度 | 权重 MXFP8，激活 BF16，累加 FP32，输出 BF16 |
| 坑 | 6448 = 50×128 + 48，按 128 列切 tile 时最后一块只有 48 列有效；split 顺序是 z、hidden_states_B_C、dt，顺序换了不会报错但三个下游全错 |

一次 GEMV 产出 6448 个值，是层内唯一一个"输出宽度超过 4096"的算子。它的输出要同时喂给三条支路，所以它在 DAG 上是单点（G1），在流水上却要求下游三条支路都能立刻接住——这意味着 6448 × 2 B = 12.6 KB 的输出缓冲必须在 in_proj 算完之前就分配好。

### A② 深度卷积 + silu（3328 → 3328）

| 项 | 内容 |
|---|---|
| 形状 | `[1,3328]` 逐通道 4 抽头，读 `conv_state[3328,3]`，卷积后接 silu |
| MAC | 3,328 × 7 = 23,296（4 抽头、1 偏置、2 silu），占 0.1% |
| 归属 | 向量单元或 1×4 卷积引擎；跨 token，状态 39,936 B |
| 精度 | 输入 BF16，累加 FP32，权重 BF16，状态 BF16 |
| 坑 | 输入是 3328 维（x 3072 + B 128 + C 128），不是 3072；因果对齐是 `t-3..t`；状态初值为 0 |

### A③ dt 计算（48 → 48）

| 项 | 内容 |
|---|---|
| 形状 | `[1,48] → [1,48]`，每头一个步长与一个衰减因子 |
| 公式 | `dt = softplus(dt_raw + dt_bias)`；`A = -exp(A_log)`；`a_h = exp(dt_h · A_h)` |
| MAC | 48 × 6 = 288，占 0.0% |
| 归属 | SFU，48 路并行，必须 FP32 |
| 精度 | 全程 FP32。`A_log` 与 `dt_bias` 在 checkpoint 里是 BF16，加载后先升 FP32 再 exp |
| 坑 | 实测 `dt_bias` 低到 -23.875，softplus 后 `dt ≈ 4.7e-11`，低于 FP16 的最小次正规数 6e-8，FP16 下直接下溢成 0、`a` 恒为 1；即使不下溢，FP16 对 dt 的相对精度只有 1e-3，误差会在 131072 步上累积。这是本模型最隐蔽的精度陷阱 |

288 次运算是全模型最小的算子，但它决定了 393,216 个状态元素这一步衰减多少。把 dt 支路做成 BF16 或 FP16 能省下的只有 48 × 2 B = 96 B 带宽，代价是整层退化成固定衰减的 SSM，收益与风险完全不成比例。

### A④ SSM 扫描（状态更新 + 读出）

| 项 | 内容 |
|---|---|
| 形状 | 状态 `[48,64,128]` FP32 原地更新；输入 `x[1,48,64]`、`B[1,128]`、`C[1,128]`、`a[1,48]`；输出 `y[1,3072]` |
| 公式 | `S_h ← a_h·S_h + (dt_h·B) ⊗ x_h`；`y_h = S_h·C` |
| MAC | dt·B 6,144 + 衰减 393,216 + 外积 393,216 + 读出 393,216 = 1,185,792，占 3.4% |
| 归属 | 定制状态单元；48 头并行，头内"衰减 → 外积 → 读出"三步串行 |
| 精度 | 状态 FP32，B/C/x BF16，累加 FP32，输出 BF16 |
| 坑 | `n_groups=1`，B/C 在 48 头之间共享，一份 128 维数据要被 48 个头各读一次；若实现成每头各取一份独立 B/C，逻辑等价但会把 256 B 的读放大 48 倍；`D·x` 在读出之后加，不在状态里 |

这 1,185,792 次运算里，只有 6,144 次是"真正的乘法"，其余 1,179,648 次全是与状态相关的逐元素乘和矩阵向量乘。它的算术强度极低：读 393,216 个 FP32（1,572,864 B）、写同样多，只换 1,179,648 次运算，比值 0.375 MAC/B。这就是为什么它必须留 SRAM——落 DRAM 时这 3.15 MB 的往返会把单层时间从 2.3 µs 拉到 10.1 µs。

| **合计** | | | **19,011,474** | |

这张表解释了 MoE 的两面性。参数上它占全模型 87.0%（6,039,797,760 / 6,939,037,248），但每 token 只读 6 个专家，实际流过的参数是 1,465,470,528 里的 782.4 MB 权重，占每 token 流量的 51.8%。也就是说：容量按 87% 算，带宽按 52% 算，中间 35 个百分点的差全部由"路由命中"决定——这是全模型唯一一个"参数规模与每 token 成本脱钩"的地方。

M4 里 9,446,400 拆开是 6 × (1,572,864 + 1,536)：每个专家 1536→1024 的 gate/up 占 1,572,864，silu 占 1,536。M7 的共享专家常开，不参与路由，4,721,664 是每 token 必定付的底价，相当于 1.6 个普通专家。

路由本身的成本是 98,706，占 0.5%，但它产出的 6 个下标决定了后面 14,594,605 B 的读取顺序。在测试上这意味着：MoE 的单算子对拍必须固定路由结果，否则同一个输入两次运行的 MAC 相同、读取地址不同，性能模型会对不上。

## 6.4 层型 D：没有

本模型没有 MTP 头，也没有视觉塔，所以"层型 D"不存在。第 3.6 节已经说明 header 与 config 里都查不到对应张量，这一节不再重复，只记两个后果：decode 没有投机解码这条路（10.3），词表成本无法通过草稿头剪枝摊薄（7.3）。

# 第 7 章　输出头、路由与采样

模板里这一章是"视觉塔 + 输出头"。本模型没有视觉塔，7.1–7.5 的篇幅全部给输出头、路由与采样，因为这三件事在端侧 decode 里占的成本常常被低估。

## 7.1 输出头：与 embedding 共享

| 项 | 内容 |
|---|---|
| 形状 | `[100352, 1536]`，与 `embedding` 逐字节共享，header 里没有独立 `lm_head` |
| MAC | 100,352 × 1536 = 154,140,672，占每 token 的 10.2% |
| 权重 | 158.919 MB（MXFP8），占每 token 带宽的 10.5% |
| logits 缓冲 | 100,352 × 4 B = 401,408 B（FP32）；BF16 时 200,704 B |
| 精度 | 权重 MXFP8，隐藏态 BF16，累加 FP32，logits FP32 后除 6 |
| 坑 | prefill 只有最后一个位置需要算 logits；若每个 token 都算，1024 token 的 prefill 会多出 157.8 GMAC，是真实算力的 10.2% |

共享的好处是容量为零：词表矩阵不额外占 158.9 MB。代价是 decode 每 token 必须完整读一遍 158.9 MB，这笔钱省不掉——除非做词表剪枝，而剪枝需要额外的草稿模型，本模型没有。

## 7.2 logits 的两步变换

| 项 | 内容 |
|---|---|
| 缩放 | `logits = logits / 6`，`logits_scaling = 6` |
| softmax | 100,352 个元素，每元素 3 次，共 301,056 次，占 0.02% |
| 时间 | 向量单元上 301,056 / 512 = 588 周期，0.59 µs；相对 4.87 ms 可忽略 |
| 精度 | 除法与 softmax 全程 FP32；除 6 不能折进 lm_head 权重（会改变权重量化尺度） |
| 坑 | 除 6 与 attention 的 1/128 都是"写错不报错"的常数；温度参数若再乘一次，等价于把 6 改成别的值 |

## 7.3 采样：三种实现差三个数量级

| 方法 | 比较/运算次数 | 向量实现（512 路） | 标量实现（1 GHz） | 占 4.87 ms 预算 |
|---|---:|---:|---:|---:|
| 全排序 | 1.67 M | 3.3 µs | 1.67 ms | 34.3% |
| nth_element（top-k） | 0.20 M | 0.4 µs | 0.20 ms | 4.1% |
| 直方图分桶（top-p 近似） | 0.10 M | 0.2 µs | 0.10 ms | 2.1% |
| 温度 + 逐元素 | 0.10 M | 0.2 µs | 0.10 ms | 2.1% |
| **合计（全排序路线）** | **1.77 M** | **3.5 µs** | **1.77 ms** | **36.4%** |

比较次数按 `V·log₂V` 估：100,352 × 16.6 ≈ 1.67 M。这张表的结论不是"采样很贵"，而是"采样的成本完全取决于放在哪"：放在 512 路向量单元上是 3.5 µs，放在单发射标量核上是 1.77 ms，后者会把 decode 从 205 token/s 拖到 151 token/s。端侧芯片通常只有一个小的控制核，这一项必须显式规划，不能默认"采样不要钱"。

0.8B 的词表是 248,320，全排序要 4.4 M 次比较，标量实现 4.4 ms，比它的 2.5 ms 前向还长；本模型词表小 2.5 倍，这个问题从"必须解决"降成"注意即可"，但并没有消失。

## 7.4 router：每层一个 64 维的"小输出头"

| 项 | 内容 |
|---|---|
| 规模 | 40 层 × 64 = 2,560 个 logits/token，是 lm_head 的 2.6% |
| MAC | 40 × 98,706 = 3,948,240，占 0.26% |
| 权重 | 40 × 101,351 B = 4.054 MB，占 0.27% |
| 下游影响 | 决定 583.784 MB 的专家权重读取顺序，占每 token 流量 38.6% |
| 精度 | logits FP32；权重 MXFP8 可以，但 11.4 会说明为什么路由矩阵值得保留更高精度 |
| 坑 | router 的 64 个 logits 必须整行算完才能比较，不能边算边淘汰；top-6 的 6 遍扫描是串行的 |

从硬件角度看，router 是一个"便宜但卡脖子"的算子：它自己只占 0.26% MAC，但它和专家读取之间是硬依赖。第 10.2 节把这条链换算成 47.1 µs/层、40 层 1.88 ms，占 token 预算的 38.6%——这是全模型最大的单点串行成本，比 SSM 扫描的 83 µs 大 22 倍。

## 7.5 与 0.8B 的对照

| 项 | 0.8B | 本模型 | 比值 |
|---|---:|---:|---:|
| 词表 | 248,320 | 100,352 | 0.40 |
| lm_head 参数 | 254,279,680 | 154,140,672 | 0.61 |
| lm_head 字节（MXFP8） | 262.16 MB | 158.919 MB | 0.61 |
| 占每 token 权重流量 | 33.8% | 10.5% | 0.31 |
| 全排序比较次数 | 4.40 M | 1.67 M | 0.38 |

0.8B 的 lm_head 是 254,279,680 个参数（248,320 × 1024），MXFP8 262.16 MB，占它 0.776 GB 每 token 流量的 33.8%。本模型的 lm_head 只占 10.5%，因为分母被 40 层专家撑大了 1.9 倍，而词表小了一半。这条对比说明"输出头占比随模型变小而升高"的规律在这里被 MoE 打断：真正决定占比的是"词表 × hidden"与"层数 × 每层活跃参数"的比值，不是总参数量。

附加流量（不在这张表里，但每 token 都要付）：

| 项 | 4K | 32K | 131072 |
|---|---:|---:|---:|
| KV 读 | 33.554 MB | 268.435 MB | 1,073.742 MB |

速度上限：

```
只看权重：       1,510.900 MB / 310 GB/s = 4.874 ms  → 205.2 token/s
S=4K：          1,544.454 MB            = 4.982 ms  → 200.7 token/s
S=32K：         1,779.335 MB            = 5.740 ms  → 174.2 token/s
S=131K：        2,584.642 MB            = 8.338 ms  → 119.9 token/s

## 8.3 缓存账

| 项 | 公式 | 4K | 32K | 128K |
|---|---|---:|---:|---:|
| 全量权重（MXFP8） | 6,939,037,248 × 1.031 B | 7,154.147 MB | 7,154.147 MB | 7,154.147 MB |
| 每 token 活跃权重 | 1,465,470,528 × 1.031 B | 1,510.900 MB | 1,510.900 MB | 1,510.900 MB |
| SSM 状态（FP32） | 36 × 48 × 64 × 128 × 4 B | 56.623 MB | 56.623 MB | 56.623 MB |
| 卷积状态（FP32） | 36 × 3328 × 3 × 4 B | 1.438 MB | 1.438 MB | 1.438 MB |
| KV cache（BF16） | 8,192 B × S | 33.554 MB | 268.435 MB | 1,073.742 MB |
| 激活 + logits | 0.408 MB | 0.408 MB | 0.408 MB | 0.408 MB |
| **合计（活跃权重口径）** | | **1,602.923 MB** | **1,837.804 MB** | **2,643.111 MB** |

表里同时给了"全量权重"和"每 token 活跃权重"两行，是因为它们回答两个不同问题：前者是容量（7.154 GB 必须驻留或被换出），后者是带宽（1.511 GB 每 token 读一次）。端侧 8 GB 设备装不下前者加 131K 的 KV（7.154 + 1.074 = 8.228 GB），这才是必须量化的根本原因。

两种"历史"必须并排看：

| 项 | SSM 状态 | KV cache |
|---|---|---|
| 份数 | 36 层各一份 | 4 层各一份 |
| 形状 | 每层 48 × 64 × 128 | 每层 4 头 × S × 128，K 与 V 各一份 |
| 精度 | FP32（不可降） | BF16，可降 FP8 |
| 随 S 增长 | 否 | 是，8,192 B/token |
| S=1 | 58.061 MB | 8 KB |
| S=4K | 58.061 MB | 33.554 MB |
| S=32K | 58.061 MB | 268.435 MB |
| S=131K | 58.061 MB | 1,073.742 MB |
| 每 token 流量 | 116.1 MB（读 + 写） | 8 KB 写 + 全量读 |
| 能否分页 / 驱逐 | 不能，逐 token 原地累积 | 能，按页管理 |
| 何时先成瓶颈 | SRAM 容量：58.061 MB 已占 64 MB 的 90.7% | 带宽：131K 时占每 token 流量 71.1% |

把两个交叉点算出来，"谁先成为瓶颈"就有确定答案：

| 交叉点 | 条件 | 结果 |
|---|---|---|
| KV 追平 SSM 状态 | 8,192 B × S = 58.061 MB | S = 7,088 |
| KV 追平每 token 活跃权重 | 8,192 B × S = 1,510.900 MB | S = 184,436，超出 131,072 上限 |
| KV 追平全量权重 | 8,192 B × S = 7,154.147 MB | S = 873,309，永远到不了 |

结论分两层。带宽上，权重先撞墙，而且 131072 之内 KV 都追不上：131K 时 KV 是权重的 71.1%，权重仍是第一瓶颈。容量上，SSM 状态先撞墙：58.061 MB 在 64 MB 的 SRAM 里已经占 90.7%，而 KV 要到 S=7,088 才和它一样大。所以"状态放哪"这个问题在 4K 上下文时就已经必须回答，而"KV 怎么办"可以拖到 32K 以后再回答。

三个必须做的设计决策：

| 决策 | 收益 | 代价 |
|---|---|---|
| 状态驻 SRAM（58.061 MB 专用） | 省 116.1 MB/token，205.2 而非 190.5 token/s；scan 串行段 114 µs 而非 365 µs | 64 MB SRAM 的 90.7% 被占，只能跑单序列；批处理时每序列再加 58.061 MB，B=2 就装不下 |
| 状态落 DRAM | 零 SRAM 占用，可批处理 | +116.1 MB/token，+375 µs，205.2 → 190.5 token/s；131K 时 8.712 ms |
| KV 用 FP8 | 131K 时省 536.871 MB，8.338 → 6.606 ms，119.9 → 151.4 token/s | softmax 输入从 BF16 降 FP8，长上下文精度需验证（12.3） |
| 专家改 4 bit | 容量 7.154 → 4.136 GB，131K 时总占用 5.21 GB 可进 8 GB；带宽 583.784 → 300.810 MB，1,510.900 → 1,227.927 MB，205.2 → 252.5 token/s | 专家精度损失需端到端验证（12.3）；4-bit GEMV 需要引擎支持 |

四个决策里没有一个能单独解决问题：容量必须靠 4-bit 专家，速度必须靠状态驻 SRAM 或接受 -7.7%，长上下文必须靠 FP8 KV。三件事的量级分别是 3.0 GB、116 MB、537 MB，差一个数量级，优先级很清楚。

| 4 | Mamba-2 层：A⑧（MoE） | 19,011,474 | 引擎 + 向量 | 19.561 MB 读 |
| 5 | Attention 层：B①–B⑧（mixer） | 6,302,244 | 引擎 + 向量 | 6.490 MB 读 + 4 KB KV 写 |

| 8 | lm_head：1536 → 100,352 | 154,140,672 | 引擎 | 158.919 MB |
| 9 | logits 除 6、softmax | 301,056 | 向量 + SFU | 401 KB |

逐层时间：Mamba-2 层 34.660 MB / 310 GB/s = **111.8 µs**，Attention 层 26.050 MB / 310 GB/s = **84.0 µs**。36 × 111.8 + 4 × 84.0 = 4,361.0 µs，加 lm_head 512.6 µs，合计 **4,873.6 µs**（采样 3.5 µs 可与 lm_head 的权重预取重叠），对应 205.2 token/s。

时间线里真正串行的只有四处：第 2 层的层型判断（可预先展开成静态表）、每层 router 出下标后的专家取数（47.1 µs）、SSM 扫描（单层 2.3 µs 计算、3.2 µs SRAM 读写）、第 9–10 步的 softmax 与采样。前两处合计 40 × 47.1 = 1,884 µs，占 4.87 ms 的 38.6%，是唯一值得做流水改造的地方。

## 9.2 Prefill 一段 prompt（S=1024）

| 项 | 值 |
|---|---:|
| 每 token MAC（分块扫描口径） | 1,512,616,416 |
| 1024 token 总算力 | 1,548,919,209,984 MAC = 3.098 TFLOP |
| 算力时间（12.5 TMAC/s） | 123.9 ms |
| 权重读取 | 1,510.900 MB |
| 权重带宽时间（310 GB/s） | 4.874 ms |
| 失衡比（算力时间 / 带宽时间） | 25.4 |
| 结论 | prefill 是算力瓶颈，decode 是带宽瓶颈 |

分块口径与 decode 的差别只在扫描：decode 用递推形式 1,185,792 MAC/token，prefill 用 256 的块，块内两次 `C×d_state` 矩阵乘摊到每 token 是 3,145,728，加块间状态更新 3,072 与衰减 1,536，共 3,150,336，比递推多 1,964,544。这一个算子就让 prefill 每 token 多 0.13% 的算力，但换来的是整个过程只有 1/256 的串行步数。

131072 的 prefill 是 131072 × 1,512,616,416 = 198.26 TMAC，15.86 s；同样的 131072 个 token 用 decode 逐个跑要 131072 × 8.338 ms = 18.2 min。两者的差别就是 GEMM 与 GEMV 的差别。

## 9.3 长上下文 decode（S=131072）

| 项 | 值 | 占 8.338 ms |
|---|---:|---:|
| 权重读取 | 1,510.900 MB，4.874 ms | 58.5% |
| KV 读取 | 1,073.742 MB，3.464 ms | 41.5% |
| QKᵀ + A·V（4 层） | 1.611 GMAC，0.129 ms | 1.5% |
| softmax（4 层，18.4 µs/层） | 73.7 µs | 0.9% |
| 合计 | 2,584.642 MB，8.338 ms | 100% |

带宽与算力之比：8.338 ms 里算力只占 0.20 ms，2.4%。此时 KV 已经占到 41.5%，但它仍然没有超过权重——要 KV 反超权重需要 S=184,436，超出 131,072 的训练上限。所以本模型在全上下文范围内都是"权重主导"，这与 0.8B 在 63K 之后转为"KV 主导"完全不同。

# 第 10 章　算子 → 硬件映射

## 10.1 分类矩阵

| 类别 | 特征 | 本模型算子 | 归属 |
|---|---|---|---|
| GEMM / GEMV | 激活 × 权重，K 是读入维 | 所有投影、专家、共享专家、router、lm_head、QKᵀ、A·V | 矩阵引擎 |
| 归约 | 沿一维求和或求最值 | RMSNorm（1536）、RMSNormGated（3072）、softmax（S）、top-6（64） | 向量单元 |
| 逐元素 | 同形状逐点 | silu、门控乘、0.22 缩放、残差、专家加权 | 向量单元 |
| 串行递推 | 后一步依赖前步 | SSM 状态更新（衰减 + 外积 + 读出） | 定制状态单元 |
| 查表 | 无乘加 | embedding | DMA |
| 搬运 | 无乘加 | KV 读写、状态读写、卷积状态滚动 | DMA |
| 控制 | 分支 | 40 次 top-6、采样 | 标量核 |

这张表与 2.3 的四个类别一一对应，只多了查表、搬运、控制三类非计算项。一条判据贯穿全篇：**凡是有 K 维归约的都能上引擎，凡是依赖前一拍结果的都上不了**。SSM 扫描、卷积状态滚动、top-6、采样四件事都属于后者。

## 10.2 引擎侧的三条结论

**第一条：decode 的引擎利用率只有 2.5%。** 每 token 1,510,651,872 MAC，在 4.874 ms 内完成，等效 310 GMAC/s，而引擎峰值是 12.5 TMAC/s。这不是设计缺陷，是 GEMV 的固有形态：M=1 时每个权重只用一次，算力被带宽锁死。任何"堆 MAC 阵列"的方案在这里都是浪费，正确的方向是加带宽、加片上缓存、或提高批大小（10.3）。

**第二条：SSM 扫描的串行段是 83 µs，不是瓶颈，但落 DRAM 后变成 365 µs。** 单层 3 遍扫描 393,216 个元素，512 路并行 2,304 周期 = 2.3 µs，36 层 83 µs，占 4.874 ms 的 1.7%；状态读写走 SRAM 1 TB/s 是 114 µs（2.3%）；一旦落 DRAM，SSM 状态本身的往返是 113.2 MB、365 µs；加上卷积状态共 116.1 MB、375 µs，占 7.7%，叠加后总时间 5.248 ms，速度 190.5 token/s。这条链的长度与上下文无关，是纯固定成本。

**第三条：最大单算子是 6 个专家的 gate/up，9.44 M MAC，占每 token 的 0.62%；但 router 到专家取数的依赖是 1.88 ms，占 38.6%。** 单看 MAC，MoE 是"很多小 GEMV"；单看时间，它是"一次路由、六次 14.59 MB 的取数"，每次 47.1 µs。40 层叠加 1,884 µs，是 token 预算里最大的一块串行时间，比 SSM 扫描大 22 倍，比采样大 500 倍以上。

三条结论指向同一个方向：这颗芯片的瓶颈不在算力，而在"权重从哪来、什么时候能开始取"。路由决定取数顺序，状态决定取数位置，两者都不吃 MAC。

## 10.3 提速手段

| 手段 | 复用倍数 | 代价 |
|---|---:|---|
| 批处理 B=2 | 1.48× | 状态 2 × 58.061 MB，SRAM 装不下；KV 也 ×2 |
| 批处理 B=4 | 2.05× | 同上；每 step 2.94 GB |
| 批处理 B=8 | 2.80× | 同上；每 step 4.32 GB |
| 批处理 B=32 | 7.01× | 同上；每 step 6.89 GB，已接近全量权重 7.15 GB |
| B=32 + 状态落 DRAM | 4.56× | 每 token 多 116.1 MB 状态流量 |
| 专家 4 bit | 1.23×（1,510.900 → 1,227.927 MB） | 精度损失（12.3）；需要 4-bit GEMV |
| 全部权重 4 bit | 1.94×（778.5 MB） | 精度损失更大；lm_head 与 embedding 通常保留 8 bit |
| 投机解码（MTP） | 不存在 | 模型没有草稿头（3.6） |
| 状态驻 SRAM | 1.08× | 58.061 MB SRAM 专用 |

批处理的收益全部来自"权重在批内只读一次"。每 token 流量 = (927.1 + 40 × u(B) × 2.432) / B MB，`u(B) = 64 × (1 − (58/64)^B)` 是 B 个 token 在一层里命中的不同专家数：B=1 时 u=6、1,510.9 MB；B=4 时 u≈20.7、735.4 MB；B=8 时 u≈34.9、540.4 MB；B=32 时 u≈61.3、215.4 MB。B 再大，每 step 就要读完全部 7.15 GB 权重，收益停在 7.0× 附近，此时每 token 223.6 MB、约 1,386 token/s，并且开始受算力约束。

真正的代价不是权重而是状态：每序列 58.061 MB 的 SSM 与卷积状态不能共享，SRAM 只能放一份。B 条序列的状态必须落 DRAM，每 token 固定加 116.1 MB，B=32 时 215.4 → 331.5 MB，收益从 7.01× 压到 4.56×。这是"批处理 + MoE + 定长状态"三件事叠在一起的真实天花板。

没有 MTP 头，投机解码这条路不存在；能用的只有批处理与量化。两者可以叠加：B=32 且专家 4 bit 时，每 step 权重 4.00 GB，摊到每 token 125.0 MB，加状态 116.1 MB 后 241.1 MB，等效 6.3×、约 1,286 token/s；此时每 step 48.3 GMAC 只需 3.9 ms，内存侧 4.00 GB 需要 12.9 ms，仍是内存受限。

# 第 11 章　量化归属

## 11.1 逐项归属

| 组件 | 每 token 参数量 | 建议精度 | 字节 | 依据 |
|---|---:|---|---:|---|
| 6 个专家（40 层） | 566,231,040 | INT4 | 300,810,240 | 占容量 87.0%，是唯一能把权重压进 8 GB 的项 |
| 共享专家（40 层） | 188,743,680 | MXFP8 | 194,594,734 | 常开，占带宽 12.9%，降 4 bit 收益不如专家 |
| router（40 层） | 3,932,160 | MXFP8，logits FP32 | 4,054,057 | 见 11.4 的边界翻转风险 |
| Mamba in/out_proj | 526,417,920 | MXFP8 | 542,736,876 | 36 层 mixer 的主体，误差随层累积 |
| attention 四个投影 | 25,165,824 | MXFP8 | 25,945,965 | 只 4 层，量化收益小 |
| 卷积、归一、标量 | 839,232 | BF16 | 1,678,464 | 参数量 0.06%，用 BF16 省心 |
| embedding / lm_head | 154,140,672 | MXFP8 | 158,919,033 | 词表行独立，可再降到 4 bit（未验证） |
| **合计** | **1,465,470,528** | | **1,228,739,369** | |

全 MXFP8 是 1,510,900,114 B；这张表的方案把专家降到 4 bit，省 282,974,000 B，同时把小件提到 BF16，多 813,423 B，净得 1,228,739,369 B，等效 252.3 token/s。容量上，全量权重从 7,154.147 MB 降到 4,135.758 MB，131K 时总占用 5,210 MB，进 8 GB 设备还有 2.8 GB 余量给激活与多序列。

## 11.2 三条硬规则

**第一条：状态与时间常数必须 FP32，且没有折中。** `A_log`、`dt_bias`、`D` 三个 48 元素的向量需要 144 个参数，占 0.00001%，却是唯一不能降精度的权重。状态 58.061 MB 的 FP32 是 11.3 的主题。

**第二条：专家 4 bit、其余 8 bit，但 router 的 logits 必须 FP32。** 专家 4 bit 是容量逼出来的（7.154 → 4.136 GB），不是精度允许的结果；router 的 64 维 logits 决定 top-6，边界翻转会让整层换专家，代价是 14.59 MB 的权重读错。

**第三条：激活 BF16、累加 FP32，归一与 silu 不量化。** 全模型 394,240 个 silu 元素与 81 次归一占 MAC 不到 0.1%，把它们量化省不下带宽，却会引入非线性误差。

## 11.3 状态精度：Mamba-2 与 DeltaNet 的不同命题

| 精度 | SSM 状态 | 卷积状态 | 合计 | 相对 FP32 |
|---|---:|---:|---:|---:|
| FP32 | 56.623 MB | 1.438 MB | 58.061 MB | 1.00 |
| FP16 | 28.312 MB | 0.719 MB | 29.031 MB | 0.50 |
| FP8 | 14.156 MB | 0.359 MB | 14.515 MB | 0.25 |

省一半只换来 29.03 MB，省四分之三也只换来 14.52 MB；而 131K 时 KV 是 1,073.742 MB。**把状态压到 FP16 省下的 29 MB，不到 KV 的 3%，却要冒 131072 步累积误差的风险，收益与风险完全不成比例。** 这是"状态必须 FP32"的量化理由。

真正逼着状态留 FP32 的是两件事。第一是衰减因子的动态范围：实测 `A` 在 [-15.16, -0.43] 之间，跨度 35 倍，`dt` 在 [4.7e-11, 2.79] 之间，两者组合出的 `a` 从 0.22 一直到 1 − 1e-11，`1-a` 跨 11 个数量级。任何共享缩放的定点格式都无法同时表示"几乎不衰减"和"一步衰减 78%"的头；按头给 48 × 36 = 1,728 个缩放因子可以缓解，但 1-a 小到 1e-11 时，缩放因子本身也要 FP32。第二是累积步数：131072 步，每步一次乘加，FP16 的 11 bit 尾数在 a 接近 1 时每步都做一次"加一个相对 1e-3 的增量"，误差按步数线性累积。

与 0.8B 的 DeltaNet 对照，两者的精度命题相反：

| 项 | DeltaNet（0.8B） | Mamba-2（本模型） |
|---|---|---|
| 状态形状 | 16 头 × 128 × 128 | 48 头 × 64 × 128 |
| 状态大小 | 18.87 MB，FP32 | 58.061 MB，FP32 |
| 更新规则 | `S ← S(I − βkkᵀ) + βkvᵀ`，3 次 matvec | `S ← a·S + (dt·B)⊗x`，1 次逐元素 + 1 次外积 |
| 是否有遗忘 | 无显式衰减，靠 delta 规则覆盖 | 每头一个标量 a，几何遗忘 |
| 量化误差的形态 | 不衰减，误差线性累积；对状态精度最敏感的是"长程保持" | 有衰减，旧误差被 a 逐步压掉；最敏感的是"每头 a 的动态范围" |
| 降 FP16 的后果 | 18.87 → 9.44 MB，长序列误差累积明显 | 58.061 → 29.03 MB，误差被 a 抑制，但 a 本身必须先算准 |
| 结论 | 省 9.44 MB 不值得 | 省 29.03 MB 也不值得，且 a 的 FP32 不可省 |

一句话：DeltaNet 的状态精度问题在"记住多久"，Mamba-2 的在"衰减多准"。前者可以靠更短的窗口绕开，后者只能靠 FP32 的 dt 与 A 保证。

## 11.4 MoE 的量化

| 项 | 全 MXFP8 | 专家 INT4 | 差值 |
|---|---:|---:|---:|
| 全量权重 | 7,154.147 MB | 4,135.758 MB | -3,018.389 MB |
| 每 token 权重 | 1,510.900 MB | 1,227.926 MB | -282.974 MB |
| 131K 总占用（含 KV） | 8,227.889 MB | 5,209.500 MB | -3,018.389 MB |
| 速度上限 | 205.2 token/s | 252.5 token/s | +47.3 |

专家的量化粒度建议按"每专家每行一个缩放"：40 层 × 64 专家 × 3 个矩阵 = 7,680 个矩阵，若每行一个 FP16 缩放，以 gate/up 的 1024 行为例，额外开销 1024 × 2 B = 2 KB/专家，占该矩阵 1.621 MB 的 0.12%，可以忽略。不要用整层共享缩放——同一层 64 个专家的权重分布不同，共享缩放会让小范数专家的有效位宽掉到 2 bit 以下。

router 是唯一建议保留 8 bit 以上的 MoE 权重。它只有 98,304 个参数（101,351 B/层），提到 FP32 也只多 11.7 MB（40 层），占每 token 流量的 0.8%，换来的是 top-6 边界的确定性。shared 专家建议留 8 bit，因为它常开、占带宽 12.9%，4 bit 的收益（约 94.3 MB）小于它对每 token 输出的直接影响。

# 第 12 章　对芯片设计的结论与待验证清单

## 12.1 九条结论

**一、这是一个 6.94 B 参数、每 token 只用 21.1% 的稀疏模型。** 6,939,037,248 个参数里 87.0% 是 40 层 × 64 个专家，每 token 只选 6 个，实际读 1,465,470,528 个。参数量与每 token 成本之间没有线性关系，容量规划与带宽规划必须分开做。依据 1.3、6.3。

**二、速度由带宽决定，算术强度 1.00 MAC/B。** 每 token 1,510.900 MB、205.2 token/s 上限，等效 310 GMAC/s，是 12.5 TMAC/s 引擎的 2.5%。这个比值与 0.8B 的 0.99 MAC/B 几乎相同，说明 GEMV 形态不随模型缩放，引擎规格可以复用。依据 8.1、8.2、10.2。

**三、容量比带宽更早撞墙。** 全量权重 7,154.147 MB 加 131K 的 KV 1,073.742 MB 是 8,227.889 MB，8 GB 设备装不下；专家降到 4 bit 后 5,209.500 MB，留 2.8 GB 余量。这是本模型与 0.8B（MXFP8 0.90 GB）最根本的差别。依据 8.3、11.4。

**四、58.061 MB 的定长状态是第二道墙。** FP32 不可降：`1-a` 跨 11 个数量级、131072 步累积，两个理由各自都足以否掉 FP16。状态驻 SRAM 要 64 MB 的 90.7%；落 DRAM 则每 token 多 116.1 MB、速度降到 190.5 token/s，scan 串行段从 83 µs 变 365 µs。依据 11.3、10.2、8.3。

**五、KV 不是长上下文的主角。** 只 4 层、每 token 8,192 B，131K 时 1.074 GB，占每 token 流量 71.1%，要反超权重需要 S=184,436，超出 131072 上限。这与 0.8B 在 63,151 token 就被 KV 反超的结论相反。依据 6.2.2、8.3。

**六、最大的一笔串行成本是路由到专家。** 47.1 µs/层，40 层 1.884 ms，占 4.874 ms 的 38.6%，是 SSM 扫描（83 µs）的 22 倍。它不吃 MAC，只吃"先出下标、再取权重"的依赖，是流水改造收益最高的一处。依据 7.4、10.2。

**七、算力分布已经换了形状。** 单算子最大是 `in_proj` 9,904,128（28.4%），lm_head 154,140,672 只占 10.2%；采样在 512 路向量单元上 3.5 µs、在标量核上 1.77 ms，两者差 500 倍。0.8B 那种"头部瓶颈"在这里不存在。依据 6.1、7.1、7.3。

**八、提速只剩批处理与量化两条路。** B=32 是 7.01×，状态落 DRAM 后 4.56×；专家 4 bit 是 1.23×；两者叠加 6.3×（1,286 token/s）。没有 MTP 头，投机解码这条路不存在。依据 10.3、3.6。

**九、"省掉"的四样东西不值钱。** 没有 RoPE、没有 q/k norm，这两项即便加上也只占 0.3% 以下的 MAC；没有 MTP、没有视觉塔，省下的是整条设计分支而不是算力。真正决定架构的是 9:1 的层型配比与 64 选 6 的 MoE。依据 1.2、5.5、3.6。

## 12.2 与 0.8B 的对照

| 项 | 0.8B | Granite 4.0-H-Tiny | 比值 |
|---|---:|---:|---:|
| 每 token 权重流量 | 0.776 GB | 1.511 GB | 1.95 |
| 速度上限 | 400 token/s | 205.2 token/s | 0.51 |
| 状态 | 18.87 MB | 58.061 MB | 3.08 |
| KV | 12,288 B/token | 8,192 B/token | 0.67 |
| KV 反超权重的上下文 | 63,151 token | 184,436 token | 2.92 |
| 算术强度 | 0.99 MAC/B | 1.00 MAC/B | 1.01 |
| lm_head 占带宽 | 33.8% | 10.5% | 0.31 |
| 批处理收益 | 未核到 | 7.01×（B=32） | |

四条"不随模型缩放"的量在这里全部对上了：算术强度 0.99 → 1.00，说明 GEMV 的形态不变；状态 18.87 → 58.061 MB 只随层数 × 头数 × 头维走，与 hidden 无关；KV 每 token 反而降了 1/3，因为 attention 层从 6 层降到 4 层；lm_head 占比从 33.8% 掉到 10.5%，因为词表小了一半而每 token 权重翻了近一倍。缩放规律被 MoE 打断的那一项是参数量：0.8B 的 87% 不在任何单一模块里，本模型的 87% 全在专家里。

| # | 项 | 影响 | 怎么核 |

# 附录 B　复现脚本

脚本只依赖标准库，直接 `python3` 运行。前半段核对参数量与 header 的差额，后半段算每 token 的活跃参数、MAC、状态与 KV。运行输出附在代码块之后，逐项与正文对应。

```python
H, V = 1536, 100352
di, nhm, dh, ns, ng, kc = 2*H, 48, 64, 128, 1, 4
conv = di + 2*ng*ns
proj = di + conv + nhm
E, topk, Ie, Is = 64, 6, 512, 1024
Lm, La = 36, 4
nq, nkv, hd = 12, 4, 128
BPP = 1.031

mix = 2*H + H*proj + conv*(kc+1) + 3*nhm + di + H*di
moe = E*H + E*(2*Ie*H) + E*(H*Ie) + H*2*Is + H*Is
A   = mix + moe
B   = 2*H + H*(nq*hd) + 2*H*(nkv*hd) + H*(nq*hd) + moe
text = V*H + Lm*A + La*B + H
for k, v in [("conv_dim",conv),("proj",proj),("mixer",mix),("moe",moe),
             ("layer A",A),("layer B",B),("text total",text),
             ("bf16 bytes",text*2),("header bytes",13878074496),
             ("diff",13878074496-text*2)]:
    print(f"{k:14s}{v:>14,}")

actA = mix + (E*H + topk*(2*Ie*H + H*Ie) + H*2*Is + Is*H)
actB = 2*H + H*nq*hd + 2*H*nkv*hd + H*nq*hd + (E*H + topk*(2*Ie*H + H*Ie) + H*2*Is + Is*H)
act  = Lm*actA + La*actB + V*H + H
print(f"{'actA':14s}{actA:>14,}")
print(f"{'actB':14s}{actB:>14,}")
print(f"{'active':14s}{act:>14,}")
print(f"{'active bytes':14s}{round(act*BPP):>14,}")
print(f"{'time ms':14s}{act*BPP/310e9*1e3:>14.3f}")
print(f"{'tok/s':14s}{1/(act*BPP/310e9):>14.1f}")

ln = 2*H
q  = H*nq*hd; kvp = 2*H*nkv*hd; o = H*nq*hd
amix  = ln + q + kvp + nq*hd + 2*nq*hd + 3*nq + o + 2*H
moeM  = ln + (H*E + E*topk + 3*topk) + topk*(2*Ie*H + H*Ie) + topk*(Ie*3 + H*2) + (H*2*Is + Is*H) + Is*3 + 3*H
mixM  = ln + H*proj + conv*(kc+1+2) + nhm*6 + (nhm*ns + nhm*dh*ns*3) + (di + di*3 + di*2) + H*di + 2*H
print(f"{'mixer MAC':14s}{mixM:>14,}")
print(f"{'moe MAC':14s}{moeM:>14,}")
print(f"{'layerA MAC':14s}{mixM+moeM:>14,}")
print(f"{'layerB MAC':14s}{amix+moeM:>14,}")
print(f"{'total S=1':14s}{Lm*(mixM+moeM) + La*(amix+moeM) + V*H + 2*H:>14,}")
print(f"{'layerB 4096':14s}{amix - 3*nq - 2*nq*hd + (2*nq*hd + 3*nq)*4096 + moeM:>14,}")

ssm = Lm*nhm*dh*ns*4; cst = Lm*conv*(kc-1)*4; kv = La*nkv*hd*2*2
print(f"{'ssm state':14s}{ssm:>14,}")
print(f"{'conv state':14s}{cst:>14,}")
print(f"{'state sum':14s}{ssm+cst:>14,}")
print(f"{'kv per token':14s}{kv:>14,}")
print(f"{'kv 131072':14s}{kv*131072:>14,}")
print(f"{'kv cross W':14s}{round(act*BPP)//kv:>14,}")
```

与 header 的核对方式：三个分片的 header 里，每个张量的 `data_offsets` 之差之和是 13,878,074,496 B，元素数之和 6,939,037,248；脚本算出 6,939,037,248 × 2 = 13,878,074,496，差额 0。这比 0.8B 的 2,592 参数缺口更干净，原因是本模型没有 FP32 参数、没有对齐填充，586 个张量全部 BF16。
