# MLA 逐层计算拆解：从 512 维潜向量到分层压缩 KV

2026-10-29 ｜ 依据 DeepSeek-V2-Lite、DeepSeek-V3.2-Exp、DeepSeek-V4-Flash 三份 `config.json`、V4 仓库内 `inference/model.py` 的注意力实现，以及三份权重清单（文件规模来自仓库目录，V2-Lite 逐层形状按 config 推导）核对

## 摘要

MLA 不是一代模型的名字，是一条持续演进的 KV 压缩路线。这条线上有三代可核对的实现：V2-Lite（经典 MLA）、V3.2-Exp（MLA 加稀疏选择）、V4-Flash（分层压缩 KV 加 MQA）。三代都把"每 token 要存多少 K/V"当成第一设计变量，区别只在于压缩的方式。

对芯片设计影响最大的几项：

- 经典 MLA 把每 token 每层的 KV 从 8,192 B 压到 **1,152 B**，省 7.11 倍。V2-Lite 27 层合 **31,104 B/token**，同规模 MHA 是 221,184 B。整 token 的算术强度从 S=1 的 0.5000 MAC/B 涨到 1M 的 3.9410。
- MLA 有三种执行形态：展开缓存、吸收、现算。现算不可行（128K 时单层 275 GMAC）；展开缓存的容量省不下来（128K 时 27 层要 29 GB）；吸收是唯一可选，代价是 Q 权重增宽 53%、核心 MAC 从 `5,120·S` 涨到 `17,408·S`，单层算术强度从 4K 的 0.57 抬到 128K 的 11.93 MAC/B。
- V3.2 的 DSA 在 MLA 之上加一个 14.0 M 参数的索引器，每 token 只对 top-2048 个历史潜向量做注意力。128K 时 KV 从 9.21 GB 降到 1.17 GB，整 token 的字节数省 17%；1M 时省 58%。它的代价是索引器要对全部历史压缩块打分，所以上下文短于 2.5K 时不划算。
- V4 已经不是"一层一个 512 维潜向量"。它改成 **512 维 MQA + 128 token 滑窗 + 逐层压缩比**（43 层里 2 层不压、21 层压 4 倍、20 层压 128 倍），只给压 4 倍的层挂 top-512 索引器。
- V4 的每 token 字节几乎不随上下文变：4K 到 128K 只从 9.67 GB 涨到 9.72 GB，1M 时 10.12 GB（多出来的部分是索引器要给 26 万个压缩块打分）。1M 上下文的 KV 合计 **0.456 GB**（主缓存 0.104 GB、索引器缓存 0.352 GB），同等条件下 V2-Lite 要 32.6 GB，V3.2 关掉 DSA 要 73.7 GB。
- 对 Hive 该沉淀的不是 512 这个数，而是三条不变量：压缩率可配、RoPE 维单独存、按需稀疏选择。把 Qwen3-0.6B 的 GQA 换成 MLA 潜向量，KV 从 114,688 B/token 降到 32,256 B，代价是权重加 7.7%；每 token 字节在 2K–32K 省 5%–53%，66K 以上字节省得更多但算术强度已过 9 MAC/B，容量始终赢 3.56 倍。

后面按"事实基线、结构、计算、核算与映射、结论"展开。所有 MAC 含逐元素与归约，只排除纯视图。

| 模型 | 参数（逐层求和） | 文件字节 | 字节/参数 | 结论 |
|---|---:|---:|---:|---|
| V2-Lite | 15,706,484,224 | 31,413,626,576 | 2.000 | BF16，差额 329,064 B 是 4 份 header 与对齐 |

## 1.2 三代各自解决了什么

V2-Lite 要回答的问题是"KV 太大"。做法是把 K/V 压成一个 512 维潜向量，注意力在潜空间里算，投影矩阵在需要时才展开。代价是 `kv_b` 这个 512→4,096 的展开矩阵，每 token 都要读一次。

V3.2 要回答的问题是"上下文太长，即使压到 1,152 B/token，128K 也要 9 GB"。做法是加索引器，先粗筛 top-2048 个潜向量，再在筛出来的集合上做完整注意力。代价是索引器自己的缓存和 top-k 选择。

V4 要回答的问题是"能不能让 KV 既不随上下文线性长，又不损失长程能力"。做法是滑窗保局部、压缩池化保长程、索引器只在轻压缩层做选择。代价是压缩本身有状态：128 个 token 的池化窗口需要 APE 和门控，跨 token 状态从"KV 数组"变成"KV 数组 + 压缩器状态"。

## 1.3 术语

**潜向量（latent）**：KV 的压缩表示。经典 MLA 里是 `c_KV`，512 维；V4 里就是那一个 512 维的 MQA 向量。

**解耦 RoPE**：把每个头的 192 维拆成 128 维内容部分和 64 维位置部分，只对 64 维旋转，并且这 64 维与 512 维潜向量分开存。

**吸收（absorption）**：把 `kv_b` 的上半部分 `W_UK` 折进 Q 投影、下半部分 `W_UV` 折进 O 投影，使推理时不再需要 `kv_b` 这个 GEMM。

**压缩比（compress ratio）**：V4 的逐层参数。比值 r 表示 r 个连续 token 的 KV 被池化成 1 个。

**索引器（indexer）**：一个轻量注意力，用 128 维的 key 给每个历史位置打分，取 top-k 交给主注意力。

# 第 2 章　三代的注意力全景

## 2.1 经典 MLA

一个 token 进层后分两条路：一条算 Q，一条算 KV 的压缩表示。

```
 x[2048]
   ├─► wq_proj [2048×3072] ─► q[3072] ─► 拆 16 头 × 192 ─► 后 64 维旋转 ─┐
   │                                                                      │
   └─► kv_a_proj_with_mqa [2048×576] ─► 拆成 c_KV[512] + k_R[64]          │
            │                              │                             │
            │                              └─► k_R 旋转 ─► 写入缓存       │
            └─► kv_a_layernorm(512) ─► kv_b_proj [512×4096]               │
                     │                        │                           │
                     │                        └─► 16 头 × (128 K_nope + 128 V)
                     │                                                    │
                     └─► c_KV 写入缓存 ────────────────────────────────┐   │
                                                                       ▼   ▼
                                                          ┌──────────────────────┐
                                                          │  Q·Kᵀ → softmax → ·V │
                                                          └──────────────────────┘
                                                                       │
                                                o_proj [2048×2048] ◄───┘
```

缓存在这里的形态是 `[S, 576]`：512 维潜向量加 64 维 RoPE key。`kv_b` 不写缓存，它在每次注意力前把整个缓存展开成 `[S, 16, 256]`——这一步是 MLA 与 GQA 最本质的差别。

## 2.2 MLA 加 DSA

V3.2 在缓存旁边挂第二个更小的缓存，存索引器的 key（128 维）。每步先用它给所有历史位置打分，取 top-2048，然后只对这 2,048 个位置展开 `kv_b` 并做完整注意力。

```
 c_KV[S, 512] ──┬─► 索引器 key[S,128] ─► 打分 ─► top-2048 下标
                │                                   │
                └─────────── gather ◄───────────────┘
                               │
                      kv_b 展开 ─► Q·Kᵀ → softmax → ·V
```

关键变化不在 `kv_b`：它的权重还是每 token 读一次。变的是缓存读取量，从 `S×576` 降到 `S×128 + 2048×576`。长上下文下这是数量级的差别。

## 2.3 V4 的压缩 KV

V4 把缓存拆成两段：滑窗段和压缩段。

```
 最近 128 个 token ─► 原始 KV[128, 512]        （滑窗，始终全读）
 更早的 token     ─► 压缩器池化 ─► [S/r, 512]  （r = 0/4/128）
                                        │
                       r=4 的层：索引器 top-512 ─┤
                       r=128 的层：全读          ┘
                                        ▼
                              注意力在 512 维上直接做（MQA）
```

三层型的分工是：不压缩层只看滑窗 128 个 token；压 4 倍的层看滑窗加 top-512 个压缩块；压 128 倍的层看滑窗加全部压缩块（1M 上下文时是 8,192 个）。

## 2.4 三代的位置

| 指标 | V2-Lite | V3.2-Exp | V4-Flash |
|---|---:|---:|---:|
| 每 token 每层新增缓存 | 1,152 B | 1,280 B | 576 / 144 / 4.5 B（r=0/4/128） |
| 每层每步读的 KV 位置数 @128K | 131,072 | 2,048 | 128 / 640 / 1,152（r=0/4/128） |
| 权重加 KV 的每 token 字节 @128K | 8.98 GB | 39.62 GB（关 DSA 47.67 GB） | 9.72 GB |
| 全模型 KV @128K | 4.08 GB | 1.17 GB | 0.065 GB |
| 全模型 KV @1M | 32.61 GB | 8.33 GB | 0.456 GB |
| 每层 attention 权重 | 13.77 M | 187.12 M + 13.96 M | 106.96 / 126.10 / 111.22 M |
| 是否需要 gather | 否 | 是（top-2048） | 是（top-512，仅 r=4） |

这张表的最后一行决定了硬件的形态：V2-Lite 的注意力是连续访存，V3.2 和 V4 是"先算下标再 gather"，DMA 必须支持按索引列表取块。

# 第 3 章　经典 MLA 的层结构

## 3.1 张量流

以 V2-Lite 为例，hidden 2,048，16 个头，每头 192 维查询、128 维 K 内容、64 维 RoPE、128 维 V。

```
 x[2048]
   │
   ├─[Q①]─► wq_proj [3072, 2048] ─► q[3072] ─[V①]─► reshape [16, 192]
   │                                              └─[Q③]─ 后 64 维旋转（RoPE）
   │
   ├─[K①]─► kv_a_proj_with_mqa [576, 2048] ─► [576]
   │            ├─ 前 512 维 ─► c_KV[512] ──[K②]─► kv_a_layernorm(512)
   │            └─ 后 64 维  ─► k_R[64] ──► 旋转 ─[K④]─► 写缓存
   │
   ├─[K③]─► kv_b_proj [4096, 512] ─► [16, 256] ─[V①]─► 拆 k_nope[16,128] + v[16,128]
   │
   ▼
 [A①]   q_nope 与 k_nope 点积 + q_rope 与 k_R 点积
   │
 [A②] softmax ─► [A③] ·V ─► [16, 128] ─[V②]─► reshape [2048]
   │
   └─[O①]─► o_proj [2048, 2048] ─► 输出
```

缓存只写 `c_KV` 和 `k_R`，合计 576 维。`k_nope` 与 `v` 在每次注意力前由 `kv_b` 现算，不落缓存——这是 MLA 省缓存的地方，也是它多一个 GEMM 的地方。

### 3.2.1 GEMM 口径

全文矩阵乘一律写 `C[M,N] = A[M,K] × B[K,N]`。A 是激活，B 是权重的逻辑形状；header 里的权重按 `nn.Linear` 存成 `[N,K]`（3.2 的形状列就是这个方向），所以 **B = Wᵀ**，不是文件里那个形状。decode 时 M=1，prefill 时 M=token 数。

| 记号 | 形状 | 内容 |
|---|---|---|
| A | `[M,K]` | 激活 |
| B | `[K,N]` | 权重的逻辑形状，等于存储张量的转置 |
| C | `[M,N]` | 输出 |

三代共有的矩阵乘（decode，M=1；`h` 是查询头数，`H` 是 hidden，`P` 是每步读的 KV 位置数，取值见 6.6）：

| 阶段 | 算子 | A | B | C | MAC（decode） |
|---|---|---|---|---|---|
| Q① | Q 投影（V2-Lite 直连） | `[1,2048]` | `[2048,3072]` = `W_qᵀ` | `[1,3072]` | 6,291,456 |
| Q① | Q 低秩（V3.2） | `[1,7168]`、`[1,1536]` | `[7168,1536]`、`[1536,24576]` | `[1,1536]`、`[1,24576]` | 11,010,048 + 37,748,736 |
| Q① | Q 低秩（V4） | `[1,4096]`、`[1,1024]` | `[4096,1024]`、`[1024,32768]` | `[1,1024]`、`[1,32768]` | 4,194,304 + 33,554,432 |
| K① | KV 压缩投影 | `[1,2048]` / `[1,7168]` / `[1,4096]` | `[2048,576]` / `[7168,576]` / `[4096,512]` | `[1,576]` / `[1,576]` / `[1,512]` | 1,179,648 / 4,128,768 / 2,097,152 |
| C① | V4 压缩器值分支 | `[1,4096]` | `[4096,512·coff]` = `W_wkvᵀ` | `[1,512·coff]` | `M·K·N`，r 个 token 摊一次（6.3） |
| C② | V4 压缩器门控分支 | `[1,4096]` | `[4096,512·coff]` = `W_wgateᵀ` | `[1,512·coff]` | 同上 |
| I① | DSA 索引 q（V3.2 / V4） | `[1,1536]` / `[1,1024]` | `[1536,8192]` / `[1024,8192]` | `[1,8192]` | 12,582,912 / 8,388,608 |

吸收把 `A·V` 与 `o_proj` 并成一次发射，两种形态的操作数：

| 形态 | A·V 的 B（= K） | A·V 的 C | o_proj 的 A | o_proj 的 B（= K） | 合并后 |
|---|---|---|---|---|---|
| 非吸收 | `[S,128]` V cache | `[h,128]` | `[1,2048]`，`[h,128]` 先 flatten（V②） | `[2048,2048]` | `[1,2048]`，中间结果过 DRAM |
| 吸收 | `[S,512]` c_KV | `[h,512]` | `[h,512]`，逐头不 flatten | `[512,128]` 逐头 | `[h,128]` 按头和，中间结果留 SRAM |

K 从 128 变成 512（V 维换成潜维），M 从 1 变成 h（16 个头并行），o_proj 的 K 从 2048 降到 512（hidden 折进头）。合并省一次发射与一次 DRAM 往返，MAC 不变：A·V 的 `8,192·S` 在 4.2 的核心系数 `17,408·S` 里，o_proj 的 1,048,576 在权重项 21,102,592 里。

## 3.3 参数分布说明什么

V2-Lite 单层 13.77 M 里，`wq_proj` 占 45.7%，`o_proj` 占 30.5%，`kv_b` 占 15.2%，`kv_a` 占 8.6%。V3.2 单层 187.12 M 里，`o_proj` 占 62.8%——128 头 × 128 维 = 16,384 的输出宽度是 hidden 的 2.29 倍。

`kv_b` 在小模型里占 15.2%，在大模型里降到 9.0%。这个比例决定了第 4 章吸收账的量级：模型越小，`kv_b` 相对越重；但绝对值越小，绝对收益也越小。

## 3.4 解耦 RoPE 的存储后果

MLA 只旋转 64 维，另外 128 维是内容。这个设计有三个直接后果。

第一，RoPE 维必须与潜向量分开存。`c_KV` 是 512 维、被 `kv_a_layernorm` 归一过、可以整块量化；`k_R` 是 64 维、旋转后的位置编码，对相位误差极敏感。V4 的实现写得直白：`act_quant(kv[..., :-rd], ...)` 只量化非 RoPE 维，`kv[..., -rd:]` 保持 BF16。

第二，`k_R` 不能被吸收。吸收的前提是"Q 与 K 的乘积可以重排成 Q 先乘一个矩阵、再与潜向量点积"。RoPE 是对角旋转，旋转后的点积依赖相对位置，不能提前折叠。所以吸收态里 `k_R` 仍逐 token 参与点积，只有 `k_nope` 与 `v` 被折进 Q 和 O。

第三，两段缓存的更新节奏不同。`c_KV` 在 `kv_a_layernorm` 之后写一次就不变；`k_R` 由原始 `k` 旋转得到，同样写一次。但两段的量化格式可以不同，这给了第 11 章一个明确的切分点：512 维可以 FP8，64 维必须高精度。

以 V2-Lite、S=4096 为例：

| 阶段 | 算子 | 形状 | MAC | 归属 |

# 第 4 章　三种执行形态

MLA 的缓存只有 576 维，但注意力需要每头的 256 维 K/V。中间这一步怎么补，决定了三种完全不同的执行形态。这三种形态在字节、算力、容量上各有一本账，混在一起算会得出相反结论。

## 4.1 三种形态

**形态 A：展开缓存。** 写缓存时就把 `kv_b` 算完，缓存里存每头的 `k_nope` 与 `v`。这就是普通 MHA 的形态，MLA 的压缩收益全部放弃。

```
 写：c_KV ─► kv_b ─► 缓存[S, 16, 256]        每 token 8,192 B
 读：q[16,192] × Kᵀ[16,192,S] ─► [16,S] ─► ×V
```

**形态 B：吸收。** `W_UK` 折进 Q，`W_UV` 折进 O，缓存只存 576 维，注意力直接在潜空间做。

```
 写：c_KV[512] + k_R[64]                     每 token 1,152 B
 读：q_latent[16,512] × c_KVᵀ[512,S] + q_rope × k_Rᵀ
```

**形态 C：现算。** 缓存存 576 维，每步对 S 个历史潜向量逐个跑 `kv_b` 展开。HuggingFace 的参考实现就是这一种。

```
 读：c_KV[S,512] ─► kv_b（S 次）─► K_nope[S,16,128] + V[S,16,128]
```

## 4.2 形状与参数

| 项 | 形态 A | 形态 B（吸收） | 形态 C（现算） |
|---|---:|---:|---:|
| 缓存每 token 每层 | 8,192 B | 1,152 B | 1,152 B |
| Q 权重 | 6,291,456 | 18,874,368 | 6,291,456 |
| `kv_a` 权重 | 1,179,648 | 1,179,648 | 1,179,648 |
| `kv_b` 权重 | 2,097,152 | 0 | 2,097,152 |
| `o_proj` 权重 | 4,194,304 | 1,048,576 | 4,194,304 |
| 每 token 流量账权重参数 | 13,762,560 | 21,102,592 | 13,762,560 |
| 核心 MAC 系数（不含 softmax） | `5,120·S` | `17,408·S` | `2,097,152·S + 5,120·S` |

吸收态 Q 从 6.29 M 涨到 18.87 M（每头 192 维变 576 维），这是吸收最大的代价：**权重增宽 53%**，且每 token 都要读。所谓"吸收省权重"只在"省掉 `kv_b` 与 `o_proj` 的展开"这个局部成立，全局是净增。

## 4.3 字节与算力账

单层每 token 的字节与 MAC（权重按 BF16 折 2 B/参数；MAC 含 softmax 的 `16·S`，与 3.5 同口径）：

| S | 形态 A MAC | 形态 A 字节 | 形态 B MAC | 形态 B 字节 | 形态 C MAC | 形态 C 字节 |
|---:|---:|---:|---:|---:|---:|---:|
| 4,096 | 34,799,616 | 61,079,552 B | 92,471,296 | 46,923,776 B | 8,624,734,208 | 32,243,712 B |
| 131,072 | 686,948,352 | 1,101,266,944 B | 2,304,901,120 | 193,200,128 B | 275,564,855,296 | 178,520,064 B |

形态 C 的 MAC 在两种上下文下都比 A、B 高两个数量级：S=4,096 就要 8.6 GMAC，S=128K 是 275 GMAC，每 token 字节却与形态 B 一样。它只适合做参考实现，不能进产品。

形态 A 的字节随 S 以 8,192 B/token 增长，128K 时单层 1.07 GB，27 层 29 GB——比整个权重还大。

形态 B 的字节在 4K 是 46.92 MB、128K 是 193.20 MB，只有形态 A 的 0.77 与 0.18；算术强度则从 4K 的 1.97 涨到 128K 的 11.93 MAC/B，形态 A 两档都不到 0.63。这是 MLA 长上下文的核心矛盾：压缩把每 token 的 KV 从 8,192 B 压到 1,152 B（7.1 倍），同时把 MAC 抬了 3.4 倍，**同一份数据上摊到的乘加从 0.57 抬到 11.93 MAC/B，主导项从流量侧翻到算力侧**。

## 4.4 交叉点由算术强度决定

B 的字节恒优于 A，4K 的比值 1.30、128K 是 5.70，只在一种情况下不占优：它每 B 上摊到的 MAC 太多。两档上下文的阈值是 `92.47M ÷ 61.08M = 1.51 MAC/B` 与 `2.30G ÷ 1.10G = 2.09 MAC/B`——引擎每读 1 B 能配的 MAC 低于它，A 先到；高于它，B 先到。

| 项 | A @4K | B @4K | A @128K | B @128K |
|---|---:|---:|---:|---:|
| 每 token MAC | 34,799,616 | 92,471,296 | 686,948,352 | 2,304,901,120 |
| 每 token 字节 | 61,079,552 B | 46,923,776 B | 1,101,266,944 B | 193,200,128 B |
| 算术强度 MAC/B | 0.5697 | 1.9707 | 0.6238 | 11.9301 |
| 优势所需引擎配比 MAC/B | — | 1.51 | — | 2.09 |

阈值随上下文抬：4K 要 1.51 MAC/B，128K 要 2.09。B 自己的算术强度在 4K 是 1.97、128K 是 11.93，A 只有 0.57 与 0.62——压缩把分母压掉 7.1 倍、把分子抬了 3.4 倍，两条线的交叉点由算术强度决定，具体引擎配比下的提法见《硬件口径》。

更重要的是容量。V2-Lite 在 128K 时 A 要 29 GB 缓存，B 只要 4.08 GB。产品上 B 是唯一可选，剩下的问题只是怎么把 B 的算术强度压下去。

## 4.5 吸收把问题从带宽搬到算力

形态 B 的算力系数 `17,408·S` 里，`8,192·S` 是 Q·Kᵀ（512 维潜向量），`8,192·S` 是 ·V（512 维潜向量），`1,024·S` 是 RoPE 部分。相比 A 的 `5,120·S`，多出来的 12,288 全部来自"在 512 维上算，而不是在 192 维上算"。

这笔代价只增加乘加，不减少字节：每 token 多 12,288·S 个 MAC，字节反而少 7,040·S 个（A 的 8,192 B/token 减 B 的 1,152 B）。于是算术强度从 0.57 抬到 1.97（4K）、从 0.62 抬到 11.93（128K），复用倍数 3.46 与 19.1。说吸收把问题从流量侧搬到算力侧，指的就是这个倍数关系，而不是某个具体芯片上慢多少。

所以从 V3.2 开始，MLA 的演进重点不再是"怎么压缓存"，而是"怎么让每个 token 只跟少量历史位置算"。这就是第 5 章的 DSA 和第 6 章的逐层压缩比。

## 4.6 prefill 必须用非吸收

prefill 时 M=1024，S=4096。吸收态的算力是形态 A 的 2.3 倍：

| 项 | 形态 A | 形态 B |
|---|---:|---:|
| 权重部分 | 13.76 M × 1024 = 14.1 G | 21.10 M × 1024 = 21.6 G |
| 注意力部分（平均上下文 2,048，含 softmax） | `5,136×2048×1024` = 10.8 G | `17,424×2048×1024` = 36.5 G |
| 单层合计 | 24.9 G | 58.1 G |

27 层是 671 GMAC 对 1.57 TMAC，prefill 多算 2.3 倍。生产实现都在 prefill 走形态 C 的变体：按 tile 展开 `kv_b`，展开结果留在 SRAM 不落 DRAM。这样 `kv_b` 的 4.19 MB 权重只读一次，展开的 K/V 也只写 SRAM。

这在硬件上有明确要求：`kv_b` 必须能常驻（4.19 MB，BF16），且 SRAM 要能放下一个 tile 的 `[T, 16, 256]` 展开结果。

## 4.7 V4 把吸收做进了架构

V4 没有 `kv_b`。每层只有一个 512 维 KV 向量（MQA），Q 直接用 `wq_b` 产出 64×512，O 用 `wo_a`/`wo_b` 两段低秩。

它相当于把形态 B 直接写进权重形状：既然 decode 必须吸收，就不要保留非吸收路径，让权重在训练时直接长成吸收态。

代价是 prefill 也失去了形态 A/C 那条更省算力的路——V4 的 prefill 只能按 MQA 512 维算。第 6 章会把这个代价量化。

# 第 5 章　DSA：在潜向量上做稀疏选择

## 5.1 索引器加了什么

V3.2 在每层挂一个索引器。它不参与主注意力，只决定"这一步该看哪 2,048 个历史位置"。四个带权重的算子，加上执行阶段的 I④–I⑥：

| 阶段 | 算子 | 形状 | 参数 | 公式 | 归属 |
|---|---|---|---:|---|---|
| I① | `wq_b`（索引器） | `[64×128, 1536]` | 12,582,912 | `1536·64·128` | 引擎 |
| I② | `wk` | `[128, 7168]` | 917,504 | `H·128` | 引擎 |
| I② | `k_norm` | `[128]` | 128 | `2·128`（平方 + 缩放） | VPU |
| I③ | `weights_proj` | `[64, 7168]` | 458,752 | `H·64` | 引擎 |
| V① | 索引 q 拆 64 头 | `[8192] ┄ [64,128]` | 0 | stride 变换，0 MAC | 地址生成器 |
| I④ | 打分 + 头加权 | `[64,128]×[128,S]` | 0 | 逐元素 + 归约，MAC 见 5.3 | 引擎 + VPU |
| I⑤ | top-2048 选择 | `S → 2,048` | 0 | 比较，不计 MAC | VPU（流式比较结构） |
| I⑥ | 按下标取 2,048 行 | `[2,048,576]` | 0 | 地址表 gather | DMA |
| **合计** | | | **13,959,296** | | |

13.96 M 是单层注意力 187.12 M 的 7.5%。索引 key 只有 128 维，是主注意力 key 的 1/4，打分用的头数 64 是主注意力 128 头的一半。两个折半叠起来，索引器打分那一步的 MAC 是主注意力核心的 1/5（`8,192·S` 对 `40,960·S`）。

## 5.2 打分与选择

```
 x[7168] ─[I①]─► wq_b（复用 q 的低秩表示）─► q_idx[64, 128]
         ├─[I②]─► wk ─► k_idx[128] ─► k_norm ─► 写索引缓存（128 B/token）
         └─[I③]─► weights_proj ─► w_head[64]
                              │
   ┌──────────────────────────┘
   ▼
 [I④] score[t] = Σ_h w_head[h] · relu(q_idx[h] · k_idx[t]) / sqrt(128)
   │
   ▼
 [I⑤] top-2048 下标 ┄┄► [I⑥] 主注意力 gather ┄┄► Q·Kᵀ → softmax → ·V
```

`relu` 之后的头加权求和意味着索引器只关心"这个位置有没有相关内容"，不区分具体是哪一类内容——权重是逐头的，逐 token 的点积结果被 relu 抹掉负半轴。这是能用 128 维粗筛的前提：它只需要排序正确，不需要数值准确。

索引缓存每 token 每层 128 B（FP8、128 维）。和主缓存分开存，也分开量化。

## 5.3 一条 64 头 × 128 维的粗筛

S=131,072 时，单层每 token：

| 阶段 | 项 | 公式 | MAC | 归属 |
|---|---|---|---:|---|
| I① | `wq_b` | `1536×8192` | 12,582,912 | 引擎 |
| I② | `wk` | `7168×128` | 917,504 | 引擎 |
| I④ | 打分 | `64×128×S` | 1,073,741,824 | 引擎 |
| I④ | 头权重 | `64×S` | 8,388,608 | VPU |
| I⑤ | top-2048 选择 | `S` 个分数取前 2,048 | 0（比较） | VPU（流式比较结构） |
| I⑥ | gather 2,048 行 | `2,048×576` | 0（搬运） | DMA |
| A①–A③ | 主注意力（top-2048） | `40,960×2,048 + 128×2,048` | 84,148,224 | 引擎 + VPU |
| **合计** | | | **1,179,779,072** | |

同一层不开 DSA 时，主注意力是 `(40,960 + 128)×131,072 = 5,385,385,984`。1.18 G 对 5.39 G，4.56 倍。

## 5.4 临界点在 3K 附近

DSA 多付索引器的固定开销和全历史打分，少付"对全部位置做完整注意力"。令两者相等：

```
13,959,296 + 8,256·S + (40,960 + 128)×2,048 = (40,960 + 128)·S
                                        S ≈ 2,988
```

字节上的临界点更早。每 token 每层少存 `1,152 − 128 = 1,024 B`，但要多读 2,048 个位置的主缓存 `2,048×576×2 = 2,359,296 B`，交叉在 2,304 token。

两个临界点都在 3K 附近，取整说：**上下文短于约 3,000 token 时 DSA 是净亏，长于 3,000 之后净赚，赚多少随 S 线性增长。**

## 5.5 三档上下文的账

整模型每 token 的 MAC 与字节：

| S | 关 DSA MAC | 开 DSA MAC | 关 DSA 每 token 字节 | 开 DSA 每 token 字节 | 关 DSA 强度 | 开 DSA 强度 |
|---:|---:|---:|---:|---:|---:|---:|
| 4,096 | 47.64 G | 44.57 G | 38.75 GB | 38.63 GB | 1.2295 | 1.1536 |
| 131,072 | 365.89 G | 108.51 G | 47.67 GB | 39.62 GB | 7.6757 | 2.7386 |
| 1,048,576 | 2,665.49 G | 570.58 G | 112.14 GB | 46.79 GB | 23.7687 | 12.1950 |

4K 时两者字节都在 38.7 GB 量级，差 0.3%，因为 38.46 GB 的权重把 KV 的差异压没了：4K 的 KV 开 DSA 是 175.9 MB、关 DSA 是 287.8 MB，只占整 token 的 0.5% 与 0.7%。

128K 时关掉 DSA 的核心算力涨到 365.89 G，算术强度 7.68 MAC/B；DSA 把它按回 108.51 G，字节从 47.67 GB 降到 39.62 GB，算术强度回到 2.74。注意力从这里开始落到算力侧。

1M 时差距最大：2,665.49 G 对 570.58 G，4.67 倍；字节 112.14 GB 对 46.79 GB。但这一步 DSA 自己也变成算力驱动了——开 DSA 的算术强度 12.20 MAC/B，比权重流式的 1 MAC/B 高一个数量级。

## 5.6 硬件要什么

三件事：

- **流式 top-k。** 1M 上下文要在一百万个分数里取前 2,048，不能落盘排序。硬件的做法是维护一个 2,048 深度的有序表，边算边插；2048/131072 = 1.6% 的保留率意味着比较逻辑可以做成阈值加淘汰。归属记在 VPU 的流式比较结构上，不是 CPU（见 10.1、10.6）。
- **按索引 gather。** 主注意力拿到的不是连续区间，是 2,048 个任意下标。DMA 必须支持"给一张下标表，取对应的行"，且这些行在 DRAM 里不连续。
- **两套缓存、两种格式。** 索引缓存 128 B/token，主缓存 1,152 B/token，量化方式不同，生命周期也不同：索引缓存写完即读，主缓存要活到序列结束。

## 5.7 它没有解决的问题

DSA 压的是"读 KV"和"算注意力"，不压"读权重"。V3.2 的 38.46 GB 权重决定了 4K 以下无论怎么稀疏，每 token 字节都停在 38.5 GB 量级。要压权重，只能动结构本身：换 MQA 把每层的 Q/O 变窄、用 FP4 存专家、用逐层压缩比把长程缓存的条目数压下来。这就是 V4 做的事。

# 第 6 章　V4：分层压缩 KV 与 MQA

## 6.1 结构变了

V4-Flash 不再是"每层一个 512 维潜向量 + 每头 192 维查询"。它改成：

- 64 个查询头，每头 512 维（448 维内容 + 64 维 RoPE）；
- 只有 1 个 KV 头（MQA），同样是 512 维，直接就是缓存；
- Q 走 4,096→1,024→32,768 的低秩，O 走 8 组、每组 1,024 的低秩；
- 缓存 = 128 token 滑窗 + 压缩块，压缩比逐层配置。

没有 `kv_b`，也就没有展开这一步。V4 把第 4 章的形态 B 直接写进了权重形状。

## 6.2 逐层参数

三种层型的公共部分完全一样：

| 阶段 | 算子 | 形状 | r=0 | r=4 | r=128 | 公式 | 归属 |
|---|---|---|---:|---:|---:|---|---|
| Q① | `wq_a` | `[1024, 4096]` | 4,194,304 | 4,194,304 | 4,194,304 | `H·1024` | 引擎 |
| Q② | `q_norm` | `[1024]` | 1,024 | 1,024 | 1,024 | `2·1024` | VPU |
| Q① | `wq_b` | `[64×512, 1024]` | 33,554,432 | 33,554,432 | 33,554,432 | `1024·h·512` | 引擎 |
| Q③ | q 侧 RoPE | `[64,64]` | 0 | 0 | 0 | `4·h·d_r` | VPU |
| K① | `wkv` | `[512, 4096]` | 2,097,152 | 2,097,152 | 2,097,152 | `H·512` | 引擎 |
| K② | `kv_norm` | `[512]` | 512 | 512 | 512 | `2·512` | VPU |
| O① | `wo_a` | `[8×1024, 4096]` | 33,554,432 | 33,554,432 | 33,554,432 | `8·1024·4096` | 引擎 |
| O① | `wo_b` | `[4096, 8×1024]` | 33,554,432 | 33,554,432 | 33,554,432 | `4096·8·1024` | 引擎 |

| V① | MQA 广播 | `[1,1,S,512] ┄ [1,64,S,512]` | 0 | 0 | 0 | stride 0，不复制 | 地址生成器 |
| 公共小计 | | | 106,964,544 | 106,964,544 | 106,964,544 | | |
| C①–C⑤ | Compressor | 见 6.3 | 0 | 8,393,216 | 4,260,352 | 见 6.3 | 引擎 + VPU |

43 层的分布是 2 层 r=0、21 层 r=4、20 层 r=128，注意力合计 `2×106,964,544 + 21×126,106,816 + 20×111,224,896 = 5,086,670,144`。

每层还有 MoE 与超连接（Hyper-Connections）：专家 `257×3×4096×2048 = 6,467,616,768`，路由 `1,048,576`，超连接 `786,486`。这三项与压缩比无关，每层都是 6,469,452,086。注意力合计 5.09 G，只占全模型 284.33 G 的 1.8%——V4 的账几乎全在专家上。

超连接是 V4 与前两代在残差流上的差别：隐状态不再是一份，而是 4 份（`hc_mult = 4`），每个子层读入前用一组 Sinkhorn 归一化的权重把 4 份混成 1 份，输出后再用另一组权重和组合矩阵写回 4 份。参数只有 786 K，但它让残差流变成 `[batch, seq, 4, 4096]`——对硬件是激活存储和搬运的 4 倍，不是权重的 4 倍。

## 6.3 压缩器

一个可学习的门控池化，把 r 个连续 token 的 512 维向量合成 1 个。

```
 x_t[4096] ─[C①]─► wkv   ─► kv_i[512×coff]   ┐
            ├─[C②]─► wgate ─► s_i[512×coff]  ├─[C③]─► 块内 softmax ─► Σ ─► kv[512]
            └────────────► + APE[i]           ┘                    │
                                                                     ▼
                                                     [C④] RMSNorm(512) ─► 最后 64 维旋转
                                                                     │
                                                                     ▼
                                               [C⑤] 前 448 维 FP8 + 后 64 维 BF16 = 576 B
```

r=4 时 `coff=2`：`wkv` 输出 1,024 维，前半用于本块的普通池化，后半与上一块的前半拼成 2r 行再做一次重叠池化，输出仍是 512 维。这样每个压缩块的边界两侧各有一份重叠权重，块与块之间不会硬切。r=128 时 `coff=1`，没有重叠。

实现里有几处和经典 MLA 不同，都值得记：

- **池化用的位置编码是另一套频率**（`compress_rope_theta = 160,000`，主 RoPE 是 10,000）。压缩块代表的是"一段位置"，不是"一个位置"。
- **压缩块也要旋转**，但只旋转最后 64 维，和主 KV 的分段方式一致。
- **量化只作用于前 448 维**，RoPE 维保持 BF16。
- **decode 有状态**：`kv_state` 与 `score_state` 各占 `coff·r` 行、`coff·512` 列，r=4 时各是 8×1,024 个 fp32、32 KB/batch。这个状态不在缓存里，在压缩器里，逐 token 更新，每 r 个 token 产出一个压缩块。

最后一条是架构级的变化：跨 token 的状态从"一个 KV 数组"变成"KV 数组 + 压缩器寄存器组"。第 10 章会讲它对硬件的意义。

## 6.4 索引器只在 r=4 的层上

V4 的索引器和 V3.2 同构，但更省：

| 阶段 | 算子 | 形状 | 参数 | 公式 | 归属 |
|---|---|---|---:|---|---|
| I① | `wq_b`（索引器） | `[64×128, 1024]` | 8,388,608 | `1024·64·128` | 引擎 |
| I② | 自带压缩器（128 维，ratio=4，重叠） | 见 6.3 | 2,098,304 | 同 6.3，输出 128 维 | 引擎 + VPU |
| I③ | `weights_proj` | `[64, 4096]` | 262,144 | `H·64` | 引擎 |
| I④ | 打分 + 头加权 | `[64,128]×[128,S/4]` | 0 | 见 5.2 的 score 式 | 引擎 + VPU |
| I⑤ | top-512 选择 | `S/4 → 512` | 0 | 比较，不计 MAC | VPU（流式比较结构） |
| **合计** | | | **10,749,056** | | |

它没有独立的 `wk`：索引 key 由它自己那个 128 维压缩器直接产出，省掉 4096→128 的投影。索引器缓存按 FP4 存，每压缩块 64 B。

r=128 的层不挂索引器，直接全读压缩块。1M 时是 8,192 个，读一遍 4.79 MB，比做一次 top-512 选择更便宜。r=0 的层只读滑窗 128 个。

## 6.5 比率怎么排

43 层：前 2 层不压，之后交替 4 和 128。配置里的第 44 个位置（r=0）留给 MTP 层。

```
layer  0   1   2   3   4   5  ...  40  41  42  | 43(MTP)
ratio  0   0   4 128   4 128  ...   4 128   4  |  0
       └──┴───────────────────────────────────┘
       滑窗  细粒度压缩 ↔ 粗粒度压缩（交替）
```

交替而不是分段，是为了让细粒度信息在每一深度上都可达：任一层堆叠后的感受野里，总有一层保留了 4 token 粒度的压缩块。如果前 21 层粗压、后 20 层细压，前半段的信息在深层就只能靠 128 倍粗压缩回溯。

## 6.6 缓存形状

主缓存是 `[128 + S/r, 512]`。每条记录 448 维 FP8 加 64 维 BF16，正好 576 B：

| 类型 | 条目数 @4K | @128K | @1M | 单条字节 | 每层 @1M |
|---|---:|---:|---:|---:|---:|
| r=0 滑窗 | 128 | 128 | 128 | 576 | 73.7 KB |
| r=4 滑窗+top-512 | 128+512 | 128+512 | 128+512 | 576 | 368.6 KB |
| r=128 滑窗+全压缩块 | 128+32 | 128+1,024 | 128+8,192 | 576 | 4.79 MB |

全模型 @1M：主缓存 0.104 GB（20×4.79 MB + 21×0.37 MB + 2×0.07 MB），索引缓存 0.352 GB（21 层 × 262,144 个块 × 64 B）。合计 0.456 GB。同样 1M 上下文，V2-Lite 是 32.61 GB，V3.2 关 DSA 是 73.69 GB。

576 这个数碰巧和经典 MLA 的 576 维一样，但含义不同：经典 MLA 是 576 个维度各 2 B，V4 是 512 个维度按精度拆开。前者靠"存得少"，后者靠"每条更小、条数也不涨"。

## 6.7 prefill 只剩一条路

V4 没有 `kv_b`，也就没有形态 A/C 那条更省算力的展开路径。prefill 时它只能在 512 维上直接算。

单层每 token 的注意力核心（S=4,096）：

| 层型 | 位置数 | MAC |
|---|---:|---:|
| V2-Lite 形态 A（16 头 × 192 维） | 4,096 | 20,971,520 |
| V4 r=0 | 128 | 8,388,608 |
| V4 r=4 | 128+512 | 41,943,040 |
| V4 r=128 | 128+32 | 10,485,760 |

r=4 的层是 V2-Lite 形态 A 的两倍，r=128 的层是一半。平均下来 V4 的 prefill 注意力不比经典 MLA 贵多少，代价被压缩比摊掉了。这是"把吸收写进架构"能成立的原因：如果每层都是全上下文注意力，512 维 × 64 头会直接把 prefill 打爆。

# 第 7 章　输出头与 MoE 路由

## 7.1 三代路由

| 项 | V2-Lite | V3.2-Exp | V4-Flash |
|---|---|---|---|
| 专家（路由 + 共享） | 64 + 2 | 256 + 1 | 256 + 1 |
| 每 token 选几个 | 6 | 8 | 6 |
| 打分函数 | softmax | sigmoid | sqrtsoftplus |
| 分组 | 无 | 8 组选 4 | 无 |
| 路由缩放 | 1.0 | 2.5 | 1.5 |
| 稠密层 | 首 1 层（10,944） | 首 3 层（18,432） | 无，首 3 层用 hash 路由 |
| 专家中间维 | 1,408 | 2,048 | 2,048 |
| 专家精度 | BF16 | FP8 | FP4，激活上限 10 |
| `lm_head` | 209,715,200 | 926,679,040 | 529,530,880 |

三代都收敛到"多专家、少激活"。后两代是 256 选 6 或 8，激活比例 2.3%–3.1%；V2-Lite 只有 64 个专家，选 6 加 2 个共享，激活比例 9.4%。V4-Flash 把专家压到 FP4，单专家 25.17 M 参数只占 12.6 MB。

## 7.2 每 token 的专家字节

| 模型 | 单专家参数 | 每 token 激活 | 单层字节 | MoE 层数 | 合计 |
|---|---:|---:|---:|---:|---:|
| V2-Lite | 8,650,752 | 8 个（6+2） | 138.4 MB | 26 | 3.60 GB |
| V3.2-Exp | 44,040,192 | 9 个（8+1） | 406.7 MB | 58 | 23.59 GB |
| V4-Flash | 25,165,824 | 7 个（6+1） | 88.1 MB | 43 | 3.79 GB |

V3.2 的专家字节占了它 38.46 GB 的 61%，是 decode 的主要开销。V4 的专家只占 9.66 GB 的 39%——不是因为专家变小了，是因为每个专家的 3 个矩阵从 8 bit 变成 4 bit。

## 7.3 hash 路由

V4 的前 3 层不用打分。每个 token id 直接查一张 `[129280, 6]` 的 int32 表（R①→R②：查表代替 gate GEMM 与 top-k），得到 6 个专家号，省掉一次 `256×4096` 的 gate GEMM 和 top-k。

对硬件是两种截然不同的取数方式：打分路由要"算 256 个分数再排序"，hash 路由要"用 token id 查表再按号 gather 权重"。前者吃引擎，后者吃访存。V4 把最容易出现"早期层路由不稳定"的前 3 层交给 hash，等于把这几层的路由逻辑从计算问题变成查表问题。

## 7.4 输出头

| 模型 | 形状 | 参数 | 每 token 字节 | 占每 token 权重 |
|---|---|---:|---:|---:|
| V2-Lite | `[102400, 2048]` | 209,715,200 | 419.4 MB | 8.6% |
| V3.2-Exp | `[129280, 7168]` | 926,679,040 | 950.8 MB | 2.5% |
| V4-Flash | `[129280, 4096]` | 529,530,880 | 546.0 MB | 5.7% |

输出头是一次 `[1, hidden] × [hidden, vocab]` 的 GEMV，形状极扁。V2 的 8.6% 不算小：419.4 MB 权重每 token 只换 209,715,200 MAC，算术强度 0.5000 MAC/B，没有任何复用余地。

对端侧硬件，这是一个独立的 tiling 问题：词表 129,280 远宽于任何单次发射的 N 维，必须切块流式算，且每块算完立刻做 argmax 或 top-p（S①，归 CPU），不能把 129,280 个 logits 全写回 DRAM。

## 7.5 专家粒度对 DMA 的要求

单专家越小、专家数越多，"按专家号取权重"这个动作越碎：

- V2-Lite：8.65 M/专家，8 个连续块，每次 17.3 MB；
- V3.2：44.04 M/专家，9 个块，每次 45.2 MB；
- V4：25.17 M/专家，7 个块，每次 12.6 MB。

V4 的取数粒度最小，但块数少（7 对 9），且 FP4 让每次只有 12.6 MB。三代的共同点是：**专家的权重在文件里是连续的一个大块，取用时按号索引**。DMA 需要"基址 + 专家号 × 固定步长"的模式（R③），而不是"按任意地址列表 gather"——方差比 KV 的 top-k 小得多。取到之后按专家号把 token 行重排（R④，DMA）、算完按原序还原并加权求和（R⑤，VPU）；decode 时 M=1，重排退化成原地，prefill 时才真的搬行。

这张表把三代的设计意图写得很清楚。V2-Lite 的 5.03 GB 里 97.5% 是权重，到 1M 时 KV 才以 32.61 GB 反超，占 86.9%；V3.2 开 DSA 的 38.63 GB 里 99.5% 是权重，DSA 在 128K 只省 16.9% 的字节，到 1M 才省 58.3%，因为那时 KV 才涨到与权重可比；V4 的 9.67 GB 也是权重为主，但它比 V3.2 开 DSA 少了 75.0%，靠的是 MQA 压窄 Q/O、专家 FP4、层数从 61 降到 43。

反过来说：**上下文长度对每 token 字节的影响，在三代里逐次减弱**。V2-Lite 从 4K 到 1M 涨 7.46 倍，V3.2 关 DSA 涨 2.89 倍，开 DSA 涨 1.21 倍，V4 只涨 1.05 倍。

算术强度：V2-Lite 从 S=1 的 2,451,557,808 / 4,903,131,520 = 0.5000 MAC/B 涨到 4K 的 0.6002、128K 的 2.2971、1M 的 3.9410；V3.2 开 DSA 是 1.1011 / 1.1536 / 2.7386 / 12.1950，关 DSA 是 0.9718 / 1.2295 / 7.6757 / 23.7687；V4 是 1.4106 / 1.5050 / 2.1965 / 6.9729。分母含 KV 读取，分子含注意力与逐元素。每 token 每 1 B 摊到的 MAC 正好是 1 时，流量侧与算力侧打平：V2-Lite 要到 23K 附近才越过，V3.2 开 DSA 与 V4 从 S=1 起就在线上（1.1011 与 1.4106）。具体配比下的提法见《硬件口径》。

## 8.3 容量账

| 模型 | @4K | @128K | @1M | 1M 时相对 V2-Lite |
|---|---:|---:|---:|---:|
| V2-Lite | 0.13 GB | 4.08 GB | 32.61 GB | 1× |
| V3.2 关 DSA | 0.29 GB | 9.21 GB | 73.69 GB | 2.3× |
| V3.2 开 DSA | 0.18 GB | 1.17 GB | 8.33 GB | 0.26× |
| V4-Flash | 0.011 GB | 0.065 GB | 0.456 GB | 0.014× |

V3.2 关 DSA 的缓存是 V2-Lite 的 2.3 倍——层数多一倍、每层一样大。DSA 的索引缓存只有 128 B/token，但它让主缓存从 1,152 B 的读取降成"固定 2,048 条"，于是 1M 时的缓存占用反而比 V2 小。V4 的 0.456 GB 里 77% 是索引器缓存，主缓存只有 0.104 GB。

## 8.4 三本账一起看

三代在三个账本上的主导项完全不同：

| 模型 | 4K 主导项 | 128K 主导项 | 1M 主导项 |
|---|---|---|---|
| V2-Lite | 权重流量 | KV 流量 | KV 流量 + 注意力算力 |
| V3.2 关 DSA | 权重流量 | 注意力算力 | 注意力算力 |
| V3.2 开 DSA | 权重流量 | 权重流量 | 注意力算力（索引器 + 稀疏核心） |
| V4-Flash | 权重流量 | 权重流量 | 索引器算力 |

V2-Lite 在 4K 到 128K 之间是唯一被 KV 主导的模型，因为它的权重太小；V3.2 把权重做到 38 GB 之后，短上下文彻底被权重流量锁死；V4 又把权重压回 9.7 GB，代价是把长上下文的主导项从"读 KV"换成了"索引器给全部压缩块打分"。

# 第 9 章　一个 token 走完三代

每一代取 S=4K / 128K / 1M 三档，给每 token 的 MAC、字节与算术强度。时间与吞吐的换算不在这里，见《硬件口径》。

先给调用关系，不含数值；`@` 是 3.2.1 的 `A[M,K] × B[K,N]`，注释里的阶段号与第 3、5、6 章的 DAG 标签、10.1 的算子清单是同一套。

```python
# ① 经典 MLA（非吸收）
q = rope((Wq @ x).view(h, d_h).transpose(1, 2))                      # Q① Q③ V①
c, kR = split(Wkv_a @ x); c = norm(c); kv.append(c, rope(kR))         # K① K② K④
k, v = split(Wkv_b @ c); p = softmax(q @ cat(k, kR).T / sqrt(d_h))   # K③ A① A②
x = x + Wo @ (p @ v).flatten()                                       # A③ V② O①
# ② 吸收：W_UK 折进 Q①，W_UV 折进 O①，A③ 与 O① 并成一次发射
q = Wq_abs @ x; p = softmax(q_lat @ c_KV.T + q_rope @ kR.T); x = x + Wo_abs @ (p @ c_KV)  # Q① A① A② A③+O①
# ③ MLA + DSA：先 I 段再主注意力，主注意力只读 top-2048
idx = topk(sum_h w_head[h] * relu(q_idx[h] @ k_idx.T), 2048)          # I①–I⑤
k, v = split(Wkv_b @ gather(c_KV, idx))                               # I⑥ K③
# ④ V4：压缩块 + MQA，索引器只在 r=4 的层
kv = quant(rope(rmsnorm(pool_gate(x, APE, wkv, wgate, kv_state))))    # C①–C⑤
cache.append(x, kv); q = rope(q_norm(Wqa @ x))                        # K④ T① Q① Q② Q③
idx = topk(sum_h w_head[h] * relu(q_idx[h] @ k_idx.T), 512)           # I②–I⑤，仅 r=4
p = softmax(q @ cache[:P].T); x = x + Wob @ (Woa @ (p @ cache[:P]))   # A①–A③ O①
tok = sample(Wlm @ rmsnorm(x))                                        # H① S① 输出
```

| V3.2 关 DSA | 1,048,576 | 2,665,488,014,976 | 112.14270 GB | 23.7687 | 注意力算力 |

| V3.2 开 DSA | 1.21× | 12.8× |
| V4-Flash | 1.05× | 4.85× |

## 10.2 decode 是 GEMV 问题

三代 decode 时 M=1，所有投影都退化成 GEMV，一次 GEMV 能填满阵列的程度取决于 N 与 M 的宽度。经典 MLA 吸收态的 Q 是 `[16, 576]`，V3.2 是 `[128, 576]`，V4 是 `[64, 512]`。这三组数字决定了同一套阵列在三代上的填充差别：

| 形态 | Q 的 M×K | 相对 V2 形态 A |
|---|---|---:|
| V2-Lite 形态 A（16 头 × 192） | 16×192 | 1× |
| V2-Lite 吸收（16 头 × 576） | 16×576 | 3× |
| V3.2 吸收（128 头 × 576） | 128×576 | 24× |
| V4 MQA（64 头 × 512） | 64×512 | 10.7× |

"相对 V2 形态 A"这个倍数就是同一次 GEMV 能填满阵列的程度。V4 的 64×512 是端侧比较舒服的量级：阵列的 N 维有 512 个并行度，M 维有 64 行。

## 10.3 缓存粒度

三代的 KV 记录都落在 576 B 与 1,152 B 两个值上：

- 经典 MLA 一条 1,152 B（512 维潜向量 + 64 维 RoPE，各 2 B）；
- V4 一条 576 B（448 维 FP8 + 64 维 BF16）。

V4 的 576 B 不是巧合，它等于"512 维、内容部分一律 1 B、RoPE 部分一律 2 B"。片上 SRAM 的 bank 粒度如果按 64 B 设计，576 B 正好 9 个 bank，1152 B 正好 18 个——两个数都不需要 padding。这是三代共用的一个对齐点，做 SRAM 布局时可以直接当约束。

## 10.4 两套新的访存模式

经典 MLA 的访存是连续的：Q 读连续的权重，K/V 读连续的缓存行。V3.2 和 V4 引入了两种新模式：

**第一是按下标表 gather。** 主注意力拿到的 2,048（或 512）个位置不是区间，是下标表。DMA 要能在一次事务里取 N 行，每行的源地址由表决定。这是 ForagerBee 的 index-list 模式，和它的多维 stride 模式是两套不同的地址生成逻辑。

**第二是压缩器状态。** V4 每层每 batch 有一组 `kv_state`/`score_state`，r=4 时是 8 行 × 1,024 列，32 KB。它必须常驻 SRAM，每 token 更新一次，每 r 个 token 清零重来。这块状态不能放在 DRAM：它的读写频率是每 token 一次，且与 KV cache 的写节奏不同步。

## 10.5 prefill 的 SRAM 要求

prefill 时三代走的路不一样：

| 模型 | prefill 路径 | 需要常驻的额外权重 |
|---|---|---|
| V2-Lite | 展开 `kv_b`，展开结果留 SRAM | `kv_b` 4.19 MB（BF16） |
| V3.2 | 同上 | `kv_b` 16.78 MB（FP8） |
| V4 | 无展开，直接 512 维 | 无 |

V3.2 的 16.78 MB 是个硬要求：`kv_b` 必须在整个 prefill 期间不被换出，否则每个 tile 都要重读一遍。V4 取消 `kv_b` 之后这笔 SRAM 需求消失，换来的是 prefill 算力上升（第 6.7 节）。

对端侧芯片，这两条路的取舍很清楚：片上 SRAM 便宜就选 V2/V3.2 的展开路，SRAM 贵就选 V4 的直接路。Hive 首版走显式 SRAM 管理，16.78 MB 的常驻块对 2 MB 级的 local SRAM 是不可能的，所以 V3.2 那一路在 Hive 上要么放弃 prefill 展开（退回现算），要么把 `kv_b` 切成若干 tile、每个 tile 重读一次。这也是第 12 章的一条结论。

## 10.6 DSA 的硬件增量

如果要在 Hive 上支持 DSA 类的稀疏选择，需要三样东西：

- 一个流式 top-k 单元，深度等于保留数（2,048 或 512），边算边插，输出下标表；
- 一条"下标表 → gather"的 DMA 通路，和现有的多维 stride 通路并列；
- 一份独立的索引缓存，粒度 128 B（FP8）或 64 B（FP4），和主缓存分开分配。

三样都不是大改动，但都不是现有通路的参数化能覆盖的。top-k 单元尤其如此：它不是 GEMM，也不是向量归约，比较树的深度和保留数是硬连线的。归属记在 VPU 的流式比较结构上，与 5.6、10.1 同一口径。

# 第 11 章　量化归属

## 11.1 三代各存了什么精度

| 项 | V2-Lite | V3.2-Exp | V4-Flash |
|---|---|---|---|
| 权重 | BF16 | FP8 e4m3，128×128 块，ue8m0 scale | 非专家 FP8，专家 FP4 |
| 激活 | BF16 | 动态 FP8 | 动态 FP8 |
| KV 潜向量 | BF16 | BF16（参考实现的缓存 dtype） | FP8（前 448 维） |
| RoPE 维 | BF16 | BF16 | BF16 |
| 索引缓存 | — | FP8，128 B/token | FP4，64 B/压缩块 |
| 压缩器权重 | — | — | BF16（参考实现里按 fp32 存） |

## 11.2 三条规律

**RoPE 维永不量化。** 三代都保留 64 维 BF16。V4 的实现写得很直白：`act_quant(kv[..., :-rd], 64, ...)` 只处理非 RoPE 维，最后 64 维原样保留。原因不是精度不够，是旋转之后的相位误差会随位置线性放大——两个 token 的相对位置越远，量化噪声在点积里的贡献越大，而这正是长上下文最需要准确的地方。

**潜向量可以整块量化。** `c_KV` 是被 `kv_a_layernorm` 归一过的，数值分布稳定，按 64 或 128 元素一块做动态 scale 就够。V3.2 的权重块是 128×128，激活块是 64，两者不同——权重的块大是为了 amortize scale，激活的块小是因为激活的离群值更集中。

**FP4 需要先旋转。** V4 的索引器在量化前做了一次 Hadamard 旋转（`rotate_activation`），把能量摊到所有维度上，再按 32 元素一块做 FP4。没有这一步，FP4 的 4 个指数位会被少数大值吃掉，其余维度全部归零。主缓存的 448 维没有走这条路，仍用 FP8——FP4 只在"数值不要求准确、只要求排序正确"的索引器上用。

## 11.3 对硬件的含义

三代的量化差异落到执行单元上是三种需求：

- 反量化必须支持按块取 scale。V3.2 的 128×128 块意味着一次 MMA 的输入 tile 要配 2 个 scale（行块、列块各一）。写出前的按块量化归 DMA，随搬运计 0 MAC，与 8.2、10.1 同一口径。
- RoPE 之后的 64 维要走 BF16 通路，不能塞进 INT8 或 FP8 的 MAC。这要求 MAC 单元支持混合精度，或者把这 64 维单独拿出来在 VPU 上算。
- FP4 的 Hadamard 旋转是矩阵乘（`x·H/√n`），不是逐元素操作。它在 VPU 上是 n² 的工作量，在阵列上是一次小 GEMM。V4 只在索引器的 q 和压缩块上做，量级是 8,192×128 一次，可以接受；如果要用到主 KV 上，成本要重新算。

# 第 12 章　对芯片设计的结论与待验证清单

## 12.1 哪些设计活到了下一代

把三代逐项对照，能活过两次迭代的只有两条：

| 设计 | V2-Lite | V3.2-Exp | V4-Flash | 判定 |
|---|---|---|---|---|
| 512 维低秩潜向量 | 有 | 有 | 变成 MQA 的单头 KV | 形态变了，思想保留 |
| 解耦 RoPE（64 维单独存） | 有 | 有 | 有 | 唯一三代未动 |
| 每 token 1,152 B 缓存 | 有 | 有 | 换成按 r 压缩的块 | 被取代 |
| 推理期吸收 `kv_b` | 有 | 有 | 训练期就吸收，无 `kv_b` | 从"推理技巧"变成"权重形状" |
| 索引器稀疏选择 | 无 | 每层 top-2048 | 仅 r=4 层 top-512 | 从全局变成局部 |
| 逐层压缩比 | 无 | 无 | 0/4/128 | 新增 |
| 滑窗 | 无 | 无 | 128 token | 新增 |
| FP8 权重 | 无 | 有 | 非专家有 | 保留 |
| FP4 权重 | 无 | 无 | 专家 | 新增 |

"解耦 RoPE"活下来不是因为它精巧，是因为它没有替代品：只要还想用位置编码，就必须有一部分维度不能被压缩、不能被量化、不能被吸收。三代都在这一点上让步，说明它是硬约束。

"低秩潜向量"活下来但换了用法。V2/V3.2 是"潜向量 + 展开"，V4 是"潜向量就是 KV"。差别在于 `kv_b` 放在哪里：前者放在推理时，后者放在训练时。V4 的选择说明，当模型足够大、上下文足够长时，"省一次 GEMM"的收益比不上"少一条执行路径"的收益。

其余设计都是过渡形态。1,152 B 的固定缓存、每层都挂索引器、推理期吸收，都在 V4 被替换。判断一项设计是否会活到下一代，看它是否依赖"某一代的具体参数"，而不是看它省了多少。

## 12.2 对 Hive 该沉淀什么

不是 512，不是 576，是三条可配置的不变量：

**压缩率可配。** 缓存记录的长度、压缩比、是否重叠，都应该是参数而不是常量。V4 的 43 层用了三种配置，硬编码任何一种都会把另外两种挡在门外。

**RoPE 维单独存、单独算、不量化。** 这条三代一致，可以直接做成硬约束：压缩缓存分两段，内容段可按任意块量化，RoPE 段固定 BF16，走独立的 MAC 通路或 VPU。

**稀疏选择是可选通路，但地址生成要预留。** DSA 的 top-k 加 gather 在 3K 以下不划算，在 128K 以上是数量级的差别。Hive 不必默认开启，但 DMA 的地址生成要能表达"按下标表取行"，否则这条路永远补不上。

## 12.3 一个 1–2B 稠密模型换 MLA 值不值

以 Qwen3-0.6B 为参照：hidden 1,024、16 查询头、8 个 KV 头、每头 128 维、28 层、0.596 B 参数。

现状的 KV 是 `2×8×128×2 = 4,096 B/token/层`，28 层合计 114,688 B/token。换成经典 MLA（潜向量 512 + RoPE 64，16 头 × 192 维查询）：

| 项 | GQA（现状） | MLA | 变化 |
|---|---:|---:|---:|
| 每 token 每层 KV | 4,096 B | 1,152 B | 0.28× |
| 28 层 KV @4K | 0.47 GB | 0.13 GB | 0.28× |
| 28 层 KV @128K | 15.03 GB | 4.23 GB | 0.28× |
| 注意力权重 | 6,291,456 | 7,929,856 | +26% |
| 全模型参数 | 595,984,384 | 641,859,584 | +7.7% |
| 权重字节（BF16） | 1.19 GB | 1.28 GB | +8% |
| 注意力核心 MAC（只计 QK^T 与 PV） | `4,096·S` | `16,384·S` | 4× |

权重多 8%，注意力核心算力多 4 倍，换来 KV 少 72%。两本账逐档对照：

| S | GQA 每 token 字节 | MLA 每 token 字节 | 字节比 | GQA 算术强度 | MLA 算术强度 |
|---:|---:|---:|---:|---:|---:|
| 1,024 | 1.31 GB | 1.32 GB | 0.99× | 0.5448 | 0.8442 |
| 4,096 | 1.66 GB | 1.42 GB | 1.17× | 0.6413 | 1.7805 |
| 16,384 | 3.07 GB | 1.81 GB | 1.69× | 0.8059 | 4.5017 |
| 32,768 | 4.95 GB | 2.34 GB | 2.11× | 0.8796 | 6.6964 |
| 131,072 | 16.22 GB | 5.51 GB | 2.94× | 0.9633 | 11.0261 |
| 1,048,576 | 121.45 GB | 35.11 GB | 3.46× | 0.9951 | 13.7205 |

分子是 28 层合计的 MAC（权重投影加 `4,096·S` 或 `16,384·S` 的注意力核心），分母是每 token 权重字节加 28 层 KV 读。这张表给出的是一个窗口，不是一条结论：

- **2K 以下，MLA 字节略亏。** 权重多 0.092 GB，而 1K 上下文的 KV 只省 84.4 MB：1K 时两者 1.32 GB 对 1.31 GB，MLA 多 0.6%；2K 时 1.35 GB 对 1.43 GB，开始反超。
- **2K 到 32K，MLA 的字节一路领先，4K–16K 的幅度最大。** 4K 省 14.5%、16K 省 40.9%、32K 省 52.7%；到 128K 是 66.0%，1M 是 71.1%。每 1K token 的 KV 少 84.4 MB，是字节省额的唯一来源。
- **算力侧同时抬高。** 注意力核心从 `4,096·S` 涨到 `16,384·S`，28 层合计的 MLA MAC 是 GQA 的 1.56 倍（1K）到 3.99 倍（1M）；算术强度从 GQA 的 0.5448–0.9951 抬到 MLA 的 0.8442–13.7205。4K 时 MLA 每 token 2.52 GMAC、1.42 GB，GQA 1.07 GMAC、1.66 GB。
- **交叉点由 `MAC_MLA ÷ 字节_GQA` 与引擎的 MAC/B 配比决定。** 这个比值在 4K 是 1.52，16K 是 2.66，32K 是 3.17，66K 是 3.53，128K 是 3.75；跨过引擎配比之后 MLA 落到算力侧，换算见《硬件口径》。
- **容量上始终占优。** 1M 时 MLA 35.11 GB、GQA 121.45 GB，3.46 倍；后者在端侧根本放不下。

所以对端侧 1B 级稠密模型：上下文窗口落在 2K–32K 之间，换 MLA 在字节上省 5%–53%，算术强度 1.2–6.7 MAC/B；只做 2K 以内，不值得，字节反而多 0.6%；窗口做到 66K 以上，字节仍省 61%，但算术强度已经到 9.04 MAC/B，主导项完全落在算力侧。

这也解释了为什么这条路线只在大模型上兑现：V3.2 的 128 头让吸收态的潜空间点积有 128 行可填，核心 MAC 的 4 倍增幅被 61 层的宽度摊薄；1B 模型只有 16 个头，同样的 4 倍增幅直接落在算术强度上（4K 从 0.64 抬到 1.78 MAC/B），没有别的账可以摊。

| 项 | 状态 | 影响 |
|---|---|---|
| V2-Lite 逐张量 header | 未核对（镜像对 4 GB 分片返回 404） | 总参数 15,706,484,224 由 config 推导，与文件字节 2.000 交叉验证，误差 0.001% |

## 12.5 一句话

MLA 的持久遗产不是"512 维"这个数，而是把 KV 压成低秩潜向量、把 RoPE 维单独拎出来这两条；DSA 和逐层压缩比都是在潜向量之上叠的调度层，调度层会随代际更换，潜向量这条底没换过。

# MLA 三代：参数、每 token MAC、每 token 字节、算术强度的复现（纯 Python）

# ---- V2-Lite：27 层，hidden 2048，16 头，moe 64 选 6 + 2 共享 ----
L2, H2, M2 = 27, 2048, 1408
attn2 = 6_291_456 + 1_179_648 + 2_097_152 + 4_194_304 + 2048*2      # 13,767,168
moe2  = 8 * 3*H2*M2
dense2 = 3 * H2 * 10944
act2 = L2*(attn2 + 64*H2) + 26*moe2 + dense2 + 102400*H2            # 2,451,550,208

def mac2(S):
    core = (5_120 + 16) * S
    per_moe, per_dense = attn2 + core + moe2 + 64*H2, attn2 + core + dense2
    return (L2-1)*per_moe + per_dense + 102400*H2

# ---- V3.2-Exp：61 层，hidden 7168，128 头 ----
L3, H3 = 61, 7168
attn3 = (11_010_048 + 1_536 + 37_748_736 + 4_128_768 + 512
         + 16_777_216 + 117_440_512 + 2*H3)                         # 187,121,664
idx3  = 12_582_912 + 917_504 + 128 + 458_752                        # 13,959,296
moe3, dense3 = 9 * 3*H3*2048, 3 * H3*18432
act3 = L3*(attn3 + idx3 + 256*H3) + (L3-3)*moe3 + 3*dense3 + 129280*H3

def mac3(S, dsa):
    core = 40_960*S if not dsa else 40_960*2048 + 64*128*S + 64*S
    soft = 128*(S if not dsa else 2048)
    per = attn3 + idx3 + core + soft + moe3
    return (L3-3)*per + 3*(attn3 + idx3 + core + soft + dense3) + 129280*H3

# ---- V4-Flash：43 层，hidden 4096，64 头 × 512，256 选 6 + 1 共享 ----
H4, M4, HD, NH, RD = 4096, 2048, 512, 64, 64
ratios = [0, 0] + [4, 128]*20 + [4]                                 # 43 层
base4 = (H4*1024 + 1024 + 1024*NH*HD + H4*HD + HD
         + (NH*HD//8)*(8*1024) + 8*1024*H4 + NH + 2*H4)             # 106,964,544
comp  = lambda r: r*512*(2 if r == 4 else 1) + H4*512*(2 if r == 4 else 1)*2 + 512
idx_c = 4*(2*128) + H4*(2*128)*2 + 128
index = 1024*64*128 + H4*64 + idx_c                                 # 10,749,056
attn  = lambda r: base4 + (comp(r) + (index if r == 4 else 0) if r else 0)
exp4, hc4 = 3*H4*M4, 2*((2+4)*4*(4*H4) + (2+4)*4 + 3)
gate4 = 1_048_576 + 256

total4 = sum(attn(r) + hc4 + gate4 + 257*exp4 for r in ratios) + 129280*H4*2 + H4

def mac4(S):
    tot = 0
    for r in ratios:
        P = 128 + (0 if r == 0 else (min(512, S//4) if r == 4 else S//r))
        m = (H4*1024 + 1024*NH*HD + H4*HD + (NH*HD//8)*(8*1024)
             + 8*1024*H4) + 2*NH*HD*P + 2*24*4*H4 + NH*(P + 1)
        if r:
            m += H4*HD*(2 if r == 4 else 1)*2
            if r == 4:
                m += 1024*64*128 + H4*64 + H4*256*2 + NH*128*(S//4) + NH*(S//4)
        tot += m + 1_048_576 + 7*exp4
    return tot + 129280*H4

# ---- 字节：V2 全 BF16，V3 全 FP8，V4 专家 FP4 其余 FP8 ----
b2 = lambda S: act2*2 + L2*576*2*S
b3 = lambda S, dsa: act3*1.026 + L3*(576*2*S if not dsa else 128*S + 2048*576*2)
b4 = lambda S: (sum((attn(r) + hc4 + 256*H4)*1.031 for r in ratios)
                + 43*7*exp4*0.5 + 129280*H4*1.031
                + sum((128 + (min(512, S//4) if r == 4 else (S//r if r else 0)))*576
                      + ((S//4)*64 if r == 4 else 0) for r in ratios))

kv4 = lambda S: sum((128 + (min(512, S//4) if r == 4 else (S//r if r else 0)))*576
                    + ((S//4)*64 if r == 4 else 0) for r in ratios)
w4 = sum((attn(r) + hc4 + 256*H4)*1.031 for r in ratios) + 43*7*exp4*0.5 + 129280*H4*1.031

print(f"V2-Lite 流量账 {act2:,} 参数  权重 {act2*2:,} B")
print(f"V3.2    流量账 {act3:,} 参数  权重 {act3*1.026:,.0f} B")
print(f"V4      流量账 {sum(attn(r)+hc4+256*H4 for r in ratios)+43*7*exp4+129280*H4:,} 参数  权重 {w4:,.0f} B")

for S in (1, 4096, 131072, 1048576):
    print(f"S={S:>8} V2   {mac2(S):,} MAC  {b2(S):,} B  KV {L2*576*2*S:,} B  强度 {mac2(S)/b2(S):.4f}")
    print(f"          V3关 {mac3(S,0):,} MAC  {b3(S,0):,.0f} B  KV {L3*576*2*S:,} B  强度 {mac3(S,0)/b3(S,0):.4f}")
    print(f"          V3开 {mac3(S,1):,} MAC  {b3(S,1):,.0f} B  KV {L3*(128*S+2048*576*2):,} B  强度 {mac3(S,1)/b3(S,1):.4f}")
    print(f"          V4   {mac4(S):,} MAC  {b4(S):,.0f} B  KV {kv4(S):,} B  强度 {mac4(S)/b4(S):.4f}")

# ---- 单层：展开 A / 吸收 B / 现算 C，权重 BF16 ----
for S in (4096, 131072):
    soft = 16*S  # softmax，每头每位置 1 MAC
    A = 13_762_560 + 5_120*S + soft
    B = 21_102_592 + 17_408*S + soft
    C = 13_762_560 + 2_097_152*S + 5_120*S + soft
    bA, bB, bC = 13_762_560*2 + 8192*S, 21_102_592*2 + 1152*S, 13_762_560*2 + 1152*S
    print(f"单层 S={S:>6} A {A:,} MAC {bA:,} B 强度 {A/bA:.4f}  "
          f"B {B:,} MAC {bB:,} B 强度 {B/bB:.4f}  C {C:,} MAC {bC:,} B 强度 {C/bC:.4f}")

# ---- prefill：M=1024、平均上下文 2048，27 层合计 ----
pA = 27*(13_762_560*1024 + (5_120 + 16)*2048*1024)
pB = 27*(21_102_592*1024 + (17_408 + 16)*2048*1024)
print(f"prefill 1024 token 形态 A {pA:,} MAC  形态 B {pB:,} MAC")
