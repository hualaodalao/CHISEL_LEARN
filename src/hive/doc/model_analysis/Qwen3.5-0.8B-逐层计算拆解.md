# Qwen3.5-0.8B 逐层计算拆解

2026-10-29 ｜ 依据 `config.json`、权重清单（488 个张量，1,746,882,752 B）、`modeling_qwen3_5.py` 与 fla kernel 源码核对

## 摘要

Qwen3.5-0.8B 是视觉语言模型，总参数 873.44 M：文本主干 752.39 M、视觉塔 100.59 M、MTP 头 20.45 M。文本主干 24 层，按 3:1 交替放置 18 层 Gated DeltaNet 和 6 层 Gated Attention，每层挂一份 SwiGLU MLP，hidden 为 1024。

对芯片设计影响最大的几项：

- decode 每 token 读 0.776 GB 权重（MXFP8）。310 GB/s 下理论上限约 400 token/s，S=4096 时算上 KV 是 375，再按 60–70% 的实际效率折算是 225–263 token/s。decode 受带宽限制，prefill 受算力限制。
- 18 层 DeltaNet 的循环状态是 FP32、16×128×128/层，共 18.87 MB。这个数与 2B 完全相同，因为 head 几何没变；它不随模型缩小，所以 SRAM 下限也不会缩小。
- 每 token 的计算量 767 MMAC（1.53 GFLOP），算术强度 0.99 MAC/B，和 2B 的 0.98 几乎一样。同一个引擎规格可以同时服务两个模型。
- lm_head 占 decode 带宽的 33.8%，比 2B 的 27% 更高。词表不随 hidden 缩小，所以它在小模型里是第一个该优化的算子。
- KV cache 每 token 12 KB，和 2B 相同。权重变小之后，上下文超过约 63K 时 KV 流量就超过权重流量（2B 的门槛是 158K）。
- 0.8B 不是 2B 的等比缩小：hidden 砍半，但 DeltaNet 和 attention 的 head 几何原样保留，每层参数只降到 2B 的 35–37%。

后面按"模型事实、层结构、逐算子、算力与带宽、硬件映射、量化、结论"展开。

# 第 1 章　事实基线

## 1.1 数据来源与核对方法

这份拆解只依赖四类材料：官方仓库里的 `config.json`；单文件权重 `model.safetensors-00001-of-00001.safetensors` 的 header（可以读出每个张量的名字、形状、dtype，共 488 个）；`transformers` 里 `qwen3_5` 的建模代码；以及 `fla` 的 Triton kernel 源码。0.8B 和 2B 共用同一份建模代码，算子语义完全一致，差别只在维度。

核对方式有两条。第一，把 header 里所有张量的元素数加起来，得到 873,438,784；权重文件 1,746,882,752 B 除以 2（全 BF16）是 873,441,376，差 2,592 个参数，占 0.0003%。这 2,592 的缺口和 2B 模型一模一样，来自 header 对齐与张量边界，不是漏算。第二，逐层求和：18 个 DeltaNet 层各 21,555,360、6 个 attention 层各 18,352,640、加上共享的 embedding/lm_head 254,279,680，与 header 的分组统计逐位相符。

**这里有一个容易搞错的点：0.8B 的参数并不是 2B 按比例缩放出来的。** hidden 从 2048 降到 1024，但 DeltaNet 的 16 头 ×128 和 attention 的 8 头 ×256 没有变。固定 head 几何意味着这些层的投影矩阵宽度不变，只有 K 维（输入维）减半，所以每层参数只降到 2B 的 35–37%，而不是 50%。

# 第 2 章　模型全景

## 2.1 三个子模型

```
Qwen3.5-0.8B ─┬─ 文本主干  752.39 M ─┬─ 18 × DeltaNet 层   388.0 M
              │                     ├─ 6 × Attention 层   110.1 M
              │                     └─ embed / lm_head    254.3 M（共享）
              ├─ 视觉塔    100.59 M ─┬─ 12 × ViT block     85.1 M
              │                     ├─ patch_embed          1.2 M
              │                     └─ pos_embed + merger  14.4 M
              └─ MTP 头     20.45 M ─┬─ 1 × Attention 层    18.4 M
                                    └─ fc + 3 norms        2.1 M
```

三个子模型只有在多模态输入和投机解码时才同时出现。纯文本、不投机解码的推理只需要文本主干的 752.4 M 参数，MXFP8 下约 0.70 GB，这是端侧最省的主存配置。

## 2.2 文本主干的层型配比

24 层按 3:1 交替，第 3、7、11、15、19、23 层是全注意力，其余 18 层是 Gated DeltaNet。这个"每 4 层一个全注意力"的排布和 2B 完全相同。

| 层型 | 层数 | 每层参数 | 每层 MAC（decode） | 结构 |
|---|---:|---:|---:|---|
| A　Gated DeltaNet | 18 | 21.56 M | 22.37 M | 4 路融合投影 + 短卷积 + delta 递推 |
| B　Gated Attention | 6 | 18.35 M | 18.36 M（不含 KV 项） | q/k/v 投影 + RoPE + KV cache |
| C　SwiGLU MLP | 24（每层挂一份） | 11.01 M | 11.01 M | gate/up 双投影 + SiLU + down |

两种 layer 的参数只差 17%，但状态性质完全不同：DeltaNet 的状态大小固定（每层 1 MiB），attention 的 KV cache 随上下文线性增长。这个差别决定了片上 SRAM 和 DRAM 的分工。

## 2.3 计算形态的四个类别

模型里所有算子按计算形态只分四类，后面所有分析都基于这个分类：

| 类别 | 特征 | 本模型里的算子 | 典型维度 |
|---|---|---|---|
| 稠密矩阵乘（GEMM / GEMV） | 激活 × 权重 | 所有投影、lm_head、QKᵀ、A·V、视觉塔 GEMM | K 是读入维，N 是输出维，M 是 token 数 |
| 归约 | 沿一维求和或求最值 | RMSNorm、L2 norm、softmax | 1024 / 128 / S |
| 逐元素 | 同形状逐点 | SiLU、sigmoid、exp、门控乘、残差、RoPE | 任意 |
| 串行递推 | 后一步依赖前一步 | delta 状态更新 | 16 头 × 128×128 |

decode 时所有矩阵乘都退化成 M=1 的 GEMV，prefill 时是 M=S 的 GEMM。同一个算子在不同阶段的计算形态差别，比不同算子之间的差别还大，这一点在第 9 章会展开。

外加两个非计算类别：查表（embedding）和搬运（KV cache、量化 pass）。

## 3.2 层的通用骨架

两种层共用同一个模板，只有中间的 mixer 不同。归一化只读不写，残差加是唯一把结果写回主总线的地方。

```
x [1,1024]
 │
 ├─ 读出 ─► r = input_layernorm(x)  [1,1024]
 │            │
 │            ▼
 │          y = mixer(r)  [1,1024]        ← 层型 A（3.3）/ B（3.4）
 │            │
 └─ x = x + y ◄┘                          ← 残差 ①，唯一写回 x 的点
 │
 ├─ 读出 ─► r = post_attention_layernorm(x)  [1,1024]
 │            │
 │            ▼
 │          z = mlp(r)  [1,1024]          ← 子模块 C（3.5）
 │            │
 └─ x = x + z ◄┘                          ← 残差 ②
 │
输出 x [1,1024]（形状与输入完全相同）
```

**读图约定（第 3 章所有 DAG 通用）**

| 记号 | 含义 |
|---|---|
| `─►` / `──►` | 同 token 内的数据依赖，箭头上带计算 |
| `┄` / `┄┄►` | 纯视图（split / reshape / transpose），0 MAC，只改索引与 stride |
| `═` / `══►` | 跨 token 状态读写（`conv_state` / `recurrent_state` / KV cache） |
| `[G0]` `[G1]` … | 并行组：同组内互不依赖，可并发发射；组号小的必须先完成 |
| 横向分支 | 只表示并行关系，不表示时间先后；汇合点之前的所有分支都必须就绪 |

层内只有三种形状变换，其余都是逐元素：

| 变换 | 形状关系 | 例子 | 通道语义 |
|---|---|---|---|
| 稠密线性 | `[K] → [N]` | `in_proj_qkv` 1024→6144、`gate_proj` 1024→3584 | 全部通道混合，每个输出 = 全 K 维内积 |
| 逐元素 / 逐通道 | `[N] → [N]` | RMSNorm 缩放、SiLU、门控乘、残差加 | 一进一出，通道对齐 |
| 纯视图 | `[N] → [M₁]…[Mₖ]`（∏Mᵢ = N） | `split` 6144→3×2048、`reshape` 2048→16×128 | 不改数，只改索引 |

维度变化只有两种来源：中间隔了一次 GEMM（宽度等于学出来的读出方向个数），或者只是换了个视图（总元素数不变）。3.3–3.6 的每张图都按这条规则标注；`[G]` 编号在同一层内连续，跨层重新从 `G0` 开始。

残差流的宽度在整个 24 层中恒为 `[1024]`。这个宽度只有 2B 的一半，意味着每层的残差读写、归一化和逐元素开销也跟着减半，只有投影矩阵的 N 维保持不变。

## 3.3 层型 A：Gated DeltaNet（18 层）

DeltaNet 替代 attention 的方式，是把所有历史 token 压缩进一个固定的 `128×128` 状态矩阵，每来一个新 token 更新一次。head 数和维度与 2B 完全一样，变化的只是输入宽度。

子模块共 9 个，全部挂在 `linear_attn.*` 下：

| 张量 | 形状 | 作用 |
|---|---|---|
| `in_proj_qkv` | [6144, 1024] | 一次投影出 q、k、v（各 2048 维，拼在一起） |
| `in_proj_z` | [2048, 1024] | 输出门控 z（进 RMSNormGated 当 gate） |
| `in_proj_b` | [16, 1024] | 每头一个 β（写入门控） |
| `in_proj_a` | [16, 1024] | 每头一个 a（衰减率） |
| `conv1d` | [6144, 1, 4] | 深度可分离因果卷积，作用在拼好的 qkv 上，卷积后接 SiLU |
| `A_log` | [16] | 衰减率的可学习基（Mamba 式离散化），FP32 |
| `dt_bias` | [16] | 同上 |
| `norm` | [128] | `RMSNormGated`，按 head 的 value 维归一后乘 `silu(z)`，FP32 |
| `out_proj` | [1024, 2048] | 输出投影 |
| `input_layernorm` / `post_attention_layernorm` | [1024] | 骨架自带 |

独有的三个算子：

1. **融合 QKV 投影**：q/k/v 是一个矩阵一次算出来的，DMA 侧要按 2048/2048/2048 切分。
2. **短因果卷积 + SiLU**：跨 token 的局部感受野，需要保存前 3 个 token 的 qkv（滚动缓存）。
3. **门控 delta 递推**：`S ← S·diag(exp(g)) + β·kᵀ(v − S·k)`，每 token 更新一次全状态。

```
      │              │                    │                                 │

                       ▼

        ┌──────────────┴──────────────┐

 [G13] x = x + z2 ──► x [1,1024]
```

### 3.3.3 关键路径与并行机会

- 关键路径：`G0 → G1(qkv) → G2(conv) → G3 → G4 → G5 → G6 → G7 → G8 → G9 → G10 → G11 → G12 → G13`。
- `z`、`a`、`b` 三条支路不延长路径，但 `a`/`b` 的产物喂给 G5，必须与 G1 同批发射。它们是 16 维的 GEMV，单独做几乎没有意义，建议与 `in_proj_qkv` 合并成一次 6176 或 6208 输出的投影。
- 单层 22.37 M MAC 里 GEMM 占 96.3%，串行与逐元素占 3.7%。其中 delta 递推一项就占 3.5%——这个数在 2B 上是 1.3%，因为递推的算力与 hidden 无关，不会随模型缩小。
- 延迟上恰恰是这 3.7% 决定一切：delta 递推的 4 个 pass 依赖前一步的状态，没法展开。
- `conv_state` 只有 36 KB/层，`recurrent_state` 是 1 MiB/层。前者可以留在 SRAM 任意角落，后者必须占满整块 SRAM bank。
- 该层有 3 处跨 token：conv（读 3 个历史 token）、delta 递推（读改写全状态）、以及隐式的"状态跨 18 层串行"。前两处是访存，第三处是调度。

## 3.4 层型 B：Gated Attention（6 层）

Mixer 子模块 6 个，加上骨架自带 2 个：

| 张量 | 形状 | 作用 |
|---|---|---|
| `q_proj` | [4096, 1024] | 双宽：前半是 query（8×256），后半是输出门控 |
| `k_proj` | [512, 1024] | 2 个 KV 头 × 256 |
| `v_proj` | [512, 1024] | 同上 |
| `o_proj` | [1024, 2048] | 输出投影（在门控之后） |
| `q_norm` | [256] | 按 head_dim 归一，不是对整个输出 |
| `k_norm` | [256] | 同上 |
| `input_layernorm` / `post_attention_layernorm` | [1024] | 骨架自带 |

和 DeltaNet 相比多出三个算子：

1. 部分 RoPE：只转 256 维中的前 64 维（`partial_rotary_factor=0.25`），其余 192 维直接透传。
2. 因果 softmax：沿 S 维归约，FP32。
3. KV cache：每层每 token 写 2×256×2 = 1 KB（FP16）。

### 3.4.1 计算流（decode 单 token，依赖 DAG）

```
x [1,1024] ──► [G0] input_layernorm ──► r [1,1024]
                                          │
      ┌──────────────┬────────────────────┴────────────┐
      ▼              ▼                                 ▼
 [G1] q_proj     [G1] k_proj                      [G1] v_proj
      [1,4096]      [1,512]                          [1,512]
      │              │                                 │
      │ view(8,512)+chunk → q [1,8,256]                  ▼
      │              │                          [G2] 写 V cache
      ▼              ▼                          v_cache [1,2,S,256]
 [G2] q_norm    [G2] k_norm [1,2,256]            （供 G6）
      ▼              ▼
 [G3] RoPE      [G3] RoPE(64/256)
      │              ▼
      │         [G3] 写 K cache
      │         k_cache [1,2,S,256]（供 G4）
      │              │
      ▼              ▼
 [G4] Q·Kᵀ ◄════════┘
      │  s [1,8,1,S]
      ▼
 [G5] +因果 mask, softmax(FP32)
      │  p [1,8,1,S]
      ▼
 [G6] A·V ◄═ v_cache
      │  o [1,8,1,256] → [1,1,2048]
      ▼
 [G7] o ⊙ σ(gate) ◄── gate [1,2048]（G1 产出，全层驻留）
      │  [1,2048]
      ▼
 [G8] o_proj ──► y [1,1024]
      ▼
 [G9] x = x + y ──► x [1,1024]
      ▼
 [G10] post_attention_layernorm ──► r2 [1,1024] ──► MLP（3.5）
```

`q_proj` 的 4096 维在 G1 内就地拆成两支：`q [1,8,256]` 进 G2；`gate [1,2048]` 是旁路，一直驻留到 G7 才参与门控。这里的 2048 是 8 头 × 256，与 hidden 的 1024 无关——**门控向量比残差流还宽**，这是 0.8B 上的一个特殊之处。

### 3.4.2 逐算子映射表

| 组 | 算子 | 形状（in → out） | 数值变换 | MAC/token | 依赖 |
|---|---|---|---|---|---|
| G0 | input_layernorm | `[1,1024] → [1,1024]` | `x·rsqrt(mean(x²)+1e-6)·(1+w)` | 2,048 | x |
| G1 | q_proj | `[1,1024] → [1,4096]` | `y = W_q·r`；`view(…,8,512)` 后 `chunk(2)` → q `[8,256]`、gate `[8,256]` | 4,194,304 | G0 |
| G1 | k_proj / v_proj | `[1,1024] → [1,512]` | `k = W_k·r`、`v = W_v·r`；`view(…,2,256)` | 1,048,576 | G0 |
| G2 | q_norm / k_norm | q `[1,8,256]`、k `[1,2,256]` 不变 | 每头 256 维 `x·rsqrt(mean₂₅₆(x²)+1e-6)·(1+w)` | 1,024 | G1 |
| G3 | 部分 RoPE | 形状不变 | 前 64 维 half-split 旋转，后 192 维透传 | 1,280 | G2 |
| G3 | K cache 追加 | k → `[1,2,S+1,256]` | 纯搬运，K 已 norm、已旋转 | 0 | G3 |
| G2 | V cache 追加 | v → `[1,2,S+1,256]` | 纯搬运，V 未 norm、未旋转 | 0 | G1 |
| G4 | Q·Kᵀ | q `[1,8,1,256]` × k `[1,8,S,256]` → s `[1,8,1,S]` | `s = α·Σ_{d=0..255} q_d·k_d`，α = 1/16 | 2,048·S | G3 |
| G5 | 因果 mask + softmax | s → p `[1,8,1,S]` | `p = exp(s−m)/Σexp(s−m)`，FP32 | 8·S | G4 |
| G6 | A·V | p × v → `[1,8,1,256]` → `[1,1,2048]` | `o = Σ_{t=1..S} p_t·v_t` | 2,048·S | G5, G2(v) |
| G7 | 输出门控 | `[1,2048] × [1,2048] → [1,2048]` | `o_i ← o_i·σ(g_i)`，在 o_proj 之前 | 2,048 | G6, G1(gate) |
| G8 | o_proj | `[1,2048] → [1,1024]` | `y_o = Σ_i W_o[o,i]·c_i`，跨头混合 | 2,097,152 | G7 |
| G9 | 残差加 ① | `[1,1024]` | `x = x + y` | 1,024 | G8 |
| G10 | post_attention_layernorm | `[1,1024] → [1,1024]` | 同 G0 | 2,048 | G9 |

### 3.4.3 关键路径与并行机会

- 关键路径：`G0 → q_proj → q_norm → RoPE → Q·Kᵀ → softmax → A·V → 门控 → o_proj → 残差`。
- 三条并行支路：Q 支路（norm→RoPE）、K 支路（norm→RoPE→写 cache）、V 支路（直接写 cache）。K/V 不占关键路径，它们的代价体现在 G4/G6 的读取上。
- gate 的生命周期最长：G1 产出、G7 消费，中间跨 3 次矩阵乘和 softmax。每 token 4 KB 必须全层驻留。
- 有几处顺序是定义性的，不能重排：`q_norm` 在 transpose 之前，RoPE 在 KV 写入之前，门控在 `o_proj` 之前。顺序错不是精度问题，是语义错误。
- `repeat_kv` 是 stride-0 的逻辑视图，8 个 Q 头共享 2 个 KV 头。硬件若按 8 头各读一份 KV，G4/G6 的 KV 带宽直接变 4 倍。
- G5 是层内唯一逐行全 S 归约加超越函数。S=4096 时 6 层合计约 19.7 万次 exp，比同层所有 GEMM 的和还慢，是 attention 的延迟核心。
- decode 时 G4/G6 是 M=8、K=S 的 GEMV，算力利用率不到 10%，受 KV 带宽支配；prefill 时它们变成 `S×S×256` 的 GEMM，mask 也变成 `S×S`，整层形态完全不同。

## 3.5 子模块 C：SwiGLU MLP（24 层各挂一份）

| 张量 | 形状 | 作用 |
|---|---|---|
| `mlp.gate_proj` | [3584, 1024] | 门控分支 |
| `mlp.up_proj` | [3584, 1024] | 值分支 |
| `mlp.down_proj` | [1024, 3584] | 回投到 1024 |

计算：`y = down( silu(gate(x)) ⊙ up(x) )`

24 层完全同构，是模型里最规整、最适合先优化也最适合先量化的部分。它占单层参数的 51%（DeltaNet 层）到 60%（attention 层），也是唯一一处 N 维（3584）明显宽于 hidden 的算子。

```
r [1,1024] ──► [M1] post_attention_layernorm ──► r' [1,1024]
                                                    │
                 ┌──────────────────────────────────┴───────────────┐
                 ▼                                                  ▼
        [M2a] gate_proj [1,3584]                          [M2b] up_proj [1,3584]
                 │                                                  │
                 ▼                                                  │
        [M3] silu(g) [1,3584]                                      │
                 │                                                  │
                 └──────────────────┬───────────────────────────────┘
                                    ▼
                        [M4] h = silu(g) ⊙ u [1,3584]
                                    ▼
                        [M5] down_proj ──► z [1,1024]
                                    ▼
                        [M6] x = x + z ──► x [1,1024]
```

M2a 与 M2b 是唯一可并行的两支，它们共用同一个 1024 维输入。M3 的 SiLU 是逐元素超越函数，3584 次/层/ token，24 层合计 86,016 次。M4 是逐元素乘。M5 的 K 维是 3584，比其它投影的 1024 长 3.5 倍，是层内单算子 MAC 第三大的项。

## 3.6 层型 D：MTP 头（1 层，仅投机解码）

MTP 由四部分组成：输入融合、一个完整的 attention 层、输出归一化、共享 lm_head。

| 张量 | 形状 | 作用 |
|---|---|---|
| `pre_fc_norm_hidden` | [1024] | 归一化上一层的 hidden |
| `pre_fc_norm_embedding` | [1024] | 归一化上一 token 的 embedding |
| `mtp.fc` | [1024, 2048] | 把两个 1024 维拼起来压回 1024 |
| `mtp.layers.0` | 同层型 B | 完整全注意力层（含 KV cache） |
| `mtp.norm` | [1024] | 输出归一化 |

```
h_prev [1,1024] ─► [D1] pre_fc_norm_hidden ─┐
                                            ├─ concat [1,2048] ─► [D3] fc ─► [1,1024]
e_prev [1,1024] ─► [D2] pre_fc_norm_embedding ┘                             │
                                                                            ▼
                                        [D4] layers.0（全注意力，同 3.4）─► [1,1024]
                                                                            ▼
                                        [D5] mtp.norm ─► 共享 lm_head ─► logits [248320]
```

MTP 层用的是全注意力而不是 DeltaNet，所以它自己也有一份 KV cache（2 头 × 256）。每个草稿 token 还要跑一遍 254.28 M 的 lm_head，这一点决定了投机解码的真实收益，第 6.4 节会算。

## 3.7 层间差异速查

| 问题 | 答案 |
|---|---|
| 18 层 DeltaNet 之间有区别吗 | 没有。张量名、形状、算子顺序完全一致 |
| 6 层 Attention 之间有区别吗 | 没有。同上 |
| 24 个 MLP 之间有区别吗 | 没有。都是 [3584,1024]×2 + [1024,3584] |
| DeltaNet 和 Attention 的本质区别 | 状态传递方式：固定 128×128 状态 vs 增长的 KV cache |
| 位置信息怎么进来 | Attention 层用 RoPE；DeltaNet 层没有 RoPE，靠短卷积和递推隐式携带 |
| 哪些层有跨 token 状态 | 全部 24 层：DeltaNet 有 conv_state 和 recurrent_state，Attention 有 KV cache |
| 0.8B 与 2B 的层结构有区别吗 | 没有。所有算子、顺序、head 几何都相同，只有 K 维（1024 vs 2048）和 MLP 宽度（3584 vs 6144）不同 |

## 3.8 单层内部张量流（以 layer 0 为例）

这一节给硬件和测试用，逐行追踪 layer 0 的形状变化（decode，S 为当前上下文）。`[G]` 编号与 3.3.1 对应，`┄` 表示纯视图，`═` 表示跨 token 状态。

```
x                        [1, 1024]          ← 残差流
│
├ [G0] input_layernorm ► r  [1, 1024]                      归约 1024
│
├ [G1] in_proj_qkv ─────► qkv [1, 6144]                    GEMM 1024×6144  ┐
├ [G1] in_proj_z ───────► z   [1, 2048]                    GEMM 1024×2048  │ 四路
├ [G1] in_proj_a ───────► a   [1, 16]                      GEMM 1024×16    │ 并行
├ [G1] in_proj_b ───────► b   [1, 16]                      GEMM 1024×16    ┘
│
├ [G2] conv1d(+SiLU) ───► qkv' [1, 6144]                   深度卷积 4 taps
│     └ ═conv_state [6144, 3]
├ [G2] β = sigmoid(b)  [16]                               逐元素
├ [G2] g = −exp(A_log) · softplus(a + dt_bias)  [16]       FP32
│
├ [G3] split ┄──────────► q,k,v 各 [1, 16, 128]            0 MAC（纯视图）
│
├ [G4] L2 norm(q), L2 norm(k)                             归约 128 ×32
│
├ [G5] gated delta rule ─► o_core [1, 16, 128]             逐头矩阵-向量
│     └ ═recurrent_state [16, 128, 128]  ← 262,144 元素
│
├ [G6] RMSNormGated(o_core, z) ─► [1, 2048]                归约 128 ×16 + silu
├ [G7] out_proj ────────────► y [1, 1024]                  GEMM 2048×1024
│
x = x + y  [G8]             [1, 1024]                      逐元素
│
├ [G9] post_attention_layernorm ► r [1, 1024]              归约 1024
├ [G10] gate_proj ──────► g [1, 3584]                      GEMM 1024×3584  ┐并行
├ [G10] up_proj ────────► u [1, 3584]                      GEMM 1024×3584  ┘
├ [G11] silu(g) ⊙ u ────► h [1, 3584]                      逐元素 + exp
├ [G12] down_proj ──────► z [1, 1024]                      GEMM 3584×1024
│
x = x + z  [G13]            [1, 1024]                      逐元素
```

**并行结构速查（decode）**

| 并行组 | 内容 | 性质 |
|---|---|---|
| G0 | `input_layernorm` | 单点，1024 宽归约 |
| G1 | `in_proj_qkv` / `in_proj_z` / `in_proj_a` / `in_proj_b` | 四路同时读同一个 r，互不依赖 |
| G2 | `conv1d` / `β` / `g` | conv 等 qkv，β 等 b，g 等 a，三者可并发 |
| G3 | `split` | 纯视图，依赖 conv 输出 |
| G4 | `L2 norm(q)`, `L2 norm(k)` | 两条 128 宽归约，可并发 |
| G5 | `gated delta rule` | 汇合点：等 q̂/k̂（G4）、v（G3）、β/g（G2） |
| G6 | `RMSNormGated` | 汇合点：等 o_core（G5）与 z（G1，存活最久） |
| G7–G13 | `out_proj` → 残差 → 后置归一 → `gate/up` → SwiGLU → `down` → 残差 | 只有 G10 两路并行，其余严格串行 |

对硬件和测试最直接的三点：

1. 关键路径是 `G0 → G1(qkv) → G2(conv) → G3 → G4 → G5 → G6 → G7 → G8 → G9 → G10 → G11 → G12 → G13`。`z`、`a`、`b` 三条支路不延长路径，但 `a`/`b` 的产物喂给 G5，必须与 G1 同批发射。
2. 测试向量的切分点就在 `[G]` 边界：组之间是完整的张量落盘点，组内是并行算子。做 per-op 对拍时，按 G0–G13 各存一份参考值，就能定位到具体算子。
3. 只有 G2 与 G5 跨 token，其余都是 token 内计算。跨 token 状态（`conv_state` 36 KB 加 `recurrent_state` 1 MiB）只在这两处读写，也是仅有的两个无法靠并行隐藏的点。

# 第 5 章　通用算子库

全模型只用到 5 个通用算子：RMSNorm、RMSNormGated、SiLU/SwiGLU、因果深度卷积、部分 RoPE。后面任何一层都是这几个算子的排列组合。

它们都上不了矩阵引擎，原因相同：没有 K 维归约加规整访存的结构，要么是行内归约（RMSNorm），要么是跨 token 滑窗（conv），要么是跨 lane 置换（RoPE）。

三条量化边界需要记住：增益是 `1+w` 而不是 `w`；`silu` 只能留在 FP16 走 LUT；RoPE 角度必须用 FP32 算，256K 上下文下建议 FP64 或整数 mod 2π。

decode 一个 token 的调用次数：归一 79 次（24 层 × 2 加 final norm，另有 6 次 q/k norm 与 18 次 RMSNormGated），SwiGLU 24 次，深度卷积 18 次，RoPE 6 次。

## 5.1 RMSNorm（zero-centered，Qwen 特有）

**作用**：按行归一化，再乘一个可学习的逐通道增益。
**公式**：

```
y_i = x_i · rsqrt(mean(x²) + ε) · (1 + w_i),   ε = 1e-6
```

注意增益是 `1 + w`，不是 `w`。初始化时 `w = 0`，等价于恒等缩放。硬件若按标准 RMSNorm 实现（乘 `w`），权重需要预加 1，否则整层输出被压到接近 0。

**形状**：`[1,1024] → [1,1024]`，归约维 1024。
**MAC**：2 × 1024 = 2,048（平方和一次、缩放一次）。24 层 × 2 次 + final 1 次 = 49 次/ token，合计约 10 万 MAC，可以忽略。
**精度**：平方和用 FP32 累加，1024 个 FP16 平方直接相加会损失约 3 位；归一后的值再降回 FP16。
**坑**：

1. `1+w` 的偏移必须在权重打包时处理。这是 Qwen 系模型和 Llama 系最大的实现差异，也是移植时最常见的静默错误。
2. 归约宽度只有 1024，一条 1024 宽的加法树，延迟约 10 级流水。它出现在每层的入口，是流水线的固定开销，不能省。
3. final norm 与 24 层的 norm 是同一个算子，只是没有后续残差。硬件复用同一单元，不要单独做一份。

## 5.2 RMSNormGated（DeltaNet 专用）

**作用**：在 DeltaNet 的递推输出上做 per-head 归一，再乘输出门控。
**公式**：

```
o_h = (RMSNorm(o_core_h) · w) ⊙ silu(z_h),   h = 0..15，每头 128 维
```

**形状**：`[1,16,128] × [1,16,128] → [1,2048]`。
**MAC**：每头 3 × 128 = 384（平方和、缩放、门控乘），16 头 6,144，加 silu 的 2,048，共 8,192。
**精度**：归约在 FP32 里做，`w` 是 FP32 权重（header 里 `linear_attn.norm.weight` 就是 FP32）。`silu(z)` 用 FP16 LUT。
**坑**：

1. 归约是按 head 做的，不是按 2048 整行。16 个 128 宽的归约可以完全并行，但输出必须按 head 顺序拼回 2048。
2. `w` 只有 128 个值，被 16 个头共用。它在 SRAM 里占 512 B，但要保证 16 路广播。
3. 门控 `z` 来自 `in_proj_z`，在 G1 产生、G6 消费，中间跨整个递推。这是层内生命周期最长的一份数据（2 KB）。

## 5.3 SwiGLU / SiLU

**作用**：MLP 的门控激活。`silu(x) = x·sigmoid(x)`。
**公式**：

```
h = silu(W_gate·r) ⊙ (W_up·r)
y = W_down·h
```

**形状**：`[1,1024] → [1,3584] ⊙ [1,3584] → [1,1024]`。
**MAC**：门控乘 3,584/层，24 层 86,016；SiLU 本身也算一次超越函数，24 层共 86,016 次 exp。
**精度**：SiLU 的负半轴把误差放大（`silu(−8) ≈ −2.7e-3`，而输入误差被 sigmoid 的斜率放大），必须 FP16。FP8 的 E4M3 在负半轴相对误差可达 6%，直接毁掉小激活。
**坑**：

1. `silu` 是层内出现次数第二多的超越函数（第一是 softmax 的 exp，但那只在 6 层）。用 LUT 实现时表大小按 FP16 索引算，16K 项 × 16 bit = 32 KB。
2. 门控乘必须在 SiLU 之后、down_proj 之前，顺序反了语义就变了。
3. 3584 维是 1024 的 3.5 倍，逐元素单元按 3584 宽设计，不要按 hidden 设计。这一点在 0.8B 上尤其容易踩：hidden 只有 1024，但 MLP 中间层是 3584。

## 5.4 因果深度卷积 + SiLU（DeltaNet 专用）

**作用**：在 qkv 上做 4-tap 的深度可分离卷积，给 DeltaNet 补一个局部感受野。
**公式**：

```
y_c,t = silu( Σ_{j=0..3} W[c,j] · x_c,t−3+j ),   c = 1..6144，逐通道独立
```

**形状**：`[1,6144] + state[6144,3] → [1,6144]`。
**MAC**：6144 × 4 = 24,576/层/ token。
**精度**：FP16 足够，`silu` 之后的值域受控。但 conv 权重不要量化到 FP8 的 MX 块结构——它是跨 token 的，块内 32 个元素的时间相关性会被块缩放破坏。
**坑**：

1. 状态是 `[6144,3]`，每 token 滚动一次。写回时要把状态整体左移一格，这是 36 KB 的读改写，不能只写新值。
2. `conv1d` 权重形状是 `[6144,1,4]`，group = 6144，是真正的 depthwise，不是普通卷积。
3. 卷积之后的 SiLU 是 6144 次，比 MLP 的 3584 次还多，属于容易被漏算的逐元素开销。
4. 它和 delta 递推一样跨 token，是 decode 时仅有的两个状态读写点之一。

## 5.5 部分 RoPE（attention 专用）

**作用**：给 Q/K 注入位置信息。只旋转 head_dim=256 的前 64 维，后 192 维原样透传（`partial_rotary_factor=0.25`）。
**公式**：

```
θ_i = pos / 1e7^(i/32),   i = 0..31
q'_i      = q_i      · cos θ_i − q_{i+32} · sin θ_i
q'_{i+32} = q_{i+32} · cos θ_i + q_i      · sin θ_i
q'_j = q_j,   j = 64..255（透传）
```

**形状**：`q [1,8,S,256]`、`k [1,2,S,256]`；`cos/sin [S,64]`（32 个角度被复制成 64 份，所以 `cos[i] == cos[i+32]`）。
**MAC**：每对 4 次乘加。q 是 8 × 32 × 4 = 1,024，k 是 2 × 32 × 4 = 256，合计 1,280/层/ token，6 层 7,680。
**精度**：角度在 FP32 里算（`position_ids.float() * inv_freq`），算完再降到模型 dtype。旋转本身 FP16 可接受。
**坑**：

1. half-split 不是 interleaved。`rotate_half` 把向量劈成前后两半再配对：`(q_0, q_32)、(q_1, q_33)…`。按 interleaved 实现不会报错，只会让模型答非所问。
2. `pos` 必须是整数、角度必须 FP32。在 262144 位置上 FP16 的 `pos` ulp 是 0.25，角度误差 0.25 rad，旋转完全失效。
3. cos/sin 表不要预存。512 B/位置，S=4096 是 2.1 MB，S=262144 是 134 MB。现算每 token 只有 32 对 sin/cos，约 1.3 µs。
4. mRoPE 在纯文本下是恒等变换：三组 pos 相同，`[11,11,10]` 的交错退化为复制。但支持图像时必须原样实现（32 = 11+11+10，正好用满 64 维的一半）。
5. cos/sin 要 broadcast 到 8 个 q head，8 个头共享同一份 512 B，不要每个头各算一遍。

# 第 6 章　四种层型的逐算子拆解

这一章把 4 种层型拆成算子卡（A①–A⑭ / B①–B⑫ / M1–M6 / D1–D8）。每张卡的字段固定：作用、形状、MAC、精度、坑。MAC 统计包含逐元素与归约，只排除纯视图算子——这样表的每一行都能直接相加，与第 8 章的总账对上。

两个前提先说清楚。层型 A 的算力 96.3% 在 GEMM，3.7% 在串行和逐元素，但延迟上那 3.7% 决定一切。层型 B 的成本重心不在权重而在 S：S=4096 时 `QKᵀ` 加 `A·V`（16.78 M）已经和四个投影之和（7.34 M）拉开两倍。

## 6.1 层型 A：Gated DeltaNet（18 层）

### A① 前置 RMSNorm

| 项 | 内容 |
|---|---|
| 形状 | `[1,1024] → [1,1024]` |
| MAC | 2,048 |
| 归属 | VPU（1024 宽归约） |
| 精度 | 平方和 FP32，输出 FP16 |
| 坑 | 增益是 `1+w`；这是每层固定的流水线入口开销 |

### A② 融合 QKV 投影

| 项 | 内容 |
|---|---|
| 形状 | `[1,1024] → [1,6144]` |
| MAC | 6,291,456（占本层 28.1%） |
| 归属 | 矩阵引擎，MXFP8 |
| 精度 | 权重 MXFP8，激活 MXFP8，输出 FP32 再切段 |
| 坑 | q/k/v 三段各 2048，DMA 落盘要按 2048 切；6144 = 6 × hidden，是层内最宽的投影 |

这是单层最大的一笔 MAC。K 维只有 1024，N 维 6144，decode 时是 M=1 的 GEMV，算术强度 = 6,291,456 MAC / 6.49 MB ≈ 0.97 MAC/B，仍然卡在带宽上。

### A③ 输出门控投影

| 项 | 内容 |
|---|---|

| MAC | 2,097,152（9.4%） |
| 归属 | 矩阵引擎，MXFP8 |
| 精度 | 输出 FP16（直接进 SiLU） |
| 坑 | 2048 = 16 × 128，与 `in_proj_qkv` 的 v 段完全同形；DMA 可以共享切分模板 |

### A④ 衰减与写入门控投影

| 项 | 内容 |
|---|---|
| 形状 | `[1,1024] → [1,16]` × 2 |
| MAC | 32,768（0.15%） |
| 归属 | 建议并入 A②，不单独发射 |
| 精度 | 输出 FP32 |
| 坑 | N=16 的 GEMV 在矩阵引擎上利用率极低；单独做等于白占一次 DMA 和一次发射 |

这两路是 16 维的瘦长矩阵。单独做时，1024×16 的 GEMV 只用到引擎的 1/64 行，实际耗时几乎等于一次完整发射的固定开销。合并进 `in_proj_qkv`（输出 6176 或 6208 维，取整到 64 的倍数）是更合理的做法。

### A⑤ 因果卷积 + SiLU

| 项 | 内容 |
|---|---|
| 形状 | `[1,6144] + state[6144,3] → [1,6144]` |

| 归属 | VPU + 状态缓存 |
| 精度 | FP16 |
| 坑 | 跨 token；状态整体左移是读改写；不能上 MX 块量化 |

### A⑥ β（写入门控）

| 归属 | VPU |

### A⑦ g（衰减）

| 项 | 内容 |
|---|---|
| 形状 | `[1,16] → [1,16]` |
| MAC | 16（exp + softplus） |
| 归属 | VPU，FP32 |
| 精度 | 必须 FP32 |
| 坑 | `g = −exp(A_log) · softplus(a + dt_bias)`；`A_log` 与 `dt_bias` 是参数，不能量化，exp 会放大相对误差 |

`A_log` 在 header 里是 FP32，`dt_bias` 是 BF16。前者必须保持 FP32，后者可以在打包时升到 FP32 使用。这两项加起来只有 32 个值，但决定了 18 层的状态衰减曲线。

### A⑧ split（纯视图）

### A⑨ L2 norm(q), L2 norm(k)

| 项 | 内容 |
|---|---|

| MAC | 8,192 |
| 归属 | VPU，32 条 128 宽归约 |
| 精度 | FP32 累加 |
| 坑 | 32 条归约宽度只有 128，比 RMSNorm 的 1024 窄得多，必须靠并行度撑带宽 |

### A⑩ gated delta rule

| 项 | 内容 |
|---|---|
| 形状 | q̂,k̂,v,β,g → `[1,16,128]` |
| MAC | 786,432（3.5%，2B 上是 1.3%） |
| 归属 | VPU / 专用状态单元，不能上矩阵引擎 |
| 精度 | 状态 FP32，永不量化 |
| 坑 | 4 个依赖 pass 串行；每层 1 MiB 状态读写；18 层串行 |

这是整个模型唯一真正的串行核心。每 token 对 16 个头各自的 128×128 状态做"衰减 → 读出预测 → 残差修正 → 写回 → 再读出"：

```
S ← S · diag(e^g)              (衰减)
p  = Sᵀ · k                    (读出预测，128×128 matvec)
δ  = v − p                     (残差)
S ← S + β · k ⊗ δ              (秩 1 更新)
o  = Sᵀ · q̂                    (读出)
```

三次 matvec 各 16 × 128 × 128 = 262,144，合计 786,432。衰减是 262,144 次逐元素乘，通常折进 matvec 的读改写里，不单列。16 个头可以并行，但 5 个步骤之间是硬依赖，每 token 至少 5 拍串行。

`delta` 的含义：`v − Sᵀk` 是当前状态对该 token 的预测残差。普通线性注意力直接写 `v`，会把已记住的信息重复写一遍；delta rule 只写修正量，等价于对状态做一次在线梯度下降。这是 DeltaNet 记忆容量高于普通线性注意力的原因，也是它的状态必须保持 FP32 的原因——状态的数值范围跨 18 层累积，FP16 会溢出。

### A⑮ 硬件归属：哪些能上 MXFP8 矩阵引擎

| 算子 | 能否上引擎 | 原因 |
|---|---|---|
| A② `in_proj_qkv` | 最佳目标 | 纯 GEMM `1×1024×6144`，K=1024 够深 |
| A③ `in_proj_z` | 最佳目标 | 同上，`1×1024×2048` |
| A④ `in_proj_a/b` | 不划算 | N=16，建议并入 A② |
| A⑤ `conv1d` | 不能 | depthwise + 跨 token 滑窗 |
| A⑥⑦ β/g | 不能 | 16 维逐元素 + 超越函数 |
| A⑨ L2 norm | 不能 | 行内归约 |
| A⑩ delta 递推 | 不能 | 串行、状态常驻，累加器结构不匹配 |
| A⑪ RMSNormGated | 不能 | 归约 + 门控 |
| A⑫ `out_proj` | 最佳目标 | `1×2048×1024`，K 最长 |

### A⑯ 精度预算表

|---|---|---|---|---|

### A⑰ 实现/测试坑（按优先级）

1. **`in_proj_a/b` 单独发射**。N=16 的两条 GEMV 会吃掉与 6144 维投影相同的固定开销，实测可能让单层耗时多 15–20%。合并投影是必做项。
2. **`conv_state` 的滚动写**。只写新值不左移，会让卷积用错历史；这个错误在单 token 测试里看不出来，只有在连续 decode 的第 4 个 token 之后才暴露。
3. **delta 状态落 DRAM**。每 token 多 37.7 MB 流量，同时把 5 拍串行变成 5 次 DRAM 往返，延迟直接翻倍。
4. **`g` 用 FP16 算**。`softplus(a+dt)` 在 `a` 接近 0 时斜率 0.5，FP16 的相对误差会经由 exp 放大成百分比级的衰减率误差。
5. **RMSNormGated 按整行归约**。按 2048 归约会得到完全不同的数值，且不会报错。
6. **把 MLP 的 3584 当成 1024 的倍数做 tile**。3584 = 3.5 × 1024，tile 切分要按 3584 的因数（如 448 或 512×7），否则尾部浪费 12.5%。

### 6.2.5 十个必须记住的坑（按危害排序）

1. **`repeat_kv` 按 4 倍读**。8 个 Q 头共享 2 个 KV 头，硬件若各读一份，S=32K 时 KV 带宽从 402 MB 变成 1.6 GB，直接吃掉整个 token 预算。
2. **softmax 用 FP16**。S=4096 时行最大值和指数和都在 FP16 边界上，噪声会经 p 放大。
3. **p 量化到 FP8**。p 集中在 [0, 0.05]，E4M3 在 denormal 区相对误差 6%，且加权平均不会抵消系统偏差。
4. **gate 只存一段**。q_proj 的 4096 维要在 DMA 落盘时就分两段存，否则 G7 时还要回头找。
5. **RoPE 在 KV 写入之后做**。写进 cache 的必须是已旋转的 K，否则每次读取都要重算，S=32K 时相当于多算 32K 次旋转。
6. **q_norm 在 transpose 之前**。顺序反了归一化的轴就错了，而且形状仍然对得上。
7. **KV cache 用 BF16**。FP16 和 BF16 都行，但不要混：K 和 V 精度不一致会让 p 的分布偏斜。
8. **attention scaling 放在 softmax 之后**。α=1/16 必须在 exp 之前乘，放在之后等价于对 p 做非线性变换。
9. **S=1 时走 GEMV 路径**。decode 的 QKᵀ 是 8×S×256，S=1 时是 8 个 256 维点积，用矩阵引擎会浪费 99% 的行。
10. **MTP 层也要 KV cache**。投机解码时 MTP 是第 25 层 attention，漏掉它的 KV 会让验证 pass 语义错误。

### 6.2.6 与其它章节的接口

- A⑮ 的引擎准入表与本节的 6.2.4 合并，就是第 10 章的分类矩阵。
- 本节的 per-token 带宽 18.92 MB 是第 8.2 节三元组中的一项。
- KV cache 的三档数值是第 8.3 节缓存账的直接输入。
- B⑧ 的串行归约是第 10.2 节"两处真串行"之一。

### D6 投机解码的数学

记 α 为单 token 接受率、γ 为草稿长度，理想加速比是 `1/(1−α)`。这个式子只在 γ→∞ 且草稿免费时成立。真实成本要算草稿 token 的权重读取：每个草稿 token 要跑一遍 MTP 层（20.45 M 参数，21.1 MB）加一遍 lm_head（254.28 M 参数，262.2 MB），合 283.3 MB。

| 方案 | 每步权重流量 | 期望产出 | 加速比 |
|---|---:|---:|---:|
| 无投机 | 0.776 GB | 1.00 | 1.00× |
| γ=2，共享 248K 词表 | 0.776 + 2×0.283 = 1.342 GB | 2.19 | **1.27×** |
| γ=3，剪枝 8K 草稿头 | 0.776 + 3×0.030 = 0.865 GB | 2.53 | **2.27×** |

α=0.7 时 `E[emitted] = (1−α^{γ+1})/(1−α)`：γ=2 得 2.19，γ=3 得 2.53。

差别全在草稿头。共享 248K 词表时，每个草稿 token 都要读 262 MB 的词表权重，草稿成本几乎等于一次完整 token，收益被吃掉一半。剪枝到 8K 词表后草稿头只有 8.65 MB，加速比才接近理论值。

**第二个约束在算力侧。** 若规划了投机解码，验证 pass 一次要吃 γ+1 个 token，算力 ×(γ+1)。γ=3 时每步 4 × 767.05 = 3.07 GMAC，配 0.865 GB 流量，算术强度 3.55 MAC/B，引擎需要 ≥1.10 TMAC/s 才不成为新瓶颈——比 M=1 的 306 GMAC/s 高 3.6 倍。要不要规划投机解码，直接决定引擎规格。

### D7 拒绝时的回滚要求

验证失败时，被拒的草稿 token 不能留下任何副作用。硬件必须支持：

1. **状态快照**：接受前把 18 层 `recurrent_state`（18.9 MB）与 `conv_state` 存一份。全量快照 19.5 MB，在 SRAM 里放不下两份，只能存被接受位置之前的增量。
2. **KV 截断**：把 6 层（加 MTP 一层）的 KV 长度回退到已接受的位置。cache 是追加写的，截断只需改长度寄存器，但已被覆盖的槽位要能重写。
3. **增量快照的代价**：如果每层都做全量快照，步成本 +19.5 MB 读写，相当于权重流量的 2.5%，可以接受；如果每层做细粒度增量，逻辑复杂度上去了但流量可忽略。

# 第 7 章　视觉塔与输出头

视觉塔是标准的 ViT：12 个 block，hidden 768，12 个 64 维 head，patch 16，2×2 merge。它和文本主干的计算形态完全不同——一张图只跑一次，M=784，算术强度 784 MAC/B，是 decode 的 800 倍。同一个引擎，两种差三个数量级的使用方式。

## 7.1 视觉塔结构

| 张量 | 形状 | 参数 |
|---|---|---:|
| `patch_embed.proj` | [768, 3, 2, 16, 16]（+bias） | 1,180,416 |
| `pos_embed` | [2304, 768] | 1,769,472 |
| 12 × block（qkv/proj/fc1/fc2 + 4 norm + bias） | 见下 | 85,054,464 |
| `merger.norm` | [768] × 2 | 1,536 |
| `merger.linear_fc1` | [3072, 3072]（+bias） | 9,440,256 |
| `merger.linear_fc2` | [1024, 3072]（+bias） | 3,146,752 |
| **合计** | | **100,592,896** |

单 block 的 7,087,872：`qkv` [2304, 768] 1,769,472、`proj` [768, 768] 589,824、`fc1` [3072, 768] 2,359,296、`fc2` [768, 3072] 2,359,296，加 bias 6,912 和两个 LN 的 3,072。

448×448 的输入切成 28×28 = 784 个 patch（temporal 2 把两帧拼进通道），过 12 个 block 后再按 2×2 合并成 196 个视觉 token，投影到 1024 维接进文本主干。`pos_embed` 支持 48×48 = 2304 个位置，448² 只用到其中 784 个，直接裁剪，不需要插值。

## 7.2 视觉塔逐算子拆解（V①–V⑩）

|---|---|---|---:|---|
| V① | `patch_embed` | `[784, 3×2×16×16] → [784, 768]` | 924.8 M | 矩阵引擎 |
| V② | `+ pos_embed` | `[784, 768]` | 0（逐元素加） | VPU |
| V③ | LN1 / LN2 | `[784, 768]` × 24（12 block × 2） | 14.5 M | VPU，FP32 统计 |

| V⑥ | softmax | `[12, 784, 784]` | 88.5 M | VPU，FP32 |

- V① 的 924.8 M = 784 × 1,179,648。`patch_embed` 用 stride = kernel 的卷积实现，等价于一次 `[784, 1536] × [1536, 768]` 的 GEMM。
- V④ 16.65 G = 784 × 1,769,472 × 12 层。
- V⑤/V⑦ 各 5.67 G = 12 block × 12 head × 784 × 784 × 64。784 个 token 的 N² 项，是唯一随分辨率平方增长的部分。注意两个 12 不能漏——漏一个就少算 12 倍。
- V⑧ 5.55 G = 784 × 589,824 × 12。
- V⑨ 44.39 G = 784 × (2,359,296 + 2,359,296) × 12，占视觉塔的 54.5%。
- V⑩ 2.467 G = 196 × 12,588,544。注意 M 是 196 不是 784，这是最常见的 4 倍高估点。

## 7.3 视觉塔的成本

| 项 | 数值 | 占比 |
|---|---:|---:|
| 12 block 的 GEMM（V④⑧⑨） | 66.59 GMAC | 81.8% |
| attention（V⑤⑦） | 11.33 GMAC | 13.9% |
| `patch_embed` | 0.925 GMAC | 1.1% |
| `merger` | 2.467 GMAC | 3.0% |
| softmax + LN + GELU | 0.13 GMAC | 0.2% |
| **合计** | **81.44 GMAC** | |

换算：162.9 GFLOP，约等于 159 个文本 prompt token（512.8 M MAC/token）。权重 103.7 MB，算术强度 785 MAC/B。

分辨率一涨，成本涨得比 token 数快：1024×1024 是 4096 个 patch，视觉塔要 674.85 GMAC，是 448² 的 8.29 倍（token 数只涨 5.22 倍，多出来的是 N² 项）。

## 7.4 视觉塔的矩阵引擎映射

视觉塔是 **M 大、K 中等** 的负载：M=784，K=768 或 3072，N=768/2304/3072。它天然契合矩阵引擎，利用率取决于 tile 高度。

| 项 | 数值 |
|---|---:|
| 25 TOPS(FP8) 下的计算时间 | 162.9 GFLOP ÷ 25 TOPS = 6.5 ms |
| 310 GB/s 下的权重读取时间 | 103.7 MB ÷ 310 GB/s = 0.33 ms |
| 失衡比 | 20:1，纯算力瓶颈 |

所以一张图的延迟由引擎峰值决定，与带宽无关。这也是为什么视觉塔的量化优先级低于文本主干：它不贡献 decode 的每 token 带宽，只影响首字延迟。

## 7.5 视觉塔的坑（速查）

1. **merger 的 M 是 196**。按 784 算会把这一项高估 4 倍（2.47 G 变 9.87 G），整图成本高估 9%。
2. **pos_embed 是裁剪不是插值**。2304 个位置支持到 48×48，448² 只用前 784 个；如果按 bilinear 插值实现，数值和官方对不上但形状对得上，是典型的静默错误。
3. **patch_embed 直接吃原始像素**。它是唯一没有前置归一化的算子，输入是 [0,1] 或 [-1,1] 的浮点；量化到 MXFP8 时要单独测，不要用文本主干的门槛。
4. **GELU 是 tanh 近似**。`gelu_pytorch_tanh` 不是 erf 版本，两者在 |x|≈2 附近差 1e-3 量级，会影响 24 层累加。
5. **`deepstack_visual_indexes` 为空**。0.8B 没有 deepstack，视觉 token 只在 merger 之后一次性注入，不存在多层注入的旁路。
6. **注意力 scaling 是 1/8**。head_dim 64 → `1/√64 = 1/8`，与文本主干的 1/16 不同，硬件若共用常数会错。
7. **merger 是数值注入点**。`linear_fc1/fc2` 共 12.59 M，占视觉塔的 12.5%，直接决定文本主干看到的视觉特征，建议留 FP16。
8. **残差流 12 层累加**。中途量化到 MXFP8 会累积到不可用，至少 FP16。
9. **A·V 里的 P 是风险点**。P ∈ [0,1] 且质量集中在 [0,0.05]，E4M3 相对误差 ~6%，若 attention 输出的相对 L2 误差超过 1%，V⑦ 整段回 VPU 用 FP16。

## 7.6 输出头与采样

| 项 | 数值 |
|---|---:|
| lm_head 形状 | [248320, 1024] |
| MAC | 254,279,680（33.1% token） |
| 权重 | 262.2 MB（33.8% token 带宽） |
| logits 缓冲 | 248,320 × 4 B = 993 KB |
| 与 embedding 共享 | 是（省 254 M 容量，不省带宽） |

采样是 CPU 上的活，但它的延迟已经不能忽略。decode 一个 token 的预算只有 2.66 ms（S=4096），而 248K 个 logit 的全排序要 4.5 M 次比较，在 1 GHz 标量核上 5–10 ms，比整个 token 还长。

必须用部分选择：

| 方法 | 比较次数 | 耗时 | 占 token 预算 |
|---|---:|---:|---:|
| 全排序 `std::sort` | 4.5 M | 5–10 ms | 190–380% |
| `nth_element` / k 堆 | 1.4 M | 1–2 ms | 38–75% |
| 256 桶直方图 + 二分 | ~0.5 M | <0.5 ms | <19% |

结论很直接：**0.8B 上采样是仅次于权重带宽的第二大延迟项**，比 2B 上严重得多（2B 的 token 预算是 6.26 ms，同样的排序只占 80–160%）。做 0.8B 的端侧方案，采样算法必须和引擎一起设计。

# 第 8 章　三本账：算力 / 带宽 / 缓存

每 token 约 767 M MAC，其中 MLP 占 34.5%、lm_head 33.1%、DeltaNet 层（含各自的 MLP）52.5%。每 token 要读 0.776 GB 权重（MXFP8），这是 decode 速度的决定因素。缓存是"一小一大"：DeltaNet 状态恒定 18.9 MB，KV cache 随上下文线性增长，而这两项都不随模型变小。

## 8.1 算力账（decode，S 较短）

| 组件 | 数量 | 单个 MAC | 小计 | 占比 |
|---|---:|---:|---:|---:|
| 层型 A（DeltaNet，含 MLP） | 18 | 22.37 M | 402.6 M | 52.5% |
| 层型 B（Attention，含 MLP，不含 S 项） | 6 | 18.36 M | 110.2 M | 14.4% |
| Attention 的 QKᵀ + AV | 6 | 4,096·S | 24,576·S | 随 S 涨 |
| lm_head | 1 | 254.28 M | 254.3 M | 33.1% |
| embedding | 1 | 0 | 0 | 0% |
| **合计（S 较短）** | | | **767.0 M** | |
| **S = 4096 时** | | | **867.7 M** | |
| **S = 32768 时** | | | **1,572.4 M** | |
| **S = 262144 时** | | | **7,209.5 M** | |

767 M MAC 折成浮点口径是 1.53 GFLOP / token。

表里有三件事。

MLP 是最大的计算块，24 层合计 264.4 M，占 34.5%。它的形状最规整，优化它最省力。

lm_head 是第二大的单个算子，254.3 M，占 33.1%。它只随 hidden 线性缩小，而层内参数随 hidden 平方缩小，所以模型越小、lm_head 的占比越高：2B 上是 26.8%，这里 33.1%。

DeltaNet 占了 75% 的层数，算力 52.5%，因为每层只有 22.4 M，比 attention 层大 22%。差别在两处：投影总量（8.42 M 对 5.24 M，多出的 3.18 M 全在 `in_proj_z` 和更宽的 `in_proj_qkv`）和递推本身（0.83 M 对 0.01 M）。

## 8.2 带宽账（decode，MXFP8 = 8.25 bit = 1.031 B/参数）

| 项 | 参数量 | 字节 |
|---|---:|---:|
| 层型 A × 18 | 388.0 M | 0.400 GB |
| 层型 B × 6 | 110.1 M | 0.114 GB |
| lm_head（= embed） | 254.3 M | 0.262 GB |
| **合计** | **752.4 M** | **0.776 GB** |

| 附加流量 | 大小（S=4096） | 说明 |
|---|---:|---|
| KV cache 读 | 50.3 MB | 6 层 × 2 头 × 256 × 4096 × 2 × 2B |
| DeltaNet 状态读写 | 37.7 MB | 18.9 MB × 2，常驻 SRAM，不落 DRAM |
| 激活 | < 1 MB | 可忽略 |

**速度上限**（310 GB/s）：

```
只看权重：0.776 GB ÷ 310 GB/s = 2.50 ms → 399.6 token/s
S=4096：  0.826 GB ÷ 310 GB/s = 2.66 ms → 375 token/s
实际效率 60~70%                → 225~263 token/s
```

对比 2B：每 token 1.94 GB，上限 160 tok/s。权重小 2.5 倍，速度就快 2.5 倍，没有别的玄机。

算术强度是 767 M MAC ÷ 0.776 GB = 0.99 MAC/B，2B 上是 0.98，两者几乎一样。这不是巧合：hidden 缩小 2 倍，激活与权重同步缩小，比值不变。好消息是同一套引擎规格能同时服务两个模型，坏消息是"把模型做小"并不能缓解带宽瓶颈，只能按比例提速。

## 8.3 缓存账

| 项 | 公式 | S=4K | S=32K | S=256K |
|---|---|---:|---:|---:|
| DeltaNet 状态（FP32） | 18 层 × 16 头 × 128 × 128 × 4B = 18.9 MB | 18.9 MB | 18.9 MB | 18.9 MB |
| DeltaNet conv 状态（FP16） | 18 × 6144 × 3 × 2B = 0.66 MB | 0.66 MB | 0.66 MB | 0.66 MB |
| Attention KV（FP16） | 12,288·S B | 50.3 MB | 402.7 MB | **3.22 GB** |
| **合计** | | **69.9 MB** | **422.2 MB** | **3.24 GB** |

第一件事没变：18.9 MB 的状态必须常驻 SRAM。它的尺寸由 18 层 × 16 头 × 128 × 128 决定，与 hidden 无关，所以 0.8B 和 2B 的状态一模一样。模型减半，SRAM 需求不减——这是 0.8B 最容易被忽略的成本项。落 DRAM 的话每 token 多 37.7 MB 流量（+4.9% 带宽），而且 5 拍串行会变成 5 次 DRAM 往返。

第二件事换了主角。256K 上下文要 3.22 GB 的 KV，而权重只有 0.776 GB。2B 上重量与 KV 的拐点在 158K 上下文，0.8B 提前到 63K（0.776 GB ÷ 12,288 B）。也就是说，0.8B 的绝大多数长上下文负载，DRAM 里装的主要是 KV 而不是权重。

第三件事是容量。4 GB 名义容量扣掉权重 0.78 GB、系统与运行时约 0.7 GB，剩下约 2.6 GB 给 KV，折合 211K token；2B 在同样约束下只有 127K。0.8B 第一次让"4 GB 设备跑满 256K 上下文"接近可行，差的那 15% 用 FP8 KV 就能补上。

# 第 9 章　时间线：一个 token 走完全程

把前面算出的 MAC 和字节数按执行顺序排一遍，看时间到底花在哪。三种负载分开算：decode 一个 token、prefill 一段 prompt、一张图的前向。

## 9.1 Decode 一个 token（S=4096）

```
 1  查表 embed[token_id]                    1 KB DRAM 读            VPU
 2  for layer 0..23:
 3      RMSNorm                             2 K MAC                 VPU
 4      ┌ 若为 DeltaNet（18 层）：
 5      │   in_proj_qkv + z + a + b          8.42 M MAC             引擎    ← 读 8.7 MB
 6      │   conv1d + SiLU                    24.6 K MAC + 6144 exp   VPU     ← 读写 36 KB 状态
 7      │   L2 norm(q,k)                     8 K MAC                 VPU
 8      │   β、g                             2×16 维超越函数         VPU     ← FP32 关键路径
 9      │   ── delta 递推 ──                 0.79 M MAC              VPU     ← 5 拍串行，读写 2.1 MB 状态
10      │   RMSNormGated + silu             8 K MAC                 VPU
11      │   out_proj                         2.10 M MAC             引擎    ← 读 2.2 MB
12      ├ 若为 Attention（6 层）：
13      │   q/k/v proj                       5.24 M MAC             引擎    ← 读 5.4 MB
14      │   q/k norm + RoPE                 ~2 K MAC                VPU
15      │   KV cache 追加                    0 MAC                   DMA     ← 写 2 KB
16      │   Q·Kᵀ + softmax + p·V             16.8 M MAC             引擎/VPU ← 读 KV 8.4 MB(FP16)
17      │   ⊙ sigmoid(gate)                  2 K 乘                  VPU
18      │   o_proj                           2.10 M MAC             引擎    ← 读 2.2 MB
19      └
20      残差加                              1 K 加                  VPU
21      RMSNorm                             2 K MAC                 VPU
22      gate/up proj                        7.34 M MAC             引擎    ← 读 7.6 MB
23      silu(g) ⊙ u                         3584 次 exp             VPU
24      ── DMA 在线量化 ──                  0 MAC                   DMA     ← 读写 11 KB
25      down proj                           3.67 M MAC             引擎    ← 读 3.8 MB
26      残差加                              1 K 加                  VPU
27  final RMSNorm                          2 K MAC                 VPU
28  lm_head                                254.28 M MAC           引擎    ← 读 262 MB
29  采样（温度/top-p/抽样）                0.5~4.5 M 运算          CPU     ← 见 7.6
```

每 token 的 DRAM 流量是 0.776 GB 权重 + 50.3 MB KV + 1 KB 激活，合计 **0.826 GB**。除以 310 GB/s 得 **2.66 ms**，对应 375 tok/s 的上限。

这个 2.66 ms 只是引擎侧的时间。第 29 行才是 0.8B 独有的问题：248K 词表的全排序在 1 GHz 标量核上要 5~10 ms，比整个前向还长。不换采样算法，前面所有的带宽优化都会被这一步吃掉。

## 9.2 Prefill 一段 prompt（S=1024）

同样的算子序列，但 `M = 1024`，全部 GEMV 变成 GEMM：

| 项 | 数值 |
|---|---|
| 每 token MAC | **512.77 M**（= decode 767.05 − lm_head 254.28；`slice_logits_to_keep` 让 lm_head 只在最后一位算一次，见 7.6） |
| 1024 token 总算力 | 525.1 GMAC = 1.05 TFLOP |
| 若系统 25 TOPS（FP8 稠密） | ≈ 42 ms |
| 权重带宽 | **0.776 GB 只读一次**（被 1024 个 token 复用）|
| 带宽时间 | 0.776 GB ÷ 310 GB/s = 2.5 ms ≪ 42 ms |
| **结论** | prefill 是**算力瓶颈**，decode 是**带宽瓶颈** |

42 ms 处理 1024 个 token，合 24.4K tok/s 的 prefill 吞吐，是 decode（375 tok/s）的 65 倍。2B 上这个比值是 58 倍，两者接近——算术强度没变，只是整体按比例缩小。

## 9.3 一张图的前向（448×448）

| 步骤 | 计算量 | 特征 |
|---|---:|---|
| patch_embed（784 patch） | 0.92 GMAC | 实为 GEMM（stride = kernel），占 1.1% |
| 12 blocks × 784 patch（qkv/proj/fc1/fc2） | 66.59 GMAC | 大 M 的 GEMM，引擎高效 |
| 12 blocks 的 QKᵀ + A·V | 11.33 GMAC | 占 13.9%，`N²` 项，tiling + online softmax |
| merger（**M=196**，不是 784） | 2.47 GMAC | 常见 4× 高估点，见 7.3 |
| **视觉塔小计** | **81.44 GMAC** | ≈ 159 个文本 prompt token |
| 196 个视觉 token 走文本 prefill（不含 lm_head） | 196 × 512.77 ≈ 100.5 GMAC | 等同 196 个 prompt token |
| **一张 448² 图合计** | **≈ 182.0 GMAC ≈ 0.36 TFLOP** | |

2B 上同样一张图是 545 GMAC，这里是 182 GMAC，差 3 倍。视觉塔本身只小 3.4 倍（81.4 对 273.1），剩下的差额来自 196 个视觉 token 过文本主干的那段——文本主干越瘦，图越便宜。

若再加 1024 个文本 token（525.1 GMAC），整段 prefill 为 707 GMAC；视觉塔占 11.5%，连同 196 个视觉 token 则图像相关共占 25.7%。

# 第 10 章　算子 → 硬件映射

Decode 全程是 M=1 的 GEMV，阵列利用率天然极低，提升空间不在阵列大小，在流水和门控。模型里有两处真串行：delta 递推和 softmax 归约。另外 lm_head 是最大的单个算子，配上 248K 词表的采样，构成 0.8B 特有的"头部瓶颈"。

## 10.1 分类矩阵

| 类别 | 特征 | 本模型算子 | 归属 |
|---|---|---|---|
| **GEMM / GEMV** | 激活 × 权重矩阵 | 所有 `*_proj`、`lm_head`、`QKᵀ`、`AV`、视觉塔全部 | 矩阵引擎 |
| **归约** | 沿一维求和/最值 | RMSNorm、L2 norm、softmax 分母、amax | VPU |
| **逐元素** | 同形状逐点 | silu、sigmoid、exp、门控乘、残差、RoPE | VPU |
| **串行递推** | 后步依赖前步 | delta 状态更新 | VPU / 专用状态单元 |
| **查表** | 索引取行 | embed_tokens | VPU / DMA |
| **搬运** | 无计算 | KV cache、量化 pass、swizzle | 引擎内部 |
| **控制流** | 分支/随机数 | 采样、停止判断 | CPU |

## 10.2 引擎侧的三条结论

**① Decode 全是 GEMV，算力用不上。**

8 个投影加 lm_head 全部是 `M=1` 的矩阵向量乘。767 M MAC 在 2.66 ms 里跑完，平均 288 GMAC/s，而 25 TOPS 的峰值是 12.5 TMAC/s，利用率 2.3%。阵列在 M=1 时的利用率是 `1/阵列行数`，与阵列多大无关。所以优化点只有三个：权重流水保持连续，别让每个 tile 重新握手；细粒度门控配合 DVFS，decode 时 98% 的阵列本来就空闲；以及不要指望把阵列做大。

**② 两处真串行，是延迟的地板。**

- Delta 递推：每层 16 个 head ×（1 次衰减 + 3 次 128×128 matvec），5 个步骤严格串行，16 head 并行时每层至少 5 拍（见 6.1 A⑩），串行 18 层。
- Softmax：沿 S 的归约，串行 6 层。

按 1 GHz、128 通道算，18 层的递推算力是 11.5 µs，状态读写 37.7 MB 在 SRAM 里约 38 µs，量级在 50 µs，占 2.66 ms 的 2%。所以它们不是 0.8B 的吞吐瓶颈——权重太贵，把一切都盖住了。但如果 VPU 和引擎不重叠，这 50 µs 会直接加到首字延迟上，而且在 2B 上（6.4 ms 预算）占比不同，同一套调度策略不能照搬。

**③ lm_head 加采样，是头部的双重瓶颈。**

lm_head 是一个 [248320, 1024] 的 GEMV，占 33.1% MAC 和 33.8% 带宽，单算子最大。它的三项特殊性与 2B 相同：输出 248,320 维 logits，要 993 KB 的缓冲；精度最敏感，直接决定采样排序；量化收益也最大，能省 0.262 GB/token。

0.8B 多出的是后半段：2.66 ms 的 token 预算里，排 248K 个 logit 要 5~10 ms。也就是说，词表一侧的成本第一次超过了模型主体。这不是精度问题，是算法问题，必须用部分选择（见 7.6）。

## 10.3 MTP 与投机解码：能绕开内存墙，但要先算草稿成本

Decode 是带宽瓶颈，根因是每个权重每 token 只用一次。任何提高复用次数的办法都是乘性提速：

| 手段 | 权重复用倍数 | 代价 |
|---|---|---|
| Batching（多用户） | ×B | 端侧通常 B=1 |
| MTP / 投机解码 | 理想 `1/(1−α)`；实际 α=0.7、γ=2 时 1.27×（共享 248K 词表）或 2.27×（γ=3、8K 剪枝草稿头） | 已有 20.45 M 的头 + 18.9 MB 状态快照 + 草稿验证/回滚逻辑 |
| 增大 KV 长度 | 无 | 不改变权重复用 |

`1/(1−α)` 这个上界拿不到，因为每产出一个草稿 token 都要跑一遍 MTP 层加 `lm_head`（283 MB），光词表就占单 token 带宽的 33.8%。把草稿成本计入（推导见 6.4 D6）：

```
γ=2，共享 248K 词表： B_step = 0.776 + 2×0.283 = 1.342 GB，E[emitted] = 2.19 → 1.27×
γ=3，剪枝 8K 草稿头： B_step = 0.776 + 3×0.030 = 0.865 GB，E[emitted] = 2.53 → 2.27×
```

0.8B 上投机解码的收益比 2B 更好，因为两种草稿头的成本差被放大了：共享词表时草稿路径占单步带宽的 42%，剪枝之后只占 3%。1.27× 对 2.27×，差 1.79 倍——是否给 MTP 配一个独立的小词表，在 0.8B 上是必须提前定的架构决策。

还有一个容易忽略的约束：若规划了投机解码，验证 pass 一次要吃 γ+1 个 token，算力 ×(γ+1)。γ=3 时每步 4 × 767.05 = 3.07 GMAC，配 0.865 GB 流量，算术强度 3.55 MAC/B，引擎需要 **≥1.10 TMAC/s** 才不成为新瓶颈。比 M=1 的 306 GMAC/s 下限高 3.6 倍。要不要规划投机解码，直接决定引擎规格。其余配套（拒绝采样、状态回滚）见 6.4 D6–D7。

# 第 11 章　量化归属

前置约束：矩阵引擎的输入只接受 FP8 / MXFP8，不接受 BF16；输出可以是 FP32 / FP16 / MXFP8。下面按这个约束逐项归属。

## 11.1 逐项归属

| 组件 | 权重 | 激活/输入 | 输出 | 说明 |
|---|---|---|---|---|
| embed_tokens | BF16/FP8 常驻 | — | — | 0 MAC，只查表；但需与 lm_head 共享，见下 |
| 层型 A `in_proj_qkv` | MXFP8 | MXFP8 | FP32 | 融合投影，切分后 q/k/v 各自用途不同 |
| 层型 A `in_proj_z` | MXFP8 | MXFP8 | **FP16** | 输出直接喂 silu |
| 层型 A `in_proj_a/b` | MXFP8 | MXFP8 | **FP32** | 各 16 维，量化收益为零，勿单独优化 |
| 层型 A `conv1d` | **FP16** | FP16 | FP16 | 深度卷积，跨 token，MX 块结构不适用 |
| 层型 A `A_log` / `dt_bias` | **FP32** | — | — | 是指数参数，量化的相对误差会被 exp 放大 |
| 层型 A `RMSNormGated` | FP16 | FP32 归约 | FP16 | |
| 层型 A **delta 递推** | — | — | — | **状态 FP32，永不量化**（config 已写死 `mamba_ssm_dtype`） |
| 层型 A `out_proj` | MXFP8 | MXFP8 | **FP32** | 直通残差 |
| 层型 B `q/k/v_proj` | MXFP8 | MXFP8 | FP32→FP16 | |
| 层型 B `q_norm/k_norm` | FP16 | **FP32** | — | |
| 层型 B **RoPE** | — | **FP32** | — | 角度误差 → 相位漂移 |
| 层型 B **softmax** | — | **FP32** | — | 分母动态范围大 |
| 层型 B `QKᵀ` | — | FP16 | — | 分数误差会被 softmax 放大；不建议 MX |
| 层型 B `p·V` | — | **FP16**（p 不建议 FP8） | — | p ∈[0,1] 且长尾，E4M3 相对误差 ~3%，加权平均**不改善**相对精度，比 FP16 差 64× |
| 层型 B `o_proj` | MXFP8 | MXFP8 | **FP32** | 直通残差 |
| 层型 B 门控 `sigmoid(gate)` | — | FP16 | — | |
| MLP `gate/up_proj` | MXFP8 | MXFP8 | **FP16** | 下一步 silu |
| MLP **SwiGLU** | — | **FP16** | — | silu 负半轴放大误差 |
| MLP `down_proj` | MXFP8 | MXFP8（**运行期在线量化**） | **FP32** | 直通残差 |
| **lm_head** | MXFP8（待验证） | MXFP8 | **FP32** | 见 11.3 |
| 视觉塔 GEMM | MXFP8 | MXFP8 | FP32 | 结构规整，无 massive activation；例外见 11.4 |
| MTP 层 | MXFP8 | MXFP8 | FP32 | 与层型 B 相同 |

## 11.2 三条硬规则

残差流永不进 FP8。误差跨 24 层累加，中途没有重新归一的机会，所以写残差的投影输出必须是 FP32。

DeltaNet 的状态、`A_log`、`dt_bias` 永不离开 FP32。config 里的 `mamba_ssm_dtype: float32` 已经把这个决定焊死了；`g = −exp(A_log)·softplus(...)` 里的 exp 会放大任何相对误差。

MXFP8 输出只在链式 GEMM 之间考虑。本模型没有链式 GEMM（每个投影后面都接了非线性或归约），所以 v1 只需要 FP32 和 FP16 两档输出。

## 11.3 lm_head 的特殊处理

| 观察 | 数字 |
|---|---|
| 占 decode MAC | 33.1% |
| 占 decode 权重带宽 | 33.8%（0.262 GB/token） |
| 与 embedding 共享 | 是（省 254 M 容量，不省带宽） |
| logits 维度 | 248,320 |
| 采样延迟 | 5~10 ms（全排序），超过 2.66 ms 的 token 预算 |

建议分三步验证。

1. 先做 MXFP8（W8A8），FP32 累加、FP32 输出，测 top-1 token 一致率，门槛 >95%。
2. 不达标就把 `lm_head` 提到 FP16 权重（+0.262 GB/token，tok/s 从 400 降到 ~299）。
3. 仍不达标则把 `lm_head` 移到 VPU 做 FP16 GEMV。算力上完全可行：254 M × 30 tok/s = 7.6 GMAC/s = **15 GFLOPS**，0.5 TOPS 的 VPU 只用 3% 的 duty。

第 2 步在这里的代价比 2B 大：带宽从 0.776 GB 涨到 1.038 GB，速度从 400 掉到 299（−25%）；2B 上同样的操作从 160 掉到 126（−21%）。`lm_head` 的占比越高，抬精度的代价越大。

共享权重还有一个隐性代价：量化策略必须同时满足查表和 lm_head 两个用途。`embed_tokens` 做查表时对精度要求低，做 lm_head 时要求高，两者冲突只能取高。

## 11.4 视觉塔的量化

视觉塔是整个模型里最容易量化的部分：标准 ViT，没有门控或递推，GELU 两侧有界。但有四处必须单独处理。

| 项 | 归属 | 理由 |
|---|---|---|
| 12 个 block 的全部 GEMM | MXFP8 | 结构规整；`1/8` 的 attention scaling 可折进 Q 的 per-block E8M0 |
| `patch_embed` | MXFP8 或 FP16 | 唯一直接吃原始像素的算子，量化前无任何前置平滑；只占 1.1% 算力 |
| 残差流 | FP16 / FP32 | 12 层累加，中途量化到 MXFP8 会累积到不可用 |
| LN 统计量、softmax | FP32 | 行均值 / 方差 / 行最大值 |
| `merger.linear_fc1/fc2`（12.59 M，12.5%） | 建议 FP16 | 唯一直接决定注入文本序列数值的层 |
| `A·V` 里的 P | 风险点 | P ∈ [0,1] 且质量集中在 [0, 0.05]，E4M3 相对误差 ~6%；若 attention 输出相对 L2 误差 >1%，V⑦ 整段（11.33 G，13.9%）回 VPU 用 FP16 |

量化点密度方面，每个 block 约 6 处（LN1 后、Q/K、P、attn_out、LN2 后、GELU 后），整图约 **43 M 元素**要过一遍 `amax(32) → E8M0 → E4M3` 流水。这是 1% 量级的向量开销，排 pipeline 时不要漏掉。

W4A4 不建议采用：视觉 token 直接进文本残差流，误差没有重新归一的机会。

# 第 12 章　对芯片设计的结论与待验证清单

前面各章的账归拢成九条结论，再和 2B 方案的资源需求对照一次，最后列出还没验证的假设。

## 12.1 九条结论

| # | 结论 | 依据 |
|---|---|---|
| 1 | decode 每 token 读 0.776 GB 权重，310 GB/s 下理论上限 400 tok/s，实际 225–263 tok/s | 8.2 |
| 2 | prefill 是算力瓶颈（42 ms / 1024 token），decode 是带宽瓶颈，两者需要的资源完全不同 | 9.2 |
| 3 | 阵列按 prefill 定尺寸；decode 平均 288 GMAC/s，只用到峰值的 2.3%，靠门控 + DVFS 省电 | 10.2 |
| 4 | 18.9 MB 的 DeltaNet 状态必须常驻 SRAM、必须是 FP32，且**不随模型缩小**——0.8B 与 2B 完全相同 | 8.3 |
| 5 | 256K 上下文要 3.22 GB KV，是权重的 4 倍；4 GB 设备实际能跑到 211K | 8.3 |
| 6 | 两处真串行（delta 递推、softmax）合计约 50 µs，占 2% —— 不是吞吐瓶颈，但会直接加到首字延迟 | 10.2 |
| 7 | lm_head 占 33.1% MAC + 33.8% 带宽；叠加 248K 词表的 5–10 ms 采样后，词表一侧第一次超过模型主体成本 | 11.3 / 7.6 |
| 8 | MTP 是现成抓手，但净收益取决于草稿头词表：γ=2 共享 248K 只有 1.27×，剪枝到 8K 才有 2.27× | 10.3 / 6.4 D6 |
| 9 | 引擎吞吐下限 306 GMAC/s（M=1 的 MXFP8 GEMV）；若规划投机解码，按 1.1 TMAC/s 定规格 | 8.2 / 10.3 |

## 12.2 与 2B 方案的资源对比

| 项 | 2B | 0.8B |
|---|---|---|
| 每 token 权重 | ≈1.94 GB | 0.776 GB |
| 310 GB/s 下 tok/s | 160（实际 96–112） | 400（实际 225–263） |
| prefill 每 token MAC | 1.387 G | 512.8 M |
| 主存需求 | 4–6 GB | 2–3 GB（短上下文） |
| 系统算力 | 10–16 TOPS | 6–10 TOPS |
| SRAM | ≥24 MB（状态 19.5 MB + 工作区） | ≥20 MB（状态 19.5 MB + 更小的工作区） |
| KV 追上权重的拐点 | 158K | 63K |
| 4 GB 设备可用上下文 | 127K | 211K |
| 特殊之处 | 视觉塔 + MTP + FP32 状态 | 同上，外加 lm_head 与采样占比显著更高 |

最反直觉的一条仍然是 SRAM：0.8B 不比 2B 省。18 层 DeltaNet 的 FP32 状态 18.9 MB 由头数和头维决定，与 hidden 无关。模型减半，SRAM 地板不动，能省的只有激活工作区。

由此得到一条产品结论：0.8B 与 2B 可以共用同一颗芯片。省下来的是 DRAM 容量和功耗，不是 SRAM，也不是引擎规格（引擎按 prefill 定，而 prefill 的算术强度两者相同）。真正需要为 0.8B 单独设计的只有两处：采样通路必须够快，以及是否给 MTP 配独立小词表。

|---|---|---|---|

# 附录 B　复现脚本

```python
H, I, V = 1024, 3584, 248320
n_h, d_h, n_kv = 8, 256, 2          # 全注意力：8 头 × 256 维，2 个 KV 头
n_lh, d_k, d_v = 16, 128, 128       # DeltaNet：16 头 × 128 维
L_lin, L_attn = 18, 6

# 层型 A：DeltaNet（14 个张量）
A = (H                              # input_layernorm
     + H*(2*d_k*n_lh + d_v*n_lh)    # in_proj_qkv = 1024×6144
     + H*(d_v*n_lh)                 # in_proj_z   = 1024×2048
     + 2*H*n_lh                     # in_proj_a + in_proj_b = 1024×16 × 2
     + (2*d_k*n_lh + d_v*n_lh)*4    # conv1d（depthwise, k=4）
     + 2*n_lh + d_v                 # A_log, dt_bias, norm
     + H*(n_lh*d_v)                 # out_proj = 2048×1024
     + H                            # post_attention_layernorm
     + 3*H*I)                       # MLP

# 层型 B：全注意力（11 个张量）
B = (H                              # input_layernorm
     + H*(n_h*d_h*2)                # q_proj（Q + gate 双宽 = 1024×4096）
     + 2*H*(n_kv*d_h)               # k_proj + v_proj = 1024×512 × 2
     + H*(n_h*d_h)                  # o_proj = 2048×1024
     + 2*d_h                        # q_norm + k_norm
     + H                            # post_attention_layernorm
     + 3*H*I)                       # MLP

text = V*H + L_lin*A + L_attn*B + H  # embed 与 lm_head 共享，只算一次
print(f"A 单层 = {A:,}")              # 21,555,360
print(f"B 单层 = {B:,}")              # 18,352,640
print(f"text   = {text/1e9:.4f} B")   # 0.7524

# 视觉塔：12 block，hidden 768，intermediate 3072，patch 16
vw, vd, vI = 768, 12, 3072
patch = 3*2*16*16*vw + vw            # 1536→768，含 bias
pos = 2304*vw                        # pos_embed
blk = ((3*vw*vw + 3*vw)             # qkv  768→2304（含 bias）
       + (vw*vw + vw)               # proj 768→768
       + (vw*vI + vI)               # fc1  768→3072
       + (vI*vw + vw)               # fc2  3072→768
       + 4*vw)                      # 两个 LN 的 weight + bias
mrg = (2*vw                         # merger.norm
       + (vI*vI + vI)               # linear_fc1 3072→3072
       + (1024*vI + 1024))          # linear_fc2 3072→1024（输出 1024 维，不是 768）
vis = patch + pos + vd*blk + mrg
print(f"vis    = {vis/1e9:.4f} B")    # 0.1006

# MTP：一个完整全注意力层 + fc(2048→1024) + 3 个 norm
mtp = B + 2*H*H + 3*H
print(f"mtp    = {mtp/1e9:.4f} B")    # 0.0205

tot = text + vis + mtp
print(f"total  = {tot:,}  ({tot/1e9:.4f} B)")   # 873,438,784 / 0.8734 B
# 实测权重文件 1,746,882,752 B ÷ 2 = 873,441,376，差 2,592（0.0003%）
```
