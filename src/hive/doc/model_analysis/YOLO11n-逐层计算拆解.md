# Ultralytics YOLO11n 逐层计算拆解

2026-10-29 ｜ 依据 `yolo11.yaml`（ultralytics main 分支）、`parse_model` 的 depth/width 规则、`yolo11n.pt`（256 个参数张量，5,248,160 B BF16）与 `nn/modules/{block,conv,head}.py` 源码核对

## 摘要

YOLO11n 是单阶段目标检测网络，总参数 2,624,080：backbone 1,365,472、neck 793,696、Detect 头 464,912。图上有 24 个节点，按 11 / 12 / 1 分成 backbone、neck、head 三段，输出 stride 8/16/32 三个尺度的特征图。640×640 输入下一帧 3,341,945,600 MAC。

对芯片设计影响最大的几项：

- 全帧 **3.3419 GMAC = 6.6839 GFLOP**。官方 6.5 GFLOP 对应纯卷积 3.2400 GMAC（-0.31%），加上 C2PSA 的注意力乘是 3.2707 GMAC（+0.63%）；再往下的 BN、SiLU 与池化比较属于各家口径的分歧，四档在 1.1 节对齐。
- Detect 头占 **28.41%**（949.54 MMAC），是最大的单个图节点；其中 80×80 那一路 621.06 MMAC（纯卷积）。前 5 个节点合计 **54.19%**；不含 Detect 的前 5 个卷积块合计 31.06%。
- 算术强度 **1,274 MAC/B**（只算权重）、**113.9 MAC/B**（权重与激活合计，激活按每层读入一次、写出一次计），比 25 TOPS / 310 GB/s 的机器平衡点 40.3 高 2.8 倍。一帧是算力瓶颈，不是带宽瓶颈。
- 权重只有 **2.62 MB**（INT8），而一帧激活流量 **26.71 MB**，是权重的 10.2 倍。CNN 的访存账要按激活算，照搬 LLM 的"权重决定带宽"会全错。
- 激活驻留峰值 **3.28 MB**（INT8，L15 的 Concat 物化）/ **2.05 MB**（Concat 与后续 1×1 融合），SRAM 工作区下限 4 MB，是 Qwen3.5-0.8B 的 20 MB 的五分之一。
- depthwise 只占 **0.39%** MAC（12.96 MMAC，7 处），但每处的引擎利用率上限等于 1/通道数，不能按 MAC 比例给它分配周期。
- BN 全部可以折叠到卷积，折叠后 0 MAC；但折叠必须在权重打包阶段完成，运行期做要额外一遍 32 位读写，2.62 MB 变 7.9 MB。
- 端到端的瓶颈在两头：预处理要搬 1.23 MB×2，后处理要算 537,600 个 16 路 softmax 加 8400 个锚点的 NMS，估算 0.4–2.5 ms，是 0.267 ms 的 MAC 时间的 1.5–9 倍。

后面按"事实、结构、逐算子、算力账、硬件映射、量化、结论"展开。

# 第 1 章　事实基线

YOLO11n 没有 `config.json`，也没有逐层超参文件。它的事实全在 `yolo11.yaml` 的 24 行结构定义加两个缩放系数里：`depth=0.50` 决定重复次数，`width=0.25` 决定通道数。这一章把这两个系数展开成真实层，并用两份独立数据把它钉死。

## 1.1 数据来源与核对方法

四条来源，按可信度排序：

| 来源 | 内容 | 用途 |
|---|---|---|
| `yolo11n.pt` 的 state_dict | 256 个参数张量的形状 | 逐层参数量与通道数的唯一真相 |
| `yaml` + `parse_model` | 24 个节点的 `from / n / module / args` | 拓扑与缩放规则 |
| `block.py` / `conv.py` / `head.py` | `C3k2`、`C3`、`Bottleneck`、`C2PSA`、`Detect` 的构造函数 | 内部张量结构 |
| 官方文档 | 2.6 M 参数、6.5 GFLOPs（640×640） | 总量校验 |

两条独立核对。

第一条是参数：按 yaml 展开后逐节点求和得 2,624,080，与 checkpoint 的 state_dict 逐节点求和逐项相等，24 个节点差额全为 0；与官方 2,624,080 也完全相等。这条核对同时验证了对 `C3k2` 内部结构的理解——`C3k2(c3k=True)` 里的 `C3k` 会再套一层 `Bottleneck(e=1.0)`，把这一层的 `e` 当成 0.5 会让第 6、8、22 三个节点各少算 18,496 / 73,856 / 73,856 个参数，总量掉到 2.47 M 而"看起来仍然合理"。

第二条是算力：纯卷积 MAC 3,239,993,600 乘 2 得 **6.4800 GFLOP**，与官方 6.5 差 -0.31%；把 C2PSA 里两组注意力矩阵乘（每张量 1 MAC）计进去得 3,270,713,600，即 **6.5414 GFLOP**，差 +0.63%；再把 BN 按 2 MAC/元素加进去得 **6.6068 GFLOP**，与 yaml 注释里的 6.6 差 +0.11%。三个官方数字指向三个口径，本文用第四个口径（再加 SiLU、残差与池化比较）得 6.6839 GFLOP，逐项差额在 8.1 节列清。

yaml 注释里的"181 layers"是 `nn.Module` 实例个数（每个 `Conv` 内部还有 `Conv2d`、`BatchNorm2d`、`SiLU` 三个），不是网络层数；图上的节点是 24 个。

张量计数：256 个参数张量 = 88 个卷积核 + 6 个 bias + 162 个 BN 仿射（81 × 2）。另有 162 个 BN buffer（`running_mean` / `running_var`）不在参数里，但部署时必须一起打包，量化为非对称 uint8 时还要用到零点。

## 1.2 关键超参

| 超参 | 值 | 与 Qwen3.5-0.8B 的差异 |
|---|---|---|
| 输入 | 640 × 640 × 3，uint8 | 无 token 概念，一次前向 = 一张图 |
| 缩放系数 | depth 0.50 / width 0.25 / max_channels 1024 | 无此机制；LLM 用 hidden 与层数直接定 |
| 图节点数 | 24（backbone 11、neck 12、head 1） | 24 层，数量巧合相同 |
| 卷积 | 87 个（35 个 3×3、45 个 1×1、7 个 depthwise） | 0 个；LLM 全是线性层 |
| BN | 81 个（61 个在 backbone+neck，20 个在 head） | 0 个；LLM 用 RMSNorm 且不在卷积后 |
| 激活 | SiLU，73 次 | SiLU，但用在门控乘里 |
| 池化 | MaxPool 5×5 ×3（仅 SPPF） | 无 |
| 输出尺度 | stride 8 / 16 / 32，80² / 40² / 20² | 无 |
| 检测方式 | anchor-free，每格 4×16 个 DFL 分箱 + 80 类 | 无 |
| 参数量 | 2,624,080 | 873,438,784，是它的 333 倍 |

三处与 LLM 的结构性差别，后面每一章都会回到它们：

宽度缩放是**乘 0.25 再向上取 8 的倍数**，不是乘 0.25 了事。`make_divisible(min(c,1024) × 0.25, 8)` 让 yaml 的 64/128/256/512/1024 变成 16/32/64/128/256，全部整除。这个规则意味着：改变 width 时的通道数是阶梯的，不是连续的。width=0.26 时 64 变 24（0.26×64=16.6→24），跳 50%。

深度缩放只作用于 n>1 的重复：`round(2 × 0.5) = 1`，所以 24 个节点里所有 `C3k2` 都只跑 1 次。`C3k2` 内部的 `C3k` 永远套 2 个 `Bottleneck`，不随 depth 缩放——这是它和 YOLOv8 的 `C2f` 最容易被忽略的区别。

不存在"层类型 × N"的重复结构。24 个节点每一个的通道数都不同，权重没法批量复用，只能逐个搬。

# 第 2 章　模型全景

## 2.1 三个子模型

```
yolo11n  640×640×3  uint8
│
├─ backbone   节点 0–10    1,365,472 参数 (52.03%)   1,594.25 MMAC (47.70%)
│   ├─ P1/2  16ch 320²    节点 0
│   ├─ P2/4  32ch 160²    节点 1
│   ├─ P3/8  64ch 80²     节点 3、4          ← 存下来给 neck 用（跨 11 个节点）
│   ├─ P4/16 128ch 40²    节点 5、6          ← 存下来（跨 6 个节点）
│   └─ P5/32 256ch 20²    节点 7–10          ← 存下来（跨 11 个节点）
│
├─ neck       节点 11–22     793,696 参数 (30.25%)     798.16 MMAC (23.88%)
│   ├─ 上采样路径 11–13、14–16（P5→P4→P3）
│   └─ 下采样路径 17–19、20–22（P3→P4→P5）
│
└─ Detect     节点 23        464,912 参数 (17.72%)     949.54 MMAC (28.41%)
    ├─ P3 80² × 64ch   → 4×16 框分箱 + 80 类
    ├─ P4 40² × 128ch  → 同上
    └─ P5 20² × 256ch  → 同上
         ↓
    8400 个锚点 × 144 维 → DFL 解码 → NMS（CPU）
```

| 跳连 | 生产节点 | 消费节点 | 存活跨度 | 张量大小 INT8 |
|---|---:|---:|---:|---:|
| P3 主干特征 | 4 | 15 | 11 个节点 | 819,200 B |
| P4 主干特征 | 6 | 12 | 6 个节点 | 204,800 B |
| P5 主干特征 | 10 | 21 | 11 个节点 | 102,400 B |
| P3 检测输入 | 16 | 23 | 7 个节点 | 409,600 B |
| P4 检测输入 | 19 | 23 | 4 个节点 | 204,800 B |

| block 类型 | 节点数 | 单块参数量 | 合计参数 | MAC | 合计 MAC | 结构特征 |

| Conv-BN-SiLU | 7 | 464 ~ 295,424 | 669,968 | 50.79 ~ 237.57 M | 883.30 M | 一个 3×3 卷积，无残差 |
| C3k2 | 8 | 6,640 ~ 378,880 | 1,074,864 | 141.00 ~ 207.87 M | 1,306.62 M | 1×1 降维 + Bottleneck + 1×1 升维 |
| SPPF | 1 | 164,608 | 164,608 | 70.20 M | 70.20 M | 1×1 + 三级 5×5 池化 + 1×1 |
| C2PSA | 1 | 249,728 | 249,728 | 132.29 M | 132.29 M | 1×1 + 2 头自注意力 + FFN |
| Detect | 1 | 464,912 | 464,912 | 949.54 M | 949.54 M | 三个尺度的 3×3 + 1×1 头 |

数量上 `C3k2` 只占 8/18，但参数占 40.96%、MAC 占 39.10%，因为它把通道"升 2 倍再降回来"——`cv2` 的输入是 `(2+n)×c`，n=1 时是 3 倍中间宽度。

## 2.3 计算形态的四个类别

| 类别 | 特征 | 本模型算子 | MAC | 占比 |
|---|---|---|---:|---:|
| GEMM（隐式） | 激活块与权重的多维张量收缩 | 3×3 卷积、1×1 卷积、C2PSA 的 QKᵀ 与 V·A | 3,257.754 M | **97.48%** |
| 逐通道 | 通道不混合，每通道独立 | depthwise 3×3、5×5 MaxPool | 16.800 M | 0.50% |
| 归约 | 沿一维归一化 | C2PSA 的 softmax | 0.960 M | 0.03% |
| 逐元素 | 同形状逐点 | BN、SiLU、残差加 | 66.432 M | 1.99% |
| 纯视图 | 0 MAC | Upsample ×2、Concat ×4 | 0 | 0% |
| **合计** | | | **3,341.945 M** | **100.0%** |

这里的 97.48% 是本文所有硬件结论的起点：一帧里只有 2.5% 的运算不能用矩阵引擎做，且其中 1.99% 是规整的逐元素。和 Qwen3.5-0.8B 对照，那边的 GEMM 只占 decode 的 60% 左右，剩下是递推与归约；CNN 的算子谱窄得多，代价在于层数少、每层小，固定开销压不住。

| 4 | 16 | C3k2 256→64 @80² | 207.87 | 6.22% | 80² 上唯一的 C3k2，`cv1` 一次就吃掉 106.50 MMAC |
| 5 | 13 | C3k2 384→128 @40² | 179.30 | 5.37% | 输入 384 通道是全网最宽，`cv1` 79.46 MMAC |
| | | **前 5 合计** | **1,811.03** | **54.19%** | |

前 5 里有 4 个不是"第一层高分辨率"，而是"分辨率与通道数同时够大"的层。第 0 层只有 3→16 通道，虽然 320² 有 102,400 个输出点，MAC 也只占 1.52%。这条结论直接否掉了"按分辨率估算力"的直觉：**决定 MAC 的是 H×W×Cin×Cout 的乘积，不是 H×W**。

## 3.2 backbone：11 个节点，5 次降采样

```
0  Conv3×3 s2  3→16      320²   50.79 MMAC
│
1  Conv3×3 s2  16→32     160²  121.24
│
2  C3k2 e0.25  32→64     160²  176.54 ──► P2 特征（不外送）
│
3  Conv3×3 s2  64→64      80²  237.57 ──► P3 入口
│
4  C3k2 e0.25  64→128     80²  170.19 ┄┄► 跳到 15（存活 11 个节点）
│
5  Conv3×3 s2  128→128    40²  236.75 ──► P4 入口
│
6  C3k2 c3k    128→128    40²  141.00 ┄┄► 跳到 12（存活 6 个节点）
│
7  Conv3×3 s2  128→256    20²  118.37
│
8  C3k2 c3k    256→256    20²  139.32
│
9  SPPF k5     256→256    20²   70.20
│
10 C2PSA 2头   256→256    20²  132.29 ┄┄► 跳到 21（存活 11 个节点）
```

五次 stride-2 把 640 一路压到 20，通道 3→16→32→64→128→256。这个"每降一次分辨率、通道翻一倍"的节奏让每次降采样的 MAC 几乎恒定在 50–238 MMAC：面积除以 4 的收益被通道乘 2（3×3 卷积的 MAC 还乘 4）抵消。backbone 的 1,594.25 MMAC 里，五个 stride-2 卷积占 764.72 MMAC，占 48.0%。

P3/P4/P5 三个出口分别在节点 4、6、10 之后（含 C3k2 的输出），不是 stride-2 卷积的直接输出。这一点影响量化：外送的三个张量都是 C3k2 的输出，动态范围比裸卷积大。

## 3.3 neck：12 个节点，两条路径

```
10 (P5 256×20²) ─► 11 Upsample×2 ─► 256×40² ─┐
6  (P4 128×40²) ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┴─► 12 Concat ─► 384×40² ─► 13 C3k2 384→128
                                                                              │
13 (128×40²) ─► 14 Upsample×2 ─► 128×80² ─┐                                   │
4  (P3 128×80²) ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┴─► 15 Concat ─► 256×80² ─► 16 C3k2 256→64 ─► P3 输出
                                                                              │
16 (64×80²) ─► 17 Conv3×3 s2 ─► 64×40² ─┐                                     │
13 (128×40²) ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┴─► 18 Concat ─► 192×40² ─► 19 C3k2 192→128 ─► P4 输出
                                                                              │
19 (128×40²) ─► 20 Conv3×3 s2 ─► 128×20² ─┐                                   │
10 (256×20²) ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┴─► 21 Concat ─► 384×20² ─► 22 C3k2 384→256 ─► P5 输出
```

两条路径的对称性值得记：上行 11→13、14→16 各一次 Upsample + Concat + C3k2；下行 17→19、20→22 各一次 stride-2 Conv + Concat + C3k2。四条路径的 MAC 分别是 179.30、207.87、139.98、152.42 MMAC，合计 679.57 MMAC，占 neck 的 85.1%。剩下 118.58 MMAC 是两个 stride-2 卷积（17 的 59.39 与 20 的 59.19）。

Upsample 用 nearest 而不是双线性：0 MAC，但把 4 个输入像素复制成 16 个，写放大 4 倍。11 和 14 各写 409,600 B 与 819,200 B 的输出，其中 3/4 是重复值。

## 3.4 head：1 个节点，三路并行

```
16 (64×80²)   ─┬─► [G0] cv2: 3×3 64→64 ─► 3×3 64→64 ─► 1×1 64→64 ─► 64 维 ─┐
               └─► [G0] cv3: DW64 ─► 1×1 64→80 ─► DW80 ─► 1×1 80→80 ─► 1×180 ─┴─► 144 维
19 (128×40²)  ─┬─► [G1] 同上，宽度 128 ─────────────────────────────────────────┤
22 (256×20²)  ─┬─► [G2] 同上，宽度 256 ─────────────────────────────────────────┘
                                                                                │
                                                        DFL softmax (16 分箱) ◄─┘
                                                                                │
                                                        8400 × 144 → NMS（CPU）
```

三路之间没有依赖，是全网唯一的天然并行组。按 MAC 排：P3 632.12、P4 226.53、P5 90.89 MMAC。P3 一路就占 Detect 的 66.6%，因为它的 3×3 在 6400 个格子上跑，而 P5 只有 400 个格子。

`cv2` 与 `cv3` 加起来是 144 维：4 个边 × 16 个 DFL 分箱 + 80 类。DFL 那一步不是卷积，是把 16 个 logits 做 softmax 再求期望，详见 7.2 节。

## 3.5 五类 block 的主参数

| 类型 | 出现节点 | 输入→输出 | 内部卷积核 | 参数 | MAC (M) |
|---|---|---|---:|---:|---:|
| Conv-BN-SiLU | 0、1、3、5、7、17、20 | 3→16 … 128→256 | 1 个 3×3，s=2 | 669,968 | 883.30 |
| C3k2（单 Bottleneck） | 2、4、13、16、19 | 32→64 … 384→128 | 4 个 1×1 + 2 个 3×3 | 262,832 | 873.88 |
| C3k2（c3k） | 6、8、22 | 128→128 … 384→256 | 5 个 1×1 + 4 个 3×3 | 812,032 | 432.74 |
| SPPF | 9 | 256→256 | 2 个 1×1 + 3 次 5×5 池化 | 164,608 | 70.20 |

C3k2 参数按变体拆开：单 Bottleneck 五个节点合计 262,832，c3k 三个节点合计 812,032，两者相加 1,074,864。MAC 同理，单 Bottleneck 873.88，c3k 432.74，合计 1,306.62。

这里要停一下：C3k2 的 5 个单 Bottleneck 节点用的卷积比 c3k 少（4 个 1×1 + 2 个 3×3 对 5 个 1×1 + 4 个 3×3），但 MAC 反而是 c3k 的两倍——因为它们都在 80² 和 40² 上，而 c3k 三个节点里有两个在 20²。**同一个 block 类型在不同分辨率下的代价差 4 倍**，这是按 block 类型做硬件预算时最容易犯的错。

## 3.6 29 条数据边

| 边类型 | 条数 | 例子 | 硬件含义 |
|---|---:|---|---|
| 顺序边 | 18 | 3→4、13→14 | 生产者写完消费者立即读，可流水，不需整帧驻留 |
| 拼接边 | 8 | 11 与 6 → 12；17 与 13 → 18 | 两路同时读，通道维拼接；本段上一层 4 条、跨段跳连 4 条 |
| 检测边 | 3 | 16、19、22 → 23 | 三个尺度必须同时可达 |
| **合计** | **29** | | |

29 条边对应 24 个节点，多出的 5 条就是跳连带来的额外入度。四条跨段拼接边（6→12、4→15、13→18、10→21）是 SRAM 驻留的唯一原因：如果只有顺序边，CNN 可以按层流式处理，片上只需要两块行缓冲；有了跳连，就必须把整张特征图存到被消费为止。

存活最久的是 4→15：节点 4 输出 819,200 B，要活 11 个节点、跨过整个上采样路径。这也是 4.5 节驻留分析的起点。

## 3.8 一个节点逐行走完：节点 4

节点 4 是 `C3k2(64, 128, n=1, c3k=False, e=0.25)`，输入 64×80×80，输出 128×80×80。它是 backbone 里第一个 stride-8 的 C3k2，也是 4.5 节激活驻留的候选峰值。

| 序 | 操作 | 张量形状 | 参数 | MAC (M) | 读写 |
|---:|---|---|---:|---:|---|
| 1 | 读入 | 64×80×80 | | | 读 409,600 B |
| 2 | `cv1` 1×1 64→64 | 64×80×80 | 4,224 | 26.2144 | 写 409,600 B |
| 3 | `m.0.cv1` 3×3 32→16 | 16×80×80 | 4,640 | 29.4912 | 写 102,400 B |
| 4 | `m.0.cv2` 3×3 16→32 | 32×80×80 | 4,672 | 29.4912 | 写 204,800 B |
| 5 | 残差加 | 32×80×80 | 0 | 0.2048 | 读 204,800 B |
| 6 | 拼接 `[x, 分支]` | 96×80×80 | 0 | 0 | 读 614,400 B |
| 7 | `cv2` 1×1 96→128 | 128×80×80 | 12,544 | 78.6432 | 写 819,200 B |
| 8 | 写出 | 128×80×80 | | | |
| | **合计** | | **26,080** | **164.0448** | |

第 6 步的拼接是"零 MAC 但满带宽"的典型：它把 `cv1` 的两半 64+64 与分支的 32 拼成 96 通道，输入侧要读 614,400 B，输出侧 1×1 立刻又读一遍。如果硬件把 Concat 实现成"物化再读"，这一处就多出 1.23 MB 的往返；如果实现成"地址映射 + 1×1 直接跨块读"，这 1.23 MB 可以全部省掉。这个选择决定了 4.5 节的峰值是 3.28 MB 还是 2.05 MB。

把 BN 与 SiLU 加上：4 个卷积的输出元素数分别是 409,600、102,400、204,800、819,200，BN 每个元素 2 MAC，SiLU 每个元素 2 MAC，再加 204,800 次残差加，合计 3,072,000 + 3,072,000 + 204,800 = 6.35 MMAC，节点总计 170.19 MMAC。

# 第 4 章　五类 block 的张量清单

第 3 章回答"哪一层"，这一章回答"每层里有哪些张量、每个多大"。张量的字节数决定 SRAM 容量与每次搬运的带宽，是第 8 章两本账的输入。约定：激活按 INT8 1 B/元素，权重按 INT8 1 B/参数、FP16 2 B/参数。

## 4.1 Conv-BN-SiLU 的张量

7 个节点的结构完全一样：一个 3×3 卷积 + BN + SiLU，stride 全是 2，没有残差。

|---:|---|---|---|---:|---:|---:|
| 0 | 3×640×640 | 3×3 s2 | 16×320×320 | 464 | 44.2368 | 50.7904 |
| 1 | 16×320×320 | 3×3 s2 | 32×160×160 | 4,672 | 117.9648 | 121.2416 |
| 3 | 64×80×80 | 3×3 s2 | 64×80×80 | 36,992 | 235.9296 | 237.5680 |
| 5 | 128×40×40 | 3×3 s2 | 128×40×40 | 147,712 | 235.9296 | 236.7488 |
| 7 | 128×20×20 | 3×3 s2 | 256×20×20 | 295,424 | 117.9648 | 118.3744 |
| 17 | 64×80×80 | 3×3 s2 | 64×40×40 | 36,992 | 58.9824 | 59.3920 |

## 4.2 C3k2 的张量

C3k2 有三种内部形态，取决于 `c3k` 与 `e`：

| 变体 | 节点 | `c` | `cv1` 输出 | 分支 | `cv2` 输入 | 实例 |
|---|---|---:|---:|---|---:|---|

| 单 Bottleneck，e=0.5 | 13、16、19 | c2/2 | c2 | 1 个 `Bottleneck(c,c,e=0.5)` | 3c | 16：64→64→96 |
| c3k，e=0.5 | 6、8、22 | c2/2 | c2 | `C3k(c,c,2)`，内含 4 个 3×3 | 3c | 6：128→128→192 |

`c3k` 的 `C3k` 里两个 `Bottleneck` 用 `e=1.0`，所以 3×3 的通道数不减半。这一点在 1.1 节已经用参数量验证过：如果按 0.5 算，节点 6 会少 18,496 个参数。

# 第 5 章　通用算子库

第二部分的 24 个节点只由 8 类算子构成。它们的形状、算术强度、可融合性差别极大，硬件设计要按类分别对待。先给总表，再逐个给卡片。

| 算子 | 个数 | MAC (M) | 占比 | 逐权重字节的 MAC | 可融合 |
|---|---:|---:|---:|---:|---|
| Conv 3×3（普通） | 35 | 2,064.384 | 61.77% | 400 ~ 102,400 | 卷积 + BN + SiLU |
| Conv 1×1 | 45 | 1,162.650 | 34.79% | 400 ~ 25,600 | 卷积 + BN + SiLU |
| Depthwise 3×3 | 7 | 12.960 | 0.39% | 400 ~ 25,600 | 卷积 + BN + SiLU |
| 注意力矩阵乘 | 2 | 30.720 | 0.92% | 不适用 | 无 |
| 注意力 softmax | 2 | 0.960 | 0.03% | 不适用 | 无 |
| MaxPool 5×5 | 3 | 3.840 | 0.11% | 不适用 | 无 |
| BN | 81 | 32.704 | 0.98% | 不适用 | 折进卷积 |
| SiLU | 76 | 32.397 | 0.97% | 不适用 | 折进上一层 |
| 残差加 | 13 | 1.331 | 0.04% | 不适用 | 折进上一层 |
| Concat / Upsample | 6 | 0 | 0% | 不适用 | 折进下一层 |
| **合计** | **270** | **3,341.946** | **100.00%** | | |

"逐权重字节的 MAC"是这张表里最容易被忽略的一列：它等于输出像素数 `Hout × Wout`，与通道数无关。原因是一个 k×k 卷积核的每个权重被用 `Hout × Wout` 次。同样一个 3×3 卷积，在 320² 的输出上每字节权重换 102,400 次乘加，在 20² 上只有 400 次，差 256 倍。

## 5.1 Conv 3×3（普通卷积）

| 项 | 内容 |
|---|---|
| 形状 | `[Cout, Cin, 3, 3]`，MAC = `Cin × Cout × 9 × Hout × Wout` |
| 规模 | 35 个，2,064.384 MMAC，61.77%；单层最大是节点 3 与 5 的 235.93 MMAC |
| 权重 | 最大 295,424 B（节点 7），最小 432 B（节点 0） |
| 归属 | 矩阵引擎；`Cin` 是一维收缩，`Cout × 9` 是另一维 |
| 坑 | stride=2 时输出 40×40 但输入要读 80×80，读放大约 4 倍；padding=1 的边缘无效乘加在 80² 上占 316/6,400 = 4.9%，40² 上占 9.75% |

35 个 3×3 里有 7 个是 stride=2（节点 0、1、3、5、7、17、20，全部属于 Conv-BN-SiLU 类），合计 883.30 MMAC，占全部 3×3 的 42.8%——**四成以上的 3×3 算力花在降采样上**，这是 CNN 与 Transformer 最不一样的地方。

## 5.2 Conv 1×1

| 项 | 内容 |
|---|---|
| 形状 | `[Cout, Cin, 1, 1]`，MAC = `Cin × Cout × Hout × Wout` |
| 规模 | 45 个，1,162.650 MMAC，34.79%；单层最大是节点 16 的 `cv1`（104.86 MMAC 纯卷积） |
| 权重 | 最大 98,816 B（节点 22 的 `cv1`/`cv2`） |
| 归属 | 矩阵引擎，是最"干净"的 GEMM：每个权重用 `Hout × Wout` 次 |
| 坑 | 输入通道是 3 的倍数时不友好；`Cin=96/192/384` 三个宽度在 INT8 下要按 32 对齐才能整除，否则补零浪费 0–3% |

1×1 卷积的算术强度只由分辨率决定：80² 上 6,400 MAC/B，20² 上 400 MAC/B。45 个里有 35 个的输出在 40² 及以下，它们的权重加载开销占比会明显上升。

## 5.3 Depthwise 3×3

| 项 | 内容 |
|---|---|
| 形状 | `[C, 1, 3, 3]`，MAC = `C × 9 × H × W` |
| 规模 | 7 个，12.960 MMAC，0.39%；全部在 Detect 的 `cv3`（6 个）与 C2PSA 的 `proj`（1 个） |
| 权重 | 单个最大 2,304 B（256 通道） |
| 归属 | 逐通道引擎；若用矩阵引擎跑，利用率为 1/通道数 |
| 坑 | 12.96 MMAC 按 25 TOPS 算是 1.04 μs，但逐通道串行要 1.44 M 个通道-输出、即 1.44 M 周期；即使 64 路并行也要 22,500 周期（1 GHz 下 22.5 μs），不能按 MAC 比例分配周期 |

这是第 2 个硬件问题的答案：depthwise 的 MAC 占比 0.39%，看起来可以忽略，但它的最佳映射是"每通道一个乘加器"，在通道维没有并行度。若硬件只提供 64×64 的矩阵引擎，一个 256 通道的 depthwise 要拆成 4 组、每组只用 1/64 的阵列。7 个 depthwise 里有 3 个的通道数是 80，不是 2 的幂，向量化更差。

## 5.4 BatchNorm

| 项 | 内容 |
|---|---|
| 形状 | 逐通道仿射：`y = (x - mean) / sqrt(var + eps) * gamma + beta` |
| 规模 | 81 个，32.704 MMAC（按 2 MAC/元素），0.98% |
| 权重 | 每通道 2 个参数 + 2 个 buffer，共 4 个 32 位值；81 个 BN 合计 1,552 通道 |
| 归属 | 推理时折进前一个卷积的权重与偏置，折叠后 0 MAC |
| 坑 | 折叠要在权重打包阶段做；运行期做要读 4 个 32 位参数、写一遍激活，2.62 MB 权重会膨胀到 7.9 MB |

BN 折叠的公式是 `W' = W * gamma / sqrt(var + eps)`、`b' = beta - gamma * mean / sqrt(var + eps)`。折叠后卷积多一个偏置项，MAC 不变。YOLO11n 的 81 个 BN 全部可以折叠，没有例外——没有哪个 BN 的输入是跨层拼接后再归一化的。

## 5.5 SiLU

| 项 | 内容 |
|---|---|
| 形状 | `y = x * sigmoid(x)`，逐元素 |
| 规模 | 76 处（73 处卷积后 + 3 处池化后），32.397 MMAC（按 2 MAC/元素），0.97% |
| 范围 | 输入约 [-8, 8]，输出约 [-0.278, 8]；负半轴最小 -0.2785 |
| 归属 | 向量单元；查表 + 插值或分段多项式 |
| 坑 | 输出有负值，不能直接接 ReLU 型 uint8 量化；`x=-1.278` 附近斜率最大，定点误差也最大 |

SiLU 的负半轴是 INT8 量化的第一个麻烦：输出范围不对称（-0.278 到 8），零点不在中点，用对称量化会浪费 30% 以上的码点。实际部署里通常把 SiLU 与后一个卷积融合，在 32 位域里算完激活再量化，避免中间结果落地。

## 5.6 MaxPool 5×5

| 项 | 内容 |
|---|---|
| 形状 | 5×5、stride 1、padding 2，逐通道取最大 |
| 规模 | 3 个，全部在 SPPF；3.840 MMAC（按 25 次比较/元素），0.11% |
| 输入 | 128×20×20，每个池化读 25 次、写 1 次 |
| 归属 | 比较树；不需要乘法器 |
| 坑 | 5×5 的感受野等价于两个 3×3，但 stride=1 时数据复用率极高（每个输入被 25 个窗口读），行缓冲要 5 行 |

25 次比较不是 25 个 MAC，但在流水线里它占 25 个周期/元素。128×20×20 = 51,200 个元素乘 25 是 1.28 M 次比较：单通道串行是 1.28 ms，64 路并行是 20 μs。Detect 的 949.54 MMAC 按 12.5 TMAC/s 算是 75.96 μs，两者同量级——这就是"0.11% MAC 却能咬住最大算子"的例子。

## 5.7 Concat 与 Upsample

| 项 | 内容 |
|---|---|
| 形状 | Concat 沿通道维拼接；Upsample 是 nearest 2 倍 |
| 规模 | Concat 4 个、Upsample 2 个，0 MAC；合计搬 3,276,800 B |
| 归属 | 数据搬运；理想实现是地址映射，不物化 |
| 坑 | 物化 Concat 会让峰值从 2.05 MB 涨到 3.28 MB；nearest 上采样写放大 4 倍，3/4 是重复值 |

## 5.8 DFL softmax

| 项 | 内容 |
|---|---|
| 形状 | 每个锚点 4 个边 × 16 个分箱，softmax 后求期望 |
| 规模 | 8400 × 4 × 16 = 537,600 个值；约 3.2 MMAC（每边 15 次加、16 次 exp、16 次乘、1 次归一化除） |
| 归属 | 向量单元 + 查表；在 3.34 GMAC 之外 |
| 坑 | exp 的查表精度直接决定框坐标误差；分箱是固定 0..15，可以用线性近似但不建议 |

DFL 的 softmax 只有 16 路，比 LLM 的 15 万路小四个数量级，但它有 537,600 个独立实例，且每个都要做除法。详细代价见 7.2 节。

## 6.1 A①　Conv-BN-SiLU（节点 3）

```
64×80×80 ─► 3×3 s2 pad1 ─► 64×40×40 ─► BN ─► SiLU ─► 64×40×40
             K=576, N=64               foldable   2 MAC/元素
```

| 步 | 操作 | 形状 | 参数 | MAC (M) |
|---:|---|---|---:|---:|
| 1 | 3×3 卷积 s2 | 64×40×40 | 36,864 | 235.9296 |
| 2 | BN（可折叠） | 64×40×40 | 128 | 0.8192 |
| 3 | SiLU | 64×40×40 | 0 | 0.8192 |
| | **合计** | | **36,992** | **237.5680** |

| 项 | 内容 |
|---|---|
| 合计 | 237.57 MMAC，36,992 参数，读 409,600 B、写 102,400 B |
| 引擎准入 | 矩阵乘 `M=1600, K=576, N=64`；64×64 阵列要 25×9 = 225 个 pass，K 与 N 都能整除，利用率可到 95% 以上 |
| 精度预算 | 权重逐通道对称 INT8，激活逐张量 INT8，累加 32 bit；BN 折叠后偏置用 32 bit，缩放因子逐通道 |
| 坑 | stride=2 的 3×3 只取偶数位置，padding 补的零占输入 1.6%；BN 折叠必须在打包阶段完成 |

这是全网最"标准"的一层：K=576 是 64 的 9 倍，N=64 正好一个阵列宽，M=1600 是 25 个 64。它在 25 TOPS 上理论 18.9 μs，是整个 backbone 里最容易被阵列吃满的一层。反面是节点 0：K=27、N=16，同样的阵列只能用到 16/64 的列。

## 6.2 B①　C3k2（节点 16）

| 步 | 操作 | 形状 | 参数 | MAC (M) |
|---:|---|---|---:|---:|

| 2 | `m.0.cv1` 3×3 32→16 | 16×80×80 | 4,640 | 29.9008 |
| 3 | `m.0.cv2` 3×3 16→32 | 32×80×80 | 4,672 | 30.3104 |
| 4 | 残差加 | 32×80×80 | 0 | 0.2048 |
| 5 | Concat（通道拼接） | 96×80×80 | 0 | 0 |
| 6 | `cv2` 1×1 96→64 | 64×80×80 | 6,272 | 40.9600 |
| | **合计** | | **32,096** | **207.8720** |

| 项 | 内容 |
|---|---|
| 合计 | 207.87 MMAC，32,096 参数，读 1,638,400 B、写 409,600 B，中间张量 1,228,800 B |
| 引擎准入 | 第 1 步 `K=256, N=64` 可打满；第 2 步 `K=288, N=16` 只能用 1/4 列；第 3 步 `N=32` 用一半；第 6 步 `K=96, N=64` 的 K 不是 64 的倍数，补零到 128 浪费 25% |
| 精度预算 | Concat 的两路动态范围不同，必须逐通道量化；残差加的 32 与 `cv1` 的前 32 通道同尺度，可直接加 |
| 坑 | N=16 的 3×3 在 64 宽阵列上浪费 75%；K=96 补到 128 浪费 25%；两处加起来让这一层的有效利用率只有满配的 62% |

这一层的 207.87 MMAC 里有 60.21（第 2、3 步）落在 N≤32 的小卷积上，占了 29%。它们不是算力问题，是形状问题：把 16 个输出通道铺到 64 列的阵列上，四分之三的列空转。可行的补救是把 4 个相邻输出像素打包到 N 维，代价是输入窗口要重复读 4 次。

| 项 | 内容 |

| 精度预算 | 池化是取最大，不引入量化误差；但输入若截断到 8 bit，最大值的尾部（>6σ）会被削掉 |
| 坑 | 三级池化串行依赖，延迟 3×；Concat 后 512 通道一次性进 `cv2`，中间缓冲 204,800 B |

SPPF 的三级池化等价于 5×5、9×9、13×13 的感受野，全部在 20×20 上。它的 MAC 只占 2.10%，但串行链最长：1×1 → 池化 → 池化 → 池化 → 1×1，五级流水，每级都要等上一级整张图算完才能开始（池化的 5 行窗口可以流水，但级与级之间是整图依赖）。

## 6.4 D①　C2PSA（节点 10）

```
256×20×20 ─► cv1 1×1 ─► 128×20×20 ─┬─► qkv 1×1 ─► QKᵀ ─► softmax ─► V·A ─► proj DW3 ─► proj2 1×1 ─► ⊕ ─┐
                                      └───────────────────────────► 直接旁路 ────────────────────────────────┤
```

C2PSA 是全网唯一"形状随分辨率平方变化"的 block。640 输入时它占 3.96%，1280 输入时（N=1600）QKᵀ 与 V·A 涨 16 倍到 491.52 MMAC，C2PSA 从 132.29 涨到 593.09 MMAC，占全网从 3.96% 升到 4.32%；单看这两项矩阵乘，占比从 0.92% 升到 3.58%。它在 20×20 上是个小角色，但一旦上高分辨率就会被注意到。

# 第 7 章　输入预处理、检测头与 NMS

第 5、6 章只覆盖了 3,341.95 MMAC 的主干。一帧真正走完还要三段：把任意尺寸的图变成 640×640（预处理）、把 8400 个锚点的 144 维向量变成框（DFL 解码）、把重叠的框去掉（NMS）。这三段都不在 6.5 GFLOP 里，却决定端到端延迟。

## 7.1 输入预处理

| 步 | 操作 | 数量 | 字节 | 说明 |
|---:|---|---:|---:|---|
| 1 | 读原图 | 1 张 | 1,228,800 | 假设原图就是 640×640×3 uint8 |
| 2 | letterbox 缩放 | 1,228,800 像素 × 3 通道 | 1,228,800 | 双线性，每像素 4 权重、4 乘加 |
| 3 | 归一化 `(x/255 - mean)/std` | 1,228,800 × 3 | 1,228,800 | 2 次运算/值；写入 INT8 需再量化 |
| 4 | 写出 | 1 张 | 1,228,800 | INT8；若走 FP16 是 2,457,600 |
| | **合计** | | **4,915,200** | 计算 4.9 MMAC（双线性）+ 7.4 M 次归一化 |

预处理的计算量只有 12.3 MMAC（约全网的 0.37%），但它是纯访存：4.9 MB 的读写按 310 GB/s 是 15.9 μs。真正的代价在缩放插值——双线性的 4 个权重随输出像素变化，无法像卷积那样复用；如果输入不是 640×640，letterbox 还会引入灰边（值 114），使有效分辨率下降 10–30%（取决于原图长宽比，未核到具体分布）。

一个容易忽略的点：letterbox 后的坐标要映射回原图，NMS 输出的框必须做逆变换。这一步在 CPU 上做，每个框 4 次乘加，量级可忽略，但它是"检测框偏移"类 bug 的常见来源。

## 7.2 检测头解码与 DFL

节点 23 输出的是 8400 × 144 的原始张量：每个锚点 64 个框 logits（4 边 × 16 分箱）加 80 个类分数。DFL 把它变成 4 个距离：

| 项 | 数量 | 计算 | 说明 |
|---|---:|---|---|
| 锚点 | 8,400 | 6,400 + 1,600 + 400 | 80² + 40² + 20² |
| 框 logits | 537,600 | 8,400 × 64 | 4 边 × 16 分箱 |
| softmax | 33,600 组 | 每组 15 加 + 16 exp + 1 除 | 每边一组 |
| 期望 | 33,600 组 | 16 乘 + 15 加 | `sum(p_i × i)`，i=0..15 |
| 类分数 | 672,000 | 8,400 × 80 | sigmoid，阈值 0.25 |
| 解码 | 8,400 × 4 | 乘 stride 加网格偏移 | stride 8/16/32 |

计算量：softmax 与期望约 2.65 MMAC，sigmoid 672,000 次，合计 3.3 M 次运算——是主干的 0.10%。但它是**纯串行的小算子**：每组 16 路，向量单元一次只能处理 4 组（64 宽），33,600 组要 8,400 个 pass 才能完；exp 走查表，每次 1–2 周期。

字节账更重：读 1,209,600 B 的原始输出，写 8,400 × 84 × 4 = 2,822,400 B 的 FP32 解码结果，再读一遍做 NMS。DFL 的中间张量（33,600 × 16 的 softmax 结果）如果物化，再加 537,600 B。

## 7.3 NMS

| 步 | 内容 | 数量级 | 说明 |
|---:|---|---:|---|
| 1 | 按类阈值筛选 | 672,000 个分数 | 阈值 0.25 后通常剩几十到几百个（未核到分布） |
| 2 | 按类排序 | 80 类各自排序 | 每类候选数不定 |
| 3 | IoU 两两比较 | 候选数² | 每对 4 次交并计算 |
| 4 | 输出 | ≤300 个框 | 标准 `max_det=300` |

NMS 的复杂度完全由第 1 步之后的候选数决定。最坏情况（80 类都满）是 80 × n² 次 IoU；实际图片通常只有 1–3 个类有高分候选，代价落在 10³–10⁵ 次比较。它在 CPU 上跑，实测 0.4–2.5 ms（未核到公开实测，按同类模型的经验区间估计，列入 12.3）。

## 7.4 端到端延迟

| 阶段 | 计算 | 字节 | 25 TOPS / 310 GB/s 下 | 备注 |
|---|---|---:|---:|---|
| 预处理 | 12.3 MMAC | 4,915,200 | 0.016 ms | 访存受限 |
| backbone | 1,594.25 MMAC | 13,414,400 | 0.128 ms | 计算受限 |
| neck | 798.16 MMAC | 11,366,400 | 0.064 ms | 计算受限 |
| head | 949.54 MMAC | 1,926,400 | 0.076 ms | 计算受限 |
| DFL 解码 | 3.3 M 次 | 4,032,000 | 0.013 ms | 串行小算子 |
| NMS | 10³–10⁵ 次比较 | 2,822,400 | 0.4–2.5 ms | CPU |
| **合计** | **3,341.95 MMAC** | **38,476,800** | **0.70–2.80 ms** | |

按 100% 利用率算，主干加解码是 0.297 ms，端到端 0.70–2.80 ms，NMS 占 57–89%；按 40% 利用率算，端到端 1.14–3.24 ms，NMS 占 35–77%。这回答第 5 个问题：**在这个模型上，后处理不是尾巴，是主项**。把 NMS 搬到 NPU 上做（或改成 anchor-free 的 top-k + 轻量 IoU）是端到端延迟最划算的一刀。

两处字节口径的差异要说清：7.4 的预处理按未融合的 4 遍读写计 4,915,200 B、NMS 只计候选读取 2,822,400 B；8.3 与 9.6 按"每级 1 读 1 写"的融合口径计 2,457,600 B 与 5,644,800 B，合计 38,841,600 B，比本表多 364,800 B。字节差不到 0.4 MB，按 310 GB/s 是 1.2 μs，不影响任何延迟结论；下文统一用 8.3 的融合口径。

# 第 8 章　三本账：算力 / 权重 / 激活

## 8.1 算力账

四种口径，从最窄到最宽：

| 口径 | 含什么 | MAC | GFLOP | 与官方比 |
|---|---|---:|---:|---|
| 纯卷积 | 3×3、1×1、depthwise | 3,239,993,600 | 6.4800 | 比 6.5 低 0.31% |
| 加注意力 | 再加 QKᵀ 与 V·A | 3,270,713,600 | 6.5414 | 比 6.5 高 0.63% |
| 加 BN | 再加 81 个 BN 的 2 MAC/元素 | 3,303,417,600 | 6.6068 | 比 yaml 的 6.6 高 0.10% |
| 全账 | 再加 SiLU、残差、池化比较 | 3,341,945,600 | 6.6839 | 比 6.5 高 2.83% |

官方 6.5 落在第一、二档之间。这个区间正好覆盖"算不算注意力"这一项，所以两种解释都成立；本文用第四档，因为它与硬件上真实要执行的周期一一对应。

按分辨率分组，得到一张比逐层表更有用的图：

| 分辨率 | 节点 | MAC (M) | 占比 | 每帧像素数 |
|---|---|---:|---:|---:|
| 320² | 0 | 50.79 | 1.52% | 102,400 |
| 160² | 1、2 | 297.78 | 8.91% | 25,600 |
| 80² | 3、4、16、23(P3) | 1,247.75 | 37.34% | 6,400 |
| 40² | 5、6、13、17、19、23(P4) | 982.95 | 29.41% | 1,600 |
| 20² | 7、8、9、10、20、22、23(P5) | 762.68 | 22.82% | 400 |
| **合计** | | **3,341.95** | **100.00%** | 136,400 |

80² 与 40² 两级吃掉 66.75% 的算力，而它们的像素数只占全网的 5.9%。20² 有 7 个节点、参数最多，算力却只有 22.82%。这条分布决定了两件事：第一，任何按"层数"分配资源的方案都会把 70% 的预算给错地方；第二，SRAM 的端口带宽要按 80² 设计，因为 80² 的节点既多又宽。

80² 这一档里，Detect 的 P3 支路（632.12）比 backbone 与 neck 在 80² 上的三层之和（237.57 + 170.19 + 207.87 = 615.63）还多 2.7%。这是第 1 个硬件问题的完整答案：**头部的高分辨率支路与 backbone 的 stride-8 段是同一量级，两者必须一起优化，只优化 backbone 会漏掉一半**。

## 8.2 权重账

| 类别 | 参数 | INT8 字节 | FP16 字节 | 占比 | 每字节复用 (MAC/B) |
|---|---:|---:|---:|---:|---:|
| Conv-BN-SiLU | 669,968 | 669,968 | 1,339,936 | 25.53% | 1,318 |
| C3k2 | 1,074,864 | 1,074,864 | 2,149,728 | 40.96% | 1,216 |
| SPPF | 164,608 | 164,608 | 329,216 | 6.27% | 426 |
| C2PSA | 249,728 | 249,728 | 499,456 | 9.52% | 530 |
| Detect | 464,912 | 464,912 | 929,824 | 17.72% | 2,042 |
| **合计** | **2,624,080** | **2,624,080** | **5,248,160** | **100.00%** | **1,274** |

INT8 下权重 2.62 MB，连一块 4 MB 的 SRAM 都装不满，可以整帧常驻；FP16 是 5.25 MB，超过 4 MB，必须分块搬。这是"能不能用 FP16 换精度"的第一个硬约束：**权重全 FP16 会让 SRAM 装不下，需要多一次 2.6 MB 的溢出搬运**，按 310 GB/s 是 8.5 μs，占 0.267 ms 的 3.2%——不算致命，但会把权重从"零成本常驻"变成"每帧一搬"。

每字节复用最低的是 SPPF（426）与 C2PSA（530）。它们的权重在 20² 上只用 400 次，接近机器平衡点 40.3 的 10 倍，仍然算算力受限，但已经是最接近带宽墙的两块。

## 8.3 激活账

| 段 | 读 (B) | 写 (B) | 合计 (B) | 占全网 |
|---|---:|---:|---:|---:|
| 预处理 | 1,228,800 | 1,228,800 | 2,457,600 | 6.33% |
| backbone | 7,270,400 | 6,144,000 | 13,414,400 | 34.54% |
| neck | 6,348,800 | 5,017,600 | 11,366,400 | 29.26% |
| head | 716,800 | 1,209,600 | 1,926,400 | 4.96% |
| DFL 解码 | 1,209,600 | 2,822,400 | 4,032,000 | 10.38% |
| NMS | 2,822,400 | 2,822,400 | 5,644,800 | 14.53% |
| **合计** | **19,596,800** | **19,244,800** | **38,841,600** | **100.00%** |

主干的 26,707,200 B 就是 backbone、neck、head 三段之和（13,414,400 + 11,366,400 + 1,926,400），与 4.5 节逐节点相加的结果一致。端到端的 38,841,600 B 比它多 12,134,400 B，全部在两头：预处理 2,457,600、DFL 4,032,000、NMS 5,644,800。

算术强度按三个口径算：

| 口径 | 字节 | MAC/B | 与机器平衡点 40.3 比 |
|---|---:|---:|---:|
| 只算主干激活 | 26,707,200 | 125.1 | 3.1 倍 |
| 主干激活 + 权重 | 29,331,280 | 113.9 | 2.8 倍 |
| 端到端全流量 | 38,841,600 | 86.0 | 2.1 倍 |

三个数都高于 40.3，最保守的一个也高 2.1 倍——一帧是算力瓶颈，不是带宽瓶颈。但余量只有 2 倍出头，若引擎利用率掉到 40% 以下，带宽就会先到墙。

权重与激活的比例是 2.62 : 26.71 = 1 : 10.2。这和 Qwen3.5-0.8B 正好相反——那边一帧的权重是 GB 级、激活是 MB 级；这边激活是权重的 10 倍。**CNN 的带宽预算要按激活做，LLM 的按权重做**，这是两份文档里最不能互相照搬的一条。

## 8.4 SRAM 工作区

| 组成 | 字节 | 说明 |
|---|---:|---|
| 常驻跳连 | 1,433,600 | 4→15、6→12、10→21、13→18 同时在片上的最大组合 |
| 流式输入 | 1,638,400 | 节点 15 的 Upsample 输出 |
| 流式输出 | 1,638,400 | 节点 15 的 Concat 结果 |
| 双缓冲余量 | 819,200 | 行缓冲 + 权重预取 |
| **合计** | **5,529,600** | 物化 Concat 的配置 |

这是最坏配置（5.53 MB）。三个降档：

| 配置 | 峰值 | 做法 | 代价 |
|---|---:|---|---|
| 物化 Concat | 3,276,800 | 拼接写回 SRAM 再读 | 多一次 1.23 MB 往返 |
| 融合 Concat | 2,048,000 | 下一层 1×1 直接跨两块读 | 地址生成复杂，1×1 的 K 维要跨块 |
| 跳连也走 DRAM | 1,638,400 | 4→15 的 819,200 落 DRAM | 每帧多 1.64 MB 读写，5.3 μs |

按"融合 Concat + 跳连全在片上"算，SRAM 下限 2.05 MB，取 2 的幂是 2 MB 或 4 MB。4 MB 可以放下权重（2.62 MB）加一个 1.38 MB 的激活窗口，是更稳的选择；2 MB 必须把权重分块流进来，每帧多 2.62 MB 的权重搬运，占 0.267 ms 的 3.2%。

第 3 个硬件问题的答案在这里：峰值不在"第一个 stride-8 的 C3k2"（节点 4，1.23 MB），而在节点 15 的 Concat——3.28 MB 物化、2.05 MB 融合。如果按节点 4 的 1.23 MB 去定 SRAM，会在 neck 的上采样段直接溢出。

# 第 9 章　时间线：一张图走完全程

## 9.1 预处理：0.02 ms

读 640×640×3 uint8，letterbox 缩放，归一化，写成 INT8 的 640×640×3。计算 12.3 MMAC，访存 2,457,600 B。按 12.5 TMAC/s 是 0.98 μs，按 310 GB/s 是 7.93 μs——访存是计算的 8 倍，这一段的瓶颈在搬运，不在插值。

## 9.2 backbone：127.5 μs

11 个节点，1,594.25 MMAC，权重 1,365,472 B，激活 13,414,400 B。算力 127.5 μs，访存 43.3 μs，计算是访存的 2.9 倍。五个 stride-2 卷积构成一条串行链，每个都要等上一层整张图算完；越往后图越小，阵列越填不满：节点 0 的 `N=16` 只用到 1/4 列，节点 7 的 `K=1152` 又需要 18 个 pass。这一段的有效利用率通常落在 45–65%。

节点 10 之后 backbone 结束，P3/P4/P5 三个跳连同时驻留 1,126,400 B。从这一刻起，SRAM 的压力从"流式"变成"常驻 + 流式"。

## 9.3 neck：63.9 μs

12 个节点，798.16 MMAC，权重 793,696 B，激活 11,366,400 B。算力 63.9 μs，访存 36.7 μs，两者只差 1.7 倍——neck 是全网最接近带宽墙的一段，因为它有 4 次 Concat 和 2 次 Upsample，纯搬运占了不少字节。

上采样路径的两次 Upsample 写 1,228,800 B，其中 921,600 B 是重复值。若硬件支持"读一次、广播四次"，这 921,600 B 可以省掉；若不支持，它就是实实在在的写带宽。

## 9.4 head：76.0 μs

1 个节点，949.54 MMAC，权重 464,912 B，激活 1,926,400 B。算力 76.0 μs，访存 6.2 μs，计算是访存的 12 倍——这是全网算术强度最高的一段。三路之间可以并行，但三路的形状不同（80²/40²/20²），很难在同一个阵列上同时铺满：P3 用 64×64 的 tile，P5 只剩 20×20 = 400 个像素，一个 tile 都填不满。

## 9.5 后处理：0.4–2.5 ms

DFL 解码 4,032,000 B、3.3 M 次运算，设备上 13 μs；NMS 5,644,800 B、10³–10⁵ 次比较，CPU 上 0.4–2.5 ms。后处理的时间是主干的 1.5–9 倍，且它跑在 CPU 上，与 NPU 串行。

## 9.6 全帧时间线

| 阶段 | 节点 | MAC (M) | 累计 MAC (M) | 权重 (B) | 激活 (B) | 算力 (μs) | 访存 (μs) |
|---|---|---:|---:|---:|---:|---:|---:|
| 预处理 | — | 12.30 | 12.30 | 0 | 2,457,600 | 1.0 | 7.9 |
| backbone | 0–10 | 1,594.25 | 1,606.55 | 1,365,472 | 13,414,400 | 127.5 | 43.3 |
| neck | 11–22 | 798.16 | 2,404.71 | 793,696 | 11,366,400 | 63.9 | 36.7 |
| head | 23 | 949.54 | 3,354.25 | 464,912 | 1,926,400 | 76.0 | 6.2 |
| DFL | — | 3.30 | 3,357.55 | 0（16 个已含在 head） | 4,032,000 | 0.3 | 13.0 |
| NMS | — | — | — | 0 | 5,644,800 | — | 18.2（CPU 0.4–2.5 ms） |
| **合计** | | **3,357.55** | | **2,624,080** | **38,841,600** | **268.6** | **125.3** |

算力时间 268.6 μs 是 100% 利用率的下限；按 45–65% 的有效利用率是 0.41–0.60 ms。访存时间 125.3 μs 是 310 GB/s 满带宽的下限，实际能到 70% 就是 179 μs。两者取大，主干加解码的现实区间是 0.41–0.60 ms。

加上预处理的 8 μs 与 NMS 的 0.4–2.5 ms，端到端是 0.82–3.11 ms。**NMS 一项就占了 49–80%**，且它的方差最大：一张只有一只狗的图与一张 300 个框的拥挤场景，NMS 时间差两个数量级。

时间线里还有一条不能忽略的串行链：neck 的 14→15→16 三步。14 的 Upsample 要等 13 整张算完，15 的 Concat 要等 14 整张写完，16 的 `cv1` 又要等 15 整张拼完。三级整图依赖，每级之间至少一次全图同步，按 80² 的 1,638,400 B 算是 5.3 μs/次，三次 15.9 μs，占 neck 的 25%。若把 15 做成融合 Concat，这条链缩到两级。

# 第 10 章　算子 → 硬件映射

## 10.1 映射表

| 算子 | 引擎 | 数据流 | 利用率上限 | 规模 |
|---|---|---|---:|---:|
| Conv 3×3 | 64×64 矩阵 | 权重常驻 + 5 行激活缓冲 | 90%（K、N 对齐后） | 2,064.38 MMAC |
| Conv 1×1 | 64×64 矩阵 | 大 K 流式，权重可分块 | 95% | 1,162.65 MMAC |
| Depthwise 3×3 | 逐通道向量 | 每通道 9 抽头 | 1/64（矩阵阵列） | 12.96 MMAC |
| 注意力矩阵乘 | 矩阵 + 向量 | 400×400 中间矩阵 | 70%（N=400 非 64 倍） | 30.72 MMAC |
| Softmax | 向量 | 行归约，跨 lane | 16%（400 路 / 64 lane） | 0.96 MMAC |
| MaxPool 5×5 | 比较树 | 5 行缓冲 | 1/25（每元素 25 比较） | 3.84 MMAC |
| Concat / Upsample | DMA / 地址映射 | 跨块读写 | 不适用 | 3,276,800 B |
| BN / SiLU | 向量（与前层融合） | 就地 | 1 元素/lane/周期 | 66.43 MMAC |
| DFL | 向量 + 查表 | 16 路一组 | 不适用 | 3.3 M 次 |
| NMS | CPU | 标量 | 不适用 | 0.4–2.5 ms |

表里有三行"利用率上限"低于 20%：depthwise、softmax、maxpool。它们的 MAC 加起来只有 17.76 MMAC（0.53%），但如果按 MAC 比例给它们分周期，实际会慢 5–60 倍。正确的做法是按"元素数 × 每元素操作数"排周期，再与矩阵引擎的时间线合并。

## 10.2 三条数字锚点

| 锚点 | 数值 | 依据 |
|---|---:|---|
| 阵列有效利用率 | 63% | 把每个卷积的 K、N 补到 64 的倍数后重新累加，可卷积展开的 3,151.8 MMAC 需要 5,002.0 MMAC 的阵列周期（估算） |
| 最长串行链 | 15.9 μs | neck 的 14→15→16 三级整图依赖，占 neck 的 25% |
| 最大单算子 | 7.06% | 单个 64→64 的 3×3（节点 3 与 Detect P3 各一个），235.93 MMAC |

63% 的含义是：即使带宽与调度都理想，64×64 阵列也只能把 63% 的周期用在有效乘加上，剩下 37% 是补零。这个数比 LLM 的 90% 低得多，因为 CNN 的 K 与 N 都是"模型宽度"的函数，而 16/32/96/192/384 这些宽度不是 64 的倍数。

## 10.3 五种手段与净收益

| 手段 | 复用倍数 | 代价 | 净收益 |
|---|---:|---|---|
| Conv+BN+SiLU 融合 | 省 2 次层内读写 | 32 bit 累加器 + 激活单元直连 | 本账已按融合计；不融合则每帧多约 12 MB |
| 权重整帧常驻 | 1,274 MAC/B | 2.62 MB SRAM | 省 8.5 μs/帧的权重搬运 |
| Concat 地址映射 | 省 1.23 MB 往返 | 地址生成器跨块 | 峰值 3.28 MB → 2.05 MB |
| nearest 广播写 | 省 921,600 B | 写口 4 路广播 | neck 访存 36.7 → 33.7 μs |
| neck 双缓冲 | 隐藏 5.3 μs/次 | 额外 1.64 MB SRAM | 串行链 15.9 → 8 μs |

五项全做，主干时间从 0.41–0.60 ms 压到 0.39–0.58 ms，SRAM 从 4 MB 降到 3 MB。收益有限是因为大头（3,341.95 MMAC）是实打实的乘加：这五项只是把访存与串行链的浪费补回来，动不了乘加本身。代价是控制逻辑复杂度上升，尤其是双缓冲——它要求 Concat 的两路输入都能同时被下一层读取，地址空间要按 2 的幂对齐。

# 第 11 章　量化归属

## 11.1 逐项归属

引擎的约束写在第一行：权重 INT8 逐通道对称，激活 INT8 逐张量，累加 32 bit，输出再量化。

| 组件 | 权重 | 激活/输入 | 输出 | 说明 |
|---|---|---|---|---|
| Conv 3×3（35 个） | INT8 逐通道 | INT8 逐张量 | INT8 | 主力，量化误差最小 |
| Conv 1×1（45 个） | INT8 逐通道 | INT8 逐张量 | INT8 | K 大，误差被平均 |
| Depthwise（7 个） | INT8 逐通道 | INT8 逐张量 | INT8 | 每通道只有 9 个权重，逐通道 scale 开销占比高 |
| 注意力矩阵乘 | INT8 | INT8 | INT8 | QKᵀ 的输出进 softmax 前要 16 bit |
| BN（81 个） | 折叠进卷积 | — | — | 折叠后只剩 32 bit 偏置 |
| SiLU（76 处） | — | 32 bit | INT8 | 先算激活再量化，避免负半轴截断 |
| MaxPool（3 个） | — | INT8 | INT8 | 取最大，无误差 |
| Concat（4 个） | — | INT8 | INT8 | 两路 scale 不同，必须先重标定 |
| 检测输出（1 个） | — | INT8 | 16 bit | 4×16 logits 直接进 DFL，不能压到 8 bit |

## 11.2 三条硬规则

第一条：**BN 必须在权重打包阶段折叠**。推理时 BN 是 `y = a*x + b`，折进卷积后 MAC 不变、参数不变；若不折叠，每帧要多读 1,552 个通道的 4 个 32 位参数、多写一遍激活，权重从 2.62 MB 膨胀到 7.9 MB。违反的后果是带宽预算直接超 3 倍。

第二条：**SiLU 的输入必须保留 32 bit**。SiLU 在 `x = -1.278` 处取最小值 -0.2785，负半轴的斜率在 0 附近最大。若把卷积输出先量化到 INT8 再算 SiLU，-0.5 到 0.5 之间的值只有 1–2 个码点，梯度信息全丢。违反的后果是浅层特征图出现块状伪影，mAP 掉点集中在中小目标。

第三条：**Concat 的两路必须先统一 scale**。4 个 Concat 的输入来自不同深度的层，动态范围差 2–8 倍；若按各自 scale 拼完再整体量化，小的一路会被压掉低位。违反的后果是 80² 的 P3 融合特征精度下降，小目标召回率下降。

## 11.3 最大单算子：Detect 的 P3 `cv2` 3×3

全网最大的单个卷积是 Detect P3 支路的两个 64→64 3×3，各 235.93 MMAC。它们的输入是 80² 的融合特征，输出直接进 DFL 回归。三步验证：

| 步 | 做法 | 代价 | 判据 |
|---:|---|---:|---|
| 1 | 权重与激活全 INT8 | 0 | 基线，先看 mAP 掉点 |
| 2 | 权重 INT8、激活 16 bit | 该层时间 ×2（18.9 → 37.9 μs，全网 +7.0%） | 若第 1 步掉点 > 0.5 |
| 3 | 整层搬到 FP16 单元 | 该层 ×2 且占 FP16 吞吐（全网 +7.0%） | 若第 2 步仍不达标 |

三步的代价都不大，因为这两层只占全网的 14.1%（235.93×2/3,341.95）。真正贵的是把整个 Detect 提到 16 bit：949.54 MMAC 翻倍，全网时间从 0.267 ms 涨到 0.343 ms（+28%），这是不能接受的。所以量化的粒度必须到"层"，不能到"block"。

## 11.4 量化点密度

| block | 量化点/块 | 块数 | 小计 |
|---|---:|---:|---:|
| Conv-BN-SiLU | 2（权重、激活） | 7 | 14 |
| C3k2（单 Bottleneck） | 8 | 5 | 40 |
| C3k2（c3k） | 18 | 3 | 54 |
| SPPF | 4 | 1 | 4 |
| C2PSA | 17 | 1 | 17 |
| Detect | 36 | 1 | 36 |
| Concat 边界 | 1 | 4 | 4 |
| **合计** | | | **169** |

169 个量化点里，C3k2 占 94 个（55.6%）。它们大多是 1×1 卷积，量化本身不难；难的是 8 个 C3k2 里有 3 个的 `c3k` 分支带残差加，加法两侧的 scale 必须一致，否则要在加之前插一次重标定——这会多出 2 次激活读写。

# 第 12 章　对芯片设计的结论与待验证清单

## 12.1 九条结论

| # | 结论 | 依据 |
|---:|---|---|
| 1 | 算力预算按 80² 与 40² 两级切分，它们合计 66.75%；按层数或按段分配都会把 70% 的预算给错地方 | 8.1 |
| 2 | Detect 头必须与 backbone 同级优化：28.41% 的 MAC，P3 支路单独 18.91%，比 backbone 的 80² 三层之和还多 2.7% | 3.1、6.5、8.1 |
| 3 | 64×64 阵列够用，但 N 维必须支持"4 个像素拼包"，否则 63% 的填充率会吃掉三分之一的算力 | 10.2、6.2 |
| 4 | depthwise 要独立通路：0.39% 的 MAC，但 64 路并行也要 22.5 μs，与 Detect 的 76 μs 同一量级 | 5.3 |
| 5 | SRAM 取 4 MB：峰值 2.05 MB 加权重 2.62 MB 需要 4.67 MB，超出的 0.67 MB 用权重分块补 | 8.2、8.4 |
| 6 | Concat 必须做成地址映射，否则峰值从 2.05 MB 涨到 3.28 MB，SRAM 要多开 1.23 MB | 4.5、8.4 |
| 7 | INT8 可用，但 SiLU 保 32 bit、Concat 先重标定、DFL 输出 16 bit 这三条不能省 | 11.2 |
| 8 | NMS 是端到端主项（49–80%），搬上 NPU 后总时间从 0.82–3.11 ms 降到 0.44–0.62 ms（NMS 按 18.2 μs 访存下限计） | 7.3、9.6 |
| 9 | 310 GB/s 够用：主干访存 125.3 μs 对算力 268.6 μs，有 2.1 倍余量；但引擎利用率低于 40% 时带宽会先到墙 | 8.3、9.6 |

第 1 条与第 2 条合起来是这份拆解最重要的一句话：YOLO11n 的算力不在"最深的那几层"，而在分辨率与通道数同时够大的 80²/40²，以及 head 的三条支路。任何"先做 backbone、head 后面再说"的排期都会把主要矛盾留到最后。

## 12.2 与 Qwen3.5-0.8B 的资源对比

| 资源项 | YOLO11n | Qwen3.5-0.8B |
|---|---:|---:|
| 参数 | 2,624,080 | 873,438,784 |
| 权重（INT8） | 2.62 MB | 873 MB |
| 每帧激活 / 状态 | 26.71 MB（激活） | 20 MB（KV cache） |
| SRAM 峰值 | 3.28 MB（融合后 2.05） | 20 MB |
| 算术强度 | 113.9 MAC/B | ≈1 MAC/B（batch=1 decode） |
| 瓶颈 | 算力 | 带宽 |
| 端到端 | 0.82–3.11 ms | 未在同一机器核对 |

最反直觉的一条是 SRAM：YOLO11n 的权重只有 2.62 MB，激活峰值 3.28 MB，整颗芯片的 SRAM 需求由 Qwen3.5-0.8B 的 20 MB KV 决定，而不是由 CNN 决定。也就是说，同一颗 20 MB SRAM、25 TOPS 的芯片可以同时跑这两个模型：YOLO 用不到 4 MB，剩下的 16 MB 给 LLM 的 KV。

产品层的结论是：**SRAM 由 LLM 定，算力与向量单元由 CNN 定**。YOLO 需要的是 64×64 矩阵引擎 + 能跑 depthwise/pool/softmax 的向量单元 + 一个 CPU 核做 NMS；Qwen 需要的是大 SRAM 与高带宽。两者的公共部分是矩阵引擎，分歧在向量单元与 CPU 核——这两个不加上，YOLO 的 0.82 ms 会退化成 2 ms 以上。

## 12.3 待验证清单

| # | 待验证项 | 方法 | 影响 |
|---:|---|---|---|
| 1 | NMS 实测 0.4–2.5 ms | 在目标 CPU 上跑 100 张不同拥挤度的图 | 端到端预算 ±2 ms，决定是否把 NMS 搬上 NPU |
| 2 | 官方 6.5 GFLOP 的确切口径 | 用 ultralytics 的 `get_flops` 复算并对照本文四档 | 差额从 0.31% 归零，或确认口径差异 |
| 3 | `c3k` 内 Bottleneck 的 `e=1.0` | 核对实际部署版本的 `block.py` | 若为 0.5，参数差 18,496/73,856，节点 6、8、22 的 MAC 各差约 1.2% |
| 4 | letterbox 后的有效分辨率 | 统计数据集的长宽比分布 | 灰边占比决定 80² 特征的可用面积 |
| 5 | INT8 的实际掉点 | 量化后跑 COCO val2017 | 决定 11.3 节走第 1、2 还是第 3 步 |
| 6 | 63% 的阵列填充率 | 用目标阵列尺寸（不一定是 64×64）重算 | ±5%，直接影响算力预算与 TOPS 选型 |
| 7 | 25 TOPS / 310 GB/s 的机器参数 | 向芯片团队确认规格 | 带宽若减半，neck 会先到墙（8.3） |
| 8 | DFL exp 查表的精度 | 对比 FP32 与查表版的框坐标 | 框误差需 < 0.05 像素，否则小目标定位漂移 |

第 3 项是唯一可能改变参数总量的：本文的 2,624,080 已经与 checkpoint 逐张量对齐，所以它更可能是"源码版本差异"而不是"本文算错"。第 6 项是唯一可能改变算力结论的：如果阵列不是 64×64，10.2 节的 63% 要重算，但 12.1 节第 1、2 条的分布结论不受影响。

# 附录 B　复现脚本

纯 Python 3，无第三方依赖。把 `yolo11.yaml` 的 24 行按 `depth`/`width` 展开，逐卷积累加参数与 MAC。

```python
import math

D, WD, MAXC, NC, REG = 0.50, 0.25, 1024, 80, 16
mdiv = lambda x: int(math.ceil(x / 8) * 8)
C = lambda c: mdiv(min(c, MAXC) * WD)
N = lambda n: max(round(n * D), 1) if n > 1 else n

P = [0, 0, 0]          # 卷积权重 / BN 仿射 / 其它
M = [0, 0, 0]          # 卷积 / BN / SiLU+残差+池化
CAT = {'3x3': 0, '1x1': 0, 'dw': 0, 'attn': 0, 'pool': 0, 'elem': 0}

def conv(tag, c1, c2, k, s=1, g=1, act=True, H=0, W=0):
    Ho, Wo = (H + s - 1) // s, (W + s - 1) // s
    kv = c1 // g * c2 * k * k
    P[0] += kv; P[1] += 2 * c2
    M[0] += kv * Ho * Wo; M[1] += 2 * c2 * Ho * Wo
    if act:
        M[2] += 2 * c2 * Ho * Wo
    key = 'dw' if (g == c1 == c2 and k > 1) else ('1x1' if k == 1 else '3x3')
    CAT[key] += kv * Ho * Wo

def add(c, H, W):
    M[2] += c * H * W; CAT['elem'] += c * H * W

def bottle(tag, c1, c2, k, H, W, sc=True, e=0.5):
    c_ = int(c2 * e)
    conv(tag + '.cv1', c1, c_, k, H=H, W=W)
    conv(tag + '.cv2', c_, c2, k, H=H, W=W)
    if sc and c1 == c2:
        add(c2, H, W)

def c3k2(tag, c1, c2, n, c3k, e, H, W):
    c = int(c2 * e)
    conv(tag + '.cv1', c1, 2 * c, 1, H=H, W=W)
    if c3k:
        c_ = int(c * 0.5)
        conv(tag + '.m.cv1', c, c_, 1, H=H, W=W)
        conv(tag + '.m.cv2', c, c_, 1, H=H, W=W)
        for i in range(2):
            bottle(tag + '.m.m%d' % i, c_, c_, 3, H, W, True, 1.0)
        conv(tag + '.m.cv3', 2 * c_, c, 1, H=H, W=W)
    else:
        for i in range(n):
            bottle(tag + '.m%d' % i, c, c, 3, H, W)
    conv(tag + '.cv2', (2 + n) * c, c2, 1, H=H, W=W)

def sppf(tag, c1, c2, k, H, W):
    c_ = c1 // 2
    conv(tag + '.cv1', c1, c_, 1, act=False, H=H, W=W)
    for i in range(3):
        M[2] += k * k * c_ * H * W + 2 * c_ * H * W
        CAT['pool'] += k * k * c_ * H * W
    conv(tag + '.cv2', c_ * 4, c2, 1, H=H, W=W)

def c2psa(tag, c1, n, H, W, e=0.5, ratio=0.5):
    c = int(c1 * e)
    conv(tag + '.cv1', c1, 2 * c, 1, H=H, W=W)
    dim = c; nh = max(dim // 64, 1); hd = dim // nh; kd = int(hd * ratio); Np = H * W
    conv(tag + '.qkv', dim, dim + kd * nh * 2, 1, act=False, H=H, W=W)
    M[0] += nh * kd * Np * Np; CAT['attn'] += nh * kd * Np * Np
    M[2] += 3 * nh * Np * Np; CAT['elem'] += 3 * nh * Np * Np
    M[0] += nh * hd * Np * Np; CAT['attn'] += nh * hd * Np * Np
    conv(tag + '.proj', dim, dim, 3, g=dim, act=False, H=H, W=W)
    conv(tag + '.proj2', dim, dim, 1, act=False, H=H, W=W)
    add(dim, H, W)
    conv(tag + '.ffn1', dim, 2 * dim, 1, H=H, W=W)
    conv(tag + '.ffn2', 2 * dim, dim, 1, act=False, H=H, W=W)
    add(dim, H, W)
    conv(tag + '.cv2', 2 * c, c1, 1, H=H, W=W)

def detect(tag, chs, HW):
    c2 = max(16, chs[0] // 4, REG * 4)
    c3 = max(chs[0], min(NC, 100))
    for ci, (H, W) in zip(chs, HW):
        conv(tag + '.cv2.0', ci, c2, 3, H=H, W=W)
        conv(tag + '.cv2.1', c2, c2, 3, H=H, W=W)
        M[0] += c2 * 4 * REG * H * W; CAT['1x1'] += c2 * 4 * REG * H * W
        P[0] += c2 * 4 * REG
        conv(tag + '.cv3.0', ci, ci, 3, g=ci, H=H, W=W)
        conv(tag + '.cv3.1', ci, c3, 1, H=H, W=W)
        conv(tag + '.cv3.2', c3, c3, 3, g=c3, H=H, W=W)
        conv(tag + '.cv3.3', c3, c3, 1, H=H, W=W)
        M[0] += c3 * NC * H * W; CAT['1x1'] += c3 * NC * H * W
        P[0] += c3 * NC; P[2] += 4 * REG + NC

def net(IMG=640):
    H = W = IMG
    conv('00', 3, C(64), 3, 2, H=H, W=W); H //= 2; W //= 2
    conv('01', C(64), C(128), 3, 2, H=H, W=W); H //= 2; W //= 2
    c3k2('02', C(128), C(256), N(2), False, 0.25, H, W)
    conv('03', C(256), C(256), 3, 2, H=H, W=W); H //= 2; W //= 2
    c3k2('04', C(256), C(512), N(2), False, 0.25, H, W)
    conv('05', C(512), C(512), 3, 2, H=H, W=W); H //= 2; W //= 2
    c3k2('06', C(512), C(512), N(2), True, 0.5, H, W)
    conv('07', C(512), C(1024), 3, 2, H=H, W=W); H //= 2; W //= 2
    c3k2('08', C(1024), C(1024), N(2), True, 0.5, H, W)
    sppf('09', 256, 256, 5, H, W)
    c2psa('10', 256, 2, H, W)
    c3k2('13', 256 + 128, C(512), N(2), False, 0.5, IMG // 16, IMG // 16)
    c3k2('16', 128 + 128, C(256), N(2), False, 0.5, IMG // 8, IMG // 8)
    conv('17', 64, 64, 3, 2, H=IMG // 8, W=IMG // 8)
    c3k2('19', 64 + 128, C(512), N(2), False, 0.5, IMG // 16, IMG // 16)
    conv('20', 128, 128, 3, 2, H=IMG // 16, W=IMG // 16)
    c3k2('22', 128 + 256, C(1024), N(2), True, 0.5, IMG // 32, IMG // 32)
    P[0] += 16                                   # DFL 固定卷积
    detect('23', [64, 128, 256], [(IMG // 8, IMG // 8), (IMG // 16, IMG // 16), (IMG // 32, IMG // 32)])
    return P, M, CAT
```
