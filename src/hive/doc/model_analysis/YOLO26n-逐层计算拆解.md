# Ultralytics YOLO26n 逐层计算拆解

2026-10-29 ｜ 依据 ultralytics main 分支 `yolo26.yaml`（24 个节点）、`parse_model` 的 depth/width 规则、`nn/modules/{block,conv,head}.py`、`yolo26n.pt` 的 state_dict（712 个张量、2,610,490 个元素）、官方 yolo26 文档与 benchmark 表（2.4 M 参数、5.5 GFLOPs、CPU ONNX 38.9 ms、T4 1.7 ms）核对

## 摘要

YOLO26n 是单阶段、anchor-free、NMS-free 的目标检测网络。图上 24 个节点，按 11 / 12 / 1 分成 backbone、neck、head 三段，输出 stride 8/16/32 三个尺度。640×640 输入下一帧 **2,762,030,400 MAC = 5.524 GFLOP**，参数 **2,417,452**（推理图，单分支）。

对芯片设计影响最大的几项：

- 全帧 **2.7620 GMAC = 5.524 GFLOP**，与官方 5.5 差 +0.4%。训图（one2many + one2one 双分支）是 3.0655 GMAC = 6.131 GFLOP，与 yaml 注释的 6.1 差 +0.5%，两条口径都在 1.1 节对齐。
- 计算量的重心从检测头移回了主干：head 只占 **10.99%**（303.48 MMAC），而 YOLO11n 的 head 占 28.5%。同一张 640×640 图，YOLO26n 比 YOLO11n 少算 **530.03 MMAC（−16.1%）**，其中 634.64 MMAC 全在检测头的框回归支路，backbone+neck 反而多算了 104.61 MMAC。
- 框回归支路变窄 4 倍：`reg_max` 从 16 降到 1，`cv2` 的中间宽度从 64 降到 16，末层 1×1 从 64→64 变成 16→4。DFL 的 softmax 与积分（8,400 锚点 × 4 边 × 16 箱）整段消失。
- 后处理从"NMS"换成"排序选前 300"：8,400 个锚点上做 300 选 1 的有界 top-k，规模与场景里的目标数无关；11n 的 NMS 成本随候选数平方增长，最坏 11.4 ms，最好 0.34 ms。
- 权重只有 **2.42 MB**（INT8），一帧激活流量 **51.00 MB**（FP16），是权重的 21 倍。只算权重时算术强度 1,142.6 MAC/B，把激活全算上只剩 **54.1 MAC/B**，刚好越过 25 TOPS / 310 GB/s 机器的平衡点 40.3——勉强算力瓶颈，裕度只有 1.3 倍。
- 激活驻留峰值 **5,529,600 B（5.53 MB，FP16）**，出现在 L15 的 Concat 物化时刻。同一时刻活着的还有 L4、L13、L10 三张跳连张量。Concat 与后续 1×1 融合能把峰值压到 2.25 MB。
- 纯视图（4 个 Concat、2 个 Upsample）占激活流量 **13.93 MB（27.3%）**，MAC 为 0。这是全帧最容易被忽略的一块钱：不融合，这 13.93 MB 白搬。
- 端到端：11n 是 56.1 ms 图 + 0.1–0.3 ms DFL + 0.34–11.4 ms NMS = 56.5–67.8 ms；26n 是 38.9 ms 图（decode 与 top-k 已含在图内）= 38.9 ms。省 17.6–28.9 ms，即 31%–43%。

后面按"事实、结构、逐算子、算力账、硬件映射、量化、结论"展开。

# 第 1 章　事实基线

YOLO26n 没有 `config.json`，也没有逐层超参文件。它的事实全在 `yolo26.yaml` 的 24 行结构定义加两个缩放系数里：`depth=0.50` 决定重复次数，`width=0.25` 决定通道数；再加两个开关 `reg_max=1` 与 `end2end=True` 决定检测头形态。这一章把这几项展开成真实层，并用三份独立数据把它钉死。

## 1.1 数据来源与核对方法

五条来源，按可信度排序：

| 来源 | 内容 | 用途 |
|---|---|---|
| `yolo26n.pt` 的 state_dict | 712 个张量，其中 126 个是卷积核，形状精确到 kernel | 通道数、核尺寸、head 结构的唯一真相 |
| `yaml` + `parse_model` | 24 个节点的 `from / n / module / args`，外加 `reg_max`、`end2end` | 拓扑与缩放规则 |
| `block.py` / `conv.py` / `head.py` | `C3k2`、`C3k`、`SPPF`、`C2PSA`、`Detect` 的构造函数与 forward | 内部张量结构、`dfl` 是否为 Identity |
| 官方文档 | 2.4 M 参数、5.5 GFLOPs（640×640） | 总量校验 |
| benchmark 表 | CPU ONNX 38.9 ms、T4 TensorRT 1.7 ms | 端到端时间校验 |

三条独立核对。

第一条是参数。按 yaml 展开后逐节点求和得 2,572,280（双分支训图），与 checkpoint 的 state_dict 求和逐位相等：126 个卷积核 2,552,208 + 12 个裸 1×1 bias 504 + 114 个 BN 的 γ 9,784 + 114 个 β 9,784 = 2,572,280。单分支推理图减去被 `fuse()` 删掉的 one2many 头 154,828，得 2,417,452，与官方 2.4 M 一致。这条核对同时验证了对 `C3k` 内部结构的理解：`C3k2(c3k=True)` 里的 `C3k` 会再套 2 个 `Bottleneck(e=1.0)`，两个 conv 都是 3×3；若按 `Bottleneck` 默认的 `e=0.5` 展开，第 6、8、13、16、19、22 六个节点各少算 14,848–73,856 个参数，总量掉到 2.33 M 而"看起来仍然合理"。

第二条是张量账。checkpoint 里一共 712 个张量、2,610,490 个元素，与参数之差 38,210 可以逐项点名：BN 的 `running_mean/var` 19,568（228 个张量）、`num_batches_tracked` 114、`Detect.anchors` 12,348、`Detect.strides` 6,174、`Detect.stride` 6。差值 0，说明没有漏掉任何一层，也没有把 buffer 混进参数。

第三条是算力。纯卷积口径 2,625,843,200 MAC（不含 attention 的 QKᵀ/AV、池化、逐元素）乘 2 得 5.2517 GFLOP；加上 attention 矩阵乘、SiLU、残差、池化比较后得 5.5241 GFLOP，与官方 5.5 差 +0.4%。同一套脚本对 YOLO11n 算得 3.2921 GMAC = 6.584 GFLOP，与官方 6.5 差 +1.3%、与 yaml 注释 6.6 差 −0.2%，说明口径本身在 1% 量级内自洽。

同目录下已有 `YOLO11n-逐层计算拆解.md`（只写到第 2 章），其口径把 BN 按 2 MAC/元素计入，总量 3,339.26 MMAC。本文把 BN 折叠为 0 MAC，重算得 3,292.06 MMAC，差 47.20 MMAC，其中 BN 占 32.70 MMAC，余下 14.49 MMAC 是该文档在池化比较与 C2PSA softmax 上的计法差异，未逐项复算（列入 12.3）。第 8 章的 11n 与 26n 两张表都由本文同一脚本重算，可以直接相减。

## 1.2 关键超参

| 超参 | 值 | 与 YOLO11n 的差异 |
|---|---|---|
| 输入 | 640 × 640 × 3，uint8 | 相同 |
| 缩放系数 | depth 0.50 / width 0.25 / max_channels 1024 | 相同 |
| 图节点数 | 24（backbone 11、neck 12、head 1） | 相同 |
| 卷积 | 63 个（57 个带 BN、6 个裸 1×1，每分支） | 11n 是 87 个（81 带 BN）+ 1 个 DFL |
| BN | 57 个 / 分支 | 11n 是 81 个 |
| 激活 | SiLU，全部卷积后 | 相同 |
| 池化 | MaxPool 5×5 ×3（仅 SPPF） | 相同 |
| 检测头 | anchor-free，`reg_max=1`，无 DFL，`end2end=True` | 11n 是 `reg_max=16` + DFL |
| 分支 | one2many + one2one 双头，fuse 后只剩 one2one | 11n 单头 |
| 后处理 | 无 NMS，top-k 300 | 11n 是 DFL 解码 + NMS |
| 参数量 | 2,417,452（单分支）/ 2,572,280（双分支） | 11n 2,624,080 |

三处与 YOLO11n 的结构性差别，后面每一章都会回到它们：

`reg_max=1` 让 `dfl` 变成 `nn.Identity()`。`Detect.__init__` 里一行 `self.dfl = DFL(self.reg_max) if self.reg_max > 1 else nn.Identity()` 就把 16 箱 softmax 与积分整段删掉了，框回归从"分类 16 个 bin 再求期望"退化成"直接回归 4 个距离"。这一改动的连带效应是 `c2 = max(16, ch[0] // 4, reg_max * 4)` 从 64 掉到 16，因为第三项 `reg_max * 4` 从 64 变成 4。

`end2end=True` 让 `Detect` 在构造时 `copy.deepcopy` 出一份 one2one 头，训练时两路都算、都监督；`fuse()` 后 one2many 头被置空，导出图只剩 one2one。参数上这正是 2,572,280 与 2,417,452 之间那 154,828。

`C3k2` 的第三个开关 `attn` 只用在第 22 节点：`[1024, True, 0.5, True]` 里的最后一个 True 让每个 Bottleneck 后面再挂一个 `PSABlock`。这一节点用 1 个节点吃掉了 215.35 MMAC，是 neck 里最贵的一层。

# 第 2 章　模型全景

## 2.1 三个子模型

```
yolo26n  640×640×3  uint8
│
├─ backbone   节点 0–10    1,365,472 参数 (56.5%)   1,564.34 MMAC (56.6%)
│   ├─ P1/2  16ch 320²    节点 0
│   ├─ P2/4  32ch 160²    节点 1、2
│   ├─ P3/8  64ch 80²     节点 3、4          ← 存下来给 neck 用（跨 11 个节点）
│   ├─ P4/16 128ch 40²    节点 5、6          ← 存下来（跨 6 个节点）
│   └─ P5/32 256ch 20²    节点 7–10          ← 存下来（跨 11 个节点）
│
├─ neck       节点 11–22     897,152 参数 (37.1%)     894.21 MMAC (32.4%)
│   ├─ 上采样路径 11–13、14–16（P5→P4→P3）
│   └─ 下采样路径 17–19、20–22（P3→P4→P5）
│
└─ Detect     节点 23        154,828 参数 (6.4%)      303.48 MMAC (11.0%)
    ├─ P3 80² × 64ch   → 4 个距离 + 80 类
    ├─ P4 40² × 128ch  → 同上
    └─ P5 20² × 256ch  → 同上
         ↓
    8400 个锚点 → ltrb 转 xyxy × stride → 类内取最大 → top-k 300（图内）
```

三条跳连线决定 SRAM 驻留而不是算力：

| 跳连 | 生产节点 | 消费节点 | 存活跨度 | 张量大小 FP16 |
|---|---:|---:|---:|---:|
| P3 主干特征 | 4 | 15 | 11 个节点 | 1,638,400 B |
| P4 主干特征 | 6 | 12 | 6 个节点 | 409,600 B |
| P5 主干特征 | 10 | 21 | 11 个节点 | 204,800 B |
| P3 检测输入 | 16 | 23 | 7 个节点 | 819,200 B |
| P4 检测输入 | 19 | 23 | 4 个节点 | 409,600 B |
| P5 检测输入 | 22 | 23 | 1 个节点 | 204,800 B |

与 YOLO11n 相比，六条跳连的起止节点、通道、分辨率**完全一样**。NMS-free 与 DFL 移除都发生在 L23 之后或 L23 内部，不动 topology。这一点决定了：驻留峰值不变，SRAM 预算不能因为"新模型更省"就往下砍。

## 2.2 五类 block 的配比

| 类型 | 节点数 | 单个参数 | 合计参数 | 单个 MAC | 合计 MAC | 结构特征 |
|---|---:|---:|---:|---:|---:|---|
| A　Conv 3×3 s2 | 7 | 464 ~ 295,424 | 669,968 | 45.88 ~ 236.34 M | 873.32 M | 一个带 BN 的 3×3，无残差 |
| B　C3k2 e=0.25 | 2 | 6,640 / 26,080 | 32,720 | 165.58 / 167.32 M | 332.90 M | 1×1 降维 + 1 个 3×3 夹心 + 1×1 升维，空间大、通道窄 |
| C　C3k2 c3k | 5 | 34,304 ~ 346,112 | 682,496 | 138.55 ~ 218.11 M | 837.38 M | C3k 内嵌 2 个 e=1.0 的 Bottleneck，参数密度高 |
| D　SPPF / C2PSA / C3k2-attn | 3 | 164,608 ~ 463,104 | 877,440 | 69.58 ~ 215.35 M | 414.96 M | 池化 + 自注意力 + FFN，参数量大、空间最小 |
| E　Detect | 1 | 154,828 | 154,828 | 303.48 M | 303.48 M | 三尺度 3×3 + 1×1 头，无 DFL |
| 视图 | 6 | 0 | 0 | 0 | 0 | Concat ×4、Upsample ×2 |
| **合计** | **24** | | **2,417,452** | | **2,762.03 M** | |

参数占比与 MAC 占比不同向，这是 YOLO26n 与 11n 最大的区别：D 类只占 15.0% MAC 却占 36.3% 参数（C2PSA 在 20² 上堆了 24.97 万参数），E 类只占 11.0% MAC 与 6.4% 参数。11n 正好相反，E 类占 28.5% MAC 与 17.7% 参数。换句话说，YOLO26n 把"贵但算得少"的模块留在了网上，把"贵且算得多"的框回归砍掉了。

## 2.3 计算形态的四个类别

| 类别 | 特征 | 本模型算子 | MAC | 占比 |
|---|---|---|---:|---:|
| GEMM（隐式） | 激活块与权重的多维张量收缩 | 3×3 卷积、1×1 卷积、C2PSA 的 QKᵀ 与 V·A（不含 depthwise） | 2,687.28 M | 97.3% |
| 逐通道 | 通道不混合，每通道独立 | depthwise 3×3、5×5 MaxPool | 18.65 M | 0.7% |
| 逐元素与归约 | 同形状逐点、沿一维归约 | SiLU、残差加、softmax、缩放 | 56.10 M | 2.0% |
| 纯视图 | 0 MAC | Upsample ×2、Concat ×4 | 0 | 0% |
| **合计** | | | **2,762.03 M** | **100.0%** |

GEMM 占 97.3%，比 11n 的 97.56% 略低 0.3 个点：因为总 MAC 少了 16%，而 attention 的 QKᵀ/AV（61.44 MMAC）一分没少，占比自然升高，把逐元素摊薄了。

按卷积类型再切一刀，看给阵列喂的形状：

| 卷积类型 | MAC | 占比 | 说明 |
|---|---:|---:|---|
| 1×1 | 1,155,699,200 | 41.8% | 通道混合的主力，最适合直接当 GEMM |
| 3×3 s2 | 873,318,400 | 31.6% | 全是 A 类，降采样 |
| 3×3 s1 | 596,825,600 | 21.6% | Bottleneck 与 C3k 内部 |
| depthwise 3×3 | 14,809,600 | 0.5% | 只在 Detect 的 cv3 里（6 处） |
| 其他 | 121,377,600 | 4.4% | attention QKᵀ/AV 61.44 M、池化 3.84 M、逐元素 56.10 M |
| **合计** | **2,762,030,400** | **100.0%** | |

表里"其他"含 61.44 MMAC 的 attention 矩阵乘，它形状上是 GEMM，但 K 维是 400 个空间点而不是通道，进同一块阵列时 tiling 完全不同，所以单列。

## 3.2 骨架与读法

```
输入 640×640×3
 │
 ├─[G0] L0 Conv 3×3 s2 3→16      320²   ─► L1 Conv 16→32 160² ─► L2 C3k2 32→64
 │                                                                   │
 │                                                              P2 32ch 160²
 ├─[G1] L3 Conv s2 64→64 80² ─► L4 C3k2 64→128 80² ┄┄┄┄┄┄┄┄┄┄┐  P3 128ch 80²
 │                                    │                      ┊
 ├─[G2] L5 Conv s2 128→128 40² ─► L6 C3k2 c3k 128→128 40² ┄┄┄┄┼┄┄┄┄┄┄┐  P4 128ch 40²
 │                                    │                      ┊      ┊
 ├─[G3] L7 Conv s2 128→256 20² ─► L8 C3k2 c3k 20² ─► L9 SPPF ─► L10 C2PSA 20²
 │                                                                  │  P5 256ch 20²
 │                                                                  │
 ├─[G4] L11 Upsample ×2 256 40² ┄┄┄┄┄┄┄┄┄┐                          │
 │      L12 Concat[11,6] 384 40² ─► L13 C3k2 c3k 384→128 40² ┄┄┄┐    │
 │      L14 Upsample ×2 128 80² ┄┄┄┐                            ┊    │
 │      L15 Concat[14,4] 256 80² ─► L16 C3k2 c3k 256→64 80² ┄┄┄┼┄┄┄┄┤  P3' 64ch 80²
 │                                    │                         ┊    │
 ├─[G5] L17 Conv s2 64→64 40² ┄┄┄┄┄┄┄┄┼┄┄┄┄┐                   ┊    │
 │      L18 Concat[17,13] 192 40² ─► L19 C3k2 c3k 192→128 ┄┄┄┄┄┼┄┄┄┄┤  P4' 128ch 40²
 │      L20 Conv s2 128→128 20² ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┤    │
 │      L21 Concat[20,10] 384 20² ─► L22 C3k2 c3k+attn 384→256 ┄┄┄┄┘    │  P5' 256ch 20²
 │
 └─[G6] L23 Detect[16,19,22] ─► 8400 锚点 ─► top-k 300 ─► (1,300,6)
```

读法三条：

`─►` 是算力依赖，右边要等左边算完；`┄` 是纯搬运（Upsample、Concat、跳连），没有 MAC，但占 SRAM 与带宽。图中 `┄┄┐`/`┄┄┤` 的纵向引线就是 6 条跳连，它们的长度直接决定驻留峰值（4.3 节）。

方括号 [G0]–[G6] 是分组编号，后文说"G4 组"就是指 11–16 这 6 个节点。分组的依据是数据流依赖链：每组内部的节点串行，组与组之间通过跳连耦合。

节点号是 `parse_model` 的 `m.i`，也是 checkpoint 里 `model.23` 那种下标。本文引用的"L13"就是 yaml 第 13 行、`m.i = 13`。

## 3.3 A 类：Conv-BN-SiLU（7 个节点）

```
x ──► Conv2d 3×3 s2 ──► BN ──► SiLU ──► y
      (c1→c2, k=3)       (折叠)   (LUT)
```

七个节点分别是 L0（3→16, 320²）、L1（16→32, 160²）、L3（64→64, 80²）、L5（128→128, 40²）、L7（128→256, 20²）、L17（64→64, 40²）、L20（128→128, 20²）。它们全是 stride 2 降采样，没有例外；YOLO26n 里**不存在** stride 1 的独立 3×3 卷积，stride 1 的 3×3 全部藏在 Bottleneck 与 C3k 里。

A 类的参数量分布极不均：L7 一个占 295,424（44.1% 的 A 类参数），L0 只有 464。原因是 `c1*c2*9` 在 L7 上是 256×128×9 = 294,912，而 L0 是 3×16×9 = 432。

## 3.4 B 类：C3k2 e=0.25（2 个节点）

```
x ──► cv1 1×1 (c1→2c) ──┬───────────────────────────┐
                        │                           │
                        └─► Bottleneck(c, e=0.5) ───┤
                             cv1 3×3 (c→c/2)        │
                             cv2 3×3 (c/2→c)        │
                             + 残差                  │
                                                     ▼
                                    Concat (3c 通道) ──► cv2 1×1 (3c→c2) ──► y
```

c = c2 × 0.25，n = 1（depth 0.5 把 yaml 的 2 取整回 1）。L2 是 32→64，c=16；L4 是 64→128，c=32。两个节点都落在 160²/80² 的大空间上，通道窄（16/32），所以 MAC 不小而参数极少：L2 只 6,640 个参数却算 167.32 MMAC，参数密度 25,200 MAC/参数，是全模型最高的。

B 类的 MAC 有 47.9% 花在 cv2 的升维上（L2：80,281,600 / 167,321,600），因为输入是 3c = 48 通道。这是 `C3k2` 的通用特征：`cv2` 的输入通道是 `(2+n)×c`，n 越大越贵。

## 3.5 C 类：C3k2 c3k=True（5 个节点）

```
x ──► cv1 1×1 (c1→2c) ──┬────────────────────────────────────────┐
                        │                                        │
                        └─► C3k(c, n=2) ──────────────────────────┤
                             cv1 1×1 (c→c/2) ─┐                   │
                             cv2 1×1 (c→c/2) ─┼─► Concat (c)      │
                             m: 2× Bottleneck(c/2, e=1.0, 3×3) ───┤
                             cv3 1×1 (c→c) ◄──────────────────────┘
                                                     ▼
                                    Concat (3c) ──► cv2 1×1 (3c→c2) ──► y
```

C3k 是 CSP 结构：cv1 的输出过 2 个 Bottleneck，再与 cv2 的输出拼接，最后过 cv3。每个 Bottleneck 是 `3×3 → 3×3 + 残差`，两个 conv 都是 3×3、e=1.0，这一点 checkpoint 说得最清楚：L6 的 `m.0.m.0.cv1` 与 `cv2` 形状都是 `(32, 32, 3, 3)`。

五个节点：L6（128→128, 40²）、L8（256→256, 20²）、L13（384→128, 40²）、L16（256→64, 80²）、L19（192→128, 40²）。C 类是 MAC 占比最高的一类（30.3%），也是参数第二高的一类（28.2%），因为 C3k 内部有 2 个 e=1.0 的 Bottleneck，参数量按 `2 × 2 × 9 × (c/2)²` 走。

## 3.6 D 类：SPPF / C2PSA / C3k2-attn（3 个节点）

三个节点形状完全不同，只因"都带非卷积算子"归为一类。

```
SPPF (L9, 20²)                       C2PSA (L10, 20²)
x ─► cv1 1×1 (无激活) ─► y0          x ─► cv1 1×1 ─► y0
     ├─ MaxPool5 ─► y1                    └─► PSABlock(c=128) ──┐
     ├─ MaxPool5(y1) ─► y2                   attn(2 头, pe 3×3) │
     └─ MaxPool5(y2) ─► y3                   FFN c→2c→c        │
     Concat[y0..y3] 4×128=512 ─► cv2 1×1                       │
     y = cv2 + x   (add=True)              y = y0 + PSABlock ──┘
```

```
C3k2 attn (L22, 20²)
x ─► cv1 1×1 (384→256) ─┬──────────────────────────────────────┐
                        └─► [ Bottleneck(128, e=0.5) ─► PSABlock(128) ] ─┐
                                                                        ▼
                                              Concat (384) ─► cv2 1×1 (384→256)
```

SPPF 的 `add=True` 是 YOLO26 相对 11n 的改动之一：11n 的 SPPF 直接返回 `cv2(concat)`，26n 多一个 `y + x`。这多出的 102,400 MAC 就是 8.1 节里 backbone 唯一的增量。

C2PSA 的 PSABlock 里有 2 头注意力（`nh = max(c//64, 1) = 2`，`hd = 64`，`kd = 32`），位置编码用 depthwise 3×3（`pe`），FFN 是 `c→2c→c`。在 20² 上，注意力矩阵只有 400×400，QKᵀ 与 AV 各 10.24 + 20.48 MMAC。

L22 的 attn 分支是"Bottleneck + PSABlock"串行，两条支路都吃 128 通道，所以这一节点 MAC 高达 215.35 MMAC，比 8 号节点（同样 256 输出、20²）的 138.09 MMAC 高 56%。

## 3.7 E 类：Detect（1 个节点）

```
P3 80²×64 ──┐
P4 40²×128 ─┼─► 每尺度一套 cv2/cv3 ─► 84 通道 ─► 按尺度拼 8400 锚点
P5 20²×256 ─┘                                  │
                                               ▼
                        ltrb ─► xyxy（×stride）─► 80 类取最大 ─► top-k 300
```

每尺度的两条支路：

```
cv2（框）: Conv 3×3 (ch→16) ─► Conv 3×3 (16→16) ─► Conv2d 1×1 (16→4)
cv3（类）: DWConv 3×3 (ch) ─► Conv 1×1 (ch→80) ─► DWConv 3×3 (80) ─► Conv 1×1 (80→80) ─► Conv 1×1 (80→80)
```

`cv2` 的末层是裸 `nn.Conv2d`（带 bias，无 BN、无激活），输出 4 个通道，直接就是 ltrb 距离；`cv3` 的末层同样是裸 1×1，输出 80 个类分数，没有单独的 objectness 分支（anchor-free 且 YOLO26 去掉了 obj）。

三个尺度的 `c2` 都是 16（因为 `max(16, 64//4, 4×1) = 16`），`c3` 都是 80（因为 `max(64, min(80,100)) = 80`）。尺度之间只有输入通道不同，这是 head 参数少（154,828）的直接原因。

# 第 5 章　通用算子库

本章的算子卡只讲"这个算子在 YOLO26n 里长什么样、花多少 MAC、量化时注意什么"，具体在哪个节点用多少，放第 6 章。

## 5.1 Conv2d 3×3，stride 2

| 项 | 内容 |
|---|---|
| 形状 | 输入 `c1×H×W`，输出 `c2×(H/2)×(W/2)`，kernel 3×3，padding 1 |
| MAC | `c1 × c2 × 9 × (H/2) × (W/2)`，例：L3 是 64×64×9×6400 = 236,339,200 |
| 归属 | 7 个 A 类节点全用，合计 873,318,400 MAC（31.6%） |
| 精度 | 第一层（L0）输入是 uint8 的 3 通道，量化误差直接进网络，建议 16 位或 per-channel INT8；其余层 per-channel INT8 |
| 坑 | `c1=3` 时 K 维只有 27，阵列填充率极低（64×64 阵列的 K 维只用 27/64）；建议 L0 走专用小卷积通路或与预处理合并 |

stride 2 的 3×3 在硬件上有两种实现：先做 padding 再按 stride 抽取，或者把 3×3 拆成 4 个 2×2（space-to-depth）后做 4 个 stride 1 的卷积。后者的好处是阵列利用率高，代价是权重排布要重排一次（离线做，不影响运行期）。

## 5.2 Conv2d 1×1

| 项 | 内容 |
|---|---|
| 形状 | 输入 `c1×H×W`，输出 `c2×H×W`，kernel 1×1 |
| MAC | `c1 × c2 × H × W`，是纯 GEMM，M=c2、N=H×W、K=c1 |
| 归属 | 全模型 1,155,699,200 MAC（41.8%），最大的一类 |
| 精度 | per-channel INT8 最划算；`C3k2` 的 cv1 输出通道是 `2c`，通道间动态范围差异大，必须 per-channel |
| 坑 | K 维小的地方（如 L2 的 32、L16 的 96）阵列 K 方向填充率低；N 维（空间）很大，适合把 N 切块做双缓冲 |

1×1 卷积是这套网络最规整的部分：没有 padding、没有 stride、没有边界，天然是 `M×K` 权重乘 `K×N` 激活。62.5% 的 1×1 出现在通道数 ≤128 的层，K 维不足以填满大阵列，切 K 会让权重重复读取，需要在"阵列利用率"和"权重带宽"之间选。

## 5.3 Depthwise Conv2d 3×3

| 项 | 内容 |
|---|---|
| 形状 | 输入输出同通道 `c×H×W`，groups=c，每通道一个 3×3 |
| MAC | `c × 9 × H × W`，全模型 14,809,600（0.5%），6 处 |
| 归属 | Detect 的 cv3 每尺度 2 处（`DWConv(ch)` 与 `DWConv(80)`），3 尺度共 6 处 |
| 精度 | per-channel 必须；depthwise 的权重动态范围极窄（常见 ±0.05），INT8 要用非对称量化 |
| 坑 | 阵列利用率上限 = 1/c。80 通道的 depthwise 在 64×64 阵列上等效利用率 1.25%，不能按 MAC 比例分配周期；按"每周期 64 个通道"的向量通路算，80 通道要 2 拍 |

## 5.4 BatchNorm（推理期折叠）

| 项 | 内容 |
|---|---|
| 形状 | 逐通道仿射，`y = γ(x-μ)/σ + β` |
| MAC | 折叠后 **0**；不折叠则 2 MAC/元素，全模型 33.60 MMAC（1.2%） |
| 归属 | 单分支 57 个 BN，8,520 个通道 |
| 精度 | 折叠后 γ/σ 吸收进权重，32 位累加即可；注意 σ 很小时权重会被放大，fold 后要做一次权重量化校准 |
| 坑 | `Detect` 的末层 1×1 是裸 conv（无 BN），它的 bias 是训练出来的，不能当 BN 的 β 处理；fold 脚本要能识别这两类层 |

折叠公式：`W' = W·γ/σ`，`b' = β - γ·μ/σ`。折叠在打包阶段做一次，运行期没有任何 BN 指令。如果为了"支持任意 BN"而在运行期做，代价是每层多一遍 32 位读改写，激活流量从 51.00 MB 涨到约 100 MB，直接毁掉 8.3 节的带宽账。

## 5.5 SiLU

| 项 | 内容 |
|---|---|
| 形状 | `y = x·sigmoid(x)`，逐元素 |
| MAC | 1 MAC/元素（本文口径），全模型包含在 56.10 MMAC 的"逐元素"里 |
| 归属 | 每个带 `act=True` 的 Conv 后；单分支 57 处（裸 conv 后没有） |
| 精度 | 输出范围约 [-0.278, +∞)，负半轴有界、正半轴线性；INT8 直接算会有 2 个数量级的动态范围问题，建议 LUT |
| 坑 | SiLU 不是单调截断函数，`x<-8` 时输出≈-0.0003，量化到 0 会让深层小激活全灭；LUT 的表长按 8 位输入 256 项即可，插值可选 |

## 5.6 MaxPool 5×5

| 项 | 内容 |
|---|---|
| 形状 | `c×H×W` → `c×H×W`，kernel 5，stride 1，padding 2 |
| MAC | `25 × c × H × W` 次比较，SPPF 里 3 次，共 3,840,000（0.14%） |
| 归属 | 只有 L9 SPPF，3 个串行 MaxPool |
| 精度 | 无（纯比较，不引入误差） |
| 坑 | 3 个串行 5×5 等效一个 13×13 的感受野（带孔），但**不能**合并成一次 13×13 池化：中间结果要保留，因为最终 concat 的是 y0..y3 四张 |

SPPF 的三次池化是串行的：`y1 = pool(y0)`、`y2 = pool(y1)`、`y3 = pool(y2)`，然后 `concat[y0,y1,y2,y3]`。硬件上只需要一行 line buffer（5 行 × W）就能流水，不需要三块全图缓冲。

## 5.7 Concat

| 项 | 内容 |
|---|---|
| 形状 | 沿通道维拼接，空间尺寸必须相同 |
| MAC | 0（纯视图），但物化时读 6,041,600 B、写 7,884,800 B（4 个 Concat 合计） |
| 归属 | L12、L15、L18、L21 |
| 精度 | 两路 scale 必须统一，否则要先 requantize 一次（每元素 1 次乘加） |
| 坑 | 拼接后的通道顺序决定下游 1×1 的权重排布。若下游是 1×1，concat 可以完全免费：把权重按通道切片，直接从两路源张量读，不写中间张量 |

## 5.8 Upsample（nearest ×2）

| 项 | 内容 |
|---|---|
| 形状 | `c×H×W` → `c×2H×2W`，最近邻 |
| MAC | 0，物化时读 614,400 B、写 2,457,600 B |
| 归属 | L11（20²→40²）、L14（40²→80²） |
| 精度 | 无 |
| 坑 | 输出是输入的元素复制，**带宽放大 4 倍**。若下游是 concat + 1×1，可以让 1×1 按"输入坐标除以 2"去取数，完全不物化 |

## 5.9 多头自注意力（C2PSA 内）

| 项 | 内容 |
|---|---|
| 形状 | `c=128`，`nh=2`，`hd=64`，`kd=32`，`n=400`（20²），qkv 输出 `c+2·kd·nh = 256` |
| MAC | QKᵀ `nh·kd·n² = 10,240,000`；AV `nh·hd·n² = 20,480,000`；另有 qkv/proj/pe/ffn 的卷积 46.44 MMAC |
| 归属 | L10（C2PSA）、L22（C3k2-attn），两处各一次 |
| 精度 | QKᵀ 的 logits 范围随 n 增大，softmax 前要减最大值；建议 attention 内部 FP16，进出 INT8 |
| 坑 | `n=400` 时注意力矩阵 2×400×400 = 320,000 个元素，SRAM 够放，但 QKᵀ 的 K 维是 32（kd），阵列填充率 32/64；这是全网络唯一"矩阵乘但 K 很小"的地方 |

## 5.10 残差加

| 项 | 内容 |
|---|---|
| 形状 | 同形状逐元素相加 |
| MAC | 1 MAC/元素，含在 56.10 MMAC 的"逐元素"里 |
| 归属 | 每个 Bottleneck 内 1 次；C3k 内 2 次；SPPF 的 `add=True`；C2PSA 内 2 次 |
| 精度 | 两个加数的 scale 必须相同，否则先 requantize |
| 坑 | 残差是"读两份、写一份"，带宽 3 倍于元素数；在 80²、128 通道的层上（L4）是 819,200×3 B ≈ 2.4 MB 的搬运，不在 MAC 账里但在带宽账里 |

## 5.11 检测头输出层（裸 1×1 + bias）

| 项 | 内容 |
|---|---|
| 形状 | cv2 末层 `16→4`，cv3 末层 `80→80`，都带 bias、无 BN、无激活 |
| MAC | 每尺度 `4×16×HW`（框）+ `80×80×HW`（类） |
| 归属 | L23，每尺度 2 个裸 conv，3 尺度 6 个 |
| 精度 | 框支路输出是 ltrb 距离（单位：格），P3 上最大到 80，量化步长直接等于定位误差，**必须 16 位**；类支路输出是 logits，INT8 + per-channel 够用 |
| 坑 | 框支路是"小网络 + 大动态范围"的组合，per-tensor INT8 的步长会到 0.63 格 ≈ 5 px，完全不可用；这是第 11 章的重点 |

# 第 6 章　五类 block 的逐算子拆解

每个 block 给三样东西：子算子表（参数与 MAC 逐项）、引擎准入（哪些算子必须进阵列）、精度预算（哪一段不能掉到 8 位）。所有子表的小计与 3.1 节逐位对齐。

## 6.1 A 类：Conv-BN-SiLU

以 L3（64→64, 80², stride 2）为例：

| 子算子 | 形状 | 参数 | MAC | 备注 |
|---|---|---:|---:|---|
| Conv2d 3×3 s2 | 64→64, 80² | 36,864 | 235,929,600 | |
| BN | 64 通道 | 128 | 0 | 折叠 |
| SiLU | 64×80² | 0 | 409,600 | 1 MAC/元素 |
| **合计** | | **36,992** | **236,339,200** | |

引擎准入：Conv 必须进阵列（K=576，M=64，N=6400）；BN 在打包阶段折叠，运行期无指令；SiLU 走向量通路或 LUT。

精度预算：权重 per-channel INT8、激活 per-tensor INT8 足够；唯一例外是 L0（输入 uint8、K=27），建议给 16 位。

坑：L0 的输出要进 L1 的 16→32 卷积，而 L0 的权重只有 432 个，量化校准样本稍有偏差就会让 P1 特征整体偏移。工程上常把 L0/L1 一起做 per-channel + 16 位激活，代价是 1.64 MB 的激活流量翻倍（3.28 MB），占全帧 6.4%，可以接受。

## 6.2 B 类：C3k2 e=0.25

以 L2（32→64, 160², c=16, n=1）为例：

| 子算子 | 形状 | 参数 | MAC | 备注 |
|---|---|---:|---:|---|
| cv1 1×1 | 32→32, 160² | 1,088 | 27,033,600 | 含 SiLU 819,200 |
| m0.cv1 3×3 | 16→8, 160² | 1,168 | 29,696,000 | Bottleneck e=0.5 |
| m0.cv2 3×3 | 8→16, 160² | 1,184 | 29,900,800 | |
| m0 残差 | 16×160² | 0 | 409,600 | 1 MAC/元素 |
| cv2 1×1 | 48→64, 160² | 3,200 | 80,281,600 | 输入 3c=48 |
| **合计** | | **6,640** | **167,321,600** | |

引擎准入：三个 1×1/3×3 全进阵列；残差走向量加。B 类的 K 维极小（32、16、8），阵列填充率是主要矛盾：m0.cv2 的 K=8，64 宽的阵列只用 1/8。

精度预算：这一层的通道只有 8–16，per-channel 量化几乎无收益（通道太少统计不稳），建议 per-tensor INT8 + 16 位累加；残差加的两路 scale 要对齐。

坑：`Bottleneck(e=0.5)` 的中间通道 `c/2 = 8`，比 INT8 的 8 位还"窄"，量化后中间特征只有 256 个可表示值。实测经验是这一层保持 8 位不会掉点，但**不能**再对它做通道剪枝，否则精度会断崖。

## 6.3 C 类：C3k2 c3k=True

以 L6（128→128, 40², c=64）为例：

| 子算子 | 形状 | 参数 | MAC | 备注 |
|---|---|---:|---:|---|
| cv1 1×1 | 128→128, 40² | 16,640 | 26,419,200 | 分成两半，各 64 通道 |
| C3k.cv1 1×1 | 64→32, 40² | 2,112 | 3,328,000 | |
| C3k.cv2 1×1 | 64→32, 40² | 2,112 | 3,328,000 | |
| C3k.cv3 1×1 | 64→64, 40² | 4,224 | 6,656,000 | |
| C3k.m0.cv1 3×3 | 32→32, 40² | 9,280 | 14,796,800 | e=1.0 |
| C3k.m0.cv2 3×3 | 32→32, 40² | 9,280 | 14,796,800 | |
| C3k.m0 残差 | 32×40² | 0 | 51,200 | |
| C3k.m1.cv1 3×3 | 32→32, 40² | 9,280 | 14,796,800 | |
| C3k.m1.cv2 3×3 | 32→32, 40² | 9,280 | 14,796,800 | |
| C3k.m1 残差 | 32×40² | 0 | 51,200 | |
| cv2 1×1 | 192→128, 40² | 24,832 | 39,526,400 | 输入 3c=192 |
| **合计** | | **87,040** | **138,547,200** | |

引擎准入：两个 3×3 Bottleneck 是主力（59.19 MMAC，42.7%）；C3k 的 cv1/cv2 是"同输入双 1×1"，可以合成一个 64→64 的 GEMM 再切分，省一次读激活。

精度预算：3×3 Bottleneck 的 e=1.0，通道不压缩，per-channel INT8 最划算；C3k 的两个 3×3 串联，中间特征动态范围逐级放大，建议第二级用 16 位或 QAT 校准。

坑：`C3k` 的 cv1、cv2 输入都是 x（同一个张量），硬件若把两者当两个独立卷积，会读两遍 x。L6 上 x 是 204,800 个元素，读两遍多花 409,600 B，占该层流量的 50%。融合成一次读、两路权重是标准优化。

## 6.4 D 类之一：SPPF（L9）

| 子算子 | 形状 | 参数 | MAC | 备注 |
|---|---|---:|---:|---|
| cv1 1×1 | 256→128, 20² | 33,024 | 13,107,200 | 无激活 |
| MaxPool 5×5 | 128×20² | 0 | 1,280,000 | 25 次比较/元素 |
| MaxPool 5×5 | 128×20² | 0 | 1,280,000 | 第二级 |
| MaxPool 5×5 | 128×20² | 0 | 1,280,000 | 第三级 |
| cv2 1×1 | 512→256, 20² | 131,584 | 52,531,200 | 含 SiLU 102,400 |
| add（y+x） | 256×20² | 0 | 102,400 | YOLO26 新增 |
| **合计** | | **164,608** | **69,580,800** | |

引擎准入：两个 1×1 进阵列；三次池化走行缓冲 + 比较器，不进阵列。cv2 的 K=512 是全网最大的 K 之一，阵列效率最高。

精度预算：max 比较不引入误差，但三路池化结果与 y0 拼接后进 1×1，四段特征的动态范围不同，concat 的 scale 要按最大值定，否则小响应被压掉。

坑：`add=True` 让输出加了输入，这一项的 scale 必须与 cv2 输出一致；如果为了迁就 cv2 的大动态范围而用小 scale，残差项的精度会损失。建议在 fold/量化阶段单独给 add 前的两路做 scale 对齐。

## 6.5 D 类之二：C2PSA（L10）

|---|---|---:|---:|---|
| cv1 1×1 | 256→256, 20² | 66,048 | 26,316,800 | |
| cv2 1×1 | 256→256, 20² | 66,048 | 26,316,800 | |

| psa.score | 2 头 ×400 | 0 | 25,600 | 缩放 |

| psa.qk | 32×400×400 | 0 | 10,240,000 | QKᵀ |
| psa.av | 64×400×400 | 0 | 20,480,000 | AV |
| psa.proj 1×1 | 128→128, 20² | 16,640 | 6,553,600 | 无激活 |
| psa.pe 3×3 dw | 128, 20² | 1,408 | 460,800 | 无激活 |

坑：C2PSA 的参数占 249,728（全模型 10.3%），MAC 只占 4.7%，是典型"参数重、算力轻"的模块。如果 SRAM 只能放一部分权重，优先把 C2PSA 的权重留在片外按需搬，因为它每帧只读一次，而 A 类权重在 80² 上被复用的次数更高。

| 子算子 | 形状 | 参数 | MAC | 备注 |
|---|---|---:|---:|---|
| cv1 1×1 | 384→256, 20² | 98,816 | 39,424,000 | |

| cv3.1 1×1 (ch→80) | 33,280,000 | 16,512,000 | 8,224,000 | 58,016,000 |
| cv3.2 dw 3×3 (80) | 5,120,000 | 1,280,000 | 320,000 | 6,720,000 |

引擎准入：全部进阵列，但 `cv2.2` 的 K=16、`cv3.2` 的 depthwise 是低效点；`cv3.1` 的 K 是 64/128/256，效率较好。

精度预算：`cv2.2` 必须 16 位输出（见 5.11）；`cv3.4` 的 80 类 logits 用 INT8 + per-channel 足够，但 top-k 阈值比较要用 16 位，否则同分排序不可复现。

坑（三条）：

一、cv2 与 cv3 是两条独立支路，输入是同一张特征图。若分两次读，P3 上多读 819,200 B；三条支路（两分支）共多读 1.43 MB，占 head 流量翻倍。

二、`c2 = 16` 是全局常量（三个尺度共用），所以 P5（256 通道输入）的 `cv2.0` 是 256→16 的 3×3，K=2304、M=16，M 维只有 16，阵列的 M 方向填充率 25%。这是 head 效率最低的一处（P5 的 cv2.0 用 14.75 MMAC 只换来 102,400 个输出）。

三、双分支（one2many + one2one）在训练时都算，推理 fuse 后只剩 one2one。若硬件按训图布局，会多算 154,828 参数与 303.48 MMAC——这正好是 1.1 节里 2,572,280 与 2,417,452 的差。部署时务必确认用的是 fused 图。

# 第 7 章　输入预处理、检测头与 NMS-free 后处理

前六章算的是图内的 2,762,030,400 MAC。这一章算图外的两块：进图之前的预处理，出图之前的解码与筛选。YOLO26n 在这两处各有一处改动：`end2end=True` 把后处理搬进图内，`reg_max=1` 把 DFL 整段删掉。两者都不改 24 个节点，但都改端到端时间。

## 7.1 输入预处理（图外）

默认推理管线的四步：letterbox 到 640×640（保持长宽比、灰度 114 填充）、HWC 转 CHW、除以 255、量化到 INT8。YOLO 系列不做减均值除方差，这一点与 ImageNet 分类模型不同，量化 scale 因此只取决于输入范围 0–1。

| 步骤 | 数据量 | 计算量 | 说明 |
|---|---|---:|---|
| letterbox 缩放（双线性） | 输出 1,228,800 元素 | 4.90 MMAC | 4 taps × 2 遍，按 640×640 输出计 |
| 填充 114 | 至 640×640 | 0 | 纯写，源分辨率小时填充更多 |
| HWC 转 CHW | 1,228,800 元素 | 0 | 纯搬运，用 DMA 的 stride 即可 |
| 除以 255 并量化 | 1,228,800 元素 | 1.23 MMAC | per-tensor scale |
| 写入片上 | 1,228,800 B INT8 | 0 | L0 的输入 |
| **合计** | **1,228,800 B** | **6.13 MMAC** | 占全帧 0.22% |

源图 1920×1080 时缩放系数 0.333，输出 640×360，上下各填 140 行；源图小于 640 时放大，双线性退化为可分离插值，计算量不变。预处理不进 2,762,030,400 的账，但它决定 L0 的输入 scale：若把 /255 折进 L0 权重（W' = W/255），可省 1.23 MMAC 与一次读写，代价是 L0 权重动态范围缩小 255 倍，INT8 下不可接受。保留独立 scale 是更稳的选择。

## 7.2 检测头的三条不变式

三条不变式决定了 head 的形状，也决定了硬件能把它当固定模式实现：

`84 = 4 + 80`：没有 objectness 通道。置信度就是 80 个类分数里的最大值。YOLO26 去掉了 obj 分支，anchor-free 加 one2one 监督让"有没有目标"由分类分数直接承担。

`8,400 = 6,400 + 1,600 + 400`：三个尺度 80²、40²、20² 各一份，stride 分别是 8、16、32。每尺度都输出 `4 + 80` 通道，`c2 = 16`、`c3 = 80` 三个尺度共用（1.2 节）。

`reg_max = 1`：`cv2` 的 4 个输出通道就是 ltrb 四个距离，没有 16 箱、没有 softmax、没有积分。解码是纯代数：

```
x1 = (gx + 0.5 - l) × s     y1 = (gy + 0.5 - t) × s
x2 = (gx + 0.5 + r) × s     y2 = (gy + 0.5 + b) × s
```

`gx, gy` 是格坐标，`s` 是 stride。算术量：8,400 个锚点 × (2 减 + 2 加 + 4 乘) = 67,200 次乘加；类内取最大 8,400 × 79 = 663,600 次比较。这两项在图内、在 top-k 之前。

训练侧的两个改动不影响这张图：STAL（小目标标签分配）与 ProgLoss（渐进损失）只改正样本的挑选与损失权重，不改 `Detect.forward` 的张量形状。核对方式有两条：`yolo26.yaml` 里没有对应节点，`Detect` 的构造参数只有 `nc / reg_max / end2end`；导出后的 state_dict 能被 `parse_model` 的展开逐位对上（1.1 节第一条）。所以这两个改动在推理图上零成本，也无法从图里"看出来"。

## 7.3 NMS-free 后处理

`end2end=True` 的 26n 导出后走 `Detect.forward` 的 e2e 分支：解码、取类内最大、再调 `postprocess`，直接输出 `(B, 300, 6)`，六列是 x1、y1、x2、y2、conf、cls。

top-k 的形态是 `_grouped_topk(conf, k=min(300, 8400), groups=8)`：8,400 个置信度按类别分成 8 组，组内先取，再合并取 300。分组不是为了美观，而是防止 300 个名额被同一个类占满——密集场景里同一类会出现大量高分框，one2one 保证了框不重复，但纯全局 top-k 仍会让类别分布失衡。

输出固定 300 行，不足时补 0（conf=0、坐标 0）。这是 NMS-free 对硬件最大的好处：**输出形状与画面里的目标数无关**，不需要动态 shape、不需要主机侧排序、不需要按 batch 重排。代价是空行要过滤，见 7.6。

复杂度：8,400 个输入、300 个输出，两遍桶选加组内堆排约 2–11 万次比较；若退化成全排序则是 8,400 × log₂(8,400) ≈ 109,000 次。这个量级与 NMS 的 O(N²) 不是一个数量级：NMS 在最坏情况下要比较 8,400 个候选之间的 IoU，量级 10⁷。

## 7.4 后处理成本模型：11n 对 26n

先算算术，再算时间。算术部分（图内或紧随图后的纯计算）：

| 步骤 | 11n | 26n | 说明 |
|---|---:|---:|---|
| DFL softmax | 537,600 次 exp | 0 | 每锚点 4 边 × 16 箱 |
| DFL 积分 | 537,600 MAC | 0 | 固定权重 0..15 |
| ltrb 转 xyxy | 67,200 | 67,200 | 含乘 stride |
| 类内取最大 | 663,600 比较 | 663,600 比较 | 80 类 |
| **合计** | **1,806,000** | **730,800** | |

时间部分（主机侧，估算值）：

| 步骤 | 11n | 26n |
|---|---|---|
| DFL 解码 | 0.1–0.3 ms | 0（无此项） |
| NMS / top-k | 0.34–11.4 ms | 0.02–0.11 ms |
| **合计** | **0.44–11.7 ms** | **0.02–0.11 ms** |

DFL 的 0.1–0.3 ms 来自 537,600 次 `exp` 加 2,150,400 B（8,400 × 4 × 16 × 4 B）FP32 中间张量的读改写。NMS 的 0.34–11.4 ms 是三个场景的估算：稀疏画面候选少，0.34 ms；常规画面 0.5 ms 量级；密集画面候选上千且互相重叠，抑制循环退化到 11.4 ms。这三个数没有在本机测过，来源与待核事项记在 12.3；本文只用它们给出区间，不用它们做单点结论。

26n 的 top-k 之所以能做到 0.02–0.11 ms，是因为它是有界的：输入固定 8,400、输出固定 300，与画面内容无关。NMS 的成本则随候选数与重叠度变化，这是"NMS-free 省时间"的真正含义——不是省了常数，而是把最坏情况消掉了。

## 7.5 端到端延迟

官方 benchmark 的 CPU ONNX 数据（640×640，单图）与 7.4 的估算叠加：

| 阶段 | 11n | 26n | 差 |
|---|---:|---:|---:|
| 图（CPU ONNX） | 56.1 | 38.9 | −17.2 |
| DFL 解码 | 0.1–0.3 | 0 | −0.1 ~ −0.3 |
| NMS / top-k | 0.34–11.4 | 0（图内） | −0.34 ~ −11.4 |
| **合计** | **56.5–67.8** | **38.9** | **−17.6 ~ −28.9** |

省 17.6–28.9 ms，相对 56.5–67.8 ms 是 **31%–43%**，与官方"最高 43%"一致（区间下端对应稀疏画面，上端对应密集画面）。

图本身从 56.1 降到 38.9，是 **−30.7%**，而 MAC 只少 16.1%。差额来自三处：`cv2` 的宽度从 64 降到 16，P3 上每层输出从 64 通道降到 16，固定开销与访存被摊薄；DFL 的两个小卷积与 softmax 从图里消失；头的三个尺度各自少了 3 个 64 通道的 3×3/1×1，调度层数下降。这些都是推理引擎层面的效应，不能只用 MAC 解释。

T4 上的方向相反：11n 1.5 ms、26n 1.7 ms（+13%）。26n 的头变成大量窄算子，GPU 上融合失败与发射开销会吃掉 MAC 的优势。这一现象的原因未核，列进 12.3；它提醒一件事：MAC 账只能预测 CPU 与 NPU 上的大致趋势，GPU 上要看算子融合。

## 7.6 坑（四条）

一、坐标已经乘 stride 回到 640 尺度。letterbox 的逆变换只在把框映射回原图时做，若硬件输出 640 坐标系，主机侧要再乘一次缩放系数，漏了会让所有框缩小到 1/3。

二、300 行固定输出里有空行（conf=0）。画框前必须过滤；直接按 300 个框统计会把空行算成假阳性，mAP 掉得莫名其妙。

三、fuse 之后 one2many 头被删，推理图权重是 2,417,452，训图是 2,572,280。拿训图的 state_dict 直接喂推理图会报一批 missing keys（涉及 154,828 个参数），反过来则会多出未使用的权重。

四、top-k 在图内，NPU 上就得有能力跑排序。标量核弱时会回退到 CPU 并引入每帧 0.3–1 ms 的同步开销，把 7.5 的收益吃掉一半。这个回退在设计评审里最容易被忽略，因为它在 ONNX 图上看不出来。

# 第 8 章　三本账：算力 / 权重 / 激活

三本账回答三个不同的问题：算力账回答"要多少 MAC"，权重账回答"片上要放多少常量"，激活账回答"要搬多少、要留多少"。三者的瓶颈点不在同一层，这是设计里最容易配错资源的地方。

## 8.1 算力账

先给与 YOLO11n 的逐节点对照。26n 一列来自 1.3 节，11n 一列由附录 B 的同一脚本换 yaml 与 `reg_max=16` 得到，两列可以直接相减。

按段汇总，重心迁移看得更清楚：

| 段 | 26n MMAC | 占比 | 11n MMAC | 占比 |
|---|---:|---:|---:|---:|

11n 的账是"头占近三成"，26n 变成"头只占一成，主干与颈部各占三成到五成"。净效果是 −530.03 MMAC（−16.1%）：head 省的 634.64 被 neck 多算的 104.50 与 backbone 的 0.10 抵掉一部分。neck 变贵全在 13/16/19/22 四层：前三层把普通 Bottleneck（两个 3×3，e=0.5）换成 C3k（三个 1×1 加两个 3×3，e=1.0），每层多 13.36–13.62 MMAC；第 22 层再挂一个 PSABlock，多 64.16 MMAC。backbone 只多了 SPPF 的一次逐元素加。

## 8.2 权重账

| 类 | 节点数 | 参数 | 占比 | INT8 字节 | FP16 字节 |
|---|---:|---:|---:|---:|---:|
| A　Conv 3×3 s2 | 7 | 669,968 | 27.7% | 669,968 | 1,339,936 |
| B　C3k2 e=0.25 | 2 | 32,720 | 1.4% | 32,720 | 65,440 |
| C　C3k2 c3k | 5 | 682,496 | 28.2% | 682,496 | 1,364,992 |
| D　SPPF / C2PSA / attn | 3 | 877,440 | 36.3% | 877,440 | 1,754,880 |
| E　Detect | 1 | 154,828 | 6.4% | 154,828 | 309,656 |
| **合计** | **18** | **2,417,452** | **100.0%** | **2,417,452** | **4,834,904** |

三个数要记住：

**2.42 MB** 是 INT8 权重总量，也是每帧至少要读一遍的常量。它小到可以整块放进 4 MB 的权重 SRAM，并留一倍余量做双缓冲；这是 YOLO26n 在端侧最值钱的属性。FP16 权重是 4.83 MB，放不进去，只能按层流式读。

**1,142.6 MAC/B** 是"每字节权重被复用的次数"（2,762,030,400 / 2,417,452）。分块看差异极大：B 类 10,175，因为通道只有 8–48 而在 160²/80² 上展开；E 类 1,960；A 类 1,303；D 类只有 473，因为 20² 的像素太少。权重放不下时，先搬 D 类（C2PSA 的 249,728 B、L22 attn 的 117,632 B、SPPF 的 164,608 B），它们每帧只读一次、复用最差。

折叠后是 **2,408,932 B**：57 个 BN 的 β 变成卷积 bias，γ 吸收进权重，参数少 8,520 个。权重字节数不变（权重个数不变，bias 本来就在裸 conv 里）。

| 类 | MAC | 激活字节（FP16） | DRAM µs @100 GB/s |
|---|---:|---:|---:|
| A | 873,318,400 | 18,944,000 | 189.4 |
| B | 332,902,400 | 7,372,800 | 73.7 |
| C | 837,376,000 | 7,987,200 | 79.9 |
| D | 414,958,400 | 1,331,200 | 13.3 |

全帧激活 **50,998,800 B = 51.00 MB**，其中读 28.67 MB、写 22.33 MB。算术强度（MAC/激活字节）逐类差别很大：A 46.1、B 45.2、C 104.8、D 311.7、E 211.2，合计 **54.2**。25 TOPS / 310 GB/s 机器的平衡点是 **40.3 MAC/B**，54.2 只比它高 1.34 倍——算力瓶颈，但没有余量可以浪费。把权重也放进分母是 51.7，结论不变。

视图的 13.93 MB 占 27.3%，MAC 为 0。四个 Concat 与两个 Upsample 若全部融合（下游卷积直接按坐标读源张量），流量降到 **37,072,400 B = 37.07 MB**，算术强度升到 74.5，带宽压力立刻松掉 27.3%。这是全设计里性价比最高的一项优化，比把阵列做大一档便宜得多。

驻留按"张量活到最后一个消费者"算，峰值 **5,529,600 B = 5.53 MB**，出现在 L15 之后：L15 输出 3,276,800 B、L4 的 P3 主干 1,638,400 B、L13 输出 409,600 B、L10 输出 204,800 B，四张同时活着。只把 L15 的 Concat 与 L16 的 cv1 融合，峰值降到 **2,252,800 B = 2.25 MB**（L16 输出尚未产生，剩下 L4、L13、L10 三张）。再加上权重 2.42 MB、attention 工作区 640,000 B（2 头 × 400 × 400 × 2 B）、top-k 缓冲 3,600 B，融合后的片上需求约 **5.31 MB**；不融合则要 8.59 MB。

11n 的同一张账：字节完全相同（拓扑与通道没变），算术强度 64.6。所以"26n 更省带宽"是错的——它省的是算力，搬运一分没少。把 26n 的模型换上去，SRAM 预算不能降，DMA 带宽也不能降。

# 第 9 章　时间线：一张图走完全程

前面的账是静态的。这一章给一个名义机器：64×64 的 MAC 阵列、1 GHz、100 GB/s 的 DRAM 带宽、单缓冲。结论只用来判断"谁先到瓶颈"，不代表任何具体实现。

## 9.1 名义时间线

按 3.2 的分组 G0–G6 串行执行，每组的 MAC 除以 4,096（阵列的每周期 MAC 数）得周期数：

| 组 | 节点 | MAC | 周期 @64×64 | 占比 |
|---|---|---:|---:|---:|
| G0 | 0–2 | 331,980,800 | 81,050 | 12.02% |
| G1 | 3–4 | 401,920,000 | 98,125 | 14.55% |
| G2 | 5–6 | 374,681,600 | 91,475 | 13.57% |
| G3 | 7–10 | 455,760,800 | 111,270 | 16.50% |
| G4 | 11–16 | 409,088,000 | 99,875 | 14.81% |
| G5 | 17–22 | 485,124,000 | 118,438 | 17.56% |
| G6 | 23 | 303,475,200 | 74,091 | 10.99% |
| **合计** | | **2,762,030,400** | **674,324** | **100.00%** |

1 GHz 下 674,324 周期就是 **674.3 µs**。加上 DRAM 侧：激活 510.0 µs、权重 24.2 µs（2,417,452 B），合计 534.2 µs。这是填充率 100% 的下界：M 或 K 不是 64 的整数倍的层会被放大，按 `ceil(M/64) × ceil(K/64) × N` 逐层精算的总周期高于 674,324，最大的一处在 9.2 节。两条时间线叠在一起：

```
计算 0 ─► 81.1 ─► 179.2 ─► 270.7 ─► 381.9 ─► 481.8 ─► 600.2 ─► 674.3 µs
     G0      G1       G2       G3       G4       G5       G6
DRAM 0 ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄ 534.2 µs
```

计算比 DRAM 长 140.1 µs，DRAM 利用率 79.2%。若 DMA 与阵列单缓冲串行，总时间是 1,208.5 µs；双缓冲能把 DRAM 完全藏进计算里，这是 1.79 倍的差距，比任何算法优化都大。

## 9.2 瓶颈判定

先看总量，再看分布：

算力瓶颈，比例 1.26 倍。674.3 / 534.2 = 1.26：频率提到 1.26 GHz 时计算才降到 534.2 µs 与 DRAM 持平，再往上就翻成带宽瓶颈。在 1 GHz 上，DRAM 有 21% 的空闲（1 − 534.2/674.3），这部分带宽买不到时间，只能靠融合去换。

G5 是最长的组。118,438 周期，其中 L22 的 215.35 MMAC 占该组 44.4%，而 L22 里 PSABlock 的 77.39 MMAC 又是全组最难调度的部分（K=32 的 QKᵀ 加 K=64 的 AV）。要压时间，先动 L22 的注意力与 L0 的填充率，而不是调卷积的 tiling：L22 的 PSABlock 减半省 9.4 µs，L0 的像素打包省 76.8 µs（见下一段）。

G0 的效率最低。81,050 周期里有 L0 的 45.88 MMAC，M=16、K=27：64×64 阵列每拍只有 432 个乘积落在有效位置，填充率 10.5%。按 `ceil(M/64) × ceil(K/64) × N` 算是 **102,400 周期**，是名义值 11,200 的 9.1 倍。把 4 个相邻像素的 16 个输出通道拼成 M=64 的一拍，可以回到 25,600 周期，省 76.8 µs——这是全帧最大的一笔单点优化。

按 30 FPS 算，帧预算是 33.3 ms，674 µs 只用 2%。也就是说在端侧，瓶颈不在阵列，而在主机侧的预处理、后处理与内存拷贝——7.5 节的 38.9 ms 里，网络只占很小一块。

## 9.3 三个 what-if

32×32 输入：MAC 降到 690,507,600（1.381 GFLOP），计算 168.6 µs；激活流量 12.75 MB，加权重 2.42 MB 共 15.17 MB，DRAM 151.7 µs。两者只差 1.11 倍，权重占比升到 15.9%。小分辨率下"权重常驻"比"阵列变大"更值钱：权重固定 2.42 MB，激活缩到 1/4，带宽账立刻变紧。

128×128 输入：MAC 11,048,121,600（22.10 GFLOP），计算 2,697.3 µs；流量 206.41 MB，DRAM 2,064.1 µs。算力仍是瓶颈（1.31 倍），结论与 640 一致：放大分辨率不改变瓶颈性质，只放大绝对时间。

1.5 GHz：计算降到 449.5 µs，低于 DRAM 534.2 µs，设计从算力瓶颈翻到带宽瓶颈，再提频率完全无效。此时只有两条路：提带宽，或做 8.3 节的视图融合——融合后激活 37.07 MB，加权重共 39.49 MB，DRAM 394.9 µs，又重新低于 449.5 µs。融合在这里等价于把带宽提高 35%。

## 10.2 三条工程约束

其一，阵列的 K 方向要能吃 8 到 384。B 类的 Bottleneck 内层 K 只有 8（8 通道 × 3×3），填不满任何大阵列；把 K 方向切到 32 以下会让权重重复读，得不偿失。可行的做法是"小 K 走 16×16 子阵列、大 K 走 64×64 主阵列"，两套 tiling 参数，按层切换。

其二，N 方向（空间）永远够大，适合切块双缓冲。最小的一层是 L9/L10/L22 的 20² = 400 个像素，仍然大于 64；把 N 切 64 的整数倍能让每一拍都满。真正需要小心的是 L0 的 320² 与 L2 的 160²，它们的输出张量是 1.64 MB 量级，双缓冲要 3.28 MB。

其三，DMA 必须在通道维上支持"跨张量 gather"，否则 Concat 融合做不了。8.3 节的 13.93 MB 里，L15 一处就占 3.28 MB；融合要求 L16 的 cv1 直接从 L14 与 L4 两个张量按通道切片取数，DMA 描述符要能表达"前 128 通道来自 A、后 128 通道来自 B"。

# 第 11 章　量化归属

## 11.1 方案

基线是 W8A8：权重 per-channel 对称 INT8，激活 per-tensor 对称 INT8，32 位整数累加，SiLU 用 256 项 LUT。三处例外：

attention 内部 16 位。L10 与 L22 的 QKᵀ、softmax、AV 用 16 位定点（Q3.12）或 FP16，进出仍是 INT8。理由是 logits 随 n 增大，且 softmax 的指数对低位敏感。

框支路输出 16 位。`cv2.2` 的 4 个通道是 ltrb 距离，范围 0–80 格（P3），1 LSB 就是定位误差，必须 16 位。

decode 与 top-k 16 位。坐标在解码时要乘 stride 并做减法，16 位能保证 0.01 px 级精度；置信度比较用 16 位，避免同分排序不可复现（5.11、6.7）。

## 11.2 七个敏感点

一、L0 的输入。3 通道、K=27、权重 432 个，量化误差直接进网络；建议权重 per-channel、激活 8 位但保留 16 位累加，输入 uint8 的零点要显式建模。

二、SiLU 的负半轴。输出下界约 −0.278，`x < −8` 时接近 0；LUT 按 8 位输入 256 项足够，但表要覆盖负半轴的饱和段，否则深层小激活会被量化成 0。

三、SPPF 的四段 concat。y0 与三次池化的动态范围不同，concat 的 scale 按最大值定会压掉小响应；建议四段各自量化、进 cv2 前再 requantize。

四、残差的两路 scale。Bottleneck、C3k、C2PSA、SPPF 的 `add` 都要两路同 scale，否则先对齐再加，每元素多一次乘加。

五、C2PSA 的 softmax。20² 上 logits 在 ±10 内，16 位够；但 score 的缩放常数 1/√kd 不能折进 softmax 的 LUT，否则不同头的表不能共用。

六、框输出的长尾。ltrb 的分布是长尾，PTQ 校准要用 99.99% 分位而不是最大绝对值，否则一个离群点就能把整层步长拉大。

七、类 logits 的 80 路比较。top-k 在量化后的分数上做，同分时的顺序取决于实现；固定 16 位比较能保证可复现，也避免"同一张图两次输出不同"的调试噩梦。

## 11.3 位宽预算

| 区域 | MAC | 占比 | 位宽 | 权重参数 | 权重字节 |
|---|---:|---:|---|---:|---:|
| 常规卷积（L0–L22 除 attention） | 2,700,052,800 | 97.76% | INT8 | 2,181,984 | 2,181,984 |
| attention（L10、L22） | 61,440,000 | 2.22% | 16 位 | 235,264 | 470,528 |
| 框末层（3 尺度 cv2.2） | 537,600 | 0.02% | 16 位 | 204 | 408 |
| **合计** | **2,762,030,400** | **100.00%** | | **2,417,452** | **2,652,920** |

若 16 位在阵列上按半速跑，多出的周期是 (61,440,000 + 537,600) / 4,096 = **15,132 周期**，占 674,324 的 2.24%。权重从 2,417,452 B 涨到 2,652,920 B（+235,468 B，+9.7%），仍然放得进 4 MB。

这个预算的含义：**97.76% 的算力可以吃满 INT8 的吞吐**，16 位只落在两个小口子上，不会拖慢整体。反过来，若为了"统一精度"把全图做成 16 位，算力等效减半，674.3 µs 变 1,348.6 µs，得不偿失。

## 11.4 DFL 移除后的量化变化

算力上，DFL 本身只有 537,600 MAC（0.02%），真正省的是 `cv2` 的宽度：64 降到 16，cv2 从 758.02 降到 123.38 MMAC。所以"DFL 移除省了 634.64 MMAC"这句话的准确说法是：**省在框回归支路的通道数，不在 DFL 的两个小卷积**。

量化上有三处实质变化。

其一，11n 的 16 箱积分是加权平均，量化噪声按 √16 = 4 缩小；26n 直接回归没有平均，1 LSB 直接等于定位误差。同样 8 位，26n 的框误差是 11n 的 4 倍量级。P3 上 ltrb 的取值范围是 ±80 格，per-tensor INT8 的步长 160/255 = 0.63 格，乘 stride 8 是 5.0 px；per-channel（4 个通道各 80 格）能到 0.31 格、2.5 px；16 位是 0.0024 格、0.02 px。**框输出 16 位不是优化项，是正确性项**。

其二，DFL 的 softmax 与积分消失，图内少了 537,600 次 `exp` 与 2,150,400 B 的 FP32 中间张量，后处理不再需要指数单元。这对 NPU 是实打实的简化：不需要为 16 箱准备 LUT，也不需要 4 边的求和树。

其三，校准对象变了。11n 的 DFL 输出是 16 个概率，分布集中、易校准；26n 的 4 个距离是长尾连续量，PTQ 要用分位数校准，QAT 时要给框支路单独的学习率。这一条目前只有分析，没有实测掉点数据，列进 12.3。

# 第 12 章　对芯片设计的结论与待验证清单

## 12.1 九条结论

一、规模与口径。640×640 一帧 **2,762,030,400 MAC = 5.524 GFLOP**，参数 **2,417,452**；与官方 5.5 GFLOP 差 +0.4%、2.4 M 差 +0.7%。FLOP 一律按 2 × MAC 计（1.1、8.1）。

二、计算重心回到主干与颈部。head 只占 **10.99%**，backbone 56.6% + neck 32.4%；1×1 占 41.8%、3×3 s2 占 31.6%，阵列要服务的是 GEMM 形状而不是检测头（2.2、2.3、8.1）。

三、与 11n 的差全在框回归。总量少 **530.03 MMAC（−16.1%）**，其中 head 的 cv2 从 758.02 降到 123.38；neck 反而多算 104.50，因为 13/16/19 换成 C3k、22 加了注意力（3.8、8.1）。

四、带宽而不是权重。激活 **51.00 MB**、权重 2.42 MB，比例 21:1；算术强度 **54.2**，只比 25 TOPS / 310 GB/s 的平衡点 40.3 高 1.34 倍（8.2、8.3）。

五、融合是最高优先级。6 个纯视图占 **13.93 MB（27.3%）**；融合后 37.07 MB，算术强度 74.5。L15 一处融合把驻留峰值从 5.53 MB 压到 **2.25 MB**（4.3、8.3）。

六、时间账。64×64 @1 GHz 一帧 **674,324 周期 = 674.3 µs**，DRAM 534.2 µs，算力瓶颈 1.26 倍；G5 最长（118.4 µs），L0 效率最低（9.1、9.2）。

七、后处理从平方变有界。NMS 的 0.34–11.4 ms 换成 top-k 的 **0.02–0.11 ms**，输出固定 300×6，与画面目标数无关（7.3、7.4）。

八、量化预算。**97.76%** 的 MAC 可 INT8；attention 2.22% 与框末层 0.02% 要 16 位，代价 +2.24% 周期、+235,468 B 权重（11.3）。

九、端到端。CPU ONNX **38.9 ms** 对 11n 的 56.5–67.8 ms，省 31%–43%；T4 上 1.7 对 1.5 ms，方向相反（7.5、12.3）。

## 12.3 待验证清单

一、checkpoint 里两个 buffer 的元素数分别是 12,348 与 6,174，本文按 8,400 个锚点记账。若它们是锚点坐标，元素数应为 16,800；12,348 = 2 × 6,174、6,174 = 3 × 2,058，说明可能是按尺度分开存。具体形状与语义未核到，需读导出代码确认。

二、同目录 `YOLO11n-逐层计算拆解.md` 的 3,339.26 MMAC 与本文的 3,292.06 差 47.20，其中 BN 口径占 32.70，余下 14.49 未逐项复算（1.1）。

三、NMS 的 0.34 / 0.50 / 11.4 ms 与 DFL 的 0.1–0.3 ms 是估算，未在同一台机器上实测；7.5 的 31%–43% 区间因此带不确定性（7.4）。

四、T4 上 26n 1.7 ms 慢于 11n 1.5 ms 的原因未核：可能是 TensorRT 版本对小算子的融合策略，也可能是 head 的 16 通道卷积落在不适合的 kernel 上（7.5）。

五、官方"最高 43%"的测试环境（batch、线程数、CPU 型号、ONNX Runtime 版本）未核；本文只按公开 benchmark 的单点值推算（7.5）。

六、STAL 与 ProgLoss 对 mAP 的影响未量化。本文只确认它们不改推理图（7.2），精度收益需查论文与消融表。

七、26n 在 `end2end=False`（NMS 模式）下的后处理成本未算。该模式保留 one2many 头，参数 2,572,280、图 6.131 GFLOP（1.1），与本文的 2,417,452 / 5.524 不是同一张图。

八、PTQ/QAT 的实际掉点未测。11.3 的位宽预算是按动态范围推的分析结论，不是实测；框支路 16 位是否为最低要求，需要真机标定。

# 附录 B　复现脚本

脚本只依赖 Python 3 标准库。输入是 `yolo26.yaml` 的 24 行层表（内联），按 `depth=0.50`、`width=0.25`、`max_channels=1024` 展开，逐层算参数与 MAC，同时做活性分析求驻留峰值。口径与正文一致：BN 折叠但参数照算、SiLU 1 MAC/元素、残差 1 MAC/元素、池化 k² 次比较、Concat 与 Upsample 记 0。

```python
# YOLO26n 逐层展开与 MAC 复算。纯 Python 3，无第三方依赖。
# 用法：python3 yolo26n_layers.py    输入：yolo26.yaml 的层表（内联）
# 口径：MAC 含逐元素与归约，只排除纯视图；1 MAC = 2 FLOP
import re
YAML = r"""
nc: 80
end2end: True
reg_max: 1
backbone:
  - [-1, 1, Conv, [64, 3, 2]]
  - [-1, 1, Conv, [128, 3, 2]]
  - [-1, 2, C3k2, [256, False, 0.25]]
  - [-1, 1, Conv, [256, 3, 2]]
  - [-1, 2, C3k2, [512, False, 0.25]]
  - [-1, 1, Conv, [512, 3, 2]]
  - [-1, 2, C3k2, [512, True]]
  - [-1, 1, Conv, [1024, 3, 2]]
  - [-1, 2, C3k2, [1024, True]]
  - [-1, 1, SPPF, [1024, 5, 3, True]]
  - [-1, 2, C2PSA, [1024]]
head:
  - [-1, 1, nn.Upsample, [None, 2, "nearest"]]
  - [[-1, 6], 1, Concat, [1]]
  - [-1, 2, C3k2, [512, True]]
  - [-1, 1, nn.Upsample, [None, 2, "nearest"]]
  - [[-1, 4], 1, Concat, [1]]
  - [-1, 2, C3k2, [256, True]]
  - [-1, 1, Conv, [256, 3, 2]]
  - [[-1, 13], 1, Concat, [1]]
  - [-1, 2, C3k2, [512, True]]
  - [-1, 1, Conv, [512, 3, 2]]
  - [[-1, 10], 1, Concat, [1]]
  - [-1, 1, C3k2, [1024, True, 0.5, True]]
  - [[16, 19, 22], 1, Detect, [80]]
"""
NC, REG_MAX, INP, DEPTH, WIDTH, MAXC = 80, 1, 640, 0.50, 0.25, 1024
TOK = re.compile(r'\s*(?:(?P<q>"[^"]*")|(?P<num>-?\d+\.?\d*)|(?P<id>[A-Za-z_][A-Za-z_0-9.]*)|(?P<p>\[|\]|,))')
def parse_list(s):                                # 只解析本 yaml 出现的子集
    toks, i = [], 0
    while i < len(s):
        m = TOK.match(s, i)
        if not m:
            break
        i = m.end()
        k, v = m.lastgroup, m.group(m.lastgroup)
        toks.append(('p', v) if k == 'p' else ('v', v[1:-1] if k == 'q' else
                     (float(v) if '.' in v else int(v)) if k == 'num' else
                     {'None': None, 'True': True, 'False': False}.get(v, v)))
    pos = [0]
    def build():
        pos[0] += 1                               # 跳过 '['
        out = []
        if toks[pos[0]] == ('p', ']'):
            pos[0] += 1
            return out
        while True:
            t = toks[pos[0]]
            if t == ('p', '['):
                out.append(build())
            elif t == ('p', ']'):
                pos[0] += 1
                return out
            elif t == ('p', ','):
                pos[0] += 1
            else:
                out.append(t[1])
                pos[0] += 1
    return build()
def div8(x):
    return max(8, int(round(x / 8.0)) * 8)
class Net:
    w = lambda self, c: div8(min(c, MAXC) * WIDTH)
    def conv(self, c1, c2, k=1, s=1, g=1, act=True, side=1):
        o = side // s
        p = (c1 // g) * c2 * k * k + 2 * c2                    # 权重 + BN 仿射
        m = (c1 // g) * c2 * k * k * o * o + (c2 * o * o if act else 0)
        return p, m
    def bottleneck(self, c, side, k=3, e=0.5):
        ch = int(c * e)
        p1, m1 = self.conv(c, ch, k, side=side)
        p2, m2 = self.conv(ch, c, k, side=side)
        return p1 + p2, m1 + m2 + c * side * side               # 残差 1 MAC/元素
    def c3k(self, c, n, side):
        ch = int(c * 0.5)
        p, m = self.conv(c, ch, side=side)
        q, r = self.conv(c, ch, side=side)
        p, m = p + q, m + r
        q, r = self.conv(2 * ch, c, side=side)
        p, m = p + q, m + r
        for _ in range(n):
            bp, bm = self.bottleneck(ch, side, k=3, e=1.0)
            p, m = p + bp, m + bm
        return p, m
    def attention(self, c, side, nh):
        hd, kd = c // nh, int(c // nh * 0.5)
        h, n = c + 2 * kd * nh, side * side
        p, m = self.conv(c, h, act=False, side=side)
        m += nh * kd * n + 5 * nh * n                           # 缩放 + softmax
        m += nh * kd * n * n + nh * hd * n * n                  # QK^T + AV
        for k, g in ((1, 1), (3, c)):
            q, r = self.conv(c, c, k, g=g, act=False, side=side)
            p, m = p + q, m + r
        return p, m + 2 * c * n
    def psablock(self, c, side):
        p, m = self.attention(c, side, max(c // 64, 1))
        q, r = self.conv(c, 2 * c, act=True, side=side)         # FFN 升维
        p, m = p + q, m + r
        q, r = self.conv(2 * c, c, act=False, side=side)        # FFN 降维
        p, m = p + q, m + r
        return p, m + 2 * c * side * side
    def c3k2(self, c1, c2, n, c3k, e, attn, side):
        c = int(c2 * e)
        p, m = self.conv(c1, 2 * c, side=side)
        q, r = self.conv((2 + n) * c, c2, side=side)
        p, m = p + q, m + r
        for _ in range(n):
            if attn:
                bp, bm = self.bottleneck(c, side)
                q, r = self.psablock(c, side)
                p, m = p + bp + q, m + bm + r
            elif c3k:
                bp, bm = self.c3k(c, 2, side)
                p, m = p + bp, m + bm
            else:
                bp, bm = self.bottleneck(c, side)
                p, m = p + bp, m + bm
        return p, m
    def sppf(self, c1, c2, k, n, add, side):
        ch = c1 // 2
        p, m = self.conv(c1, ch, act=False, side=side)
        q, r = self.conv(ch * (n + 1), c2, side=side)
        p, m = p + q, m + r
        m += 3 * k * k * ch * side * side                       # 三次 maxpool
        return p, m + (c2 * side * side if add else 0)
    def c2psa(self, c1, c2, n, side):
        c = int(c1 * 0.5)
        p, m = self.conv(c1, 2 * c, side=side)
        q, r = self.conv(2 * c, c1, side=side)
        p, m = p + q, m + r
        for _ in range(n):
            bp, bm = self.psablock(c, side)
            p, m = p + bp, m + bm
        return p, m
    def detect(self, chs, sides):
        c2 = max(16, chs[0] // 4, REG_MAX * 4)
        c3 = max(chs[0], min(NC, 100))
        p = m = 0
        for ch, side in zip(chs, sides):
            bp, bm = self.conv(ch, c2, 3, side=side)
            q, r = self.conv(c2, c2, 3, side=side)
            bp += q + c2 * 4 * REG_MAX + 4 * REG_MAX            # 末层裸 1x1
            bm += r + 4 * REG_MAX * c2 * side * side
            cp, cm = self.conv(ch, ch, 3, g=ch, side=side)      # 分类支路 DW 3x3
            q, r = self.conv(ch, c3, 1, side=side)
            cp, cm = cp + q, cm + r
            q, r = self.conv(c3, c3, 3, g=c3, side=side)
            cp, cm = cp + q, cm + r
            q, r = self.conv(c3, c3, 1, side=side)
            cp, cm = cp + q, cm + r
            cp += c3 * NC + NC
            cm += NC * c3 * side * side
            p, m = p + bp + cp, m + bm + cm
        return p, m

          if l.strip().startswith('- ')]
    net, ch, uses, last, side = Net(), {}, {}, 3, INP
    rows, tp, tm = [], 0, 0
    for idx, (f, n, mod, args) in enumerate(bb + hd):
        n = max(round(n * DEPTH), 1) if n > 1 else n
        froms = f if isinstance(f, list) else [f]
        c1 = last if froms[0] == -1 else ch[froms[0]]
        cat = {'Conv': 'A', 'SPPF': 'D', 'C2PSA': 'D'}.get(mod, mod)
        if mod == 'Conv':
            c2 = net.w(args[0])
            p, m = net.conv(c1, c2, args[1], args[2], side=side)
            side //= args[2]
            tag = 'k%d s%d' % (args[1], args[2])
        elif mod == 'nn.Upsample':
            c2, p, m = c1, 0, 0
            side *= 2
            tag = 'nearest x2'
        elif mod == 'Concat':
            c2 = sum(last if i == -1 else ch[i] for i in froms)
            p = m = 0
            tag = 'cat'
        elif mod == 'SPPF':
            c2 = net.w(args[0])
            p, m = net.sppf(c1, c2, args[1], args[2], args[3], side)
            tag = 'k%d n%d' % (args[1], args[2])
        elif mod == 'C2PSA':
            c2 = net.w(args[0])
            p, m = net.c2psa(c1, c2, n, side)
            tag = 'n=%d' % n
        elif mod == 'C3k2':
            c2 = net.w(args[0])
            rest = args[1:]
            c3k = rest[0] if rest else False
            e = rest[1] if len(rest) > 1 else 0.5
            attn = rest[2] if len(rest) > 2 else False
            p, m = net.c3k2(c1, c2, n, c3k, e, attn, side)
            tag = 'c3k=%s e=%.2f attn=%s' % (c3k, e, attn)

                   if i <= t and max(uses.get(i, {i})) >= t)
```
