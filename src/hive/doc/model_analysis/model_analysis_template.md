# 模型逐层计算拆解：写作模板

用来写"某个 LLM/VLM 每一层到底算了什么、对芯片意味着什么"这类文档。同目录下的 `*-逐层计算拆解.md` 都是实例，其中 Qwen3-0.6B 是按本模板最新口径改过的一篇，可作参照。新模型照这个骨架填，不要重新设计章节。

模板本身不写内容，只规定每节必须回答什么问题、必须放哪张表、数字怎么核。

## 一、动笔顺序

1. 先写**附录 B 的复现脚本**，跑通，让总参数与权重文件对上。数字没锁死之前不要写正文。
2. 再填**第 1 章**（超参、参数量核算），这是全文唯一的数字来源。
3. 然后按第 3 → 6 章自底向上写结构，第 7 → 11 章自顶向下算账，最后写第 12 章和摘要。
4. 摘要最后写，每条都得能在后文找到出处。

## 二、全局约定

### 2.1 数字口径

**MAC 统计包含逐元素与归约，只排除纯视图算子**（`split`、`reshape`、`transpose`、`expand`/`repeat_kv`）。这样每张表都能直接加总，硬件侧也能把归约和激活的周期算进去。若某节改用"只算乘加"的口径，必须在该节首行注明。

**纯视图算子必须单列，不能省略。** 源码里每出现一次 `view`、`transpose`、`expand`、`repeat_kv`、`flatten`，映射表里就要有一行，MAC 写 0，并注明它改的是哪一维（stride 变化还是真实搬运）。省略它们会让表的步序与源码调用序对不上，也会让人误以为这些步骤不存在。`repeat_kv` 之类的 GQA 头复制是 stride 0 的视图，不是拷贝：MAC 与字节都记 0，但要写一句"硬件若真的读两遍，KV 流量翻倍"。

- 1 MAC = 2 FLOP。
- 权重字节按实际部署精度折算：MXFP8 = 8.25 bit = 1.031 B/参数，FP16 = 2 B，FP32 = 4 B。不要用整数 bit 近似。
- 参数量写全数字（`21,555,360`），正文引用写三位有效（`21.56 M`）；同一节内不要混用两套写法。
- 百分比保留一位小数；行和与合计对不上时改行不改合计。

### 2.1.1 只写模型侧的量

模型文档只写参数、MAC、字节、算术强度、KV 与激活容量，以及由此推出的容量需求。带宽、引擎峰值算力、效率区间、毫秒数、token/s 属于硬件假设，一律不写，集中在同目录 `硬件口径.md`。需要给读者一个"这有多快"的概念时，写一句"换算见《硬件口径》"即可。

原因：这些数字随芯片口径变，写进模型文档会被当成模型事实；而且历史文档沿用的 P310（310 GB/s、12.5 TMAC/s）与已批准的 G0（17.064 GB/s、0.512 TMAC/s）相差 18 倍，两套口径必须分开记。

### 2.2 图形符号

层内依赖图统一用 ASCII，列对齐，符号固定：

| 符号 | 含义 |
|---|---|
| `─►` | 有计算的依赖 |
| `┄` | 纯视图，0 MAC |
| `═` | 跨 token 状态 |
| `[G0]…[Gk]` | 一层内的并行组编号 |
| `[A①]…[A⑰]` / `[B①]…` | 各层型的算子编号，按执行顺序 |
| `[M1]…[M6]` / `[D1]…[D8]` | 共用子模块与投机头 |
| `[V①]…[V⑩]` | 视觉塔 |
| `┌ ├ │ └` | 分支与汇合 |

并行组编号要能回答三个问题：哪些算子同时发射、哪个是汇合点、哪条支路活到最后。每张 DAG 后面配一张"并行结构速查"表，一列写组号，一列写内容，一列写性质（单点 / 并行 / 汇合 / 严格串行）。

### 2.3 表格纪律

- 每张表必须有合计行；合计 = 各行之和，误差为 0。
- 一节的逐算子表与另一节的成本表若描述同一对象，两表加总必须相等（视觉塔、MLP、输出头最容易在这里对不上）。
- 形状写成 `[out, in]`（权重）或 `[1, N]`（激活），与框架的 `nn.Linear` 方向一致，不要混。
- 同一量在不同章节出现时，用同一个数：`767.05 M` 不要在某处写成 `767 M`、另一处写成 `768 M`。

### 2.3.1 GEMM 口径与维数约定

全文矩阵乘一律写 `C[M,N] = A[M,K] × B[K,N]`。A 是激活，B 是权重的逻辑形状。权重在 header 里按 `nn.Linear` 存成 `[N,K]`，所以 **B = Wᵀ**，不是文件里那个形状。开篇（3.2.1）用一张表把全模型每个 GEMM 的 A、B、C、MAC 列全，后续章节只引用，不重新定义。

- 张量清单（第 1、4 章）写存储形状 `[N,K]`；计算流与映射表（3.3、6.x、9.x）写 `[M,K] × [K,N]` 并标注 `B = Wᵀ`。
- Q·Kᵀ 与 A·V 是唯一 M ≠ token 数的例外：它们的 M 是头数。要在 3.2.1 明写"这两行是例外"，否则读者按 M=1 验算会对不上。
- A·V 的 B 是 V cache，不是权重，`[S,D]` 本身就是 `[K,N]`，不做转置。

**维数写法只允许两套，且同一张表内不能混**：3.3.1 与 3.8 的 DAG 省略恒为 1 的 batch 维；3.3.2、第 6 章与 9.1 保留 `[1,…]`，涉及多头时写全 `[1,H,T,D]`。`view` 的输出与 `transpose` 的输入必须同为四维，否则 `transpose(1,2)` 在三维上得到的结果与文中写的形状对不上。

### 2.4 算子的五个必填项

每个被源码调用的函数都要能映射到一个算子，并同时给出：

| # | 项 | 写在哪 |
|---:|---|---|
| 1 | 在计算流中的位置 | 3.3.1 DAG 的组号、9.1 的步号 |
| 2 | 形状（`A[M,K]×B[K,N]→C[M,N]` 或 `in→out`） | 3.3.2 形状列、第 6 章算子的"形状"行 |
| 3 | 计算公式 | 3.3.2 数值变换列、第 5 章对应算子 |
| 4 | MAC | 3.3.2 MAC 列、第 6 章算子的"MAC"行 |
| 5 | 硬件归属（引擎 / VPU / DMA / CPU） | 9.1 归属列、10.1、11.1 |

五项可以分处不同小节，但必须能被指到；第 6 章引言要写清这个分工，避免读者按单张卡去找公式。归属不允许写 `—`：没有计算单元的视图算子写"地址生成器（0 周期近似）"，查表写"按 index 取行的是 DMA；整表驻留时由 VPU 索引"。

### 2.5 文风

- 不用 emoji 或警告/对勾图标标记优先级；优先级用"按危害排序"的文字。
- 不写章节要点式的块引用（每章开头一段导语，直接进正文）。
- 不写版本变更、勘误表、修订记录。改掉就行。
- 直引号 `"`，不用弯引号。
- 加粗只用于两类：表内需要跳出来的数字、结论章的一行判定。整段加粗等于没加粗。
- 每条判断后面跟一个数字。"占用偏高"要写成"占 33.8% 的权重流量"。
- 至少每章与上一个同类模型对照一次（本仓库的用法是 0.8B ↔ 2B），对照要点是"哪一项不随模型缩放"。

### 2.6 每篇必算的 12 个量

| # | 量 | 算法 | 出现在 |
|---:|---|---|---|
| 1 | 单层参数 | 见附录 B，逐张量加总 | 1.3 / 3.1 / 4.x |
| 2 | 单层 token MAC | 逐算子表加总 | 3.3 / 6.1 |
| 3 | 每 token 权重字节 | 参数 × B/param | 8.2 |
| 4 | 算术强度 | token MAC ÷ 权重字节 | 8.2 / 12.1 |
| 5 | 每 token 总流量 | 权重字节 + KV 读 | 8.2 |
| 6 | KV 每 token | 层 × KV 头 × head_dim × 2(K,V) × 2 B | 6.2.2 / 8.3 |
| 7 | 跨 token 状态 | 线性层 × 头 × dk × dv × 4 B（FP32） | 8.3 / 12.2 |
| 8 | 缓存三档 | 状态 + KV，S = 4K / 32K / 256K | 8.3 |
| 9 | prefill 每 token MAC | token MAC − lm_head | 9.2 |
| 10 | 视觉塔 GMAC | 逐算子表，注意 block × head 两层循环 | 7.2 / 9.3 |
| 11 | 算术强度分档 | S=1 与最长上下文各一档 | 8.2 / 12.1 |
| 12 | 总参数校验 | 附录脚本 vs header | 1.1 / 附录 B |

时间、吞吐、引擎吞吐下限这几个量不在这张表里：它们属于 `硬件口径.md`。

## 三、章节骨架

下面是可以直接复制到新文件的骨架。写什么一栏是该节必须回答的问题，不是建议。

```markdown
# <厂商> <模型名> 逐层计算拆解

<日期> ｜ 依据 `config.json`、权重清单（<N> 个张量，<bytes> B）、`<modeling 文件>` 与 <算子库> 源码核对

## 摘要
```

**摘要**：6～8 条，每条一行，必须带一个数量级的数字，必须是"对硬件有影响的"结论而不是模型简介。至少覆盖：每 token 权重字节、算术强度、跨 token 状态、最大单算子、显存/KV 的拐点，以及这个模型与同系列上一个模型的**结构性差异**（不是等比缩小）。

```markdown
## 目录
```

**目录**：五部分 + 附录，不加页码，不加锚点。

### 第一部分　事实与全景

```markdown
# 第 1 章　事实基线

## 1.1 数据来源与核对方法
## 1.2 关键超参
## 1.3 参数量核算
```

- **1.1**：两条独立核对——header 元素数之和 vs 权重文件字节 ÷ 每参字节；逐层求和 vs header 分组统计。写出差额及其占比，并说明差额来自对齐而非漏算。列出本文引用了哪些源码（modeling、kernel）。
- **1.2**：三张表——文本主干、视觉塔、特殊 token。每行三列：超参名 | 值 | 与对照模型的差异。"差异"列是这一节的核心，不要省略。
- **1.3**：总账表（子模型 | 份数 | 单个参数 | 小计 | 占比），再给每层张量的明细表（# | 张量名 | 形状 | dtype | 元素数 | 归属）。参数量异常的层（MTP、视觉 merger）单独列式推导。

```markdown
# 第 2 章　模型全景

## 2.1 三个子模型
## 2.2 文本主干的层型配比
## 2.3 计算形态的四个类别
```

- **2.1**：ASCII 树画出子模型关系，标出各子模型的参数与是否参与 decode / prefill / 视觉前向。
- **2.2**：层型配比表（层型 | 层数 | 单层参数 | 合计 | 结构特征），再加一句"为什么是这个比例"。
- **2.3**：把全部算子归到四类——GEMM/GEMV、归约、逐元素、串行递推，外加查表与搬运。这一节是第 10 章分类矩阵的前身，两处结论要一致。

### 第二部分　结构

```markdown
# 第 3 章　层清单

## 3.1 <L> 层总表
## 3.2 层的通用骨架
## 3.3 层型 A：<名称>（N 层）
### 3.3.1 计算流（decode 单 token，依赖 DAG）
### 3.3.2 逐算子映射表
### 3.3.3 关键路径与并行机会
## 3.4 层型 B：<名称>（N 层）
## 3.5 子模块 C：<名称>
## 3.6 层型 D：<投机头>
## 3.7 层间差异速查
## 3.8 单层内部张量流（以 layer 0 为例）
```

- **3.1**：总表用双列布局（层 | 类型 | 参数 ‖ 层 | 类型 | 参数），省一半纵向空间。表后给一行加总式，落到子模型总数。
- **3.2**：通用骨架的 DAG + **读图约定**（符号表）+ **三种形状变换**（投影改宽度、视图改分组、残差保持宽度）。读图约定只写一次，后续 DAG 不再解释符号。
- **3.3/3.4**：每层型三小节固定——DAG、映射表、关键路径。映射表列固定为 `组 | 算子 | A × B → C（非矩阵乘写 in → out） | 数值变换 | MAC/token | 依赖`，矩阵乘行在形状后标 `B = Wᵀ`；"数值变换"列写公式本身，不写"做投影"。源码里出现的每个调用都要有一行，包括 `view`、`transpose`、`repeat_kv` 这类 0 MAC 的纯视图；行序尽量与源码调用序一致，"依赖"列指回上游算子而不是只写组号。
- **3.3.1 的组号是全文唯一的并行组定义**：3.3.2 的"组"列、3.8 的 `[Gk]` 标号都必须与它一致。同一个步骤在三处必须同组，不能一处 G1、一处 G2。
- **3.5/3.6**：共用子模块与投机头，结构同上，篇幅减半。
- **3.7**：问答式速查表（问题 | 回答），专收"读者会误以为不同、其实相同"的点，以及"与对照模型的差异"。
- **3.8**：以 layer 0 为例的逐行张量流，每条标形状、MAC、归属；纯视图与跨 token 状态各用固定符号，`repeat_kv` 这类 stride-0 展开也要画一行。末尾给"并行结构速查"表，并归纳 2～3 条对硬件/测试最直接的结论（关键路径、切分点、只有哪几处跨 token）。

```markdown
# 第 4 章　四种层型的子模块清单（对照用）

## 4.1 层型 A 的 <n> 个张量（<份数> 份，完全一致）
## 4.2 层型 B 的 <n> 个张量（<份数> 份，完全一致）
## 4.3 运行时状态（不在权重里，但决定 SRAM）
```

- **4.1/4.2**：表头固定 `# | 张量 | 形状 | dtype | 元素数 | 归属`，表尾写合计并与 1.3 对账。这一章是给写测试的人查名字用的，不加解释段。
- **4.3**：状态表（状态 | 公式 | 字节 | 生命周期 | 是否量化），并明确指出哪些状态与模型宽度无关。

### 第三部分　计算

```markdown
# 第 5 章　通用算子库

## 5.1 RMSNorm
## 5.2 <门控归一>
## 5.3 <激活>
## 5.4 <卷积>
## 5.5 <位置编码>
```

- **5.x**：每个算子固定五段——形状、公式、MAC、精度要求、实现坑。公式用 `inline code` 写，不要用 LaTeX 块。
- 只收"跨层型复用"或"容易算错"的算子；一次性的算子留在第 6 章。

```markdown
# 第 6 章　四种层型的逐算子拆解

## 6.1 层型 A
### A① <算子>
…
### A<k> 层型 A 单 token 合计
### A<k+1> 硬件归属：哪些能上矩阵引擎
### A<k+2> 精度预算表
### A<k+3> 实现/测试坑（按优先级）
## 6.2 层型 B
### 6.2.1 层型 B 单 token 合计
### 6.2.2 KV cache 三档
### 6.2.3 本层权重字节
### 6.2.4 引擎准入：哪些算子不能上
### 6.2.5 十个必须记住的坑（按危害排序）
### 6.2.6 与其它章节的接口
## 6.3 子模块 C
## 6.4 层型 D
```

- 每个算子小节用两列表（项 | 内容），项名固定为：形状、MAC、归属、精度、坑。缺项就写"无"，不要删行。
- **算子编号只定义一次，全文引用同一套。** 层型用 `A①…`、共用子模块用 `M1…`、视觉塔用 `V①…`。一个源码级算子对应一个编号：SwiGLU 门控（silu 与逐元素乘）算一个算子，不要拆成 `M3 silu` 和 `M4 ⊙`；gate/up 是同一编号下的两路并行，不要写成 `M2a`/`M2b`。3.4 的框图、6.x 的小节标题、合计表的行名必须用同一套编号，改号时全文一起改。第 6 章引言要写明本层型的编号范围（如 `A①–A⑯ / M1–M6`），新增算子时同步更新这一句。
- 层型末尾四张表不能少：**合计**（项 | MAC | 占比，行和 = 单层 token MAC）、**引擎准入**（算子 | 能否上引擎 | 原因）、**精度预算**（算子 | 权重 | 激活 | 累加 | 输出）、**坑**（编号 + 一句话危害 + 触发现象）。
- 合计表之后必须给一句"能上引擎的部分贡献了 x% 权重流量和 y% MAC"，把结构结论落到数字。
- `6.2.6` 是接口章：列出本节哪些数字被第 8、9、10 章直接引用。写文档时这一节最省事，读文档时最有用。

```markdown
# 第 7 章　视觉塔与输出头

## 7.1 视觉塔结构
## 7.2 视觉塔逐算子拆解（V①–V⑩）
## 7.3 视觉塔的成本
## 7.4 视觉塔的矩阵引擎映射
## 7.5 视觉塔的坑（速查）
## 7.6 输出头与采样
```

- **7.2**：表头 `编号 | 算子 | 形状 | MAC | 归属`，每个算例写清 token 数 N 与批 M。"逐项核对"列表给每个数字一条乘法式，**每个因子都要写出来**——这里最容易漏掉 block 或 head 的那一层循环。
- **7.3**：成本表分类到 GEMM / attention / patch / merger / 归约，给出总 GMAC、GFLOP、等价文本 token 数、权重字节、算术强度。再给一个"分辨率翻倍/四倍"的算例，说明 N² 项的增速。
- **7.4**：算术强度与负载性质，给出与文本主干的倍数。结论要回答"这块量化优先级高不高"、以及它和文本是不是同一类负载。
- **7.6**：输出头形状、MAC、权重、logits 缓冲、是否与 embedding 共享；采样单列一张表（方法 | 比较次数 | 占 lm_head MAC）。词表大时采样开销仍远小于输出头本身，这一条要算出来给人看。

### 第四部分　核算与映射

```markdown
# 第 8 章　三本账：算力 / 流量 / 容量

## 8.1 算力账（decode，S 较短）
## 8.2 流量账（decode，<精度> = <bit> bit = <B> B/参数）
## 8.3 容量账（KV 与常驻）
```

- **8.1**：组件 | 数量 | 单个 MAC | 小计 | 占比；结尾补三档 S 的总量。S 相关项（QKᵀ、AV）单独一行，标"随 S 涨"，不要摊进固定项。

## 四、常见错误

写完对照一遍，这几条都踩过：

1. **两层循环只乘一层**。视觉塔的 MAC 是 `block 数 × head 数 × N² × head_dim`，漏掉 head 就差 12 倍，而且表仍然"看起来合理"。
2. **merger 的 M 用 patch 数**。2×2 合并之后 token 数除以 4，按 patch 数算会高估 4 倍。
3. **逐算子表与成本表不对账**。两张表描述同一对象时，各自加总必须相等；不等说明有一张用了别的 token 数。
4. **按模型比例估 SRAM**。状态大小由"层数 × 头数 × 头维"决定，hidden 砍半它不动。模型减半不等于 SRAM 减半。
5. **以为输出头按比例缩小**。lm_head = 词表 × hidden，只随 hidden 线性缩小；层内参数随 hidden 平方缩小。模型越小，输出头占比越高。
6. **prefill 把 lm_head 算进每个 token**。实际只有最后一个位置算 logits，否则 prefill 算力高估 30% 以上。
7. **S 相关项混进固定项**。QKᵀ 和 AV 随上下文线性增长，必须单列，否则 decode 的账在长上下文下全错。
8. **精度按整数 bit 估**。MXFP8 是 8.25 bit（每 32 个值一个 E8M0），差 3% 会让每 token 流量与容量预算系统性偏低。
9. **忘了算采样**。词表 20 万以上时要把采样比较次数算出来并除以 lm_head MAC；凭感觉写"采样开销很大"或"可以忽略"都不算数。
10. **把硬件数字写进模型文档**。310 GB/s、12.5 TMAC/s、毫秒、token/s 一律不进正文，只写"换算见《硬件口径》"。换芯片后这些结论要能整体重算，不能被钉死在模型描述里。
11. **附录脚本没实跑**。模板里每个 `print` 的期望值都要来自真实输出，不能手算后填。
12. **同一算子在两处用两个编号**。3.4 的框图写一套 M 号、第 6 章的小节写另一套，读者无法交叉引用，合计表的行名也会指错。编号只定义一次。
13. **一个算子拆成两个号**。SwiGLU 拆成“silu”和“门控乘”两个编号，会让第 6 章引言的范围声明与合计表的行名同时过期。
14. **三维与四维混写**。`view` 输出写 `[1,H,D]`、`transpose(1,2)` 输入写 `[1,1,H,D]`，同一张表里两套口径，按 transpose 的语义对不上。
15. **量化只在一处出现、归属两处打架**。10.1 把 amax 记成 VPU 归约、9.1 把量化记成 DMA 0 MAC。二者只能选一个，并在 11.1 说明量化是否融在上一级写出。
16. **残差 dtype 与字节数对不上**。FP32 的 `[1,N]` 与 FP16 的同一张量相差一倍；写 "残差 2 KB" 却同时在精度列写 FP32，就是这种错。
17. **归属列写 `—`**。读起来像"没想清楚"。视图算子写地址生成器，查表写 DMA 或 VPU 索引，逐元素写 VPU。
