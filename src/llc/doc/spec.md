### 文档版本规则

文档采用 `v主版本.次版本.修订号`：

- 主版本：外部可见规格契约发生不兼容变更；

## 1. 文档说明

### 1.1 目的

本文定义 LLC 的缓存行为、接口协议、寄存器映射、软件编程模型和配置约束，供 RTL、软件与验证三方对齐。带 ID 的 Feature List 见第 3 章；文档版本规则与修订记录见文首“版本控制”章节。

### 1.2 范围

本文覆盖：

- 256KB、8 路、64B 行的组相联组织，以及 Tree-PLRU 替换和 way 分区；
- 写回（write-back）+ 写分配（write-allocate）策略，MSHR、写回缓冲、写合并缓冲；
- AXI4 上游 slave 端口、AXI4 下游 master 端口和 AxiLite4 控制端口；
- clean-flush / invalidate 维护操作、控制/状态寄存器与性能计数器；
- 当前 RTL 的已知缺陷、限制与支持边界（第 14 章）。

本文不定义：缓存一致性协议与 inclusion 策略、多 master 访问 LLC 时的外部仲裁、上游私有可能更小层级的 cache 行为、系统物理地址映射。

### 1.3 规范性用语

- “必须”表示违反该要求会导致数据破坏、事务挂起或行为未定义；
- “应”表示推荐做法，违反时功能仍可工作但可能损失性能或可观测性；
- “默认配置”指第 8.1 节列出的 `LlcConfig()` 参数值。

### 1.4 定义、注册与验证状态

本文对每一项能力区分三种状态，Feature List 的“状态”列使用同样的措辞：

| 状态 | 含义 |
|---|---|
| 已定义 | 行为在本文中有明确契约 |
| 已注册 | 控制寄存器已分配地址并可经 AxiLite4 端口读写 |
| 已验证 | 行为有纳入测试集（`LlcTest` 或 `LlcSimSpec`）的检查 |

当前状态必须按下列事实理解：

- **`LlcTest` 只验证能生成 RTL**：共 13 例，均为对 `ChiselStage.emitSystemVerilog` 输出做模块名/信号名子串或正则断言，其中 1 例检查数据阵列 SRAM 的写口掩码、1 例检查数据阵列 8 个存储体的读口各自按所读的路门控、1 例检查 PLRU 状态为带写掩码的 SRAM 且读在 S0 发出，另有 4 路与 16 路配置各能生成 RTL；均不驱动任何事务。
- **功能仿真（`LlcSimSpec`）共 47 例，全部通过**，覆盖“32 字节对齐单拍读的未命中取回、再次读命中、invalidate 后重新取回（含下游首拍紧随 AR 到达）”“行已驻留时的整行写命中（含 1 字节 strobe）”“行已驻留时写到 line 后半的单拍写”和“整行写未命中、单拍写未命中后读回、同 line 的整行写未命中排在读未命中之后”“同组连续未命中时 victim 避让正在取回的路、同分区全部路都在取回时等待”“同组连续 4 笔整行写未命中各返回一次 B”“单拍写返回 B 并在 flush 后到达下游、两笔单拍写各返回一次 B、B 之后同一 line 的两笔写不合并、W 拍后立即读不挂起、读的 snoop 落在自动冲刷进行中（W 拍之后空闲 0–4 拍再读）”“AW 已握手而 W 拍晚于 flush（或 invalidate）触发到达的写在 flush 后到达下游、写之后立即 flush”“读未命中的取回进行期间整行重写同组各行，flush 后下游均为后写的数据”“脏淘汰的写回缓冲只有 2 项时的未命中取回”“读未命中的早响应与写命中相遇时读数据正确且该写返回一次 B”“超出一个 line 的写、从 line 后半起的 2 拍读、3 拍读、WRAP burst、窄传输、非对齐地址均返回 `SLVERR`，非法写不改动 cache 与下游数据，AW 与首拍 W 同拍握手的非法写返回 `SLVERR`，之后合法读写照常”“复位后不执行 invalidate 直接读写，读未命中取回，flush 只写回实际写入的行”“ID 为 3、1、4、2 的 4 笔整行写各返回一次 ID 正确的 B、上游 `b_ready` 压低期间 6 笔单拍写的 B 全部返回、两个 MSHR 项同时等待写回完成时先完成写回的那项先推进”“纯读流量下只有读命中、读未命中与取回计数，清零后全部为 0；读写混合、脏行与干净行淘汰、写合并、等在途取回的写各计一次，读命中加读未命中等于发出的读次数、写命中加写未命中等于发出的 W 拍数、取回次数等于下游 AR 次数”“脏行被淘汰后在其写回等待下游 B 期间对它写未命中，取回等写回完成后再发，读回与 flush 后下游均为后写的数据”“写合并缓冲与 B FIFO 均为 8 项时上游 `b_ready` 压低期间 6 笔写全部被接收、各返回一次 B，均为 2 项时写合并缓冲被满的 B FIFO 压住、6 笔写的 B 全部返回”“PLRU 查询在下一拍给出 victim 且读发出拍与消费拍上的两次更新都在结果中、读命中与取回完成相遇时数据正确、4 路单分区下替换最近最少使用的行、16 路配置的读写与 flush”“空 cache 的 flush 约 2 拍一组、只回写一组中的脏行且按路序、干净行保留；invalidate 同时清掉脏行之间的干净行”，下游读延迟为 2 拍，其中 2 例为 1 拍、5 例在 40 拍写回延迟或 20 拍读延迟下运行、3 例在相邻读之间插入空闲拍。遍历期间到达的请求等未覆盖，Feature List 的状态不因这 47 例改变。
- **写路径各流量数据正确**：单拍写、整行写，命中与未命中，取回进行期间写到刚被淘汰的行，flush 后下游均为后写的数据，且各返回一次 B。
- 第 14.1 节缺陷的确认方式分“仿真”（用 `LlcSimSpec` 的用例或 v1.0.0 修订时的临时探针仿真复现）与“代码”（未复现，依据源码逻辑判断）两种，表中逐条标注。已修复的缺陷保留编号，列于该节末尾。

## 2. 模块概述

### 2.1 定位

LLC 是单 master 口的末级缓存：面向单一 AXI4 slave 端口（`cpu`）缓存来自下游 AXI4 master 端口（`mem`）的数据，采用写回 + 写分配，不参与任何一致性协议（non-inclusive、无 coherence）。多个发起方共用 LLC 时由外部仲裁后接入 `cpu` 端口。

### 2.2 默认几何

| 项目 | 值 |
|---|---|
| 容量 | 256KB（512 组 × 8 路 × 64B） |
| 行大小 | 64B，256-bit 数据总线下为 2 拍 |
| 替换 | Tree-PLRU，每组 7 位 |
| 分区 | 2 个 way 分区，每分区 4 路（32KB） |
| MSHR | 4 项 |
| 写回缓冲 | 4 项 |
| 写合并缓冲 | 4 项 |
| 性能计数器 | 16 × 64 位（10 个有效，6 个保留） |

### 2.3 快速上手（新手流程）

环境：JDK、sbt，以及 CIRCT（随 Chisel 依赖自动下载）；仅生成 RTL 不需要其他 EDA 工具。功能仿真另需 Verilator。

在仓库根目录执行：

```bash
sbt "runMain LlcElaborate"   # 生成 RTL 并打包
sbt "testOnly LlcTest"        # 运行 elaboration 测试
sbt "testOnly LlcSimSpec"     # 运行功能仿真
```

**输入**：无运行期输入文件；全部参数来自 `LlcConfig()` 默认值（第 8.1 节）。

**输出与结果判读**：

- 第一条命令在 `src/llc/verilog/` 生成 `Llc.sv`、`LlcPipeline.sv`、`LlcMshr.sv`、`LlcWbBuffer.sv`、`LlcWriteMergeBuffer.sv`、`LlcTagArray.sv`、`LlcDataArray.sv`、`LlcPlru.sv`、`LlcWayPartition.sv`、`LlcPerfCounters.sv`、三个 SRAM 模型 `dataMems_512x512.sv`、`tagMem_512x144.sv` 与 `plruState_512x7.sv`、`filelist.f`、`verification/` 断言与覆盖层，以及打包全部文件的 `Llc_rtl.zip`。控制台出现 `[LlcElaborate] RTL generation complete in src/llc/verilog` 和 `[LlcElaborate] Packaged N files into ...` 即成功。
- 第二条命令成功时显示 `Tests: succeeded 13, failed 0`。
- 第三条命令成功时显示 `Tests: succeeded 47, failed 0`；运行前需先编译 Verilator 模型。驱动封装在 `LlcAxiBench.scala`，复位后直接驱动，不执行 invalidate。用例超时时报 `TIMEOUT: ...` 并附带末尾若干拍的下游访问记录。
- elaboration 期间打印 6 条 `[W004] Dynamic index with width 2 is too wide for Vec of size 2` 警告，属已知的非阻塞警告，可忽略。

**必须注意**：`LlcElaborate` 在生成前会清空 `src/llc/verilog/` 目录内的全部内容，不要把手工文件放在该目录。

**排错**：

| 现象 | 处理 |
|---|---|
| `require failed: ... ways must be ...` 一类错误 | 修改配置时违反第 8.2 节约束，最常见是 `ways` 不是 2 的幂或不整除容量（8.2 节） |
| 找不到 `LlcElaborate` | 确认在仓库根目录执行，且 `build.sbt` 的 LLC 源码目录未改动 |
| 测试通过但行为不对 | `LlcTest` 只验证能生成 RTL；`LlcSimSpec` 未覆盖的行为见第 1.4 节与第 14.1 节 |

## 3. 功能清单（Feature List）

### 3.1 Feature ID 规则

- `LLC-Fxxx`：功能项；
- `LLC-Pxxx`：性能项（描述带宽、接受率与并行度，不描述实现机制）；
- `LLC-Dxxx`：Debug/观测项。

ID 一经分配保持稳定，不重排、不复用；功能下线时在清单中标注“下线”并保留 ID。

### 3.2 功能清单

状态列中，“存在缺陷”指行为与第 5 章契约不符，详见第 14.1 节。

| Feature ID | 功能 | 状态 | 能力与主要约束 | 规格章节 |

### 3.5 支持边界

当前 RTL 能正确工作的流量范围非常有限，集成前必须确认：

- **纯读流量**：`len=0`、地址 32 字节对齐的单拍读，未命中取回后再次读取命中，数据与下游一致（仿真确认）。
- **行已驻留时的整行写命中**：`len=1`、地址行对齐的写，按 strobe 写入并返回一次 B，flush 后下游数据一致（仿真确认）。
- **单拍写**：32 字节对齐地址的单拍写（命中与未命中）落在地址对应的拍，B 返回一次，读回与 flush 后下游数据一致（仿真确认）。
- **整行写未命中**：`len=1`、地址行对齐，两拍数据完整，B 返回一次（仿真确认）。
- **非法 burst**：超出一个 line、非 `INCR`、非全位宽、非对齐的读写均返回 `SLVERR`，不改动 cache 与下游数据（仿真确认）。
- **多笔写的 B**：连续多笔写每笔各返回一次 ID 正确的 B；上游 `b_ready` 为低时后续写的 B 不丢失，`b_ready` 恢复后依次返回（仿真确认）。
- **淘汰后立即重访**：脏行被淘汰后，在它的写回被下游应答之前对它的读或写不会发出取回 AR，读回与写回后的数据一致（仿真确认）。
- **其余限制**：B 返回之前，读不保证看到该笔写；B 的顺序不保证与 AW 一致。

第 14.2 节列出的能力不属于本规格支持范围。

### 4.1 组织

## 5. 功能行为规范

本章先给出契约行为，再给出“当前实现偏差”。偏差均对应第 14.1 节缺陷编号。

### 5.1 读事务

1. 顶层读状态机依次经过 idle → snoop 检查 → 等待流水线接受 → 回数据。
2. snoop 检查：若写合并缓冲中有同一 line 的驻留写，必须先将其冲刷进流水线并等待冲刷完成，再发出读请求。
3. 读请求经流水线查找：命中时读出目标 line 数据；未命中时分配 MSHR 并取回整行。
4. R 通道按 `len+1` 拍返回数据，`last` 在末拍置位；合法事务的 `resp` 为 `OKAY`，非法 burst 不查 cache，直接返回 `len+1` 拍零数据且 `resp=SLVERR`（第 10 章）。

### 5.2 写事务

1. 顶层接受 AW；合法 burst 收集 `len+1` 拍 W 数据后逐拍送入写合并缓冲，非法 burst 收完全部 W 拍后丢弃。
2. 写合并缓冲在一笔 burst 内按 line 地址合并写拍；burst 的末拍被接收后，或缓冲满时，逐拍送入流水线。
3. 写命中：按 strobe 更新数据阵列并置脏；写未命中：分配 MSHR，取回整行后按 strobe 合并写入并置脏。
4. 每笔写 burst 在其全部写拍处理完成后返回一次 B，`id` 为该笔写的 ID；合法事务的 `resp` 为 `OKAY`，非法 burst 的 B 在更早的写全部返回 B 之后返回，`resp=SLVERR`（第 10 章）。
5. B 按写 burst 逐笔跟踪：上游 `b_ready` 为低时，后一笔写的写拍照常被流水线应答，各笔的 B 等待各自的写拍全部应答后依次返回，不丢失。
6. B 的顺序不保证与 AW 一致：读 snoop 冲刷的写可以先于更早的写返回 B。

### 5.3 命中与缺失判定

- 流水线 3 级：S0 接受请求并发出 tag 与 PLRU 状态的读；S1 比较 tag、得到 PLRU victim 并发出 data 读；S2 处理命中或缺失。
- 三个阵列都是同步读 SRAM，读出数据只在读后一拍有效。请求只在不停住的拍进入 S1，下一拍要么进入 S2、要么被取回完成重放，S1 不停留，因此 tag 与 PLRU 读一次即可；S2 会停住（早响应占用了响应槽、读命中等到取回完成），停住期间每拍重发本级 way 的 data 读。
- 命中判定为 `valid && tag` 全 8 路比较，不受分区限制。
- 分配 MSHR 项的同一拍把 victim 路的 tag 置无效，取回完成后才写入新 tag；正在取回的路不参与命中比较，读到分配前旧 tag 的请求按未命中处理。
- 流水线每 2 拍接受 1 个请求；S2 有未完成缺失且 MSHR 满或存在同一 line 的未完成项时停住。
- 同一 line 的写后读依赖由顶层 snoop 冲刷保证，流水线自身不做请求合并。

### 5.4 写回与取回

- 未命中分配 MSHR 项并把 victim 路的 tag 置无效：victim 路有效且脏时，先把 victim 数据连同该项的项号送入写回缓冲，写回请求保持到缓冲可接收，该笔写回的 B 返回后该项才发 AR；否则直接发 AR。多项同时等待写回完成时，各自只由自己的写回推进。
- AR 为 `INCR`、`len=beatsPerLine-1`、`size=log2(bytePerBeat)`，地址行对齐；取回各拍写入 MSHR 项。
- 发 AR 之前检查该 line 的写回是否仍在写回缓冲中、或已交给下游写状态机而 B 尚未返回；命中时 AR 等待，B 返回后的下一拍才发。做转发而非等待不在当前范围内。
- MSHR 项进入发送态后，取回请求保持在该项上直到 AR 被接受，期间更低编号的项进入发送态不改变选择；顶层锁存的地址因此总与被推进的项一致。
- 取回完成后一次性写入数据阵列与 tag（置 valid，写未命中置脏），并产生响应。
- 同时最多 4 项缺失等待；写回与取回各经单一通道串行发出。

### 5.5 关键字优先早响应

- 读未命中时，目标拍一到达即产生响应，不必等整行取回；其余拍随后补齐。
- 不使用 WRAP burst，因此目标拍之后到达的数据不保证早于整行取回完成。
- 早响应只在响应槽可用的拍发出；响应槽被占用时不发，由取回完成时的响应代替。
- 早响应与同一拍 S2 的命中相遇时，早响应先占用响应槽，流水线停一拍，命中随后响应，两者都返回。
- 当前实现偏差：响应中目标拍之外的拍填 0，取回完成后不补发（K21，仿真确认）。

### 5.6 写合并与 RAW 冲刷

- 写合并缓冲按 line 地址匹配：命中则按 strobe 合并到对应拍，否则分配新项。已接收末拍、等待冲刷的项不再参与合并，合并不跨 burst。
- 冲刷进流水线的顺序：读 snoop 请求优先，其次整行自动冲刷，最后缓冲满时淘汰最早项。
- snoop 请求到来时匹配的项已被自动冲刷带走，则直接给出 `flushDone`：该笔冲刷的写拍已先于读进入流水线。
- 每笔冲刷先向顶层发出该笔写的 B 响应描述（ID、待返回的 B 数、写拍数），顶层接收后才把第一拍送入流水线；顶层的 B FIFO 满时该笔冲刷原地等待，因此 FIFO 不会溢出。

### 5.7 替换与分区

- 分区号取请求 ID 的低 `log2(wayPartitions)` 位；路到分区的映射固定为 `way / waysPerPartition`。
- victim 在分区内部选择：优先无效路，其次属于本分区的 PLRU victim，最后候选路中的首路；正在取回（已分配 MSHR 项、取回尚未完成）的路不作候选，分区内全部路都在取回时请求停住等待。PLRU 状态按全部路维护，不分区间。
- Tree-PLRU：每组一棵 `ways - 1` 位的二叉树（节点 0 为根，节点 n 的子节点为 2n+1、2n+2，叶节点按序对应各路），节点位为 0 表示下次向左，victim 是从根按节点位走到叶的那一路。访问某一路时把该路径上的各节点置为背离该路，其余节点不变。状态在同步读 SRAM 中：查询的读在 S0 发出、victim 在 S1 可用；更新只写被访问路径上的节点，不读旧状态；读发出拍与消费拍上的两次更新由旁路补在读出数据上。
- `wayPartitions = 1` 时分区逻辑退化为全 cache 范围选择，victim 完全由 PLRU 决定。
- 当前实现偏差：PLRU victim 不属于本分区时退化为固定选分区内首路，替换行为退化；`WAY_PARTITION_CFG` 寄存器不改变映射（K10）。
- 取回期间访问刚被淘汰的行：该行的 tag 已在分配时置无效，读写都按未命中处理，在分区内另选一路重新取回，数据不丢失；分区内全部路都在取回时请求停住等待。

### 5.8 flush 与 invalidate

- `flush`（clean-flush）：遍历全部 512 组 × 8 路，脏行回写后清脏位并保留在 cache；`invalidate`：脏行回写后清 valid，干净行直接清 valid。
- 遍历方式：每组 2 拍读出全部路的 tag 与状态，之后只在需要动作的路之间跳转——脏行（两种模式）花 5 拍，干净且有效的行只在 invalidate 下花 2 拍；同一组内按路号升序处理，写回因此按组、路的顺序到达下游。
- 触发：`LLC_CTRL` 的 flush 或 invalidate 位出现上升沿且遍历状态机空闲。忙期间新的触发被静默忽略。
- 遍历开始前等待流水线、MSHR、写合并缓冲排空，且顶层没有已接受 AW 而未发完全部 W 拍的写；等待期间触发之前已接受的请求继续处理，新写进 cache 的行对本次遍历可见。结束后等待写回缓冲排空且最后一笔写回的 B 已返回，再置 `flushDone`。
- 从触发到 `flushDone`，`ar_ready` 与 `aw_ready` 为低；触发之前已接受的 W 拍照常接收。
- 软件流程：写 1 启动 → 轮询 `STATUS.flushDone` → 向 `LLC_CTRL` 写 0 清除 sticky 位，之后才能再次触发。
- 当前实现偏差：遍历期间（仿真观测空 cache 1032 拍）所有读写流量阻塞（K10）。

| AR | `valid`/`ready`，`addr`，`id`，`len`，`size`，`burst`，`lock`，`cache`，`region`，`qos`，`prot` | 32 / 4 / 8 / 3 / 2 / 1 / 4 / 4 / 4 / 3 | 入 | 仅在无读在途时 `ready` |
| R | `valid`/`ready`，`data`，`id`，`resp`，`last` | 256 / 4 / 2 / 1 | 出 | `id` 回显 AR 的 `id`，`resp` 恒 `OKAY` |
| AW | `valid`/`ready`，`addr`，`id`，`len`，`size`，`burst`，`lock`，`cache`，`region`，`qos`，`prot` | 同 AR | 入 | 仅在无写在途时 `ready` |
| W | `valid`/`ready`，`data`，`strb`，`last` | 256 / 32 / 1 | 入 | 接受 2 拍后 `ready` 拉低 |
| B | `valid`/`ready`，`id`，`resp` | 4 / 2 | 出 | `resp` 恒 `OKAY` |

`burst`、`size`、`cache`、`prot`、`region`、`lock`、`qos` 均被忽略，不参与任何判定。

### 6.2 AXI4 master 端口（mem）

| 通道 | 方向 | 说明 |
|---|---|---|
| AR | 出 | 行对齐地址，`INCR`，`len=1`，`size=5`，`id` 为对应读请求的 `id` |
| R | 入 | `resp` 被忽略，按 `OKAY` 处理 |
| AW | 出 | 行对齐地址，`INCR`，`len=1`，`size=5`，`id=0` |
| W | 出 | 2 拍，`strb` 全 1 |
| B | 入 | `resp` 被忽略 |

### 6.3 AxiLite4 控制端口（ctrl）

地址 8 位、数据 32 位，字段为 `aw`/`w`/`b`/`ar`/`r` 的 `valid`/`ready`、`addr`、`prot`、`data`、`strb`、`resp`。

## 7. 数据表示规范

### 7.1 地址划分

| 字段 | 位（默认配置） | 位宽 | 说明 |
|---|---|---|---|
| tag | `[31:15]` | 17 | 与 tag 阵列比较 |
| set index | `[14:6]` | 9 | 512 组 |
| byte offset | `[5:0]` | 6 | 64B 行 |
| beat index | `[5:5]` | 1 | 2 拍，每拍 32 字节 |

通用公式：`setBits = log2Ceil(sets)`，`offsetBits = log2Ceil(lineBytes)`，`tagBits = addressWidth − setBits − offsetBits`，`beatsPerLine = lineBytes × 8 / dataWidth`。

### 7.2 行内布局

一行 = `beatsPerLine` 拍，每拍 `dataWidth` 位，按小端字节通道排列：beat `i` 的字节 `b` 位于 line 字节 `i × bytePerBeat + b`。`strb` 逐字节有效，`strb[b]` 对应 `data[8b+7:8b]`。

### 7.3 ID 与分区映射

`partitionId = id[log2Ceil(wayPartitions)−1 : 0]`；默认 `wayPartitions=2`，即 `id[0]`。`wayPartitions=1` 时不使用 `id`。路 `w` 属于分区 `w / waysPerPartition`。

## 8. 配置与寄存器规范

### 8.1 默认编译期配置

| 参数 | 默认值 | 含义 |
|---|---|---|
| `capacity` | 262144 | 总容量（字节） |
| `ways` | 8 | 相联度 |
| `lineBytes` | 64 | 行大小（字节） |
| `addressWidth` | 32 | 地址位宽 |
| `dataWidth` | 256 | AXI4 数据位宽 |
| `idWidth` | 4 | AXI4 ID 位宽 |
| `mshrEntries` | 4 | MSHR 项数 |
| `wbBufEntries` | 4 | 写回缓冲项数 |
| `wmBufEntries` | 4 | 写合并缓冲项数，一笔未冲刷的写 burst 占一项 |
| `bFifoDepth` | 4 | B 响应跟踪项数，必须为 2 的幂 |
| `wayPartitions` | 2 | way 分区数 |
| `ctrlAddrWidth` | 8 | 控制端口地址位宽 |
| `ctrlDataWidth` | 32 | 控制端口数据位宽 |

派生量：`sets = capacity / (ways × lineBytes)`，`bytePerBeat = dataWidth / 8`。

### 8.2 编译期约束

- `capacity`、`ways`、`lineBytes`、`sets`、`dataWidth` 必须为 2 的幂；`dataWidth ≥ 8`。
- `ways % wayPartitions == 0`。
- `mshrEntries ≥ 1`，`wbBufEntries ≥ 1`，`wmBufEntries ≥ 1`；`bFifoDepth` 为 2 的幂（≥ 1）。
- `lineBytes × 8 ≥ dataWidth`。
- `addressWidth > setBits + offsetBits`。
- Tree-PLRU 要求 `ways >= 2`（8.2 节已要求为 2 的幂），树位宽为 `ways - 1`。

### 8.3 寄存器索引总表

地址空间 256 字节，按字节寻址，32 位对齐访问。

| 地址 | 名称 | 访问 | 含义 |
|---|---|---|---|
| `0x00` | `LLC_CTRL` | RW | flush / invalidate 触发位，见 8.4 |
| `0x04` | `LLC_STATUS` | RO | 状态位，见 8.5 |
| `0x08` | `WAY_PARTITION_CFG` | RW | 分区映射配置，见 8.6 |
| `0x0C` | 保留 | — | — |
| `0x10`–`0x8F` | `PERF_CNTn_LO/HI` | RO | 16 个 64 位计数器，`n` 的低/高 32 位分别位于 `0x10 + 8n` / `0x14 + 8n` |
| `0x90` | `PERF_CNT_CLR` | W1P | 写 1 清零全部性能计数器 |
| 其他 | 保留 | — | 读写效果未定义 |

### 8.4 LLC_CTRL（0x00）

| 位 | 名称 | 复位值 | 说明 |
|---|---|---|---|
| 0 | enable | 0 | 保留，无硬件效果 |
| 1 | flush | 0 | 写 1 启动 clean-flush |
| 2 | invalidate | 0 | 写 1 启动 invalidate；两位同时为 1 时 invalidate 优先 |
| 31:3 | — | 0 | 保留 |

flush 或 invalidate 任一位置 1 构成请求；请求的上升沿且遍历状态机空闲时启动。再次触发前必须先写 0。

### 8.5 LLC_STATUS（0x04）

| 位 | 名称 | 说明 |
|---|---|---|
| 0 | wbBufEmpty | 写回缓冲为空 |
| 1 | wbBufFull | 写回缓冲已满 |
| 2 | mshrFull | 当拍出现因 MSHR 满而停住，为单拍脉冲，不是稳定电平 |
| 3 | wmBufFlushing | 写合并缓冲正在冲刷 |
| 4 | flushBusy | flush/invalidate 遍历进行中 |
| 5 | flushDone | 最近一次 flush/invalidate 完成，sticky，启动新一次时清除 |
| 31:6 | — | 读 0 |

### 8.6 WAY_PARTITION_CFG（0x08）

16 位读写字段，复位值 0。当前 RTL 中该字段未接入任何逻辑，写入不影响分区映射，分区映射固定为 7.3 节的静态规则。

### 8.7 PERF_CNT（0x10–0x8F）

| 索引 `n` | 事件 |
|---|---|
| 0 | 读命中次数 |
| 1 | 读未命中次数 |
| 2 | 写命中次数 |
| 3 | 写未命中次数 |
| 4 | 脏行淘汰次数 |
| 5 | 干净行淘汰次数 |
| 6 | MSHR 满导致的停住周期数 |
| 7 | 写回缓冲满的周期数 |
| 8 | 写合并次数 |
| 9 | 取回完成次数 |
| 10–15 | 保留，恒读 0 |

低、高 32 位分两次读取，不保证原子；需要一致快照时应在流量静止时读取。

### 8.8 PERF_CNT_CLR（0x90）

位 0 写 1 产生一个清零脉冲，全部计数器清零；读回 0。

## 9. 时序与复位规范

### 9.1 时钟与复位

同步高有效复位。复位后：读写状态机、下游状态机、B FIFO、MSHR 项、写回缓冲、写合并缓冲、flush 遍历状态机、性能计数器均在空闲态，cache 为空。

tag 阵列的 `valid` 位在带复位的寄存器中，复位后全部为 0；SRAM 中的 tag、`dirty` 位与数据阵列的内容未定义，只在 `valid` 置位时才被读取，因此不需要复位初始化。PLRU 状态在 SRAM 中，复位后同样未定义：任何树状态都给出一个合法的 victim，替换选择在相应组各路都被访问过后才完全由访问历史决定。

### 9.2 在途约束

- 同时最多 1 笔读、1 笔写；读的 R 突发结束、写的全部 W 拍收完之前，对应通道的 `ready` 不再置起。
- 下游同时最多 1 个 AR、1 个 AW 在途。
- flush/invalidate 遍历期间不接接受任何读写请求。

### 9.3 下游时序要求

下游可以在 AR 握手后的下一拍给出首个 R 数据；R 各拍与 W 各拍均应连续。

## 10. 异常处理规范

- 合法 burst：`INCR`、`size = log2(bytePerBeat)`、地址按拍对齐，且整笔 burst 落在单个 cache line 内（首个拍的行内位置 + `len` ≤ `beatsPerLine-1`）。落在单个 line 内的 burst 不会跨 4KB 边界。
- 不满足上述条件的 burst 返回 `SLVERR`（LLC-F017），不进入流水线：读返回 `len+1` 拍零数据，`last` 在末拍；写收完全部 `len+1` 拍后丢弃并返回一次 B。非法写的 B 排在更早的写之后。
- LLC 不产生 `DECERR`。非法事务不记录到任何寄存器，也不置任何状态位。
- 下游 `RRESP`/`BRESP` 被忽略；下游错误不会向上游传播，也不会记录到任何寄存器。
- 不支持按地址属性区分可缓存性，所有访问一律按可缓存处理。

## 11. 状态与观测规范

### 11.1 运行状态

`LLC_STATUS` 是唯一的运行状态来源：`flushBusy` 表示维护操作进行中，`flushDone` 为完成 sticky 位，其余位反映缓冲占用。没有“全局 idle”指示位；判断 LLC 是否空闲需要同时满足无在途事务、`wbBufEmpty=1`、`wmBufFlushing=0`、`flushBusy=0`。

### 11.2 性能事件

事件定义见 8.7。事件由流水线与缓冲的内部信号直接产生，按拍计数。

- 每个进入流水线的请求计一次命中或未命中：在 S2 被取回冲掉后重放的请求只在重放后计一次；等在途取回完成的写重放后计为写命中，不计未命中。
- 淘汰计数只在分配 MSHR 项时产生，一次分配计一次干净或脏淘汰；fill 到无效路的分配不计。
- flush 遍历自身的写回不产生任何事件。
- 第 6、7 项按信号电平计拍，不是事件次数。

### 12.2 结构性处理拍数

以下由 RTL 结构推出，未逐拍仿真核对。

| 场景 | 拍数 |
|---|---|
| 读命中，AR 握手到 R 有效 | 约 6 拍：snoop 1 拍，流水线 3 拍，响应寄存与状态切换 2 拍 |
| 流水线连续请求 | 1 个 / 2 拍 |
| 读未命中（无写回） | 分配后：下游 AR 握手 + R 2 拍 + 写回 line；目标拍到达即可早响应 |

| flush / invalidate | 每组 2 拍（tag 读发出、读出并判定）；每条脏行另加 5 拍（data 读发出、读出、写回入队、写 tag、重新判定），写回缓冲满时入队等待；invalidate 下每条干净行另加 2 拍 |

### 12.3 实测指标边界

本版没有纳入测试集的性能测试。修订本版时用临时探针仿真（下游读写零延迟、读数据 2 拍后到达）观测到：

- 空 cache 执行一次 clean-flush 为 1032 拍（每组 2 拍）；每条脏行另加 5 拍：4 路为脏时 11284 拍，8 路全脏时约 2.15 万拍。遍历期间下游读写零延迟、读数据 2 拍后到达。
- 整行写命中后 B 响应不返回，因此写时延无法测得。

## 13. 集成与使用规范

### 13.1 基本使用流程

1. 释放复位。
2. 发起读写事务。读必须满足：`INCR`、`size=5`、32 字节对齐地址、整笔 burst 落在单个 line 内（`len=0` 可落在任意一拍，`len=1` 须从 line 首拍开始）；写的要求相同。不满足的事务返回 `SLVERR`（第 10 章）。
3. 需要把脏数据写回下游时执行 flush（第 5.8 节流程）；需要丢弃全部内容时执行 invalidate。
4. 需要性能数据时读取 `PERF_CNT`，使用 `PERF_CNT_CLR` 清零。

第 2 步的写事务中，单拍写与整行写（命中与未命中）数据正确并各返回一次 B；其余限制见第 3.5 节。

### 13.2 重复执行

- 再次触发 flush/invalidate 前必须先把 `LLC_CTRL` 写 0，否则没有新的上升沿。
- `flushBusy=1` 期间写入的触发位被静默丢弃，软件必须在 busy 清除后再触发。
- 同一时刻读写各最多 1 笔在途，上游 master 不得依赖多笔并发。

### 13.3 地址与 burst 要求

- 上游 burst 必须按 32 字节对齐，且不得跨 cache line；`len=0` 的读写支持 line 内任意一拍，`len ≥ 1` 的读写只支持从 line 首拍开始。不满足时返回 `SLVERR`（第 10 章）。

### 13.4 Cache 与一致性

LLC 不含一致性机制，也不与上游 cache 保持 inclusion。软件必须：

- 其他发起方（DMA、其他 master）改写下游内存后，在读取这些地址前执行 invalidate；
- LLC 改写过的区域要被其他发起方读取前，执行 flush 并等待 `flushDone`。

### 14.2 不属于规格支持功能的项目

以下能力当前不实现，也不在本文契约内：

- 缓存一致性、inclusion、snoop 过滤、原子操作；
- WRAP / FIXED burst、窄传输（`size` 小于数据位宽）、非对齐访问（这些 burst 返回 `SLVERR`，第 10 章）；
- 按地址属性选择的可缓存 / 不可缓存访问；
- 按 line 或按组的单点维护操作、按 tag 的 hit/invalid 查询（上游请求带 flush 标记的按 line 维护已有需求，标记走 AXI `user` 还是控制口寄存器、clean 还是 invalidate 语义、完成如何反馈均未定）；
- ECC、`DECERR` 与错误记录、中断输出；
- 写合并缓冲的驻留超时、同一 line 的 MSHR 请求合并；
- 可配置的 way 分区映射、按 ID 配置的 QoS 策略、每分区独立的 PLRU；
- 周期计数器、寄存器访问超时保护。

### A.1 关键公式

- `sets = capacity / (ways × lineBytes)`
- `offsetBits = log2Ceil(lineBytes)`，`setBits = log2Ceil(sets)`，`tagBits = addressWidth − setBits − offsetBits`
- `beatsPerLine = lineBytes × 8 / dataWidth`，`bytePerBeat = dataWidth / 8`
- `waysPerPartition = ways / wayPartitions`
- `partitionId = id[log2Ceil(wayPartitions) − 1 : 0]`（`wayPartitions > 1`）
- beat index = `addr[offsetBits − 1 : log2Ceil(bytePerBeat)]`；写 burst 第 i 拍的 beat index = `beat index + i`（i 为 burst 内拍序号，不跨 line）
- 写回/取回 burst：地址 = `{tag, set, offsetBits 个 0}`，`AxLEN = beatsPerLine − 1`，`AxSIZE = log2Ceil(bytePerBeat)`
